## 1. 秘匿化（暗号化）フロー

### 1-1. 暗号化フロー

```
[フロントエンド]                        [バックエンド]
     │
     │  ① 要素選択・秘匿レベル設定
     │  ② 鍵を設定（生成/ファイル読込）
     │
     │ POST /api/v1/encryption/projects/:name/encrypt
     │ ─────────────────────────────────────────────────→
     │                                    │
     │                                    ├─ UPA制約チェック（maimlSchemaHelper）
     │                                    │    └─ 違反あり → エラー返却
     │                                    │
     │                                    ├─ MAIMLをストレージから取得
     │                                    │
     │                                    ├─ 対象要素を選択（XPath）
     │                                    │
     │                                    ├─ 鍵を取得（テストモード: 固定ファイル参照）
     │                                    │
     │                                    ├─ AES暗号化
     │                                    │    ├─ L1: 要素全体を暗号化
     │                                    │    └─ L2: コンテンツのみ暗号化
     │                                    │
     │                                    ├─ <EncryptedData>に変換・MAIML埋め込み
     │                                    │
     │                                    ├─ 鍵メタデータをDB保存（encryption_keys）
     │                                    │
     │                                    └─ 更新済みMAIMLをストレージへ保存
     │
     │ ←─────────────────────────────────────────────────
     │  ③ 成功レスポンス・ツリー更新
```

### 1-2. 復号化フロー

```
[フロントエンド]                        [バックエンド]
     │
     │  ① <EncryptedData>要素を選択
     │  ② 復号化用鍵を選択
     │
     │ POST /api/v1/encryption/projects/:name/decrypt
     │ ─────────────────────────────────────────────────→
     │                                    │
     │                                    ├─ MAIMLをストレージから取得
     │                                    │
     │                                    ├─ <EncryptedData>要素を特定
     │                                    │
     │                                    ├─ 鍵を取得（key_identifierで引き当て）
     │                                    │
     │                                    ├─ AES復号化
     │                                    │
     │                                    ├─ 元の要素に復元（<EncryptedData>を除去）
     │                                    │
     │                                    └─ 更新済みMAIMLをストレージへ保存
     │
     │ ←─────────────────────────────────────────────────
     │  ③ 成功レスポンス・ツリー更新
```

## 2. 改竄防止（署名）フロー

### 2-1. 署名フロー（signMaiml）

```
[フロントエンド]                [バックエンド（maimlIntegrityService）]
     │
     │ POST /api/v1/signature/projects/:name/sign
     │ ────────────────────────────────────────→
     │                              │
     │                              ├─ S-1: MAIMLをストレージから取得
     │                              │
     │                              ├─ S-2: excl-C14N正規化 + SHA-256
     │                              │       → DigestValue 計算
     │                              │
     │                              ├─ S-3: 秘密鍵取得
     │                              │       （テストモード: test-keys/signing/private.pem）
     │                              │
     │                              ├─ S-4: RSA署名 → SignatureValue 生成
     │                              │
     │                              ├─ S-5: TSQ構築
     │                              │       <SignatureValue>をXMLフラグメントにラップし
     │                              │       computeCanonicalHashOfFragment() で
     │                              │       excl-C14N正規化後にSHA-256
     │                              │
     │                              ├─ S-6: TSAへリクエスト
     │                              │   ⚠️ 意図的未実装: local-mock のみ
     │                              │      外部TSA通信は throw で安全に停止
     │                              │
     │                              ├─ S-7: TSR受信・TSTを取得
     │                              │       verifyMessageImprintAndNonce() で
     │                              │       messageImprint/nonce を検証
     │                              │       失敗時は例外スロー
     │                              │
     │                              ├─ S-8: XAdES-T形式の<Signature>XML構築
     │                              │       <xades:UnsignedProperties>/
     │                              │       <xades:UnsignedSignatureProperties> 配下に
     │                              │       <xades:SignatureTimeStamp> を格納（XAdES-T仕様準拠）
     │                              │
     │                              ├─ S-9: MAIMLに<Signature>を追記・ストレージ保存
     │                              │
     │                              └─ S-10: 監査ログ記録（integrity_audit_log）
     │
     │ ←────────────────────────────────────────
     │  署名済みレスポンス
```

### 2-2. 検証フロー（verifyMaiml）

```
[フロントエンド / curl]         [バックエンド（maimlIntegrityService）]
     │
     │ POST /api/v1/signature/projects/:name/verify
     │ ────────────────────────────────────────→
     │                              │
     │                              ├─ V-1: MAIMLから<Signature>要素取得
     │                              │
     │                              ├─ V-2: <UnsignedSignatureProperties>からTST取得
     │                              │       <xades:UnsignedSignatureProperties> 配下の
     │                              │       <xades:SignatureTimeStamp> →
     │                              │       <xades:EncapsulatedTimeStamp> を取得
     │                              │       （旧構造への2段階フォールバックあり）
     │                              │
     │                              ├─ V-3: TSTの正当性検証
     │                              │   ⚠️ 意図的未実装: local-mockのみ有効
     │                              │      外部TSAは isValid:false + reason で安全に拒否
     │                              │      本来: CMS署名検証・EKU確認・証明書チェーン
     │                              │
     │                              ├─ V-4: messageImprint・nonce一致確認
     │                              │       verifyMessageImprintAndNonce() で検証
     │                              │       失敗時は overallValid=false に反映
     │                              │
     │                              ├─ V-5: SignatureValue検証
     │                              │       公開鍵で復号 → DigestValueと照合
     │                              │
     │                              ├─ V-6: MAIML再C14N正規化 → SHA-256
     │                              │       → DigestValueと比較（改ざん検知）
     │                              │
     │                              ├─ V-7: genTime確認
     │                              │       extractMaimlDate() でMAIML内<date>要素取得
     │                              │       <date>要素が存在しない場合はエラースロー
     │                              │
     │                              ├─ V-8: 証明書有効性確認
     │                              │   ⚠️ 意図的未実装: 有効期限チェックは実装済み
     │                              │      CRL/OCSP拡張情報の検出ロジックも実装済みだが
     │                              │      実HTTPアクセスによる失効確認は未実装
     │                              │
     │                              ├─ V-9: 総合判定
     │                              │       overallValid = 全ステップの AND
     │                              │
     │                              └─ V-10: 監査ログ記録（integrity_audit_log）
     │
     │ ←────────────────────────────────────────
     │  { overallValid, hashMatch, signatureValid,
     │    certificateValid, timestampValid, ... }
```

## 3. 秘匿化と改竄防止の組み合わせフロー

### 推奨実行フロー

```
[MAIMLファイル準備]
       │
       ▼
[秘匿化：暗号化]  ← POST /encryption/projects/:name/encrypt
       │              対象要素 → <EncryptedData>に変換
       │              MAIMLが更新される
       │
       ▼
[改竄防止：署名]  ← POST /signature/projects/:name/sign
       │              暗号化済みMAIML全体にC14N + SHA-256
       │              RSA署名 → タイムスタンプ → <Signature>埋め込み
       │
       ▼
[改竄防止：検証]  ← POST /signature/projects/:name/verify
       │              <Signature>の正当性確認
       │              改ざんあり/なし判定
       │
       ▼
[秘匿化：復号化]  ← POST /encryption/projects/:name/decrypt
                     必要な要素のみ復号化
```

> ⚠️ **注意**: 署名済みのMAIMLに対して暗号化を実行した場合、MAIMLの内容が変更されるため**既存の署名が無効**になります。暗号化後は必ず再署名してください。

### 状態遷移

```
[未処理]
   │ 暗号化
   ▼
[暗号化済み]                   [署名済み]
   │ 署名                          │ 改ざん
   ▼                              ▼
[暗号化済み＋署名済み]      [改ざん検知]
   │ 検証(OK)                      │ 検証(NG)
   ▼                              ▼
[正当性確認済み]            [検証失敗・要調査]
   │ 復号化
   ▼
[復号化済み＋署名済み]
```
