# リリースノート作成ガイド

## 概要

このドキュメントは、mmdpf プロジェクトにおけるリリースノートの作成手順・テンプレート・記載ルールを定義します。

---

## 1. 情報収集手順

### 1-1. コミット一覧の取得

```bash
git log --oneline <前回リリースのコミットハッシュ>..<今回リリースのコミットハッシュ>
```

### 1-2. 詳細変更の確認

各コミットの変更内容は以下を参照して把握する：

- `docs/` 配下のタスクフォルダ（例: `docs/20260409_1124_MAIML編集属性制限対応/PLAN.md`）
- PR のマージコミットに含まれるブランチ名・PR 番号

### 1-3. マイグレーションファイルの確認

```bash
git diff --name-only <前回ハッシュ>..<今回ハッシュ> -- backend/migrations/
```

## 3. セクション記載ルール

### 新機能・改善

- 機能単位でまとめ、番号付きの見出しで整理する
- 改善仕様書番号がある場合は見出しに付記する（例: `（改善仕様書 No.2）`）
- 各機能の中のサブ項目は `**太字**:` で始める
- 技術的な変数名・ファイル名はバッククォートで囲む

### バグ修正

- 修正したバグを機能単位またはモジュール単位で整理する
- 修正前の問題と修正後の動作を簡潔に記載する

### インフラ・デプロイ対応

- アプリケーションのソースコード変更ではなく、インフラ・ビルド・デプロイに関する変更を記載する

### DB マイグレーション

- `backend/migrations/` 配下に追加されたSQLファイルを一覧化する
- ファイル名と変更内容（カラム追加・テーブル作成 等）を記載する

### 主な変更ファイル

- 新規作成ファイルには **（新規）** と付記する
- 重要な変更のみ抜粋し、全ファイルを列挙しない
- バックエンドとフロントエンドで分けて記載する

---

## 4. 保存ルール

| 項目 | 規則 |
|-----|------|
| 保存先 | `docs/deliverables/` |
| ファイル名 | `release_notes_YYYYMMDD.md`（リリース日付） |
| 例 | `docs/deliverables/release_notes_20260413.md` |

---

## 5. 記載しないもの

以下は原則としてリリースノートに含めない：

- 個々のコミットハッシュ一覧（コミット一覧セクション）
- テストコードのみの変更
- ドキュメント（`docs/`）のみの変更
- リファクタリングのみで機能変化がない変更
