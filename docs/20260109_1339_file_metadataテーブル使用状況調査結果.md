## ❌ file_metadataが使用されていない箇所

### ファイル一覧取得（listingRoutes.js）

**理由:**
- S3が常に最新の状態を保持
- DBとS3の同期問題を回避
- リアルタイム性を優先

  const checkoutQuery = `

  `;

**設計思想:**
- **Single Source of Truth**: S3がファイル情報の真実の情報源
- **整合性**: DBとS3の同期ずれを防ぐ
- **シンプルさ**: 複雑な同期ロジック不要

// backend/src/routes/fileUploadRoutes.ts

export const uploadFile = async (req: Request, res: Response) => {
  const { organizationId } = req.tenantContext;
  const file = req.file;
  
  try {
    // Step 1: S3にアップロード
    const s3Key = await uploadToS3(organizationId, file);
    
    // Step 2: file_metadataに保存
    const metadata = await fileMetadataService.saveFileMetadata({
      organizationId,
      fileKey: s3Key,
      originalFilename: file.originalname,
      fileSize: file.size,
      fileType: file.mimetype,
      uploadedBy: req.user.userId,
      isMaimlFile: file.originalname.endsWith('.maiml')
    });
    
    // Step 3: MAIMLファイルなら解析開始
    if (metadata.isMaimlFile) {
      // 非同期で解析実行
      maimlParserService.parseFile(organizationId, s3Key);
    }
    
    res.json({
      success: true,
      file: metadata
    });
    
  } catch (error) {
    console.error('Upload error:', error);
    res.status(500).json({
      success: false,
      error: 'File upload failed'
    });
  }
};

// backend/src/services/maimlParserService.ts

export class MaimlParserService {
  async parseFile(organizationId: string, fileKey: string) {
    try {
      // Step 1: S3からファイル取得
      const fileContent = await s3Service.getFileContent(fileKey);
      
      // Step 2: XML解析
      const parsedData = await this.parseXml(fileContent);
      
      // Step 3: file_metadataに解析結果保存
      await fileMetadataService.updateMaimlAnalysisResult(
        organizationId,
        fileKey,
        {
          transitionsCount: parsedData.transitions.length,
          placesCount: parsedData.places.length,
          arcsCount: parsedData.arcs.length,
          nodes: parsedData.nodes,
          transitions: parsedData.transitions
        }
      );
      
      console.log(`✅ MAIML解析完了: ${fileKey}`);
      
    } catch (error) {
      console.error(`❌ MAIML解析エラー: ${fileKey}`, error);
      
      // エラー情報も保存
      await fileMetadataService.updateMaimlAnalysisResult(
        organizationId,
        fileKey,
        {
          maimlAnalysisStatus: 'failed',
          maimlErrorCount: 1
        }
      );
    }
  }
}

## ⚠️ 注意点とベストプラクティス

### 1. S3とDBの整合性

**DO（推奨）:**
```typescript
// ✅ S3アップロード成功後にDBに保存
const s3Key = await uploadToS3(file);  // S3アップロード
await saveFileMetadata({ fileKey: s3Key });  // DB保存
```

**DON'T（非推奨）:**
```typescript
// ❌ DB保存してからS3アップロード
await saveFileMetadata({ fileKey: s3Key });  // DB保存
await uploadToS3(file);  // S3アップロード（失敗したらDBに不整合）
```

### 2. マルチテナント分離

**DO（推奨）:**
```typescript
// ✅ すべてのクエリにorganization_idフィルタ
const query = `
  SELECT * FROM file_metadata
  WHERE organization_id = $1 AND file_key = $2
`;
```

**DON'T（非推奨）:**
```typescript
// ❌ organization_idフィルタなし
const query = `
  SELECT * FROM file_metadata
  WHERE file_key = $1
`;
```

### 3. JSONB型の活用

**DO（推奨）:**
```typescript
// ✅ JSONB型で柔軟に保存
await db.query(`
  UPDATE file_metadata
  SET maiml_nodes = $1::jsonb
  WHERE file_key = $2
`, [JSON.stringify(nodes), fileKey]);
```

-- ✅ 複合インデックス（よく使う組み合わせ）
CREATE INDEX idx_file_metadata_org_maiml
