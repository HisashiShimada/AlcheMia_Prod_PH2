## 3. 差異分析結果

### 3.1. 組織追加ダイアログの差異

#### ❌ 差異1: フィールド名の不一致

**設計書:**
- 組織CD（organizationCd）
- 組織表示名（organizationDisplayName）
- 組織e-mail（organizationEmail）
- 代表システム管理者名（chiefUserName）
- 代表者メールアドレス（chiefUserEmail）
- 会社名（corporationId）- Select
- 二段階認証判定（isEntry）- Radio: 有効(1) / 無効(0)
- 状態（isActive）- Radio: アクティブ / 非アクティブ

**現実装:**
- 組織CD（organizationCd）✅
- 組織表示名（organizationDisplayName）✅
- 組織e-mail（organizationEmail）✅
- 代表システム管理者（chiefUserName）✅
- 代表者メールアドレス（chiefUserEmail）✅
- 会社名（corporationId）✅
- 二段階認証判定（isEntry）- **Select**: なし(0) / あり(1) ❌
- 状態（isActive）- **Select**: アクティブ / 非アクティブ ❌

**問題点:**
- 二段階認証判定と状態がSelectで実装されている（設計書ではRadio）
- 二段階認証判定の選択肢が「有効/無効」ではなく「あり/なし」

#### ❌ 差異2: パスワード確認フィールドの追加

**設計書:** パスワード確認フィールドなし

**現実装:**
```typescript
<Form.Item name="confirmChiefUserPassword" label="代表者パスワード確認">
  <Input.Password />
</Form.Item>
```

**問題点:** 設計書に記載されていないフィールドが実装されている

#### ❌ 差異3: バリデーションメッセージの不一致

**設計書:**
```typescript
{
  pattern: /^[a-zA-Z0-9_-]+$/,
  message: '組織CDは英数字、アンダースコア、ハイフンのみ使用できます'
}
```

**現実装:** このバリデーションが未実装

#### ❌ 差異4: 組織CD重複チェック機能の欠如

**設計書:** リアルタイム重複チェック（500msデバウンス）、背景色を黄色に変更

**現実装:** 重複チェック機能が未実装

#### ❌ 差異5: プレースホルダーの不一致

**設計書:**
- 組織CD: 「組織CDを入力」
- 組織表示名: 「組織表示名を入力」
- 組織e-mail: 「organization@example.com」
- 代表システム管理者名: 「管理者名を入力」
- 代表者メールアドレス: 「admin@example.com」

**現実装:**
- 組織CD: 「maiml_lab_001」
- 組織表示名: 「MAIML研究所」
- 組織e-mail: 「sample@sample.co.jp」
- 代表システム管理者: 「サンプル　太郎」
- 代表者メールアドレス: 「sample@sample.co.jp」

#### ❌ 差異11: 検索プレースホルダー

**現実装:** 「組織CD、組織e-mail、代表システム管理者、更新日時で検索」✅

#### ❌ 差異12: 二段階認証判定の表示

**設計書:**
```typescript
render: (isEntry: number) => (
  <Badge 
    status={isEntry === 1 ? 'success' : 'default'} 
    text={isEntry === 1 ? '有効' : '無効'} 
  />
)
```

**現実装:**
```typescript
render: (value: number) => (
  <Text>{value === 1 ? 'あり' : 'なし'}</Text>
)
```

**問題点:** BadgeコンポーネントではなくTextで実装、テキストが「有効/無効」ではなく「あり/なし」


**現実装:**
```typescript

<Button icon={<EditOutlined />}>編集</Button>
<Button>アクティブ / 非アクティブ</Button>
```

**問題点:** 証明書ダウンロードボタンが追加されている（設計書にはない）
