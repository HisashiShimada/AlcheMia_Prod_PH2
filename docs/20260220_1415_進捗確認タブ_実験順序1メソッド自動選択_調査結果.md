# 調査結果: メソッド自動選択が動作しない問題

## 📋 問題の症状

プロジェクト選択時に、メソッドが自動選択されない。

## 🔍 原因の特定

### 問題のコード

```typescript
// 現在の実装（149-155行目）
useEffect(() => {
  if (methods.length > 0 && !selectedMethodId) {
    // 実験順序でソートして最も小さいメソッドを選択
    const sortedMethods = [...methods].sort((a, b) => a.experimentOrder - b.experimentOrder);
    onSelectMethod(sortedMethods[0].methodId);
  }
}, [methods, selectedMethodId, onSelectMethod]);
```

### 根本原因

**`!selectedMethodId` という条件が問題**

1. **初回プロジェクト選択時**: 
   - `selectedMethodId`は`null`なので、条件を満たし、メソッドが自動選択される ✅

2. **2回目以降のプロジェクト選択時**:
   - 前のプロジェクトの`selectedMethodId`が残っている
   - `!selectedMethodId`が`false`になるため、useEffectの中身が実行されない ❌
   - 結果: メソッドが自動選択されない

### 具体例

```
1. プロジェクトAを選択
   → selectedMethodId = null
   → メソッド1が自動選択される
   → selectedMethodId = "method_1"

2. プロジェクトBを選択
   → selectedMethodId = "method_1" （プロジェクトAのメソッドIDが残っている）
   → !selectedMethodId が false
   → useEffectが実行されない
   → メソッドが自動選択されない ❌
```

## 💡 解決策

### 解決策1: プロジェクト変更を検知して強制選択（推奨）

プロジェクトIDを依存配列に追加し、プロジェクトが変わったことを検知してメソッドを強制的に選択する。

```typescript
useEffect(() => {
  if (methods.length > 0) {
    // 実験順序でソートして最も小さいメソッドを選択
    const sortedMethods = [...methods].sort((a, b) => a.experimentOrder - b.experimentOrder);
    onSelectMethod(sortedMethods[0].methodId);
  }
}, [methods, onSelectMethod]);
```

**変更点:**
- `!selectedMethodId`条件を削除
- `selectedMethodId`を依存配列から削除
- プロジェクト変更で`methods`が変わるたびに、常に最小の実験順序のメソッドを選択

**メリット:**
- プロジェクト切り替え時に確実にメソッドが自動選択される
- シンプルで分かりやすいロジック

**懸念点:**
- ユーザーが手動でメソッドを選択した後、何らかの理由で`methods`が再設定されると、選択がリセットされる可能性がある
  - ただし、現在の実装では`methods`はプロジェクト選択時のみ変更されるため、実質的に問題ない

### 解決策2: プロジェクトIDを追跡して条件判定

プロジェクトIDが変わったときのみメソッドを選択する。

```typescript
useEffect(() => {
  if (methods.length > 0) {
    // プロジェクトが変わった場合、または選択されていない場合
    const currentProjectMethods = methods.map(m => m.methodId);
    const isSelectedMethodInProject = selectedMethodId && currentProjectMethods.includes(selectedMethodId);
    
    if (!isSelectedMethodInProject) {
      // 実験順序でソートして最も小さいメソッドを選択
      const sortedMethods = [...methods].sort((a, b) => a.experimentOrder - b.experimentOrder);
      onSelectMethod(sortedMethods[0].methodId);
    }
  }
}, [methods, selectedMethodId, onSelectMethod]);
```

**メリット:**
- 現在のプロジェクト内でユーザーが手動選択した場合、それを維持できる
- プロジェクトが変わったときのみ自動選択される

**デメリット:**
- ロジックが複雑になる

## 🎯 推奨解決策

**解決策1**を推奨します。

理由:
1. シンプルで分かりやすい
2. プロジェクト切り替え時に確実に動作する
3. 現在の実装では`methods`の変更 = プロジェクト変更なので、副作用がない

## 📝 実装方針

1. useEffectの条件から`!selectedMethodId`を削除
2. 依存配列から`selectedMethodId`を削除
3. プロジェクト変更時（methodsが変わるとき）に常に最小の実験順序のメソッドを選択

## ✅ 期待される動作

- プロジェクトAを選択 → 実験順序が最小のメソッドが自動選択
- プロジェクトBに切り替え → 実験順序が最小のメソッドが自動選択
- 同じプロジェクト内でメソッドを手動選択 → 選択が維持される（methodsが変わらないため）
