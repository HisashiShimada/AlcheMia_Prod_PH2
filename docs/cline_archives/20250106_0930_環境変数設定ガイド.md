# 環境変数設定ガイド

## 概要

mmdpfアプリケーション（フロントエンドとバックエンド）の動作に必要な環境変数の設定方法を説明します。

## バックエンド環境変数

### 設定ファイル: `backend/.env`

以下の内容で `backend/.env` ファイルを作成してください。テンプレートとして `backend/.env.example` を参考にできます。

```bash
# .env.exampleをコピーして.envを作成
cd backend
cp .env.example .env
```

### 必須環境変数

#### `JWT_SECRET`（重要）
- **説明**: JWT認証に使用する秘密鍵
- **必須**: はい
- **セキュリティ**: 本番環境では必ず変更してください
- **生成方法**:
```bash
# セキュアなランダム文字列を生成
node -e "console.log(require('crypto').randomBytes(64).toString('hex'))"
```
- **例**: `a1b2c3d4e5f6...`（64文字以上推奨）

#### `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`
- **説明**: PostgreSQLデータベース接続情報
- **必須**: はい
- **デフォルト値**: 
  - `DB_HOST`: `localhost`
  - `DB_PORT`: `5432`
  - `DB_NAME`: `mmdpf_dev`
  - `DB_USER`: `postgres`
  - `DB_PASSWORD`: （設定が必要）

#### その他の環境変数

詳細は `backend/.env.example` を参照してください。

### バックエンドの起動

環境変数を設定後、バックエンドを起動します。

```bash
cd backend
npm run dev
```

**注意**: `JWT_SECRET`が設定されていない場合、以下のエラーが発生します。

```
Error: JWT_SECRET environment variable is required. 
Please set JWT_SECRET in your .env file. 
See docs/20250106_0930_環境変数設定ガイド.md for details.
```

## フロントエンド環境変数

### 設定ファイル: `frontend/.env.local`

以下の内容で `frontend/.env.local` ファイルを作成してください。

```bash
# バックエンドAPIのベースURL
NEXT_PUBLIC_API_URL=http://localhost:3001

# 組織ID（開発環境用）
# 注意: UUIDフォーマットである必要があります
NEXT_PUBLIC_ORGANIZATION_ID=00000000-0000-0000-0000-000000000001
```

### 環境変数の説明

#### `NEXT_PUBLIC_API_URL`
- **説明**: バックエンドAPIのベースURL
- **デフォルト値**: `http://localhost:3001`
- **本番環境**: 本番サーバーのURLに変更してください
- **例**: 
  - 開発環境: `http://localhost:3001`
  - 本番環境: `https://api.yourdomain.com`

#### `NEXT_PUBLIC_ORGANIZATION_ID`
- **説明**: 開発環境で使用する組織ID
- **形式**: UUID（xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx）
- **注意**: 
  - この値はバックエンドの `organization` テーブルに存在する必要があります
  - 本番環境では、ログイン時にユーザーが選択した組織IDを使用します
  - 開発環境では固定値を使用して動作確認を行います

### 環境別の設定

#### 開発環境
```bash
NEXT_PUBLIC_API_URL=http://localhost:3001
NEXT_PUBLIC_ORGANIZATION_ID=00000000-0000-0000-0000-000000000001
```

#### ステージング環境
```bash
NEXT_PUBLIC_API_URL=https://api-staging.yourdomain.com
NEXT_PUBLIC_ORGANIZATION_ID=<ステージング環境の組織ID>
```

#### 本番環境
```bash
NEXT_PUBLIC_API_URL=https://api.yourdomain.com
NEXT_PUBLIC_ORGANIZATION_ID=<本番環境の組織ID>
```

## 設定手順

### 1. ファイル作成

```bash
cd frontend
touch .env.local
```

### 2. 内容を記述

エディタで `frontend/.env.local` を開き、上記の環境変数を記述します。

```bash
# 例: Visual Studio Code で開く
code .env.local
```

### 3. 開発サーバーの再起動

環境変数を変更した場合は、開発サーバーを再起動する必要があります。

```bash
# 開発サーバーを停止（Ctrl+C）
# 再起動
npm run dev
```

## 組織IDの取得方法

### データベースから取得

```sql
-- PostgreSQLで組織一覧を取得
SELECT organization_id, organization_name 
FROM organization 
WHERE is_active = true;
```

### 開発環境用のサンプル組織作成

開発環境で使用する組織がない場合は、以下のSQLで作成できます。

```sql
-- サンプル組織の作成
INSERT INTO organization (
  organization_id,
  organization_name,
  organization_name_kana,
  is_active,
  created_at,
  updated_at
) VALUES (
  '00000000-0000-0000-0000-000000000001',
  'MAIML研究所',
  'マイエムエルケンキュウジョ',
  true,
  NOW(),
  NOW()
);
```

## トラブルシューティング

### エラー: 「組織IDヘッダーが必要です」

**原因**: `NEXT_PUBLIC_ORGANIZATION_ID` が設定されていない、またはUUID形式ではない

**解決方法**:
1. `.env.local` ファイルが存在するか確認
2. `NEXT_PUBLIC_ORGANIZATION_ID` が正しく設定されているか確認
3. 値がUUID形式（xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx）であることを確認
4. 開発サーバーを再起動

### エラー: 「サーバーに接続できません」

**原因**: バックエンドサーバーが起動していない、またはURLが間違っている

**解決方法**:
1. バックエンドサーバーが起動しているか確認: `http://localhost:3001/api/v1/health`
2. `.env.local` の `NEXT_PUBLIC_API_URL` が正しいか確認
3. ファイアウォールやプロキシの設定を確認

### エラー: 「CORS エラー」

**原因**: バックエンドのCORS設定が正しくない

**解決方法**:
1. バックエンドの `backend/src/routes/authRoutes.ts` でCORS設定を確認
2. `origin` に フロントエンドのURL（`http://localhost:3000`）が含まれているか確認
3. `credentials: true` が設定されているか確認

## セキュリティ上の注意

### DO（推奨）
✅ `.env.local` ファイルは Git にコミットしない（既に `.gitignore` に含まれています）
✅ 本番環境では環境変数を安全に管理する（AWS Secrets Manager等）
✅ 組織IDは実在する組織のものを使用する

### DON'T（非推奨）
❌ `.env.local` をパブリックリポジトリにコミットしない
❌ 本番環境の認証情報をハードコーディングしない
❌ 開発環境と本番環境で同じ環境変数ファイルを使用しない
