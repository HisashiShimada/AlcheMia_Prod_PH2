## 1. タスク概要

ログインエンドポイントのレート制限が正しく機能していない問題を修正します。

### 現在の問題
1. `req.body.username`（存在しないフィールド）を使用しているためキー生成が失敗
2. `login_sf = false`（失敗のみ）をカウントしているため、正しい認証情報でのログインが無制限

### 期待される成果
- 不正なパスワードでのログイン試行がレート制限される
- 正しい認証情報でのログイン試行もレート制限される
- ブルートフォース攻撃を防げる

## 2. 目的と期待される成果

### 目的
レート制限を正しく機能させ、セキュリティを向上させる

### 期待される成果
- [x] キー生成が正しく動作する（`userId`を使用）
- [x] 成功・失敗に関わらず全試行がカウントされる
- [x] 15分以内に5回のログイン試行で制限がかかる

## 5. 技術的詳細

### 修正箇所1: キー生成（129行目）

**修正前**:
```typescript
keyGenerator: (req) => `${req.query.orgId}_${req.body.username}`,
```

**修正後**:
```typescript
keyGenerator: (req) => `${req.query.orgId}_${req.body.userId}`,
```

**理由**: `req.body.username`は存在せず`undefined`になるため、正しいフィールド名`userId`を使用

### 修正箇所2: カウント条件（67-76行目）

**修正前**:
```typescript
const query = `
  SELECT COUNT(*) as count 
  FROM login_history 
  WHERE login_at > $1 
  AND login_sf = false  // ← この行を削除
  AND user_name = $2 
  AND organization_id = $3
`;
```

**修正後**:
```typescript
const query = `
  SELECT COUNT(*) as count 
  FROM login_history 
  WHERE login_at > $1 
  AND user_name = $2 
  AND organization_id = $3
`;
```

**理由**: 成功・失敗に関わらず全試行をカウントすることで、ブルートフォース攻撃を防ぐ

### データベースへの影響
- ✅ 既存のインデックス`idx_login_history_rate_limit`を引き続き使用
- ✅ クエリパフォーマンスへの影響なし
