#### 3.1 基本型階層

```
hasIdAttributeType (abstract)
  ├─ id: xs:ID (required)
  │
  ├─ simpleObjectType (abstract)
  │   ├─ 継承: hasIdAttributeType
  │   ├─ name: xs:QName (オプション)
  │   └─ description: xs:string (オプション)
  │
  ├─ referenceObjectType (abstract)
  │   ├─ 継承: simpleObjectType
  │   └─ ref: xs:IDREF (required)
  │
  └─ tripleObjectType (abstract)
      ├─ 継承: simpleObjectType
      ├─ source: xs:IDREF (required)
      └─ target: xs:IDREF (required)
```

#### 3.2 globalObjectContentGroup

すべてのグローバルオブジェクト（Protocol, Method, Document等）に共通の構造：

```xml
<xs:group name="globalObjectContentGroup">
  <xs:sequence>
    <xs:element name="uuid" type="uuid" />
    <xs:choice>
      <xs:group ref="encryptionGroup" />
      <xs:sequence>
        <xs:element name="insertion" type="insertionType" minOccurs="0" maxOccurs="unbounded" />
        <xs:element name="name" type="xs:QName" minOccurs="0" />
        <xs:element name="description" type="xs:string" minOccurs="0" />
        <xs:element name="annotation" type="xs:string" minOccurs="0" />
        <xs:group ref="genericDataContainerGroup" />
      </xs:sequence>
    </xs:choice>
  </xs:sequence>
</xs:group>
```

**重要:**
- `uuid`: 必須（minOccurs指定なし = 1）
- `name`, `description`, `annotation`: オプション
- `insertion`: 配列（minOccurs="0" maxOccurs="unbounded"）

## ⚠️ 差異分析結果

### 【Critical】重要度：高

#### 1. Content型の値プロパティ定義の誤り

**問題箇所:** `frontend/src/types/maiml-unified.ts` Line 167-173

```typescript
// ❌ 現在の定義（誤り）
export interface Content {
  /**
   * リスト値（すべてのContent型で使用）
   * - contentStringListType: string[]
   * - contentIntListType, contentDoubleListType等: number[]
   * - contentBooleanListType: boolean[]
   */
  value?: (string | number | boolean);  // ← 単一値型（誤り）
```

**XSD仕様:**
```xml
<!-- すべてのContent型でmaxOccurs="unbounded"（配列） -->
<xs:element name="value" minOccurs="0" maxOccurs="unbounded" type="stringList" />
<xs:element name="value" minOccurs="0" maxOccurs="unbounded" type="intList" />
```

**修正案:**
```typescript
// ✅ 修正後
export interface Content {
  /**
   * リスト値（すべてのContent型で配列）
   * XSD仕様: maxOccurs="unbounded"
   */
  value?: (string | number | boolean)[];  // 配列型に修正
}
```

**影響度:** 🔴 Critical
- Content型を使用する全てのコードに影響
- 実行時エラーの原因となる可能性が高い

#### 2. Property型のvalueとvaluesの混在

**問題箇所:** `frontend/src/types/maiml-unified.ts` Line 259-270

```typescript
// ❌ 現在の定義（一部不正確）
export interface Property {
  value?: string | number | boolean;     // 単一値型用
  values?: (string | number | boolean)[]; // リスト型用
}
```

**XSD仕様分析:**
- 単一値型（stringType, intType等）: `<value>` 単一要素（minOccurs="0"、maxOccursなし = 1）
- リスト型（stringListType等）: `<value>` 配列要素（maxOccurs="unbounded"）

**問題点:**
- XSDでは単一値型も`<value>`タグを使用
- リスト型も`<value>`タグを使用（複数個または空白区切り）
- TypeScriptでは`value` vs `values`で区別しているが、XSDには`values`タグは存在しない

**修正案（選択肢）:**

**案A: XSD厳密準拠（推奨）**
```typescript
export interface Property {
  /**
   * 値（単一値またはリスト）
   * - 単一値型: value: string | number | boolean
   * - リスト型: value: (string | number | boolean)[]
   * 
   * 型による使い分けはxsiType属性で判定
   */
  value?: string | number | boolean | (string | number | boolean)[];
}
```

**案B: 実用性重視（現状維持 + ドキュメント強化）**
```typescript
export interface Property {
  /**
   * 単一値（stringType, intType等で使用）
   * XML: <value>single value</value>
   */
  value?: string | number | boolean;
  
  /**
   * リスト値（stringListType, intListType等で使用）
   * XML: <value>item1 item2 item3</value>（空白区切り）
   * または: <value>item1</value><value>item2</value>（複数要素）
   * 
   * 注意: XSDでは "values" タグは存在せず、すべて "value" タグ
   * この型定義では実装上の便宜のため分離
   */
  values?: (string | number | boolean)[];
}
```

**影響度:** 🟡 High
- パーサー実装に影響
- ただし、現在の実装で動作している場合は後方互換性を考慮すべき

#### 3. Template型の`stereoType`プロパティ

export interface Template {

**XSD仕様:**

### 【High】重要度：中

#### 4. 配列型の一貫性（単数形 vs 複数形）

**問題箇所:** 複数

```typescript
// ❌ 不統一な命名
export interface Document {
  creators: Creator[];   // 複数形
  vendors: Vendor[];     // 複数形
  owners: Owner[];       // 複数形
  instruments?: Instrument[];  // 複数形
}

export interface Protocol {
  methods: Method[];  // 複数形
}

export interface Method {
  pnml: PNML[];      // 単数形（不統一）
  program: Program[]; // 単数形（不統一）
}
```

**XSD仕様:**
```xml
<!-- すべて単数形 -->
<xs:element name="creator" ... maxOccurs="unbounded" />
<xs:element name="vendor" ... maxOccurs="unbounded" />
<xs:element name="method" ... maxOccurs="unbounded" />
<xs:element name="pnml" ... maxOccurs="unbounded" />
<xs:element name="program" ... maxOccurs="unbounded" />
```

**修正案:**

**推奨: XSD準拠（単数形で統一）**
```typescript
export interface Document {
  creator: Creator[];      // 単数形に修正
  vendor: Vendor[];        // 単数形に修正
  owner: Owner[];          // 単数形に修正
  instrument?: Instrument[]; // 単数形に修正
}

export interface Protocol {
  method: Method[];  // 単数形に修正
}
```

**影響度:** 🟡 High
- 破壊的変更（既存コード全体に影響）
- ただし、一貫性向上により保守性が大幅に改善
