## 実装概要

マルチテナント組織認証を強化するため、Nginxによるクライアント証明書認証を実装しました。証明書のCN（Common Name）から組織IDを自動抽出し、X-Organization-Idヘッダーとして設定することで、セキュアなアクセス制御を実現します。

## 技術仕様

### 証明書のCN形式

```
CN={organization_id}
```

**例**: `CN={c9621ed6-5def-4970-8e7f-fbe97c98e3ed}`

### Nginxが設定するヘッダー

| ヘッダー名 | 内容 | 例 |
|-----------|------|-----|
| X-Client-Cert-DN | 証明書のSubject DN | `CN={c9621ed6-5def-4970-8e7f-fbe97c98e3ed}` |
| X-Client-Cert-CN | 証明書のCN | `{c9621ed6-5def-4970-8e7f-fbe97c98e3ed}` |
| X-Client-Cert-Verify | 証明書検証結果 | `SUCCESS` |
| X-Organization-Id | CNから抽出した組織ID | `c9621ed6-5def-4970-8e7f-fbe97c98e3ed` |

### エラーコード

| エラーコード | HTTPステータス | 説明 |
|-------------|---------------|------|
| CERT_VERIFICATION_FAILED | 403 | 証明書検証失敗 |
| INVALID_ORGANIZATION_ID | 403 | 組織IDが取得できない |
| INVALID_ORGANIZATION_ID_FORMAT | 403 | 組織IDがUUID形式ではない |
| CERT_MIDDLEWARE_ERROR | 500 | ミドルウェアエラー |

## セキュリティ考慮事項

### ✅ 実装済み

1. **証明書の必須化**
   - NginxでX-Organization-IdはNginxレベルでクライアント証明書検証を必須化
   - 検証失敗時は403エラー

2. **UUID形式の検証**
   - 組織IDがUUID形式であることを確認
   - 不正な形式はリジェクト

3. **開発環境の柔軟性**
   - `NODE_ENV=development`時は証明書なしでもアクセス可能
   - `skipClientCertInDev`ミドルウェアで制御

4. **監査ログ**
   - 証明書検証結果をコンソールに出力
   - 組織ID、CN、パス、メソッド、IPアドレスを記録

### ⚠️ 今後の検討事項

1. **証明書失効リスト（CRL）**
   - 現状は未実装
   - 証明書の無効化が必要な場合の対応

2. **OCSP（Online Certificate Status Protocol）**
   - 証明書の有効性をリアルタイムで確認
   - パフォーマンスとセキュリティのバランス

3. **証明書の有効期限管理**
   - 自動更新の仕組み
   - 有効期限切れ前の通知

4. **DHパラメータの生成**
   - より強固な暗号化のため
   - `openssl dhparam -out dhparam.pem 2048`

## テスト手順

### 1. 証明書生成

```bash
# CAとクライアント証明書の生成
cd certs
bash generate-certificates.sh c9621ed6-5def-4970-8e7f-fbe97c98e3ed

# サーバー証明書の生成
bash generate-server-cert.sh
```

### 2. クライアント証明書をブラウザにインポート

1. `certs/clients/{org_id}/client.p12`をダブルクリック
2. パスワードは空欄でOK
3. 証明書ストアは「個人」を選択

### 3. Nginxコンテナの起動

```bash
# docker-compose.ymlでbackend/frontendのコメントを外す
docker-compose up -d nginx
```

### 4. アクセステスト

```bash
# HTTPSでアクセス（証明書選択ダイアログが表示される）
https://localhost

# curlでテスト
curl -k --cert certs/clients/{org_id}/client.crt \
     --key certs/clients/{org_id}/client.key \
     https://localhost/api/v1/auth/login
```

### 5. ログ確認

```bash
# Nginxログ
docker logs mmdpf-nginx

# バックエンドログ
docker logs mmdpf-backend

# 証明書情報の確認
docker exec mmdpf-nginx cat /var/log/nginx/access.log | grep cert_cn
```

## トラブルシューティング

### 証明書が認識されない

**症状**: ブラウザで証明書選択ダイアログが表示されない

**対策**:
1. 証明書が正しくインポートされているか確認
2. ブラウザを再起動
3. 証明書ストアの「個人」に証明書があるか確認

### 403 Forbidden エラー

**症状**: `CERT_VERIFICATION_FAILED`エラー

**対策**:
1. 証明書のCNがUUID形式か確認
2. CA証明書がNginxに正しくマウントされているか確認
3. Nginxログで詳細を確認

### 開発環境で証明書なしでアクセスしたい

**対策**:
1. `backend/.env`で`NODE_ENV=development`を設定
2. `frontend/src/services/authService.ts`のコメントアウト部分を有効化

## 運用手順

```bash
cd certs
bash generate-certificates.sh <新しい組織のUUID>
```

### 証明書の配布

1. `certs/clients/{org_id}/client.p12`をユーザーに配布
2. インポート手順を案内
3. パスワードは設定していないことを伝達

### 証明書の更新

```bash
# 古い証明書を削除
rm -rf certs/clients/{org_id}

# 新しい証明書を生成
bash generate-certificates.sh {org_id}
```
