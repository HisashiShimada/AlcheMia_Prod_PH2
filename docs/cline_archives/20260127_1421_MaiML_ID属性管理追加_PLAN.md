## 3. MaiML ID属性の仕様

### ID属性の役割
MaiML（Materials Informatics Markup Language）において、ID属性は以下の用途で使用されます：

1. **要素の一意識別**: XML内で要素を一意に識別
2. **内部参照**: 他の要素からID参照（ref属性）で参照
3. **外部参照**: 外部ドキュメントからのXPath参照

### ID属性の形式
```xml
<property key="compound" id="compound_001" xsi:type="stringType">
  <value>Sample Compound</value>
</property>

<!-- 参照側 -->
<property key="reference" ref="compound_001" xsi:type="idRefType" />
```

### ID命名規則（推奨）
- 形式: `{prefix}_{連番}` または `{descriptive_name}`
- 例: `compound_001`, `material_temperature`, `result_analysis_01`
- 制約: XML ID型の仕様に準拠（英数字、アンダースコア、ハイフン）

## 5. 実装方針の決定

### オプション1: 簡易版（推奨）
- **範囲**: テンプレートルートレベルのID属性のみ管理
- **UI**: 基本情報セクション内に1つのフィールド

### オプション2: 完全版
- **範囲**: 全プロパティのID属性を管理
- **UI**: 各プロパティ編集時にID属性フィールド

**決定: オプション1（簡易版）を採用**

理由:
- プロパティ個別のID管理はNestedPropertyEditorで実装済み（attributes編集）
- ルートレベルのID管理は頻繁に使用される
- 実装コストと実用性のバランス

### 一意性チェック（オプション）
```typescript
const isMaimlIdDuplicate = useCallback((id: string): boolean => {
  if (!id) return false;
  
  // 簡易版: templateRefレベルのIDのみチェック
  return allNodes.some(n => {
    if (n.id === node?.id) return false;
    const template = n.data?.templateRef || n.data?.template;
    return template?.maimlId === id;
  });
}, [allNodes, node]);
```
