## 🔍 重要な発見

### SaveDialog.jsx (Reference独自) と SaveConfirmDialog.tsx (現行) の比較

#### 1. SaveDialog.jsx (Reference)

**機能:**
- Draft名と説明を入力して保存
- バリデーション機能
- MUI (Material-UI) を使用

**UI構造:**
```
Dialog
├── DialogTitle: "ペトリネットを保存"
├── DialogContent
│   ├── Alert (エラー表示)
│   ├── TextField (Draft名 - 必須)
│   ├── TextField (説明 - 任意、複数行)
│   └── CircularProgress (保存中)
└── DialogActions
    ├── Button: キャンセル
    └── Button: 保存 (SaveIcon付き)
```

**主要機能:**
- Draft名のバリデーション（必須、100文字以内）
- Enterキーで保存
- 保存中の無効化処理

#### 2. SaveConfirmDialog.tsx (現行)

**機能:**
- S3キー（保存先パス）を指定して保存確認
- Ant Design を使用

**推測される UI構造:**
```
Modal
├── Title: "保存確認"
├── Content
│   ├── Alert (注意メッセージ)
│   ├── Input (S3キー入力)
│   └── Spin (保存中)
└── Footer
    ├── Button: キャンセル
    └── Button: 保存
```

**主要機能:**
- S3キーの編集
- 保存先の確認
- 保存処理のコールバック

### TemplateEditMode.tsx (現行独自) の役割

#### 機能概要

**目的:**
- ペトリネットからテンプレート（Material/Condition/Result）のみを抽出
- 一覧表示・編集・削除を専用ビューで提供
- PetriNetEditor の `editorMode` で切り替え可能

**UI構造:**
```
Card (全体コンテナ)
├── Typography.Title: "テンプレート編集モード"
├── Typography.Text: 説明文
└── Tabs
    ├── Tab: Material (件数)
    │   └── TemplateCard[] (編集/削除ボタン付き)
    ├── Tab: Condition (件数)
    │   └── TemplateCard[] (編集/削除ボタン付き)
    └── Tab: Result (件数)
        └── TemplateCard[] (編集/削除ボタン付き)
```

**各TemplateCard:**
```
Card (small)
├── Title: テンプレート名
├── Description: 説明文
├── Text: プロパティ件数
└── Extra (操作ボタン)
    ├── Button: 編集 (EditOutlined)
    └── Button: 削除 (DeleteOutlined, danger)
```

#### Reference での対応実装

Reference では **TemplateEditMode.tsx に相当する専用コンポーネントは存在しない**と推測されます。

**理由:**
1. TemplateViewer/ フォルダは存在するが、用途が異なる
   - TemplateItem.jsx: テンプレート項目の表示
   - TemplateList.jsx: テンプレート一覧の表示
   - これらはビューア機能であり、編集モードとは異なる

2. PetriNetEditorInner.jsx で直接管理している可能性
   - Reference は編集可能ノード（EditablePlaceNode, EditableTransitionNode）を使用
   - ペトリネット図上で直接編集する設計

3. 現行の editorMode 切り替えは後から追加された機能
   - Reference にはこの概念がない可能性が高い

## 📊 実装アプローチの違い

### 保存フロー

#### Reference:
```
1. SaveDialog で Draft名・説明を入力
2. onSave コールバックでデータを渡す
3. 親コンポーネントで保存処理
```

#### 現行:
```
1. SaveConfirmDialog で S3キーを確認
2. onSave コールバックで targetS3Key を渡す
3. PetriNetEditor 内で API呼び出し
```

**差異:**
- Reference: Draft概念が強い（名前と説明で管理）
- 現行: ファイルベース（S3キーで管理）

### テンプレート編集フロー

#### Reference (推測):
```
1. ペトリネット図上で直接編集
2. EditablePlaceNode/EditableTransitionNode でインライン編集
3. TemplateViewer で一覧確認のみ
```

#### 現行:
```
1. EditorToolbar で editorMode を切り替え
   - 'petri-net' モード: ReactFlow 表示
   - 'template' モード: TemplateEditMode 表示
2. TemplateEditMode で一覧表示・編集・削除
3. 編集ボタンで TemplateEditorDialog を開く
```

**差異:**
- Reference: ペトリネット図中心（常に図を表示）
- 現行: モード切り替え型（図とテンプレート一覧を切り替え）

## 🎨 UI/UX の違い

### レイアウト構造

#### Reference (推測):
```
┌─────────────────────────────────────┐
│ EditorToolbar                       │
├─────────────────────────────────────┤
│                                     │
│  ReactFlow (Petri Net)              │
│  - EditablePlaceNode                │
│  - EditableTransitionNode           │
│  - インライン編集可能               │
│                                     │
├─────────────────────────────────────┤
│ PropertyPanel (右側)                │
│ - 選択ノードのプロパティ編集        │
└─────────────────────────────────────┘
```

#### 現行:
```
┌─────────────────────────────────────┐
│ EditorToolbar                       │
│ [ペトリネット|テンプレート]        │ ← editorMode切り替え
├─────────────────────────────────────┤
│ editorMode === 'petri-net':         │
│   ReactFlow + PropertyPanel         │
│                                     │
│ editorMode === 'template':          │
│   TemplateEditMode (一覧表示)      │
│   - Material タブ                   │
│   - Condition タブ                  │
│   - Result タブ                     │
└─────────────────────────────────────┘
```

**差異:**
- Reference: 単一ビュー（常にペトリネット図）
- 現行: 複数ビュー（ペトリネット図とテンプレート一覧を切り替え）

### ノード編集方法

#### Reference:
- EditablePlaceNode: ノード上で直接編集
- ダブルクリックやフォーカスでインライン編集
- PropertyPanel で詳細編集

#### 現行:
- MaterialTemplateNode/etc: ビューア専用（編集不可）
- PropertyPanel で編集ボタンをクリック
- TemplateEditorDialog モーダルで編集
- または TemplateEditMode の一覧から編集

**差異:**
- Reference: インライン編集重視（図上で直接編集）
- 現行: ダイアログ編集重視（モーダルで編集）

## 🎯 結論

### 主要な違いのまとめ

1. **保存フロー**
   - Reference: Draft概念（名前と説明）
   - 現行: ファイルベース（S3キー）

2. **編集アプローチ**
   - Reference: インライン編集重視（図上で直接編集）
   - 現行: モード切り替え＋ダイアログ編集

3. **UIライブラリ**
   - Reference: MUI (Material-UI)
   - 現行: Ant Design v6

4. **レイアウト構造**
   - Reference: 単一ビュー（常にペトリネット図）
   - 現行: 複数ビュー（図とテンプレート一覧を切り替え）

### どちらが優れているか？

#### Reference の利点:
- ✅ インライン編集で操作が直感的
- ✅ ペトリネット図を常時表示（全体像を把握しやすい）
- ✅ EditableNode で統一された編集体験

#### 現行の利点:
- ✅ Ant Design v6 で統一されたUI
- ✅ TemplateEditMode でテンプレート管理が容易
- ✅ モード切り替えで用途に応じた表示
- ✅ デザイントークンによる一貫性

### 推奨事項

現行の実装を維持しつつ、Reference の良い部分を取り入れる：

1. **TemplateEditMode を維持**
   - テンプレート管理に特化したビューは有用
   - Reference にはない独自の価値

2. **インライン編集の検討**
   - 小規模な変更（名前・説明）は図上で直接編集できると便利
   - ただし、Ant Design v6 との統合が課題

3. **UIポリシー違反の修正を優先**
   - 現在進行中のデザイントークン化を完了
   - Reference の MUI スタイルは参考程度に留める

## 補足: SaveDialog.jsx の現行での対応

SaveDialog.jsx (Reference) の機能は、現行では以下のように実装されています：

### Draft名・説明の管理:

1. **DraftManager.tsx**: Draft一覧・読み込み
   - localStorage でドラフトを管理
   - 自動保存機能

2. **SaveConfirmDialog.tsx**: 保存先の確認
   - S3キーを指定
   - 上書き保存の警告

3. **DocumentEditDialog.tsx**: Document情報の編集
   - プロジェクト名（Draft名に相当）
   - 説明（description）

**結論**: Reference の SaveDialog.jsx の機能は、現行では複数のコンポーネントに分散して実装されています。
