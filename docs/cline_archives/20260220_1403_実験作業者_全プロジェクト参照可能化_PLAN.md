## 1. タスク概要

実験作業者（Worker）が、自分に割り当てられたタスクを持つプロジェクトだけでなく、組織内のすべてのプロジェクトを参照できるように修正します。

現在は`project_task_detail.experiment_user_id`で絞り込んでいるため、自分に割り当てられたタスクがあるプロジェクトのみが表示されますが、これを削除して組織内の全プロジェクトを表示するようにします。

## 2. 目的と期待される成果

### 目的
- 実験作業者が組織内のすべてのプロジェクトを参照できるようにする
- 他の作業者がどのようなプロジェクトを進行しているかを把握できるようにする
- プロジェクトの全体像を俯瞰できるようにする

### 期待される成果
- [ ] `findWorkerAccessible.sql`から不要なWHERE句を削除
- [ ] `countWorkerAccessible.sql`から不要なWHERE句を削除
- [ ] `workerProjectRepository.ts`のパラメータ配列を修正
- [ ] 実験作業者が組織内の全プロジェクトを参照できる

## 3. 実装ステップ

- [x] `findWorkerAccessible.sql`を修正

  - パラメータ番号を調整（$3 → $2）

- [x] `countWorkerAccessible.sql`を修正
  - WHERE句から`AND project_task_detail.experiment_user_id = $2`を削除
  - パラメータコメントから`$2: user_id`を削除
  - パラメータ番号を調整（$3 → $2）

### Phase 2: Repositoryファイルの修正

## 5. 技術的詳細

### SQL JOIN の維持理由
`INNER JOIN project_task_detail`は残します。理由：
- プロジェクトにタスクが存在するかを確認するため
- タスクが存在しないプロジェクトは表示しない仕様のため

### パラメータ番号の調整
- `$2: user_id`を削除することで、`$3`が`$2`になります
- マルチテナント分離のため、両方のテーブルに`organization_id`フィルタが必要です

## 6. リスクと対策

| JOINの削除ミス | 高 | 極低 | JOINは残すことを明確化（WHERE句のみ修正） |
| マルチテナント分離の破損 | 高 | 極低 | 両テーブルのorganization_idフィルタは維持 |
