## 3. 現状分析と要件変更

### 【重要】ユーザーフィードバック（2025-12-26 16:50）

**変更された要件:**
1. **表示方式はDrawerとする** - split-paneレイアウトではなくDrawer形式
2. **Drawerの右ペインに表示する内容はPropertyViewerをベースに、左端に選択用のチェックボックスを追加**
3. **チェックボックス選択時の処理はStructuredPropertySelectorの方に合わせる**

### 現状のコンポーネント構成

#### PropertyViewer（プロパティ表示専用）
- タブ形式（基本情報、テンプレート、データ）
- Tableで表示（プロパティ名と値の2列）
- チェックボックスなし
- 表示のみ

#### StructuredPropertySelector（プロパティ選択機能）
- タブ形式（基本情報、テンプレート、データ）
- Listで表示（Checkboxあり）
- チェックボックスでプロパティ選択
- `onPropertyToggle`コールバックで選択状態を通知

#### SubNetViewer（参考実装）
- 左右分割レイアウト（60% / 40%）
- 右ペインでPropertyViewerを使用
- ノードクリック時に右ペインが開く

### ViewRendererDialog + PetriNetViewerの現状

ViewRendererDialogは以下の3つのcontentTypeを持つ:
1. `'file'` - ViewRenderer → PetriNetViewerを表示
2. `'subnet'` - SubNetViewerを直接表示
3. `'edit'` - ViewRenderer → PetriNetEditorを表示

**問題点:**
- `'file'`モードでPetriNetViewerを表示した際、ノードクリック時の表示がSubNetViewerと統一されていない
- PropertyViewerは表示のみ、StructuredPropertySelectorは選択機能あり
- 統一されたUI/UXが必要

## 6. 技術的詳細

### PropertyViewerWithSelection コンポーネント設計

```tsx
interface PropertyViewerWithSelectionProps {
  properties: Record<string, any>;
  maimlData: string;
  selectedProperties: SelectedProperties;  // 選択状態
  onPropertyToggle: (structure: keyof StructuredProperties, property: string) => void;
  onClose?: () => void;
}

interface SelectedProperties {
  basic: string[];
  template: string[];
  data: string[];
}

interface StructuredProperties {
  basic: Record<string, PropertyObject>;
  template: Record<string, PropertyObject>;
  data: Record<string, PropertyObject>;
}
```

### PropertyViewerとStructuredPropertySelectorの統合

**PropertyViewerから取り入れる要素:**
- ヘッダーカラー（ノードタイプ別: Result=マゼンタ、Condition=シアン、Material=黄色、Transition=グレー）
- タブ形式（基本情報、テンプレート、データ）
- プロパティの表示ロジック

**StructuredPropertySelectorから取り入れる要素:**
- Checkboxコンポーネント
- `onPropertyToggle`コールバック
- Listコンポーネントによる表示
- 選択状態の管理

### Drawer表示パターン（PetriNetViewer）

```tsx
// 状態管理
const [drawerOpen, setDrawerOpen] = useState(false);
const [selectedNode, setSelectedNode] = useState<Node | null>(null);
const [selectedProperties, setSelectedProperties] = useState<SelectedProperties>({
  basic: [],
  template: [],
  data: [],
});

// ノードクリックハンドラー
const handleNodeClick: NodeMouseHandler = useCallback((event, node) => {
  setSelectedNode(node);
  setDrawerOpen(true);
}, []);

// プロパティ選択ハンドラー
const handlePropertyToggle = useCallback((structure: string, property: string) => {
  setSelectedProperties(prev => {
    const current = prev[structure] || [];
    const isSelected = current.includes(property);
    return {
      ...prev,
      [structure]: isSelected 
        ? current.filter(p => p !== property)
        : [...current, property]
    };
  });
}, []);

// Drawer表示
<Drawer
  open={drawerOpen}
  onClose={() => setDrawerOpen(false)}
  width={400}
  getContainer={() => document.getElementById('petri-net-viewer-container') || document.body}
>
  <PropertyViewerWithSelection
    properties={selectedNode?.data}
    maimlData={maimlData}
    selectedProperties={selectedProperties}
    onPropertyToggle={handlePropertyToggle}
    onClose={() => setDrawerOpen(false)}
  />
</Drawer>
```

### 計画からの変更点
- 当初予定していたsplit-paneレイアウトではなく、Drawer表示（PetriNetViewer）とsplit-pane（SubNetViewer）の両方に対応
- PropertyViewerをベースとしたTable形式（3列構造）を採用
- ESLintエラーを修正し、型安全性とReactのベストプラクティスに準拠

### 発生した問題と解決方法

#### 問題1: PropertyViewerWithSelectionの設計方針の変更
- **問題**: 当初、StructuredPropertySelectorのList形式を採用する予定だった
- **解決**: ユーザーフィードバックにより、PropertyViewerのTable形式（3列構造）に変更
- **結果**: より見やすく、PropertyViewerとの一貫性が保たれた

#### 問題2: ESLintエラー（型安全性）
- **問題**: `any`型の使用、useEffect内でのsetState、パフォーマンス最適化の問題
- **解決**: 
  - `any` → `unknown`に変更
  - useEffect内のsetStateを適切に処理
  - useMemoを使用してヘッダーカラーを最適化
- **結果**: 型安全性が向上し、パフォーマンスも改善

#### 問題3: PetriNetViewerの状態管理の複雑さ
- **問題**: ノード単位でプロパティ選択状態を管理していたため複雑だった
- **解決**: 現在選択中のノードのプロパティ選択状態のみを管理する簡易な方式に変更
- **結果**: コードがシンプルになり、保守性が向上
