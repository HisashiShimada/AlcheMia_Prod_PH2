### 失敗したテストケース（4個）

#### ❌ 1-3. creator/vendor/owner配列チェック失敗

**失敗理由:** xml2jsのパース設定の問題（型定義の問題ではない）

```typescript
// xml2jsの設定
const parsed = await parseStringPromise(maimlXml, {
  explicitArray: false,  // ← これが原因
  mergeAttrs: true,
  explicitRoot: true,
});
```

**現状:** `explicitArray: false`により、要素が1個の場合は配列にならない
- `document.creator` → オブジェクト（配列ではない）
- `document.vendor` → オブジェクト（配列ではない）
- `document.owner` → オブジェクト（配列ではない）

**型定義は正しい:**
```typescript
export interface DocumentType extends HasIdAttributeType {
  creator?: CreatorType[];  // ✅ 配列として定義されている
  vendor?: VendorType[];    // ✅ 配列として定義されている
  owner?: OwnerType[];      // ✅ 配列として定義されている
  // ...
}
```

**対策:** 実際のアプリケーションコードでは配列として扱う必要がある。

#### ❌ 4. description/annotationのin演算子チェック失敗

**失敗理由:** 実MAIMLファイルにdescription/annotationがない場合、xml2jsはプロパティ自体を作成しない

```typescript
const document: DocumentType = maimlData.document;
'description' in document  // ❌ false（プロパティが存在しない）
```

**型定義は正しい:**
```typescript
export interface DocumentType {
  description?: string;  // ✅ オプショナルとして定義されている
  annotation?: string;   // ✅ オプショナルとして定義されている
}
```

**評価:** これは期待通りの動作。オプショナルプロパティは存在しない場合もある。
