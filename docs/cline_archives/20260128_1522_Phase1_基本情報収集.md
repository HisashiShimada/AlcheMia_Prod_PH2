## 2. アーキテクチャの違い

### V2版のアーキテクチャ
```
PetriNetEditorV2 (index.jsx)
  └─ ReactFlowProvider
      └─ PetriNetEditorInner
          ├─ 実際のエディタロジック
          ├─ State管理
          ├─ イベントハンドラ
          └─ UI描画
```

**特徴:**
- シンプルなエントリーポイント
- 実際の処理は `PetriNetEditorInner` に委譲
- Props変換を行うシム層として機能
- デバッグログ付き

### 現行版のアーキテクチャ
```
PetriNetEditor (PetriNetEditor.tsx)
  ├─ PetriNetEditor (エントリーポイント)
  │   └─ ReactFlowProvider
  │       └─ TemplateProvider
  │           └─ PetriNetEditorInner
  │               ├─ 全State管理
  │               ├─ 全イベントハンドラ
  │               ├─ React Flow
  │               ├─ サブコンポーネント群
  │               └─ ダイアログ群
  └─ 2,100行以上のモノリシック実装
```

**特徴:**
- エントリーポイントとメインロジックが同一ファイル
- TypeScript完全対応
- 多機能・高機能化
- TemplateProviderが追加されている

## 3. Props定義の比較

### V2版 - Props
```jsx
const PetriNetEditorV2 = (props) => {
  // 受け取るprops（型定義なし、JSなので動的）
  - initialMaiMLData
  - editingFileName
  - originalFileName
  - sourceS3Key
  - initialEditMode
  - その他（...props で全て渡す）
}
```

### 現行版 - PetriNetEditorProps
```typescript
export interface PetriNetEditorProps {
  // 基本Props
  maimlData?: string;
  onError?: (error: Error) => void;
  editingFileName?: string;
  editMode?: 'normal' | 'draft';
  originalFileName?: string;
  sourceS3Key?: string;
  
  // Phase 6追加Props
  initialContent?: string;              // maimlDataのエイリアス
  projectId?: string;
  projectName?: string;
  onSave?: (content: string) => Promise<void>;
  onContentChange?: () => void;
  
  // フォーマット管理統合用
  sourceContext?: 'project' | 'format'; // デフォルト: 'project'
}
```

**差異:**
- ✅ V2の `initialMaiMLData` → 現行版の `maimlData` / `initialContent`
- ✅ V2の `initialEditMode` → 現行版の `editMode`
- ✅ 型定義が完全追加（TypeScript化）
- ✅ Phase 6で保存コールバックなど拡張
- ✅ sourceContextでプロジェクト/フォーマットを区別
