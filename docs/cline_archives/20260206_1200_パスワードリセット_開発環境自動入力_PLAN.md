## 1. タスク概要

開発環境でメール送信ができないため、一時パスワード発行後に自動的にログイン画面のパスワード欄に一時パスワードが入力される仕様を実装します。

## 2. 目的と期待される成果

### 目的
- 開発環境でのパスワードリセット機能のテスト効率化
- メール確認の手間を省き、開発フローをスムーズにする
- PINコード機能と同様の開発支援機能を提供

### 期待される成果
- [x] 開発環境でパスワードリセット要求時、一時パスワードがレスポンスに含まれる
- [x] ログイン画面に戻る際、一時パスワードが自動入力される
- [x] 本番環境ではセキュリティを維持（一時パスワードは返さない）

## 3. 実装ステップ

### Phase 1: バックエンドAPI修正
- [x] authController.ts の `resetPasswordRequest` を修正
  - 開発環境時（`NODE_ENV === 'development'`）にレスポンスに一時パスワードを含める
  - `devMode: true` フラグも追加
  - PINコードと同様の実装パターンを適用

### Phase 2: フロントエンド修正
- [x] PasswordResetRequest.tsx の修正
  - レスポンスから一時パスワードとdevModeフラグを受け取る
  - `onSuccess` コールバックに一時パスワードを渡す

- [x] page.tsx の修正
  - `handlePasswordResetRequest` で一時パスワードを受け取る
  - 一時パスワードを状態管理に追加
  - `handleBackToLogin` で一時パスワードをクリア

- [x] LoginPage.tsx の修正
  - Props に `autoFillPassword` を追加
  - パスワード欄に自動入力する機能を実装
  - 自動入力時にユーザーに通知（Alert表示）

### Phase 3: 型定義の更新
- [x] types/api.ts の修正
  - `ResetPasswordRequestResponse` に `tempPassword` と `devMode` を追加

## 5. 技術的詳細

### 使用する技術・ライブラリ
- TypeScript
- React Hooks（useState, useEffect）
- Ant Design（Alert, Input）

### アーキテクチャ上の考慮事項
- 開発環境と本番環境で動作を分離
- セキュリティ: 本番環境では一時パスワードをレスポンスに含めない
- PINコード機能と同様の実装パターンを採用

### セキュリティ考慮事項
- [x] 本番環境では一時パスワードをレスポンスに含めない
- [x] `NODE_ENV === 'development'` で厳密に制御
- [x] ログイン画面に戻る際は一時パスワードをクリア

## 6. リスクと対策

| リスク | 影響度 | 発生確率 | 対策 |
|--------|--------|----------|------|
| 本番環境で一時パスワードが漏洩 | 高 | 低 | NODE_ENV チェックを厳密に行う |
| 自動入力がユーザーに気づかれない | 低 | 中 | Alert で通知メッセージを表示 |
| 既存のフローが壊れる | 中 | 低 | Props をオプショナルにする |
