## 📐 具体的な整理案

### 案1: 純粋型安全（推奨）

**maiml-unified.tsには追加なし**

```typescript
// maiml-unified.ts（変更なし）
export interface Transition extends MaimlElementBase {
  // XSD準拠型のみ
}

export interface MaterialTemplate extends MaimlElementBase {
  placeRef: PlaceRef[];
  templateRef?: TemplateRef[];
  property?: Property[];
}
```

**パーサーは基本メソッドと拡張メソッドを提供**

```typescript
// maimlParserExp.ts
class MaiMLParser {
  // 基本メソッド（XSD準拠型をそのまま返す）
  getTransitions(): Transition[] {
    const method = this.typedMaiml.protocol.method[0];
    return method.pnml[0].transition;
  }

  // 拡張メソッド（計算情報を含む）
  getTransitionsExtended(): Array<Transition & {
    methodId: string;
    hasInstruction: boolean;
    arcCount: number;
    arcs: Arc[];
    category: string;
  }> {
    const transitions = this.getTransitions();
    return transitions.map(t => ({
      ...t,
      methodId: '...',
      hasInstruction: this.hasInstruction(t.id),
      arcCount: this.getArcCount(t.id),
      arcs: this.getArcs(t.id),
      category: this.categorizeTransition(t)
    }));
  }
}
```

**メリット:**
- ✅ 型定義が完全にXSD準拠
- ✅ 型定義ファイルがシンプル
- ✅ 柔軟な拡張が可能

**デメリット:**
- ❌ 拡張情報の型定義がない（インラインで定義）

### 案2: 最小限の拡張型追加

**maiml-unified.tsに最小限の拡張**

```typescript
// maiml-unified.ts の末尾に追加

// ============================================================================
// Extended Types for Parser Convenience（パーサー利便性のための拡張型）
// ============================================================================

/**
 * パーサーが計算する拡張情報のインターフェース
 * XSD準拠型には含まれない計算値や統計情報
 */

/**
 * Transitionの拡張情報
 */
export interface TransitionExtras {
  /** 所属するMethod ID */
  methodId: string;
  /** instructionを持つか */
  hasInstruction: boolean;
  /** 接続されているArcの数 */
  arcCount: number;
  /** 接続されているArc一覧 */
  arcs: Arc[];
  /** カテゴリ分類 */
  category: 'experiment' | 'preparation' | 'finalization' | 'other';
}

/**
 * Templateの拡張情報
 */
export interface TemplateExtras {
  /** 参照先Template ID（templateRefがある場合） */
  resolvedFromRef: string | null;
  /** templateRefを持つか */
  hasTemplateRef: boolean;
  /** insertionを持つか */
  hasInsertion: boolean;
  /** 接続されているTransition ID */
  transitionRef: string | null;
}
```

**パーサーの実装**

```typescript
// maimlParserExp.ts
import type { Transition, MaterialTemplate, TransitionExtras, TemplateExtras } from '@/types/maiml-unified';

class MaiMLParser {
  // 基本メソッド
  getTransitions(): Transition[] { ... }
  
  // 拡張メソッド
  getTransitionsExtended(): Array<Transition & TransitionExtras> { ... }
  
  getTemplates(): {
    materials: MaterialTemplate[];
    conditions: ConditionTemplate[];
    results: ResultTemplate[];
  } { ... }
  
  getTemplatesExtended(): {
    materials: Array<MaterialTemplate & TemplateExtras>;
    conditions: Array<ConditionTemplate & TemplateExtras>;
    results: Array<ResultTemplate & TemplateExtras>;
  } { ... }
}
```

**メリット:**
- ✅ 拡張情報の型が定義される
- ✅ XSD準拠型と明確に分離
- ✅ 型安全性が向上

**デメリット:**
- ❌ 型定義ファイルが少し複雑になる
- ❌ `*Extras`型の管理が必要

### 案3: 完全分離（maiml-extended.ts作成）

**新規ファイル作成: maiml-extended.ts**

```typescript
// frontend/src/types/maiml-extended.ts
/**
 * MAIML拡張型定義
 * XSD準拠型（maiml-unified.ts）に対する拡張情報
 */

import type {
  Transition,
  Arc,
  MaterialTemplate,
  ConditionTemplate,
  ResultTemplate
} from './maiml-unified';

/**
 * Transitionの拡張情報を含む型
 */
export interface TransitionExtended extends Transition {
  methodId: string;
  hasInstruction: boolean;
  arcCount: number;
  arcs: Arc[];
  category: 'experiment' | 'preparation' | 'finalization' | 'other';
}

/**
 * MaterialTemplateの拡張情報を含む型
 */
export interface MaterialTemplateExtended extends MaterialTemplate {
  resolvedFromRef: string | null;
  hasTemplateRef: boolean;
  hasInsertion: boolean;
  transitionRef: string | null;
}

/**
 * ConditionTemplateの拡張情報を含む型
 */
export interface ConditionTemplateExtended extends ConditionTemplate {
  resolvedFromRef: string | null;
  hasTemplateRef: boolean;
  hasInsertion: boolean;
  transitionRef: string | null;
}

/**
 * ResultTemplateの拡張情報を含む型
 */
export interface ResultTemplateExtended extends ResultTemplate {
  resolvedFromRef: string | null;
  hasTemplateRef: boolean;
  hasInsertion: boolean;
  transitionRef: string | null;
}
```

**メリット:**
- ✅ maiml-unified.tsが完全にXSD準拠のまま
- ✅ 拡張型が明確に分離
- ✅ 管理しやすい

**デメリット:**
- ❌ ファイルが1つ増える
