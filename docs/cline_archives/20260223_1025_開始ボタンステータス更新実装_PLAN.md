## 1. タスク概要

進捗確認タブのタスク一覧テーブルで、開始ボタン押下時にタスクステータスを「作業中（in_progress）」に更新する機能を実装します。

### API仕様
**エンドポイント**: `PATCH /api/v1/progress/projects/:projectName/methods/:methodId/tasks/:taskNo/status`

**権限**: experiment_worker（書込可）

**リクエストボディ**:
```json
{
  "status": "in_progress",
  "comment": "(optional)",
  "currentUpdatedAt": "(optional, 楽観的ロック用)"
}
```

**レスポンス**:
```json
{
  "success": true,
  "data": {
    "task_no": 1,
    "project_name": "Sample Project",
    "method_id": "method1",
    "previous_status": "not_started",
    "new_status": "in_progress",
    "updated_by": "user-uuid",
    "updated_by_name": "User Name",
    "updated_at": "2026-02-23T10:00:00Z"
  },
  "meta": {
    "timestamp": "2026-02-23T10:00:00Z",
    "requestId": "req_abc123"
  }
}
```

### セキュリティ考慮事項
- [x] JWT認証が必要
- [x] experiment_worker権限が必要
- [x] 自分に割り当てられたタスクのみ更新可能
- [x] プロジェクトが編集可能な状態である必要がある
- [x] マルチテナント分離（organization_id）

### ステータス遷移ルール
```
not_started → in_progress  ✅ 許可（開始ボタン）
not_started → started      ✅ 許可
started → in_progress      ✅ 許可
in_progress → completed    ✅ 許可
completed → in_progress    ✅ 許可（再開）
```

**注意**: UI設計書では「作業中（in_progress）」への更新を想定していますが、API設計書では `not_started → started → in_progress` の段階的遷移も定義されています。今回は要件に従って `not_started → in_progress` への直接遷移を実装します。

### 計画からの変更点
- **currentUpdatedAtパラメータの追加**: バックエンドAPIが楽観的ロックを実装しており、`currentUpdatedAt`パラメータが必須であることが判明。このパラメータを追加する修正を実施。

### 発生した問題と解決方法

#### 問題1: currentUpdatedAtパラメータが必須
**症状**: 開始ボタン押下時に以下のエラーが発生
```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "details": [
      {
        "field": "currentUpdatedAt",
        "message": "currentUpdatedAtは必須です"
      }
    ]
  }
}
```

**原因**: バックエンドAPIが楽観的ロック（Optimistic Locking）を実装しており、タスクステータス更新時に現在の`updated_at`値を`currentUpdatedAt`として送信する必要があった。

**解決方法**:
1. `updateTaskStatus`呼び出し時に`task.updatedAt`を`currentUpdatedAt`パラメータとして渡すように修正
2. UI設計書に楽観的ロックについての説明を追加
3. 409 Conflictエラー（楽観的ロック競合）のエラーハンドリングを強化
