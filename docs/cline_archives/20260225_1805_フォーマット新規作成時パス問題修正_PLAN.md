## 1. タスク概要

フォーマット管理画面で、サブフォルダに移動した状態で新規ファイル・新規フォルダを作成すると、現在のフォルダではなくフォーマットフォルダ直下に生成されてしまうバグを修正する。

## 2. 目的と期待される成果

### 目的
- サブフォルダ内で新規作成を行った際、正しくそのフォルダ内に生成されるようにする
- ユーザーが期待する動作（現在のフォルダ内に作成）を実現する

### 期待される成果
- [x] サブフォルダ移動後の新規ファイル作成が正しいパスで行われる
- [x] サブフォルダ移動後の新規フォルダ作成が正しいパスで行われる

## 3. 問題分析

### 現状の実装
```typescript
// currentFolderPathは配列として管理されている
const [currentFolderPath, setCurrentFolderPath] = useState<string[]>([]);

// モーダルに渡す際、配列のまま渡している
<CreateFormatFileModal
  currentPath={currentFolderPath}  // ❌ 配列
  ...
/>

<CreateFormatFolderModal
  currentPath={currentFolderPath}  // ❌ 配列
  ...
/>
```

### 問題点
- `currentFolderPath`は`['folder1', 'folder2']`のような配列
- モーダルコンポーネントは文字列パス（`'folder1/folder2'`）を期待している
- 配列を文字列に変換せずに渡しているため、APIに正しいパスが送信されない

## 4. 実装ステップ

### Phase 1: パス変換の修正
- [x] `CreateFormatFileModal`の`currentPath`プロップを配列から文字列に変換
- [x] `CreateFormatFolderModal`の`currentPath`プロップを配列から文字列に変換
- [x] `currentFolderPath.join('/')`を使用してパス文字列を生成

### 修正箇所
```typescript
// 修正前
<CreateFormatFileModal
  currentPath={currentFolderPath}
  ...
/>

// 修正後
<CreateFormatFileModal
  currentPath={currentFolderPath.join('/')}
  ...
/>
```

## 6. 技術的詳細

### 配列から文字列パスへの変換
```typescript
// 例
currentFolderPath = ['subfolder1', 'subfolder2']
↓
currentFolderPath.join('/') = 'subfolder1/subfolder2'

// ルート直下の場合
currentFolderPath = []
↓
currentFolderPath.join('/') = ''  // 空文字列（ルート直下を意味する）
```

### API側での処理
- 空文字列: フォーマットフォルダ直下
- `'subfolder1'`: subfolder1内
- `'subfolder1/subfolder2'`: subfolder1/subfolder2内
