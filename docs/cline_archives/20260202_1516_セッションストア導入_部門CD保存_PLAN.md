## 1. タスク概要

Express.jsの標準的な`express-session`を使用してセッション管理を実装。ログイン時に部門CD等のユーザー情報を`req.session`に保存し、後続リクエストで利用できるようにする。

1. ✅ **express-sessionを使用**

   - 標準的なExpress.jsのセッション管理

2. ✅ **セッションストアは環境変数で切り替え**
   - デフォルト: MemoryStore（開発・テスト用）
   - 本番: RedisStore（環境変数で指定）

3. ✅ **BEで必要になったときにreq.sessionから部門CDを読み取る**
   - `req.user`には設定しない

4. ✅ **部門CD以外も今後保存可能**

## 3. アーキテクチャ設計

### 3.1. express-sessionの仕組み

```
[ログイン成功]
  ↓
[req.session.departmentCd = 'DEPT001' に保存]
  ↓
[express-sessionがセッションストアに保存]
  - MemoryStore（デフォルト）
  - RedisStore（環境変数で指定）
  ↓
[クライアントにセッションIDをCookieで返却]

[後続リクエスト]
  ↓
[CookieからセッションIDを取得]
  ↓
[express-sessionがセッションストアから復元]
  ↓
[req.sessionにデータが自動設定される]
  ↓
[コントローラーでreq.session.departmentCdを使用]
```

### 3.2. セッションストアの切り替え

**環境変数:**
```
SESSION_STORE=memory  # デフォルト（開発・テスト用）
SESSION_STORE=redis   # 本番環境
```

**MemoryStore（デフォルト）:**
- express-sessionに標準搭載
- プロセスメモリに保存
- サーバー再起動でセッション消失
- スケールアウト不可（単一サーバーのみ）

**RedisStore:**
- `connect-redis`パッケージを使用
- Redis外部ストアに保存
- サーバー再起動でもセッション維持
- 複数サーバーでセッション共有可能

## 6. 技術的詳細

### 6.1. backend/src/middleware/sessionMiddleware.ts

```typescript
import session from 'express-session';
import RedisStore from 'connect-redis';
import { createClient } from 'redis';
import { logError } from '../utils/logger';

// セッションストアの設定
export function setupSessionMiddleware() {
  const sessionStore = process.env.SESSION_STORE || 'memory';
  const sessionSecret = process.env.SESSION_SECRET || 'default-secret-change-in-production';

  // セッションオプション（共通）
  const sessionOptions: session.SessionOptions = {
    secret: sessionSecret,
    resave: false,
    saveUninitialized: false,
    cookie: {
      httpOnly: true,
      secure: process.env.NODE_ENV === 'production', // 本番環境ではHTTPSのみ
      maxAge: 24 * 60 * 60 * 1000, // 24時間
      sameSite: 'strict',
    },
  };

  // ストアの切り替え
  if (sessionStore === 'redis') {
    console.log('Using Redis Session Store');

    // Redisクライアント作成
    const redisClient = createClient({
      url: `redis://:${process.env.REDIS_PASSWORD}@${process.env.REDIS_HOST}:${process.env.REDIS_PORT}`,
    });

    redisClient.on('error', (err) => {
      logError('Redis Client Error', err as Error, { service: 'sessionMiddleware' });
    });

    redisClient.on('connect', () => {
      console.log('Redis session store connected');
    });

    redisClient.connect().catch((err) => {
      logError('Failed to connect Redis session store', err as Error, { service: 'sessionMiddleware' });
    });

    // RedisStoreを設定
    sessionOptions.store = new RedisStore({
      client: redisClient,
      prefix: 'sess:',
      ttl: 24 * 60 * 60, // 24時間（秒）
    });
  } else {
    console.log('Using Memory Session Store (development only)');
    // デフォルトのMemoryStoreを使用（storeオプション省略）
  }

  return session(sessionOptions);
}
```

## 7. セキュリティ考慮事項

### 7.1. セッションCookie
- `httpOnly: true` - JavaScriptからアクセス不可（XSS対策）
- `secure: true` - HTTPS通信のみ（本番環境）
- `sameSite: 'strict'` - CSRF対策

### 7.2. セッションシークレット
- 環境変数で管理
- 本番環境では強力なランダム文字列を使用

### 7.3. セッション有効期限
- デフォルト: 24時間
- ロール別に調整可能（将来的に）

### 7.4. Redis認証（Redis使用時）
- パスワード認証必須
- Dockerネットワーク内通信

## 8. パフォーマンス考慮事項

### 8.1. MemoryStore
- **メリット**: 高速、設定不要
- **デメリット**: 
  - サーバー再起動でセッション消失
  - スケールアウト不可
  - メモリ使用量増加
- **用途**: 開発・テスト環境のみ

### 8.2. RedisStore
- **メリット**: 
  - 永続化
  - 複数サーバーでセッション共有
  - メモリ効率的
- **デメリット**: 
  - Redis接続が必要
  - わずかなネットワークオーバーヘッド
- **用途**: 本番環境推奨

### 8.3. セッションアクセスパターン
- 各リクエストで`req.session`から取得
- セッションストアへのアクセスはexpress-sessionが最適化

## 9. リスクと対策

| リスク | 影響度 | 発生確率 | 対策 |
|--------|--------|----------|------|
| Redis接続失敗 | 高 | 低 | フォールバック設定、アラート |
| セッション期限切れ | 中 | 中 | 適切な期限設定、再ログイン促進 |
| セッションハイジャック | 高 | 低 | HTTPS強制、セキュアCookie設定 |
| MemoryStore使用時のメモリ枯渇 | 中 | 中 | 本番環境ではRedisStore必須 |
