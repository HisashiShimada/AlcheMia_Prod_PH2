### ID生成ロジック

```typescript
const generateDocumentIds = (baseName: string, sourceContext: 'project' | 'format') => {
  const sanitizedName = baseName.replace(/\s+/g, '_').replace(/[^a-zA-Z0-9_]/g, '');
  const uuidFull = crypto.randomUUID();
  const uuidPrefix = uuidFull.substring(0, 8);
  
  return {
    id: `document_${sanitizedName}_${uuidPrefix}`,
    protocolId: `protocol_${sanitizedName}_${crypto.randomUUID().substring(0, 8)}`,
    methodId: `method_${sanitizedName}_${crypto.randomUUID().substring(0, 8)}`,
    pnmlId: `pnml_${sanitizedName}_${crypto.randomUUID().substring(0, 8)}`,
    programId: `program_${sanitizedName}_${crypto.randomUUID().substring(0, 8)}`,
    name: baseName,
    uuid: uuidFull,
  };
};
```

### 条件表示ロジック（TemplateEditorDialog）

// ヘッダー表示
const dialogTitle = useMemo(() => {

## 6. リスクと対策

| リスク | 影響度 | 発生確率 | 対策 |
|--------|--------|----------|------|
| 既存のプロジェクト管理機能への影響 | 高 | 中 | Props型にデフォルト値を設定し、既存の呼び出しに影響しないようにする |
| ID生成ロジックの衝突 | 中 | 低 | UUID使用により衝突を回避。ベース名のサニタイズ処理を追加 |
| ファイル名変更によるモックデータ不整合 | 中 | 中 | 変更前後のマッピングテーブルを作成し、段階的に移行 |
| テンプレート種別の判定失敗 | 中 | 中 | フォールバック値を設定。拡張子と内容の両方で判定 |
