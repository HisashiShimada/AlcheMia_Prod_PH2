## 1. タスク概要

現在、メニュー切り替えボタンに権限チェックが実装されていないため、ユーザーの権限（Permission）に基づいてメニューの活性/非活性を制御する機能を実装します。

**実装方針:**
1. ログインユーザーの権限（Permission配列）を取得
2. Permissionの`functionId`がアクセスできる各画面を表している
3. `functionId`を見てメニューボタンを制御する（権限のないメニューは非表示）

**注意:** 権限のないメニューは表示されないため、クリックできません。そのため、page.tsx内での権限チェック・エラーメッセージ表示は不要です。

## 5. 技術的詳細

### バックエンド - Permission情報の構造

`req.user`が持つPermission情報（既存）:
```typescript
interface User {
  id: string;
  username: string;
  email: string;
  roleName: string;
  roleCd: string;
  organizationId: string;
  organizationName: string;
  displayName: string;
  departmentCd: string;
  initialScreenFunctionCd: string;
  permissions?: Permission[];  // ★この配列を利用
}

interface Permission {
  functionId: string;      // ★メニューへのアクセス権を表す
  permission: number;      // 0=書込専用, 1=読取権限
}
```

### フロントエンド - メニューとfunctionIdのマッピング

```typescript
// メニュータイプとfunctionIdのマッピング
export const MENU_FUNCTION_IDS: Record<MenuType, string> = {
  provider: '010000',
  system_admin: '020000',
  data_admin: '030000',
  experiment_admin: '040000',
  experiment_worker: '050000',
  mi_engineer: '060000',
} as const;
```

### フロントエンド - 権限チェックロジック

```typescript
/**
 * ユーザーが指定されたメニューにアクセスする権限があるかチェック
 * 
 * @param permissions - ユーザーのPermission配列
 * @param menuType - チェック対象のメニュータイプ
 * @returns アクセス権限がある場合true
 */
export function hasMenuPermission(
  permissions: Permission[] | undefined,
  menuType: MenuType
): boolean {
  if (!permissions || permissions.length === 0) {
    return false;
  }
  
  // メニュータイプに対応するfunctionIdを取得
  const targetFunctionId = MENU_FUNCTION_IDS[menuType];
  
  // permissions配列の中に該当functionIdが存在するかチェック
  return permissions.some(p => p.functionId === targetFunctionId);
}
```

### page.tsx - 実装例

```typescript
// SubHeaderにuserPermissionsを渡す
<SubHeader
  title={t('menu.provider.title')}
  tabs={tabItems}
  activeTabKey={currentTab}
  onTabChange={handleTabChange}
  currentMenu="provider"
  onMenuChange={handleMenuChange}
  userPermissions={user.permissions}  // ★追加
/>
```

**注意:** `handleMenuChange`内での権限チェックは不要です。
理由: SubHeaderで非活性化されたメニューはクリックできないため、権限のないメニューへのアクセスは発生しません。

### セキュリティ考慮事項

1. **フロントエンド制御の限界**
   - あくまでUIレベルの制御であり、バックエンドでの権限チェックが必須
   - JavaScriptは改ざん可能なため、完全なセキュリティは保証できない

2. **バックエンドでの二重チェック**
   - 各APIエンドポイントで必ず権限チェックを実施
   - フロントエンドの制御はUX向上のための補助的な役割

3. **Permission情報の信頼性**
   - JWTトークンまたはセッションから取得したPermission配列を使用
   - トークン検証を必ず実施
