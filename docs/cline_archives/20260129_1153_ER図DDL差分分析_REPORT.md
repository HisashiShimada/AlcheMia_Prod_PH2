## 分析結果サマリー

### 共通パターン
ほとんどのテーブルに以下の監査証跡カラムが追加されています：
- `create_user_id` (UUID)
- `create_at` (TIMESTAMP)
- `update_user_id` (UUID)
- `update_at` (TIMESTAMP)

**既存カラム:** create_at, update_at

#### 4. project（プロジェクト）

#### 6. issue（問題）
**不足カラム:**

- `update_user_id` UUID
- `update_at` TIMESTAMP

**カラム名の不一致:**
- ER図: `task_no` NUMERIC(3,0)
- DDL: `task_id` NUMERIC(3,0)
→ **要修正**: DDLを `task_no` に変更

1. **優先対応テーブル（ビジネスロジックへの影響大）:**

   - ER図の命名規則に合わせる

3. **監査証跡カラムの配置順序:**
   ```sql

   ...
   -- タイムスタンプ
   create_at TIMESTAMP,
   update_at TIMESTAMP,
   -- 監査証跡
   create_user_id UUID,
   update_user_id UUID,
   ```
