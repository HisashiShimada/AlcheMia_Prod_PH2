- 実験記録データ取得: `GET /api/experiment-records/by-work-id/:workId`

これらは実験作業者画面（ExperimentWorker）専用で、実験管理者の4画面では使用しません。

## 📊 統合時の主要な発見

### ✅ 良好な点
1. プロジェクト管理の基本機能（CRUD、チェックイン/アウト）は実装済み
2. API設計書が詳細に記述されており、実装の指針が明確
3. UI仕様書とAPI設計書の連携が取れている（プロジェクト管理）

### ⚠️ 課題と対応
1. **API数の最適化**
   - 削除: プロジェクト更新、削除、チェックアウト状態取得
   - 削除: フォーマット削除、進捗確認の問題管理関連API
   - **結果**: 37個 → 26個に削減（30%削減）

2. **共通API化による重複排除**
   - ファイルアップロード/ダウンロードを共通API化
   - プロジェクト管理とフォーマット管理から共通ルートに分離
   - contextパラメータで保存先を判定（project/format）

3. **API責任の明確化**
   - プロジェクト詳細取得を分割 → ファイル一覧、タスク一覧
   - 各APIが単一責任を持つように再設計

### 🔧 推奨対応
1. **即座の実装**: 設計済み2 API（指示送信、詳細検索）
2. **最優先設計**: 共通API（ファイルアップロード、ダウンロード）
3. **設計書作成順**: 共通API → プロジェクト管理 → フォーマット管理 → Maiml編集 → 進捗確認
