## 📋 概要

ロール管理画面のCSVアップロード機能は、ロール（role）テーブルとロール権限（role_permission）テーブルに複数のロールと権限情報を一括登録する機能です。

### 機能の目的
- 複数のロールを一括登録
- 各ロールに複数の機能権限を設定
- 既存データとの重複チェック
- トランザクション処理による安全な登録

## 📝 CSV形式仕様

### ヘッダー行（必須）

```csv
role_cd,role_name,function_cd,permission,initial_screen_function_cd,is_active,update_at
```

### カラム定義

| カラム名 | 必須 | 型 | 説明 | 例 | 備考 |
|---------|------|-----|------|-----|------|
| **role_cd** | ✅ | string | ロールCD（主キー） | `ROLE007` | DBで一意 |
| **role_name** | ✅ | string | ロール名 | `統合運用管理` | - |
| **function_cd** | ✅ | string | 機能名 | `システム管理者メニュー` | FunctionListに存在する機能名 |
| **permission** | ✅ | string | 権限記号 | `Ⓦ` または `Ⓡ` | 書込または読取 |
| **initial_screen_function_cd** | ❌ | string | 初期画面機能名 | `システム管理者メニュー` | 省略可（nullになる） |
| **is_active** | ❌ | boolean | 有効/無効 | `true` | デフォルト: true |
| **update_at** | ❌ | - | 更新日時 | `Invalid Date` | **無視される（任意の値でOK）** |

### 権限記号の定義

| 記号 | 意味 | DBの値 | 英語名 |
|------|------|--------|--------|
| **Ⓦ** | 書込権限 | `0` | WRITER |
| **Ⓡ** | 読取権限 | `1` | READER |

### 有効な機能名（function_cd, initial_screen_function_cd）

**FunctionListで定義された機能名のみ有効:**

| 機能ID | 機能名 | CSV記載方法 |
|--------|--------|------------|
| 010000 | プロバイダーメニュー | `プロバイダーメニュー` |
| 020000 | システム管理者メニュー | `システム管理者メニュー` |
| 030000 | データ管理者メニュー | `データ管理者メニュー` |
| 040000 | 実験管理者メニュー | `実験管理者メニュー` |
| 050000 | 実験作業者メニュー | `実験作業者メニュー` |

**重要:** CSVには「機能名」（日本語）を記載します。機能ID（数値）ではありません。

## 📦 CSVファイルの構造

### 基本ルール: 1ロール = 複数行

**同じ`role_cd`を持つ行は1つのロールとしてグループ化されます。**

### パターンA: 1ロール × 1権限（最小構成）

```csv
role_cd,role_name,function_cd,permission,initial_screen_function_cd,is_active,update_at
ROLE007,統合運用管理,システム管理者メニュー,Ⓦ,システム管理者メニュー,true,
```

**登録結果:**
- roleテーブル: 1件（ROLE007）
- role_permissionテーブル: 1件

### パターンB: 1ロール × 複数権限

```csv
role_cd,role_name,function_cd,permission,initial_screen_function_cd,is_active,update_at
ROLE001,管理者,プロバイダーメニュー,Ⓦ,プロバイダーメニュー,true,
ROLE001,管理者,システム管理者メニュー,Ⓦ,プロバイダーメニュー,true,
ROLE001,管理者,データ管理者メニュー,Ⓡ,プロバイダーメニュー,true,
```

**登録結果:**
- roleテーブル: 1件（ROLE001）
- role_permissionテーブル: 3件

**注意点:**
- 同じ`role_cd`の行は、`role_name`と`initial_screen_function_cd`も同じ値を使用すること
- `is_active`も統一すること

### パターンC: 複数ロール × 各ロール複数権限

```csv
role_cd,role_name,function_cd,permission,initial_screen_function_cd,is_active,update_at
ROLE008,上級管理者,プロバイダーメニュー,Ⓦ,プロバイダーメニュー,true,
ROLE008,上級管理者,システム管理者メニュー,Ⓦ,プロバイダーメニュー,true,
ROLE009,一般作業者,実験作業者メニュー,Ⓦ,実験作業者メニュー,true,
ROLE009,一般作業者,実験管理者メニュー,Ⓡ,実験作業者メニュー,true,
```

**登録結果:**
- roleテーブル: 2件（ROLE008, ROLE009）
- role_permissionテーブル: 4件

## ✅ バリデーションルール

### Phase 1: CSVパースチェック

| チェック項目 | エラーコード | 説明 |
|-------------|-------------|------|
| CSV形式の正当性 | `CSV_PARSE_ERROR` | PapaParseでパースエラーが発生 |
| データ行の存在 | `EMPTY_CSV` | ヘッダー行のみでデータ行がない |

### Phase 2: 必須項目チェック

| 項目 | ルール | エラーメッセージ例 |
|------|--------|-------------------|
| **role_cd** | 空白不可 | `2行目: role_cdは必須です` |

### Phase 3: 型チェック（is_active）

**有効な値:**
- `true`, `TRUE`, `1` → true
- `false`, `FALSE`, `0` → false
- 空文字 `""` → true（デフォルト）

**無効な値の場合:**
```
2行目: is_activeは true/false/1/0 のいずれかである必要があります
```

### Phase 4: CSV内重複チェック（role_cd）

**同じrole_cdがCSV内で複数回定義されていないかチェック**

```csv
ROLE001,管理者A,...
ROLE001,管理者A,...  ✅ OK（同じロール名）
ROLE001,管理者B,...  ❌ NG（異なるロール名）
```

**エラーメッセージ:**
```
3行目: role_cd「ROLE001」はCSV内で重複しています
```

### Phase 5: DB既存チェック

**すでにDBに存在するrole_cdを登録しようとしているかチェック**

**エラーメッセージ:**
```
2行目: role_cd「ROLE001」は既に存在します
```

### Phase 6: 機能名の存在チェック

**function_cdとinitial_screen_function_cdがFunctionListに存在するかチェック**

**エラーメッセージ:**
```
初期画面機能「システム管理メニュー」が見つかりません
機能「プロバイダメニュー」が見つかりません
```

**よくある間違い:**
| 誤った記載 | 正しい記載 |
|-----------|-----------|
| `システム管理メニュー` | `システム管理者メニュー` |
| `プロバイダメニュー` | `プロバイダーメニュー` |
| `実験管理メニュー` | `実験管理者メニュー` |
| `実験作業メニュー` | `実験作業者メニュー` |

## 🔄 処理フロー

### Phase 1: CSVパース

```
1. PapaParseでCSVをパース
2. ヘッダー行を自動検出
3. 空行をスキップ
4. データ行を配列に格納
```

### Phase 2: バリデーション

```
1. 必須項目チェック（role_cd）
2. 型チェック（is_active）
3. CSV内重複チェック（role_cd）
```

### Phase 3: DB既存チェック

```
各role_cdに対してDB存在チェック
EXISTS(SELECT 1 FROM role WHERE organization_id = $1 AND role_cd = $2)
```

### Phase 4: role_cdでグループ化

```javascript
{
  "ROLE001": [行1, 行2, 行3],
  "ROLE002": [行4]
}
```

### Phase 5: トランザクション処理

```sql
BEGIN;

  -- 各ロールごとに処理
  FOR EACH ロール:
    
    -- 1. initial_screen_function_cd（機能名）→ 機能ID変換
    SELECT function_id FROM FunctionList WHERE name = '機能名';
    
    -- 2. is_activeの変換（文字列 → boolean）
    true/TRUE/1/"" → true
    false/FALSE/0 → false
    
    -- 3. roleテーブルにINSERT
    INSERT INTO role (
      organization_id, role_cd, role_name, 
      initial_screen_function_cd, is_active,
      create_user_id, update_user_id, create_at, update_at
    ) VALUES (...);
    
    -- 各権限行ごとに処理
    FOR EACH 権限行:
      
      -- 4. function_cd（機能名）→ 機能ID変換
      SELECT function_id FROM FunctionList WHERE name = '機能名';
      
      -- 5. permission記号（Ⓦ/Ⓡ）→ 数値（0/1）変換
      Ⓦ → 0
      Ⓡ → 1
      
      -- 6. role_permissionテーブルにINSERT
      INSERT INTO role_permission (
        organization_id, role_cd, function_cd, permission,
        create_user_id, update_user_id, create_at, update_at
      ) VALUES (...);

COMMIT;
```

**エラー発生時:**
- 自動的にROLLBACK
- すべての変更が取り消される
- エラー情報をクライアントに返す

### role_permissionテーブル

| カラム名 | データソース | 変換処理 | 例 |
|---------|-------------|---------|-----|
| organization_id | ログインユーザー | - | `a0718dc5-21f3-44e6-87e9-cc2ae83f3385` |
| role_cd | CSVから取得 | trim() | `ROLE007` |
| function_cd | CSVから取得 | 機能名→ID変換 | `020000` |
| permission | CSVから取得 | 記号→数値変換 | `0` |

| update_at | システム生成 | new Date() | `2026-02-04 18:00:00` |

### 変換処理の詳細

#### 1. 機能名 → 機能ID の変換

```typescript
// FunctionListから逆引き
const entries = Object.entries(FunctionList);
const found = entries.find(([, value]) => value === functionName);
const functionId = found ? found[0] : null;

// 例: "システム管理者メニュー" → "020000"
```

#### 2. 権限記号 → 数値 の変換

```typescript
const permissionSymbol = row['permission']?.trim();
const permission = permissionSymbol === 'Ⓦ' ? 0 : 1;

// Ⓦ → 0 (WRITER)
// Ⓡ → 1 (READER)
```

#### 3. is_active の変換

```typescript
const isActiveStr = row['is_active']?.trim().toLowerCase();
const isActive = isActiveStr === 'true' || isActiveStr === '1' || isActiveStr === '';

// "true", "TRUE", "1", "" → true
// "false", "FALSE", "0" → false
```

## 🚨 よくある問題と対処法

### 問題1: 「正常終了」と表示されるがデータが登録されない

**原因:**
1. **機能名の誤り**: FunctionListに存在しない機能名を使用
2. **全角/半角の違い**: スペースや文字の全角/半角が異なる
3. **文字コードの問題**: UTF-8以外でCSVを保存

**対処法:**
- バックエンドコンソールのログを確認（デバッグログが出力される）
- 機能名を正確にコピー&ペースト
- CSVファイルをUTF-8 BOM付きで保存

**確認方法:**
```bash
# バックエンドコンソールで以下のログを確認
=== CSV Upload Debug ===
Parsed rows: [...]
Processing role: ROLE007
Initial screen function name: システム管理者メニュー
Initial screen function CD: 020000  # nullの場合は機能名が間違っている
```

### 問題2: 「role_cdが既に存在します」エラー

**原因:**
既にDBに登録されているrole_cdを使用

**対処法:**
- 異なるrole_cdを使用
- または既存データを削除してから再アップロード

### 問題3: 「機能が見つかりません」エラー

**原因:**
FunctionListに定義されていない機能名を使用

**有効な機能名（厳密に一致する必要がある）:**
```
プロバイダーメニュー
システム管理者メニュー
データ管理者メニュー
実験管理者メニュー
実験作業者メニュー
```

**対処法:**
上記のいずれかを**正確に**使用（コピー&ペースト推奨）

### 問題4: CSV内重複エラー

**原因:**
同じrole_cdが異なる内容で複数回定義されている

**悪い例:**
```csv
ROLE001,管理者A,プロバイダーメニュー,Ⓦ,プロバイダーメニュー,true,
ROLE001,管理者B,システム管理者メニュー,Ⓦ,システム管理者メニュー,true,  ❌
```

**良い例:**
```csv
ROLE001,管理者A,プロバイダーメニュー,Ⓦ,プロバイダーメニュー,true,
ROLE001,管理者A,システム管理者メニュー,Ⓦ,プロバイダーメニュー,true,  ✅
```
