# write_to_fileツール使用時のエラー原因分析

## メタデータ
- **作成日時**: 2026-01-14 16:20
- **問題**: タスクのコンテキストをwrite_to_fileで書き出す際にエラー発生
- **調査担当**: Cline

---

## 🔍 問題の原因

### 主な原因: XMLパースエラー

`write_to_file`ツールはXML形式でパラメータを指定するため、**content内にXML特殊文字やツールタグが含まれているとパースエラー**が発生します。

---

## 📊 具体的なエラーパターン

### パターン1: ツールタグの衝突 ⚠️（最も重要）

**問題の説明:**
content内にツールのXMLタグ（例: `write_to_file`, `execute_command`等）を記述すると、XMLパーサーがツールタグの終了位置を誤認識してエラーになります。

**エラーになる例:**
```
タスク計画書には以下のツールを使用します：

【ここにwrite_to_fileツールのXML例を書くとエラー】

この部分でXMLパーサーが混乱し、ファイルが途中で切れる
```

**エラーの原因:**
- content内の閉じタグ（例: `</content>`）が、外側のcontentタグを閉じていると誤認識される
- XMLの入れ子構造が壊れ、パースエラーが発生
- ファイルが途中で切断される

### パターン2: XML特殊文字のエスケープ不足

**エラーになる例:**
```
比較演算子: a < b && c > d
この < と > がXMLタグと誤認識される
```

**エラーの原因:**
- `<`と`>`がXMLタグの開始/終了と誤認識される
- `&`がXMLエンティティの開始と誤認識される

### パターン3: 非常に長いコンテンツ

**問題:**
10,000行以上の非常に長いコンテンツをwrite_to_fileで書き込もうとすると、コンテキストウィンドウ制限に達してエラーになる可能性があります。

---

## ✅ 解決策

### 解決策1: ツールタグを記述する際の回避方法

#### 方法A: コードブロックで記述（推奨）
```markdown
ツールの使用例：

` ` `xml
ここにツールのXML例を記述
write_to_file等のタグを含めても問題なし
` ` `
```
※実際は` ` `の間にスペースなし

#### 方法B: テキストで説明
```markdown
write_to_fileツールは以下の形式で使用します：
- pathパラメータにファイルパスを指定
- contentパラメータにファイル内容を指定
```

#### 方法C: HTMLエンティティでエスケープ
```markdown
&lt;write_to_file&gt; タグを使用します
```

### 解決策2: XML特殊文字のエスケープ

**推奨される記述方法:**
```markdown
# 比較演算子を書く場合
- 不等号: a 小なり b かつ c 大なり d
- または: a は b より小さい

# アンパサンドを書く場合
- AND演算子: a AND b（&&ではなく）
```

### 解決策3: 長いコンテンツの分割

**10,000行を超える場合:**
1. ファイルを複数に分割する
2. 各ファイルを個別にwrite_to_fileで作成
3. または`execute_command`でファイル結合

## 🎯 ベストプラクティス

### DO（推奨）

✅ **ツール例を記述する際はコードブロックを使用**
```markdown
` ` `xml
ツールのXML例
` ` `
```

✅ **XML特殊文字は日本語や代替表現を使用**
- `<` → 「小なり」「より小さい」
- `>` → 「大なり」「より大きい」  
- `&` → 「AND」「かつ」

✅ **長いコンテンツは分割する**
- 1ファイルあたり5,000行以内を推奨
- 論理的な単位で分割

✅ **タスク計画書やドキュメントでは説明文を重視**
- ツールのXML構文をそのまま書かない
- 使い方を日本語で説明する

### DON'T（非推奨）

❌ **content内にツールタグを直接書かない**
```
write_to_fileのXMLタグをそのまま書くとエラー
```

❌ **XML特殊文字をエスケープせずに書かない**
```
a < b && c > d このまま書くとエラー
```

❌ **非常に長いコンテンツを一度に書き込まない**
```
10,000行以上のファイルを一度に作成するとエラーの可能性
```

## 💡 今回の問題の実例

### 何が起きたか
タスクのコンテキストをwrite_to_fileで書き出そうとした際、content内にツールのXML例（`<write_to_file>`タグ等）を含めようとしたため、XMLパーサーがエラーになりました。

### このドキュメント自体でもエラー発生
このドキュメントの初稿でも同じエラーが発生し、ファイルが途中で切れてしまいました。これが問題の完璧な実例です。

### 修正方法
`replace_in_file`ツールを使用して、ツールタグをテキスト説明に置き換えました。

## 📝 まとめ

### 問題の本質
`write_to_file`はXMLベースのツールなので、**content内にXMLタグやXML特殊文字が含まれるとパースエラー**が発生します。

### 重要なルール
1. **ツールのXML例はコードブロックで記述する**
2. **XML特殊文字（<, >, &）は日本語表現を使う**
3. **長いコンテンツは分割する**
4. **ツールの使い方は説明文で記述する**
