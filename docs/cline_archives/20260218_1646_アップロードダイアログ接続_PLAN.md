g# アップロードダイアログのバックエンド接続修正計画

## 調査日時
2026-02-18 16:46

## 目的
BulkUploadDialogをバックエンドAPIと正しく接続し、実際に動作するようにする

## 前提調査
- 調査ドキュメント: `docs/20260218_1415_ファイルアップロード機能_現状調査.md`

## 特定された問題点

### 1. モックデータの使用
- `folderStructureOptions`というハードコーディングされたモックデータを使用
- 実際のプロジェクトと連動していない

### 2. プロパティの未使用
- `projectId`プロップを受け取るが使用していない
- `preselectedFolder`プロップも実質使用されていない

### 3. パス管理の不整合
- フロントエンドで組織IDを付与: `${userOrganization.id}/${selectedFolderPath.join('/')}`
- バックエンドでも組織IDを付与するため、二重付与の可能性
- パラメータ名も間違っている（`targetFolder`ではなく`targetPath`）

### 4. アップロード先の不明確
- プロジェクトに紐付いたアップロードになっていない

## 修正方針

### 修正1: モックデータを削除
- `folderStructureOptions`を削除
- Cascaderコンポーネントも削除（プロジェクトは既に選択済み）

### 修正2: プロジェクトベースのアップロード
- `projectId`と`preselectedFolder`（プロジェクト名）を使用
- アップロード先を`projects/{projectName}`に固定
- サブフォルダオプションを追加（ルート or archive）

### 修正3: パス管理の統一
- 組織IDはバックエンドで自動付与
- フロントエンドは相対パスのみ送信: `projects/{projectName}`

### 修正4: APIパラメータの修正
```typescript
// 修正前
await fileService.uploadFiles({
  projectId,
  uploadMode,
  targetFolder: selectedFolderPathString,  // ❌ 間違ったパラメータ名
  files,
  ...
});

// 修正後
await fileService.uploadFiles({
  uploadMode,
  targetPath: `projects/${preselectedFolder}`,  // ✅ 正しいパラメータ名
  files,
  metadata: {
    projectId,
    batchName: batchName || undefined,
    preserveFolderStructure: uploadMode !== 'single' && preserveFolderStructure,
  },
  ...
});
```
