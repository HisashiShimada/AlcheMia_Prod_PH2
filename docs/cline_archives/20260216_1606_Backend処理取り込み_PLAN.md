`backend/reference/routes/s3/` フォルダ内の古いS3 APIエンドポイントの処理を、現行のバックエンドに取り込みます。

3. `/api/s3/maiml-auto-correct-realtime` → `/api/maiml/auto-correct` - 自動補正（2箇所）

## 5. 技術的詳細

### 5.1 ファイル一覧取得API

**Reference実装**: `listingRoutes.js` - GET `/api/s3/files`

**主要機能**:
- マルチテナント対応（organization_id必須）
- チェックアウト状態の取得・付与
- キャッシュ機能（CACHE_DURATION_MINUTES）
- S3プレフィックスの組織別フィルタリング

**新API仕様**:
```typescript
// GET /api/maiml/files?organizationId=xxx
interface ListFilesRequest {
  organizationId: string;
}

interface ListFilesResponse {
  success: boolean;
  files: Array<{
    key: string;
    name: string;
    size: number;
    lastModified: string;
    isFolder: boolean;
    organizationId: string;
    isCheckedOut: boolean;
    checkedOutBy: string | null;
    managerId: string | null;
    checkoutTime: string | null;
    workId: string | null;
    workUuid: string | null;
    workerId: string | null;
    assignedWorkerId: string | null;
    assignedTo: string | null;
  }>;
  hierarchicalData: any[];
  totalCount: number;
  organizationId: string;
  cached: boolean;
  processingTime?: number;
  cacheAge?: number;
  timestamp: string;
}
```

**実装ポイント**:
- `getOrganizationS3Prefix()` でDB取得したs3_root_prefixを使用
- テナント検証: `tenantContext.allowedOrgIds`
- チェックアウト状態: `file_checkout_status` テーブル結合
- キャッシュ管理: `cacheManager` 使用

### 5.2 ファイル内容取得API

**Reference実装**: `retrievalRoutes.js` - GET `/api/s3/file-content`

**主要機能**:
- S3からファイル内容取得
- UTF-8テキスト変換
- Content-Typeの自動判定

**新API仕様**:
```typescript
// GET /api/maiml/file-content?key=xxx
interface GetFileContentRequest {
  key: string;
}

interface GetFileContentResponse {
  success: boolean;
  data: {
    content: string;
    fileKey: string;
    contentLength: number;
    lastModified: string;
    contentType: string;
  };
}
```

**実装ポイント**:
- S3 GetObjectCommand使用
- ストリームからBuffer結合 → UTF-8変換
- エラーハンドリング: NoSuchKey, AccessDenied

---

### 5.3 自動補正API

**Reference実装**: `validationRoutes.js` - POST `/api/s3/maiml-auto-correct-realtime`

**主要機能**:
- Base64デコード処理（必須）
- maimlParser.analyzeMaiMLFile()によるバリデーション
- 選択されたエラーに対する自動補正適用
- 補正後のMaiMLコンテンツを返す

**新API仕様**:
```typescript
// POST /api/maiml/auto-correct
interface AutoCorrectRequest {
  maimlContent: string; // Base64エンコード済み
  selectedErrors?: number[];
  organizationId: string;
}

interface AutoCorrectResponse {
  success: boolean;
  correctedContent?: string;
  appliedCorrections: Array<{
    errorIndex: number;
    type: string;
    description: string;
    applied: boolean;
    reason?: string;
  }>;
  correctionCount: number;
  totalAttempted: number;
  message: string;
  timestamp: string;
}
```

**実装ポイント**:
- Base64デコード: `Buffer.from(maimlContent, 'base64').toString('utf-8')`
- UTF-8 BOM除去処理
- maimlParser統合（既存サービス利用）
- エラータイプ別の補正ロジック
  - `missing_attribute`: 属性追加
  - `invalid_value`: 値補正（未実装）

---

### 5.4 ドラフト保存API

**Reference実装**: `draftRoutes.js` - POST `/api/s3/maiml-drafts`（パス: `/save`）

**主要機能**:
- マルチテナント対応（organization_id必須）
- ノード・アーク・テンプレート・Document情報の保存
- ON CONFLICT での更新（upsert）
- 孤立アークのクリーニング（読み込み時）

**新API仕様**:
```typescript
// POST /api/maiml/drafts
interface SaveDraftRequest {
  draftKey: string;
  draftName: string;
  originalFileKey?: string;
  nodes: Node[];
  arcs: Edge[];
  templates: TemplatesByCategory;
  documentData: DocumentData;
  organizationId: string;
}

interface SaveDraftResponse {
  success: boolean;
  draft: {
    id: number;
    draft_key: string;
    draft_name: string;
    organization_id: string;
    node_count: number;
    arc_count: number;
    template_count: number;
    last_saved_at: string;
  };
  message: string;
}
```

**実装ポイント**:
- テーブル: `maiml_drafts`
- カラム: draft_key, user_id, organization_id, nodes（JSON）, arcs（JSON）, templates（JSON）, document_data（JSON）
- テナント検証: `tenantContext.allowedOrgIds`
- カウント計算: node_count, arc_count, template_count

## 6. リスクと対策

| リスク | 影響度 | 発生確率 | 対策 |
|--------|--------|----------|------|
| マルチテナント分離の不備 | 高 | 中 | テナント検証を全エンドポイントに実装、テスト |
| 既存キャッシュ機能の互換性 | 中 | 中 | cacheManagerの動作確認、タイムアウト設定調整 |
| Base64デコードエラー | 中 | 低 | try-catchでエラーハンドリング、エラーメッセージ改善 |
| 孤立アーククリーニングの漏れ | 中 | 低 | ドラフト読み込み時に必ず実行、ログ出力 |
| パフォーマンス低下 | 低 | 低 | キャッシュ活用、バッチ処理最適化 |
