## 1. タスク概要

Reference版uploadRoutes.jsの高優先度機能を現行版に取り込むPhase1実装。以下の3つの機能を実装します：

1. **Task 1-1**: MAIMLメタデータ自動抽出機能（5日）
2. **Task 1-2**: ファイルサイズ上限引き上げ（3日）
3. **Task 1-3**: 空フォルダプレースホルダー機能（5日）

## 2. 目的と期待される成果

### 目的
- Reference版の重要機能を現行版に統合し、ファイルアップロード機能を強化する
- MAIMLファイルのメタデータ自動抽出により、データ管理を効率化する
- 大容量ファイルのアップロードを可能にする
- S3/Swiftの制約（空フォルダ不可）を解消する

### 期待される成果
- [ ] MAIMLファイル保存時に自動的にメタデータがDBに保存される
- [ ] 500MBまでのファイルアップロードが可能になる
- [ ] 空フォルダ構造が完全に保持される
- [ ] すべての機能が現行の3層アーキテクチャ（Route→Controller→Service）に統合される
- [ ] TypeScript型定義が完全に実装される
- [ ] 単体テスト・統合テストがすべて合格する

## 5. 技術的詳細

### 使用する技術・ライブラリ
- TypeScript: 型定義の完全実装
- Express.js: ルーティング・ミドルウェア
- Multer: ファイルアップロード処理
- express-validator: リクエストバリデーション
- PostgreSQL: メタデータ保存
- S3/Swift: ファイルストレージ

### アーキテクチャ上の考慮事項
- 3層アーキテクチャ（Route→Controller→Service）を維持
- Repository層を活用したDB操作
- エラーハンドリングの統一
- 非同期処理の適切な使用

### セキュリティ考慮事項
- [ ] organization_idによるマルチテナント分離の維持
- [ ] ファイルパスのバリデーション（パストラバーサル対策）
- [ ] ファイルサイズ制限の適切な設定
- [ ] エラーメッセージに機密情報を含めない

## 6. リスクと対策

| リスク | 影響度 | 発生確率 | 対策 |
|--------|--------|----------|------|
| maimlMetadataExtractorサービスが存在しない | 高 | 中 | Phase 1-0で事前確認、不足時は簡易版実装を検討 |
| 500MBファイルでメモリ不足 | 高 | 中 | メモリ監視、必要に応じてディスクストレージへ変更 |
| プレースホルダー重複作成 | 中 | 低 | 重複チェックロジックの厳密な実装 |
| タイムアウト発生 | 中 | 中 | Nginx・Express両方でタイムアウト設定を調整 |
| 既存機能への影響 | 中 | 低 | 十分な統合テスト、段階的リリース |
