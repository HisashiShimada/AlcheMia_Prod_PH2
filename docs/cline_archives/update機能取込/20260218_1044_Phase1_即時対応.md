## Task 1-1: MAIMLメタデータ自動抽出

**期間**: 5日間  
**優先度**: 最優先

### Step 0: 機能説明セッション（実装開始前）

**所要時間**: 2-3時間

#### 理解すべき内容

1. **機能概要**
   - MAIMLファイル保存時に自動的にメタデータをDBに抽出・保存
   - `maimlMetadataExtractor.extractSingleFile()`を呼び出し
   - 失敗しても保存は成功とする（非同期処理）

2. **Reference版の実装**
   ```javascript
   if (validatedFileKey.toLowerCase().endsWith('.maiml')) {
     try {
       const maimlMetadataExtractor = require('../../services/maimlMetadataExtractor');
       const extractResult = await maimlMetadataExtractor.extractSingleFile(
         validatedFileKey, 
         organizationId
       );
       metadataExtracted = extractResult.success;
     } catch (metadataError) {
       console.error('メタデータ抽出エラー:', metadataError.message);
     }
   }
   ```

3. **抽出されるメタデータ**
   - Petri Net構造（place、transition、arc）
   - ステレオタイプ情報
   - メソッド情報（複数method対応）
   - その他MAIML固有情報

4. **現行版への適用方法**
   - `maimlService.saveMaiML()`に統合
   - TypeScript型定義追加
   - エラーハンドリング統一

5. **依存関係**
   - `maimlMetadataExtractor`サービスの存在確認
   - DBスキーマ（file_metadata、maiml_analysis_results等）
   - キャッシュマネージャーの実装状況

**実装例**:
```typescript
async function saveMaiML(
  fileKey: string, 
  content: string, 
  organizationId: string
): Promise<SaveResult> {
  // 1. S3保存
  await storageService.uploadFile(organizationId, fileKey, content);
  
  // 2. メタデータ自動抽出
  let metadataExtracted = false;
  if (fileKey.toLowerCase().endsWith('.maiml')) {
    try {
      const result = await maimlMetadataExtractor.extractSingleFile(
        fileKey, 
        organizationId
      );
      metadataExtracted = result.success;
    } catch (error) {
      console.warn('メタデータ抽出失敗（保存は成功）:', error);
    }
  }
  
  return { success: true, fileKey, metadataExtracted };
}
```

## Task 1-2: ファイルサイズ上限引き上げ

**期間**: 3日間

### Step 0: 機能説明セッション（実装開始前）

**所要時間**: 1時間

#### 理解すべき内容

1. **現状の制限**
   - 現行版: 100MB
   - Reference版: 500MB
   - フィールドサイズ: 50MB

2. **引き上げの影響**
   - メモリ使用量の増加
   - アップロード時間の増加
   - サーバー負荷への影響

3. **Multer設定**
   ```typescript
   const upload = multer({
     storage: multer.memoryStorage(),
     limits: {
       fileSize: 500 * 1024 * 1024, // 500MB
       fieldSize: 50 * 1024 * 1024,  // 50MB
       files: 100,
     },
   });
   ```

4. **考慮事項**
   - メモリストレージの使用
   - タイムアウト設定の調整
   - Nginxのclient_max_body_size設定

## Task 1-3: 空フォルダプレースホルダー

**期間**: 5日間

### Step 0: 機能説明セッション（実装開始前）

**所要時間**: 2時間

#### 理解すべき内容

1. **なぜ必要か**
   - S3/Swiftは空フォルダを保持できない
   - フォルダ構造の完全な再現が必要

2. **Reference版の実装**
   ```javascript
   for (const folderPath of emptyFolders) {
     const placeholderKey = `${folderPath}/.folder_placeholder`;
     
     // 重複チェック
     const existingCheck = await pool.query(
       'SELECT id FROM file_metadata WHERE file_key = $1 LIMIT 1',
       [placeholderKey]
     );
     
     if (existingCheck.rows.length > 0) continue;
     
     // S3にプレースホルダーファイル作成
     await s3Client.send(new PutObjectCommand({
       Bucket: S3_BUCKET_NAME,
       Key: placeholderKey,
       Body: Buffer.from(`# Folder Placeholder\n...`),
       ContentType: 'text/plain'
     }));
     
     // DBメタデータ保存
     await dbOperations.saveFileMetadata({
       file_key: placeholderKey,
       original_filename: '.folder_placeholder',
       file_category: 'placeholder',
       custom_metadata: { isPlaceholder: true, folderPath },
       tags: ['placeholder', 'empty-folder']
     });
   }
   ```

3. **現行版への統合方法**
   - `fileAccessService.uploadFiles()`の`mode=folder`に統合
   - リクエストパラメータに`emptyFolders: string[]`追加
   - バリデーション追加
