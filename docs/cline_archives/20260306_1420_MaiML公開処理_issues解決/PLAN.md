### Issue 2.2: 公開対象ファイルのURIとSwift/S3連携方法

**仕様書からの類推（基本設計書 v1.3 セクション2・8）:**
- 仕様書のセクション2に **Storage 抽象** として `file://` / `nfs://` / `smb://` / `s3://` の4スキームが列挙されている
- セクション8のCLI例では `--file-uri "file:///data/maiml/raman_001.xml"` のようにURIを直接指定している（`file://` はローカルテスト用の例示）
- **Storage 抽象の実体** は以下の想定:
  - **オンプレ環境**: OpenStack Swift
  - **クラウド環境**: AWS S3
- mmdpf の `storageService.ts` は S3/Swift を統一的に扱う抽象層として実装されており、この Storage 抽象に対応する
- `file_uri` には Swift オブジェクトパスまたは S3 キーを格納することが想定される

**判断: ⚠️ URIスキームの具体的な形式は別途確定が必要**
- Storage 抽象の実体（Swift/S3）は明確になったが、`file_uri` カラムに保存する URI の具体的な形式（Swift の場合のコンテナ名・オブジェクトパスの表現形式、S3 の場合のバケット名・キーの表現形式）は別途設計が必要
- issues.md には上記の仕様書上の想定（オンプレ=Swift、クラウド=S3）を記載し、「URI形式の設計が必要」と明記する
