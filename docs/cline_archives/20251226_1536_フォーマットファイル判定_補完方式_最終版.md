# フォーマットファイル判定ロジック（補完方式・最終版）

## 日時
2025-12-26 15:36

## 方針変更

### 以前の方式（上書き方式）
- ❌ フォーマットファイルと判定したら、基本情報を全て上書き
- ❌ Creator/Vendor/Ownerだけを引き継ぐ

### 新しい方式（補完方式）
- ✅ ファイル情報をまず全て引き継ぐ
- ✅ 基本情報とMaimlID属性を確認
- ✅ **不足しているフィールドだけ**を生成して設定

## メリット

1. **柔軟性**: フォーマットファイルでも一部のフィールドが設定されていれば尊重
2. **安全性**: 既存の値を不要に上書きしない
3. **拡張性**: 将来的に半完成のフォーマットにも対応可能

## 実装

### 1. 補完関数の実装

```typescript
/**
 * DocumentDataの不足フィールドを補完する
 * 
 * 基本情報とMaiML ID属性が空またはデフォルト値の場合、新しい値を生成して設定する
 * 
 * @param doc 元のDocumentData
 * @param baseName 基準となる名前（プロジェクト名など）
 * @returns 補完されたDocumentData
 */
const fillMissingDocumentFields = (
  doc: DocumentData,
  baseName: string
): DocumentData => {
  const sanitizedBaseName = baseName
    .replace(/\s+/g, '_')
    .replace(/[^a-zA-Z0-9_]/g, '');
  
  // 既存の値を保持しつつ、空のフィールドだけを補完
  return {
    ...doc,
    
    // 基本情報の補完
    id: doc.id && doc.id !== 'documentID' && doc.id !== '' 
      ? doc.id 
      : `document_${sanitizedBaseName}_${crypto.randomUUID().substring(0, 8)}`,
    
    name: doc.name && doc.name !== 'document' && doc.name !== '' 
      ? doc.name 
      : baseName,
    
    description: doc.description || '',  // 空文字列はそのまま
    
    date: doc.date && doc.date !== '' 
      ? doc.date 
      : new Date().toISOString(),
    
    uuid: doc.uuid && doc.uuid !== '' 
      ? doc.uuid 
      : crypto.randomUUID(),
    
    // MaiML ID属性の補完
    protocolId: doc.protocolId && doc.protocolId !== 'protocolID' && doc.protocolId !== '' 
      ? doc.protocolId 
      : `protocol_${sanitizedBaseName}_${crypto.randomUUID().substring(0, 8)}`,
    
    methodId: doc.methodId && doc.methodId !== 'methodID' && doc.methodId !== '' 
      ? doc.methodId 
      : `method_${sanitizedBaseName}_${crypto.randomUUID().substring(0, 8)}`,
    
    pnmlId: doc.pnmlId && doc.pnmlId !== 'pnmlID' && doc.pnmlId !== '' 
      ? doc.pnmlId 
      : `pnml_${sanitizedBaseName}_${crypto.randomUUID().substring(0, 8)}`,
    
    programId: doc.programId && doc.programId !== 'programID' && doc.programId !== '' 
      ? doc.programId 
      : `program_${sanitizedBaseName}_${crypto.randomUUID().substring(0, 8)}`,
    
    // Creator/Vendor/Owner/Instrumentsはそのまま引き継ぐ（補完しない）
    creators: doc.creators || [],
    vendors: doc.vendors || [],
    owners: doc.owners || [],
    instruments: doc.instruments || [],
    
    // XML署名は引き継ぐ（undefinedの場合はデフォルト）
    signature: doc.signature || { enabled: false },
  };
};
```

### 2. PetriNetEditor.tsx の修正

```typescript
// PetriNetEditor.tsx の fetchPetriNetData 関数内

const extractedDocument = extractDocumentFromMaiML(effectiveMaimlData || '');

      : 'document')
```

## DocumentEditDialogの修正

DocumentEditDialogでは判定ロジックが不要になります：

```typescript
// DocumentEditDialog.tsx

const DocumentEditDialog: React.FC<DocumentEditDialogProps> = ({
  open,
  documentData,
  onClose,
  onSave,
}) => {
  // ✅ 判定不要: PetriNetEditorで補完済み
  // すべての必要なフィールドは既に設定されているので、
  // 通常のバリデーションとUIでOK
  
  // バリデーションロジック（通常通り）
  const validateDocumentData = useMemo(() => (data: DocumentData): string[] => {
    const errors: string[] = [];
    
    if (!data.name?.trim()) {
      errors.push('❌ Document name is required');
    }
    
    if (!data.id?.trim()) {
      errors.push('❌ Document ID is required');
    }
    
    // Creator/Vendor/Ownerの必須チェック
    if (!data.creators || data.creators.length === 0) {
      errors.push('❌ At least one Creator is required');
    }
    if (!data.vendors || data.vendors.length === 0) {
      errors.push('❌ At least one Vendor is required');
    }
    if (!data.owners || data.owners.length === 0) {
      errors.push('❌ At least one Owner is required');
    }
    
    // ... その他のバリデーション
    
    return errors;
  }, []);
  
  // ... 通常の実装
};
```

## フォーマット管理側の修正

フォーマット管理で保存する際に、基本情報とMaiML ID属性を空にする処理は**TemplateEditorDialog**で行います：

```typescript
// TemplateEditorDialog.tsx

const handleSave = useCallback(() => {
  if (sourceContext === 'format') {
    // フォーマット管理モード: 基本情報とMaiML ID属性を空にして保存
    const dataToSave = {
      ...editingDocument,
      // 基本情報を空にする
      id: '',
      name: '',
      description: '',
      date: '',
      uuid: '',
      // MaiML ID属性を空にする
      protocolId: '',
      methodId: '',
      pnmlId: '',
      programId: '',
      // XML署名を無効化
      signature: { enabled: false },
      // Creator/Vendor/Ownerは保持
    };
    
    onSave(dataToSave);
  } else {
    // プロジェクト管理モード: そのまま保存
    onSave(editingDocument);
  }
}, [editingDocument, sourceContext, onSave]);
```

## まとめ

### 処理フロー

1. **フォーマット管理で作成**
   - TemplateEditorDialog: sourceContext='format' で基本情報を空にして保存
   - Creator/Vendor/Ownerは設定する

2. **プロジェクト管理でアップロード**
   - PetriNetEditor.fetchPetriNetData:
     - ファイルから全情報を引き継ぐ
     - fillMissingDocumentFieldsで不足フィールドを補完
     - 結果: すべてのフィールドが埋まった状態

3. **DocumentEditDialogで編集**
   - 通常のバリデーション
   - すべてのフィールドが設定済みなのでエラーなし

### メリット

1. ✅ **柔軟性**: 既存の値を尊重
2. ✅ **シンプル**: DocumentEditDialogに特別なロジック不要
3. ✅ **安全性**: 不要な上書きを避ける
4. ✅ **拡張性**: 半完成フォーマットにも対応

### 実装箇所

1. `frontend/src/utils/documentParser.ts` に `fillMissingDocumentFields()` を追加
2. `frontend/src/components/editor/PetriNetEditor.tsx` で補完関数を使用
3. `frontend/src/components/editor/TemplateEditorDialog.tsx` でフォーマット保存時に空にする
