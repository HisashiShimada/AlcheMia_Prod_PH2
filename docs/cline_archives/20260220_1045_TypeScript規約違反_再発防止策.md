# 規約違反 再発防止策

## 作成日時
2026-02-20 10:45
最終更新: 2026-02-20 10:57

## 問題の概要

タスク実装中に、以下の規約に違反しかけた：

1. **TypeScript規約違反**: `.clinerules/development/typescript.md`に明記されている「インライン型定義を乱用しない」という規約
2. **バリデーション規約違反**: `.cline/skills/backend-develop-skill/docs/backend.md`に明記されている「バリデーションはミドルウェアで実施」という規約

## 根本原因の分析

### 共通の根本原因

両方の規約違反に共通する原因：

#### 1. 規約ドキュメントの所在が分散
- **TypeScript規約**: `.clinerules/development/typescript.md`
- **バリデーション規約**: `.cline/skills/backend-develop-skill/docs/backend.md`
- 規約が2つのディレクトリに分散しており、実装中の確認が漏れた

#### 2. 規約確認の不徹底
- タスク開始時に関連規約ファイルを確認したが、長時間のタスク中に内容を忘れてしまった
- `.cline/skills/` 配下のドキュメントは補足的なガイドラインとして扱い、実装中に再確認しなかった
- 実装中に規約を再確認する仕組みがなかった

#### 3. 一般的な習慣の優先
- **TypeScript**: 一般的なTypeScriptコーディングでは、インライン型定義が許容される場面が多い
- **バリデーション**: 一般的なExpress.jsアプリケーションでは、コントローラー内でバリデーションチェックすることが多い
- プロジェクト固有の規約よりも、一般的なベストプラクティスを優先してしまった

#### 4. 既存コードパターンの参照不足
- 既存のコードベースのパターンを十分に確認せず、新規実装を行った
- ミドルウェアチェーンの理解が不十分だった

### 個別の原因

#### TypeScript規約違反
- 型定義ファイルへの集約という方針を忘れ、手軽なインライン型定義を使おうとした

#### バリデーション規約違反  
- `auth → tenantIsolation → validation → handleValidationErrors → controller`というミドルウェアチェーンの順序を忘れた
- コントローラー内で`validationResult()`を使う一般的なパターンを書こうとした

## 再発防止策の方針

### skillsディレクトリの目的

- `.clinerules/` = **共通規約**（フロント・バック両方で必要な基本ルール）
- `.cline/skills/` = **専門領域別の詳細規約**（コンテキスト圧迫を防ぐため分離）
  - `backend-develop-skill/` = バックエンド専用の詳細ルール
  - `frontend-develop-skill/` = フロントエンド専用の詳細ルール
  - `test-skill/` = テスト専用の詳細ルール

### 再発防止策のアプローチ

**skillsディレクトリの規約を確認する仕組みを作る**

- backend実装時 → `backend-develop-skill`を確認
- frontend実装時 → `frontend-develop-skill`を確認
- test実装時 → `test-skill`を確認

## ❌ よくある違反パターンと対処法

### 違反パターン1: 関数引数にインライン型定義

```typescript
// ❌ 悪い例: インライン型定義
export async function createProject(data: {
  name: string;
  description: string;
  metadata: {
    tags: string[];
    priority: string;
  }
}): Promise<void> {
  // ...
}

// ✅ 正しい例: 型定義ファイルに集約
import { CreateProjectRequest } from '../types/api';

export async function createProject(
  data: CreateProjectRequest
): Promise<void> {
  // ...
}
```

**対処法:**
1. `backend/src/types/api.ts` または `frontend/src/types/api.ts` に型定義を作成
2. 必要な箇所でimportして使用
3. 他の場所でも再利用できる形で命名

---

### 違反パターン2: コンポーネントPropsにインライン型定義

```typescript
// ❌ 悪い例: インライン型定義
const TaskList: React.FC<{
  tasks: Array<{
    id: string;
    name: string;
    status: string;
  }>;
  onTaskClick: (taskId: string) => void;
}> = ({ tasks, onTaskClick }) => {
  // ...
};

// ✅ 正しい例: 型定義ファイルに集約
import { TaskListProps, Task } from '@/types/components';

const TaskList: React.FC<TaskListProps> = ({ tasks, onTaskClick }) => {
  // ...
};
```

**対処法:**
1. `frontend/src/types/components.ts` に型定義を作成
2. Props型とデータ型を分離して定義
3. 他のコンポーネントでも再利用できる形で命名

---

### 違反パターン3: API型定義の重複

```typescript
// ❌ 悪い例: 各ファイルで型定義を重複
// file1.ts
interface Project {
  id: string;
  name: string;
}

// file2.ts
interface Project {
  id: string;
  name: string;
}

// ✅ 正しい例: 型定義ファイルに一元化
// backend/src/types/database.ts
export interface Project {
  id: string;
  name: string;
  // ...
}

// file1.ts
import { Project } from '../types/database';

// file2.ts
import { Project } from '../types/database';
```

**対処法:**
1. 既存の型定義ファイルを検索（`grep -r "interface Project" src/types/`）
2. 既に定義されている場合は、それを再利用
3. 定義されていない場合は、適切な型定義ファイルに作成

## TypeScript型定義の必須ルール

### すべての型定義は専用ファイルに集約

**禁止事項:**
```typescript
// ❌ インライン型定義（禁止）
function createUser(data: { name: string; email: string }) { }

// ❌ ファイル内に型定義（再利用不可）
interface User {
  name: string;
  email: string;
}
function createUser(data: User) { }
```

**推奨事項:**
```typescript
// ✅ 型定義ファイルに集約
// types/user.ts
export interface User {
  name: string;
  email: string;
}

// service.ts
import { User } from './types/user';
function createUser(data: User) { }
```

### 型定義作成時の確認ポイント

1. **既存の型定義を検索する**
   ```bash
   # バックエンド
   grep -r "interface Project" backend/src/types/
   
   # フロントエンド
   grep -r "interface Project" frontend/src/types/
   ```

2. **適切な型定義ファイルを選択する**
   - `database.ts` - DBテーブルの型
   - `api.ts` - API リクエスト/レスポンス
   - `components.ts` - コンポーネントProps
   - `common.ts` - 共通型

3. **JSDocコメントを追加する**
   ```typescript
   /**
    * ユーザー情報の型定義
    * 
    * @remarks
    * user テーブルのスキーマに対応
    */
   export interface User {
     // ...
   }
   ```

詳細は `.clinerules/development/typescript.md` を参照してください。
```
