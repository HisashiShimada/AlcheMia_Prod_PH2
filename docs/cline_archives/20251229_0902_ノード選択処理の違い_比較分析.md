# ノード選択処理の違い - Reference vs 現状実装

## メタデータ
- **作成日時**: 2025-12-29 09:02
- **問題**: チェックボックス反応遅延の根本原因
- **重要度**: 高（パフォーマンス問題の根本）

## 1. 根本的な違いの概要

### Reference版（正しい実装）
```
ノードクリック
  ↓
node.data から直接プロパティ情報を取得
  ↓
structuredProperties を構築（XMLパース不要）
  ↓
StructuredPropertySelector に渡す
```

### 現状の実装（問題あり）
```
ノードクリック
  ↓
maimlData（XML文字列全体）をそのまま渡す
  ↓
PropertyViewerWithSelection 内で毎回XMLをパース
  ↓
プロパティを抽出
  ↓
表示
```

**問題点:**
- **毎回XMLをパース**: 大きなMAIMLファイルの場合、数百ms~数秒かかる
- **不要な処理**: ノードに必要なプロパティ情報は既に`node.data`に含まれている
- **チェックボックスクリックでも発生**: PropertyViewerWithSelectionが再レンダリングされるたびにパースが実行される可能性

## 2. Reference版の実装詳細

### 2.1. ノードクリックハンドラー（reference/frontend/src/components/PetriNetViewer/index.js）

```javascript
const handleNodeClick = useCallback((event, node) => {
  console.log('👆 [PetriNetViewer] ノードクリック:', node.id, node.data.nodeType);
  
  setSelectedNodeId(node.id);
  setSelectedNode(node);
  setNodeType(node.data.nodeType);

    console.log('🔍 [PetriNetViewer] Placeノード処理開始');
    
    // ★★★ 重要: node.data.template から直接プロパティを取得 ★★★
    const template = node.data.template;
    console.log('🔍 [PetriNetViewer] template:', template);
    
    if (template) {
      // 基本情報を構築
      const basicProperties = {
        id: { key: 'id', value: String(node.id), type: 'string', description: 'ノードID' },
        type: { key: 'type', value: String(template.type || 'material'), type: 'string', description: 'ノード種別' },
        name: { key: 'name', value: String(template.name || node.id), type: 'string', description: 'ノード名' },
        description: { key: 'description', value: String(template.description || '説明なし'), type: 'string', description: 'ノード説明' }
      };
      
      // テンプレートプロパティを構築
      const templateProperties = {};
      if (template.properties && Array.isArray(template.properties)) {
        template.properties.forEach(prop => {
          templateProperties[prop.key] = {
            key: prop.key,
            value: prop.defaultValue || '値なし',
            type: prop.type || 'stringType',
            description: prop.description || '説明なし'
          };
        });
      }
      
      // データプロパティを構築
      const dataProperties = {
        coordinates: {
          key: 'coordinates',
          value: `(${node.position.x.toFixed(2)}, ${node.position.y.toFixed(2)})`,
          type: 'coordinates',
          description: 'ノード座標'
        }
      };
      
      console.log('🔍 [PetriNetViewer] プロパティ設定:', {
        basic: Object.keys(basicProperties).length,
        template: Object.keys(templateProperties).length,
        data: Object.keys(dataProperties).length
      });
      
      // ★★★ 構築したプロパティをセット（XMLパース不要） ★★★
      setStructuredProperties({
        basic: basicProperties,
        template: templateProperties,
        data: dataProperties
      });
      
      console.log('🔍 [PetriNetViewer] dropdownVisible設定: true');
      setDropdownVisible(true);
    }
  }
}, [maimlData, templateMap, multiMethodMode, currentMethodData]);
```

**ポイント:**
1. `node.data.template` から直接プロパティ情報を取得
2. `structuredProperties` を構築（{ basic, template, data }形式）
3. XMLパースは一切不要
4. 処理時間: **数ms**

```typescript
// PropertyViewerWithSelection.tsx
React.useEffect(() => {
```

**問題点:**
1. `maimlData`（XML文字列全体、数MB～数十MB）を毎回パース
2. DOMParser による XML パース: **100ms～数秒**（ファイルサイズに依存）
3. チェックボックスをクリック → PropertyViewerWithSelection再レンダリング → 再パース
4. テンプレートプロパティが空になっている（パースロジックが未実装）

## 4. パフォーマンスへの影響

### Reference版の処理時間
```
ノードクリック: 1-2ms
  ↓
node.data から取得: 1-2ms
  ↓
structuredProperties 構築: 1-2ms
  ↓
StructuredPropertySelector 表示: 5-10ms
─────────────────────────────
合計: 10-20ms
```

### 現状の実装の処理時間
```
ノードクリック: 1-2ms
  ↓
maimlData を渡す: 1ms
  ↓
PropertyViewerWithSelection レンダリング: 5ms
  ↓
useEffect 発火: 1ms
  ↓
★ XML パース（DOMParser）: 100-1000ms（ファイルサイズに依存）
  ↓
プロパティ抽出: 5-10ms
  ↓
再レンダリング: 10ms
─────────────────────────────
合計: 120-1030ms

チェックボックスクリック時:
  ↓
handlePropertyToggle: 1ms
  ↓
setSelectedPropertiesByNode: 1ms
  ↓
setNodes（全ノード走査）: 50-100ms
  ↓
React Flow 再レンダリング: 50-100ms
  ↓
★ PropertyViewerWithSelection 再レンダリング: 1ms
  ↓
★ useEffect 発火（再パース）: 100-1000ms
─────────────────────────────
合計: 200-1200ms
```

**差分:**
- **初回表示**: 10倍～50倍遅い（100ms vs 10ms）
- **チェックボックスクリック**: 10倍～60倍遅い（200-1200ms vs 20ms）

## 5. node.data の構造の違い

### Reference版の node.data 構造

```javascript
node.data = {
  nodeType: 'place',
  label: 'Sample Material',
  templateType: 'material',
  
  // ★★★ 重要: template オブジェクトに詳細情報が含まれている ★★★
  template: {
    id: 'mat_template_001',
    name: 'Sample Material Template',
    type: 'material',
    description: 'This is a sample material template',
    properties: [  // ★プロパティ配列
      {
        key: 'density',
        defaultValue: '1.5',
        type: 'numberType',
        description: 'Material density'
      },
      {
        key: 'melting_point',
        defaultValue: '100',
        type: 'numberType',
        description: 'Melting point in Celsius'
      }
      // ... その他のプロパティ
    ]
  },
  
  selectedProperties: {} // 選択されたプロパティ

```

### 現状の実装の node.data 構造

```typescript
node.data = {
  nodeType: 'place',
  label: 'Sample Material',
  templateType: 'material',
  description: 'Sample description',
  
  // ★★★ 問題: properties は簡易的な key-value のみ ★★★
  properties: {
    density: '1.5',
    melting_point: '100'
    // ... 値のみで、type や description がない
  },
  
  selectedProperties: {}

```

**問題点:**
- `template` オブジェクトがない
- `properties` にプロパティの詳細情報（type, description）がない
- テンプレート情報を取得するには XML をパースするしかない

## 6. 解決策

### 解決策A: node.data に template オブジェクトを含める（推奨）

**方針:**
- React Flow 変換時に、`node.data.template` にテンプレート情報を含める
- Reference版と同じ構造にする

**実装箇所:**
1. `frontend/src/utils/reactFlowConverter.ts` を修正
2. `convertToReactFlow` 関数でノード変換時に template 情報を含める
3. `parseMaimlToPetriNet` または `convertToReactFlow` で templateMap から取得

**メリット:**
- XMLパースが不要（初回のみ）
- Reference版と同じ構造で保守性が高い
- パフォーマンスが大幅に改善

**デメリット:**
- convertToReactFlow の修正が必要

### 解決策B: PropertyViewerWithSelection を StructuredPropertySelector に戻す

**方針:**
- PropertyViewerWithSelection を使用せず、StructuredPropertySelector に戻す
- structuredProperties を渡す方式に戻す

**メリット:**
- Reference版と完全に同じ動作
- 実績のある実装

**デメリット:**
- UI/UX統一タスクの成果が失われる

### 解決策C: PropertyViewerWithSelection の propsインターフェースを変更

**方針:**
- `maimlData` の代わりに `structuredProperties` を受け取る
- PropertyViewer と同じインターフェースにする

**実装:**
```typescript
interface PropertyViewerWithSelectionProps {
  // maimlData を削除
  // maimlData: string;
  
  // structuredProperties を追加
  structuredProperties: {
    basic: Record<string, PropertyObject>;
    template: Record<string, PropertyObject>;
    data: Record<string, PropertyObject>;
  };
  
  // その他は同じ
  properties: {
    id: string;
    name: string;
    type: 'Material' | 'Condition' | 'Result' | 'Transition';
  };
  
  selectedProperties: SelectedProperties;
  onPropertyToggle: (structure: string, property: string) => void;
  onClose?: () => void;
}
```

**メリット:**
- XMLパースが不要
- PropertyViewerWithSelection のUI/UXを維持
- パフォーマンス大幅改善

**デメリット:**
- PropertyViewerWithSelection の修正が必要

## 7. 推奨実装

## 8. まとめ

### 根本原因
1. **PropertyViewerWithSelection が毎回XMLをパース**: 最大の原因
2. **node.data に template 情報が不足**: パースしないとテンプレートプロパティが取得できない
3. **PropertyViewerWithSelection の再レンダリング**: チェックボックスクリック時も再パース

### 推奨解決策
1. **node.data に template オブジェクトを含める**（convertToReactFlow修正）
2. **PropertyViewerWithSelection を structuredProperties 方式に変更**（propsインターフェース修正）
3. **handleNodeClick で structuredProperties を構築**（Reference版と同じロジック）

### 期待効果
- **10-60倍の高速化**
- **テンプレートプロパティの正常表示**
- **Reference版と同等の動作**
