**修正後の handleLogin:**
```typescript
const handleLogin = async (credentials: LoginCredentials): Promise<void> => {
  setError(null);
  setLoading(true);

  try {
    // 常にバックエンドAPIにログインリクエスト
    const response = await authService.login(credentials);

    // ログイン成功 - PINコード送信完了
    console.log('Login successful:', response);

    // 仮セッショントークンと組織IDを保存
    setSessionToken(response.sessionToken);
    setOrganizationId(credentials.organizationId);
    setMaskedEmail(response.email);

    // 開発環境の場合、PINコードをsessionStorageに保存
    if (response.devMode && response.pinCode) {
      if (typeof window !== 'undefined') {
        sessionStorage.setItem('devPinCode', response.pinCode);
      }
    }

    // PINコード入力画面へ遷移
    setAuthStep('pin-code');
  } catch (err) {
    // エラーハンドリング（既存のまま）
  } finally {
    setLoading(false);
  }
};
```

#### 2. PinCodeInputPage.tsx の修正

**追加する機能:**
- useEffect で開発環境かつ devPinCode が存在する場合、自動入力
- 自動入力後、少し遅延してから自動的に検証を実行

```typescript
// PinCodeInputPage.tsx に追加
useEffect(() => {
  // 開発環境かつ devPinCode が存在する場合、自動入力
  if (process.env.NODE_ENV === 'development' && typeof window !== 'undefined') {
    const devPinCode = sessionStorage.getItem('devPinCode');
    
    if (devPinCode && devPinCode.length === 6) {
      // PINコードを自動入力
      setPinCode(devPinCode);
      
      // 少し遅延してから自動検証（UIが更新されてから）
      setTimeout(() => {
        handleVerify(devPinCode);
      }, 500);
    }
  }
}, [sessionToken]); // sessionToken が設定されたときに実行
```

## 6. リスクと対策

| リスク | 影響度 | 発生確率 | 対策 |
|--------|--------|----------|------|
| 自動入力が早すぎてUIが追いつかない | 低 | 中 | setTimeout で適切な遅延を設定 |
| 本番環境で誤って devPinCode が使われる | 高 | 低 | process.env.NODE_ENV のチェック |
| PINコード検証失敗 | 中 | 低 | エラーハンドリングを適切に実装 |
