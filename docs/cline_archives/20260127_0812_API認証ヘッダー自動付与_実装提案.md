## ✅ 推奨方法: Axiosリクエストインターセプター

### 実装箇所
`frontend/src/services/authService.ts` の `createApiClient()` 関数内

### 実装内容

```typescript
/**
 * Axiosインスタンスの作成
 */
const createApiClient = (): AxiosInstance => {
  const baseURL = process.env.NEXT_PUBLIC_API_URL || 'http://localhost:3001/api/v1';
  
  const client = axios.create({
    baseURL: `${baseURL}`,
    timeout: 10000,
    headers: {
      'Content-Type': 'application/json',
    },
    withCredentials: true,
  });

  // 🎯 ここに追加: リクエストインターセプター
  client.interceptors.request.use(
    (config) => {
      // SessionStorageからセッショントークンを自動取得
      if (typeof window !== 'undefined') {
        const sessionToken = sessionStorage.getItem('sessionToken');
        if (sessionToken) {
          config.headers.Authorization = `Bearer ${sessionToken}`;
        }
      }
      return config;
    },
    (error) => {
      return Promise.reject(error);
    }
  );

  return client;
};
```

## 📊 メリット

### 1. **1か所の修正で全API対応**
- `createApiClient()` にインターセプターを追加するだけ
- 既存の全メソッドで自動的にトークンが付与される
- 今後追加するAPIでもトークン設定が不要

### 2. **コードの簡潔化**
```typescript
// Before（現在）- 各メソッドで個別設定
await apiClient.post('/auth/logout', {}, {
  headers: { Authorization: `Bearer ${sessionToken}` }
});

// After（変更後）- トークン設定不要
await apiClient.post('/auth/logout', {});
```

### 3. **保守性の向上**
- トークン管理ロジックが1か所に集約
- トークンの取得方法を変更する場合も1か所を修正するだけ
- バグ混入リスクの低減

### 4. **将来の拡張性**
- 新しいAPIエンドポイントを追加してもトークン設定不要
- リフレッシュトークンの実装も容易

## ⚠️ 注意点

### 1. **ログイン前のAPI**
現在の実装では、ログイン前（トークンがない状態）でも正常に動作します：
- `sessionStorage.getItem('sessionToken')` が `null` を返す
- `if (sessionToken)` で判定してスキップ
- ログインAPIは認証なしで実行される

### 2. **トークンの保存場所**
現在SessionStorageを使用していますが、以下の特徴があります：
- ✅ タブを閉じると自動削除（セキュリティ向上）
- ❌ 別タブで開くと再ログインが必要
- ❌ ページリロード後も保持される

LocalStorageに変更する場合：
```typescript
// SessionStorage → LocalStorageに変更
const sessionToken = localStorage.getItem('sessionToken');
```
