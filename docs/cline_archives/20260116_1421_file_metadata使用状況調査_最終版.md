## 🏗️ file_metadataテーブル構造（完全版）

### 基本カラム（V1.16α）

```sql
CREATE TABLE file_metadata (
  -- 基本識別子
  id SERIAL PRIMARY KEY,
  file_key VARCHAR(500) UNIQUE NOT NULL,                    -- S3オブジェクトキー
  original_filename VARCHAR(255) NOT NULL,                  -- 元のファイル名
  file_size BIGINT NOT NULL,                                -- ファイルサイズ（バイト）
  file_type VARCHAR(100),                                   -- ファイルタイプ（MIME type）
  file_extension VARCHAR(10),                               -- ファイル拡張子
  file_hash VARCHAR(64),                                    -- ファイルハッシュ（重複検出用）
  
  -- S3ストレージ情報
  s3_bucket VARCHAR(100) NOT NULL,                          -- S3バケット名
  s3_region VARCHAR(50) DEFAULT 'ap-northeast-1',           -- S3リージョン
  s3_storage_class VARCHAR(50) DEFAULT 'STANDARD',          -- ストレージクラス
  s3_etag VARCHAR(100),                                     -- S3 ETag
  
  -- アップロード情報
  uploaded_by VARCHAR(100) NOT NULL,                        -- アップロード実行者
  upload_batch_id VARCHAR(255),                             -- バッチアップロードID
  upload_source VARCHAR(50) CHECK (upload_source IN 
    ('web_upload', 'bulk_upload', 'folder_upload', 'api_upload')) DEFAULT 'web_upload',
  upload_method VARCHAR(50) CHECK (upload_method IN 
    ('single', 'multipart', 'resumable')) DEFAULT 'single',
  
  -- ファイル分類・タグ
  file_category VARCHAR(100),                               -- ファイルカテゴリ（maiml, template, data, image等）
  content_language VARCHAR(10),                             -- コンテンツ言語
  encoding VARCHAR(50),                                     -- エンコーディング
  tags JSONB DEFAULT '[]'::jsonb,                          -- ファイルタグ（検索用）
  
  -- フォルダ構造情報
  parent_folder_path VARCHAR(500),                          -- 親フォルダパス
  folder_structure JSONB DEFAULT '{}'::jsonb,               -- フォルダ階層情報
  is_folder_root BOOLEAN DEFAULT FALSE,                     -- フォルダルートフラグ
  
  -- 処理状態
  processing_status VARCHAR(50) CHECK (processing_status IN 
    ('pending', 'processing', 'completed', 'failed', 'quarantine')) DEFAULT 'pending',
  validation_status VARCHAR(50) CHECK (validation_status IN 
    ('pending', 'valid', 'invalid', 'warning')) DEFAULT 'pending',
  validation_errors JSONB DEFAULT '[]'::jsonb,              -- バリデーションエラー詳細
  
  -- MAIMLファイル専用フィールド
  is_maiml_file BOOLEAN DEFAULT FALSE,                      -- MAIMLファイルフラグ
  maiml_version VARCHAR(20),                                -- MAIMLバージョン
  maiml_transitions_count INTEGER,                          -- トランジション数
  maiml_places_count INTEGER,                               -- プレース数
  maiml_validation_result JSONB DEFAULT '{}'::jsonb,        -- MAIML文法チェック結果
  
  -- メタデータ・拡張情報
  custom_metadata JSONB DEFAULT '{}'::jsonb,                -- カスタムメタデータ
  search_keywords TEXT[],                                   -- 検索キーワード配列
  description TEXT,                                         -- ファイル説明
  
  -- アクセス制御
  access_level VARCHAR(20) CHECK (access_level IN 
    ('public', 'internal', 'restricted', 'private')) DEFAULT 'internal',
  owner_user_id VARCHAR(100),                               -- 所有者ユーザーID
  access_permissions JSONB DEFAULT '{}'::jsonb,             -- アクセス権限詳細
  
  -- 監査・履歴
  created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
  last_accessed_at TIMESTAMP WITH TIME ZONE,                -- 最終アクセス日時
  archived_at TIMESTAMP WITH TIME ZONE,                     -- アーカイブ日時
  
  -- 統計情報
  download_count INTEGER DEFAULT 0,                         -- ダウンロード回数
  view_count INTEGER DEFAULT 0,                             -- 閲覧回数
  share_count INTEGER DEFAULT 0                             -- 共有回数
);
```

## 🎯 フロントエンド画面での具体的な用途まとめ

### SearchModal.js - MAIML検索画面

**目的**: MAIMLファイルをメタデータで検索

**file_metadata使用目的:**
1. **検索対象データソース** - custom_metadata, tagsから検索
2. **ファイル特定** - file_key, original_filenameで識別
3. **検索結果表示** - ファイル情報、マッチ件数、属性詳細
4. **マルチテナント分離** - organization_idで組織別フィルタリング
5. **ファイル選択** - 選択されたファイルのS3パス取得

**検索パフォーマンス:**
- custom_metadataのGINインデックスで高速検索
- tagsのGINインデックスで高速検索
- organization_idの単一インデックスでテナント分離

**今後の拡張可能性:**
- 検索履歴の保存（file_access_logテーブルと連携）
- お気に入り機能（tagsに"favorite"追加）
- 最近使用したファイル表示（last_accessed_at活用）
- ファイルダウンロード統計（download_count活用）
