# クライアント証明書生成手順ガイド

## 概要

Nginxクライアント証明書認証用の証明書を生成するための手順書です。

**作成日**: 2026-01-13  
**対象**: 開発者、システム管理者

---

## 前提条件

### 必須ソフトウェア

1. **OpenSSL**
   - **Windows**: [Win32/Win64 OpenSSL](https://slproweb.com/products/Win32OpenSSL.html)
   - **macOS**: `brew install openssl`
   - **Linux**: `sudo apt-get install openssl` または `sudo yum install openssl`

2. **Bash環境**
   - **Windows**: Git Bash、WSL、または Cygwin
   - **macOS/Linux**: 標準で利用可能

### 確認方法

```bash
openssl version
# 出力例: OpenSSL 3.0.2 15 Mar 2022 (Library: OpenSSL 3.0.2 15 Mar 2022)
```

## 生成されるファイル

### ディレクトリ構造

```
certs/
├── ca/
│   ├── ca.crt          # CA証明書（Nginxで使用）
│   ├── ca.key          # CA秘密鍵（厳重管理）
│   └── ca.srl          # シリアル番号ファイル
├── clients/
│   ├── c9621ed65def49708e7ffbe97c98e3ed.crt    # 組織1の証明書
│   ├── c9621ed65def49708e7ffbe97c98e3ed.key    # 組織1の秘密鍵
│   ├── c9621ed65def49708e7ffbe97c98e3ed.p12    # 組織1のブラウザ用
│   ├── a0718dc521f344e687e9cc2ae83f3385.crt    # 組織2の証明書
│   ├── a0718dc521f344e687e9cc2ae83f3385.key    # 組織2の秘密鍵
│   └── a0718dc521f344e687e9cc2ae83f3385.p12    # 組織2のブラウザ用
└── generate-certificates.sh    # 生成スクリプト
```

### 証明書の詳細

| ファイル | 用途 | 有効期限 | 鍵長 |
|---------|------|----------|------|
| ca/ca.crt | Nginx設定で使用 | 10年 | 4096bit RSA |
| ca/ca.key | CA秘密鍵（厳重管理） | - | 4096bit RSA |
| clients/*.crt | クライアント証明書 | 3年 | 2048bit RSA |
| clients/*.key | クライアント秘密鍵 | - | 2048bit RSA |
| clients/*.p12 | ブラウザインポート用 | 3年 | - |

## Nginx設定への適用

### ca.crt の配置

```bash
# Dockerコンテナの場合
docker cp certs/ca/ca.crt nginx-container:/etc/nginx/certs/ca/ca.crt

# 直接配置の場合
sudo cp certs/ca/ca.crt /etc/nginx/certs/ca/ca.crt
sudo chmod 644 /etc/nginx/certs/ca/ca.crt
```

### nginx.conf 設定例

```nginx
server {
    listen 443 ssl http2;
    
    # クライアント証明書検証
    ssl_client_certificate /etc/nginx/certs/ca/ca.crt;
    ssl_verify_client on;
    ssl_verify_depth 2;
    
    # CNから組織IDを抽出
    set $client_cn $ssl_client_s_dn_cn;
    set $org_id "";
    
    if ($client_cn ~ "^\{([a-f0-9\-]+)\}$") {
        set $org_id $1;
    }
    
    location /api/ {
        proxy_set_header X-Organization-Id $org_id;
        proxy_pass http://backend:3001;
    }
}
```

## トラブルシューティング

### 問題1: OpenSSLが見つからない

**エラー:**
```
bash: openssl: command not found
```

**解決策:**
- OpenSSLをインストールしてください（前提条件を参照）
- Windowsの場合、環境変数PATHにOpenSSLのパスを追加

### 問題2: 証明書が既に存在する

**メッセージ:**
```
⚠ CA秘密鍵が既に存在します。スキップします。
```

**解決策:**
- これは正常な動作です
- 再生成したい場合は、既存のファイルを削除してから再実行
- **注意**: CA証明書を再生成すると、既存のクライアント証明書は無効になります

### 問題3: ブラウザで証明書が認識されない

**確認事項:**
1. `.p12` ファイルが正しくインポートされているか
2. パスワード `mmdpf123` が正しく入力されているか
3. ブラウザを再起動したか
4. Nginxが正しく設定されているか

## セキュリティ上の注意事項

### ⚠️ 重要な警告

1. **CA秘密鍵（ca/ca.key）の管理**
   - 外部に流出させないこと
   - アクセス権限を厳格に設定（Unix系: 600）
   - バックアップは暗号化して保管

2. **クライアント秘密鍵（clients/*.key）の管理**
   - 外部に公開しないこと
   - 各組織にのみ配布
   - 漏洩時は即座に証明書を失効

3. **.p12ファイルのパスワード**
   - 本番環境では必ず変更すること
   - デフォルトパスワード `mmdpf123` は開発環境専用

4. **Git管理**
   - `.gitignore` に `certs/` を追加
   - 証明書ファイルをリポジトリにコミットしないこと

### .gitignoreへの追加（手動）

`.gitignore` ファイルに以下を追加してください：

```gitignore
# クライアント証明書（機密情報）
certs/ca/ca.key
certs/ca/ca.srl
certs/clients/*.key
certs/clients/*.crt
certs/clients/*.p12
```

**CA証明書（ca/ca.crt）のみバージョン管理する場合:**
```gitignore
# クライアント証明書（機密情報）
certs/ca/ca.key
certs/ca/ca.srl
certs/clients/
```

## 証明書の更新・失効

### 証明書の更新（有効期限切れ前）

1. 既存の証明書を削除
   ```bash
   rm clients/*.crt clients/*.key clients/*.p12
   ```

2. スクリプトを再実行
   ```bash
   bash generate-certificates.sh
   ```

3. 新しい `.p12` ファイルをユーザーに配布

### 証明書の失効（漏洩時）

1. CA証明書を再生成
   ```bash
   rm ca/ca.key ca/ca.crt ca/ca.srl
   bash generate-certificates.sh
   ```

2. すべてのクライアント証明書を再発行
3. Nginxに新しい `ca.crt` を配置
4. すべてのユーザーに新しい `.p12` を配布

## 参考資料

### 証明書のCN（Common Name）形式

生成される証明書のCNは以下の形式です：

```
CN={c9621ed6-5def-4970-8e7f-fbe97c98e3ed}
```

この形式により、Nginxで組織IDを抽出できます。
