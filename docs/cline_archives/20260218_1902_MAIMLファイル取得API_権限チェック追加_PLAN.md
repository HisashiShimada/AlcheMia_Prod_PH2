### アーキテクチャ上の考慮事項

**ミドルウェアチェーンの順序（重要）**:
```typescript
router.get(
  '/:projectId/maiml',
  authMiddleware,              // 1. JWT認証（req.userを設定）
  checkPermission('050000', 0), // 2. 権限チェック（実験作業者のみ、読み取り専用）
  tenantIsolation,             // 3. テナント分離（req.organizationIdを設定）
  [...バリデーション],         // 4. 入力バリデーション
  projectController.getProjectMaiml  // 5. コントローラー処理
);
```

**理由**:
- `authMiddleware`が最初：`req.user`を設定する必要がある
- `checkPermission`が2番目：`req.user.permissions`を参照する
- `tenantIsolation`が3番目：組織情報を設定
- バリデーションは権限チェック後：権限のないユーザーはバリデーションまで到達しない

### 機能CDと権限レベル

| ロール | 機能CD | 権限レベル | アクセス可否 | 説明 |
