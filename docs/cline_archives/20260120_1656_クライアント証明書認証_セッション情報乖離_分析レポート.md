# クライアント証明書認証とセッション情報の乖離分析レポート

**作成日時**: 2026-01-20 16:56  
**分析対象**: クライアント証明書認証ミドルウェアとログイン画面のセッション保存処理

---

## 🔍 分析結果サマリー

### 発見された乖離

1. **セキュリティ上の重大な問題**: 証明書の `organizationId` とユーザーの `organizationId` の整合性チェックが未実装
2. **フロントエンドの仮実装**: `organizationId: ''` を渡す不完全な実装
3. **型定義の不整合**: `LoginCredentials` に不要な `organizationId` フィールドが存在

---

## 📋 詳細分析

### 1. クライアント証明書認証ミドルウェア（backend/src/middleware/clientCertMiddleware.ts）

#### 設定される情報
```typescript
req.organizationId = organizationId;  // NginxのX-Organization-Idヘッダーから取得
req.clientCert = {
  dn: certDN || '',
  cn: certCN || '',
  verified: certVerify
};
```

#### 問題点
- ✅ **正**: Nginxから渡された `organizationId` を `req.organizationId` に設定
- ❌ **問題**: 現在は `return next()` で実質的にスキップされている（コメントアウトされている）

---

### 2. authController.login（backend/src/controllers/authController.ts）

#### organizationId の取得と使用
```typescript
// 取得
const organizationId = req.headers['x-organization-id'] as string;

// 使用（ユーザー検索）
const userQuery = `
  SELECT ...
  FROM organization_user
  WHERE user_name = $1 AND organization_id = $2
`;
const userResult = await pool.query(userQuery, [username, organizationId]);
```

#### ❌ **重大な問題**: 整合性チェックの欠如
- 証明書の `organizationId` とDBから取得したユーザーの `organization_id` の一致を検証していない
- マルチテナント分離の観点から、この検証は**必須**

#### ✅ **推奨**: 以下のチェックを追加すべき
```typescript
// ユーザー取得後
if (user.organization_id !== organizationId) {
  // 証明書の組織IDとユーザーの組織IDが不一致
  res.status(403).json({
    success: false,
    error: {
      code: 'AUTH_ORGANIZATION_MISMATCH',
      message: '組織IDが一致しません',
    },
  });
  return;
}
```

---

### 3. authController.verifyPin（backend/src/controllers/authController.ts）

#### セッション（JWT）に保存される情報
```typescript
const jwtResult = await jwtService.generate(
  {
    userId: userInfo.id,
    organizationId: userInfo.organizationId,  // ← DBから取得した値
    role: userInfo.role,
    sessionId: uuidv4(),
  },
  userInfo.role
);
```

#### ❌ **問題**: 
- `userInfo.organizationId` はPINコード検証時にDBから取得
- 証明書の `organizationId`（`req.organizationId`）との整合性チェックなし

#### ✅ **推奨**: verifyPinでも整合性チェックを追加
```typescript
const organizationId = req.headers['x-organization-id'] as string;

// ユーザー情報取得後
if (userInfo.organizationId !== organizationId) {
  res.status(403).json({
    success: false,
    error: {
      code: 'AUTH_ORGANIZATION_MISMATCH',
      message: '組織IDが一致しません',
    },
  });
  return;
}
```

### 4. フロントエンド（frontend/src/components/LoginPage.tsx）

## 🚨 セキュリティ上の懸念事項

### 1. マルチテナント分離の脆弱性

**シナリオ**: 攻撃者が別組織の証明書を使用してログイン

```
1. 攻撃者が組織Aの証明書を入手
2. 組織Bのユーザー名/パスワードでログイン試行
3. 現在の実装では、証明書の組織IDとユーザーの組織IDの整合性チェックなし
4. ログイン成功してしまう可能性がある
```

**影響**: データ漏洩、不正アクセス

## ✅ 修正提案

### 修正1: authController.login に整合性チェック追加

```typescript
// ユーザー検索後、パスワード検証前に追加
if (user.organization_id !== organizationId) {
  // ログイン履歴に記録
  const historyQuery = `
    INSERT INTO login_history (user_name, organization_id, login_at, login_sf, failure_reason)
    VALUES ($1, $2, NOW(), $3, $4)
  `;
  await pool.query(historyQuery, [
    user.user_name,
    organizationId,  // 証明書の組織ID
    false,
    'Organization ID mismatch',
  ]);

  res.status(403).json({
    success: false,
    error: {
      code: 'AUTH_ORGANIZATION_MISMATCH',
      message: '組織IDが一致しません。正しいクライアント証明書を使用してください',
    },
    meta: {
      timestamp: new Date().toISOString(),
      requestId,
    },
  });
  return;
}
```
