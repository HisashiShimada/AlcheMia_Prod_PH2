## 証明書の発行

### 新規組織の証明書発行

```bash
# 1. certsディレクトリに移動
cd certs

# 2. 組織IDを指定して証明書生成
bash generate-certificates.sh <organization_id>

# 例: 組織ID c9621ed6-5def-4970-8e7f-fbe97c98e3ed の場合
bash generate-certificates.sh c9621ed6-5def-4970-8e7f-fbe97c98e3ed
```

### 生成されるファイル

```
certs/clients/{organization_id}/
├── client.key       # クライアント秘密鍵（配布しない）
├── client.crt       # クライアント証明書
└── client.p12       # PKCS#12形式（ブラウザインポート用）
```

### 発行ログの記録

証明書を発行した際は、以下の情報を記録してください：

```markdown
| 発行日時 | 組織ID | 組織名 | 有効期限 | 発行者 | 備考 |
|---------|--------|-------|---------|--------|------|
| 2026-01-13 14:00 | c9621ed6-... | サンプル組織 | 2027-01-13 | 管理者A | 初回発行 |
```

## 証明書の配布

### 配布ファイル

**配布するファイル**: `client.p12`のみ

**配布しないファイル**: 
- `client.key`（秘密鍵）
- `client.crt`（証明書単体）

### 配布方法

#### セキュアな配布方法（推奨）

1. **暗号化されたメール**
   - 証明書をZIPファイルにパスワード保護
   - パスワードは別経路で伝達

2. **セキュアファイル共有サービス**
   - Box、OneDrive、Google Drive等
   - アクセス権限を適切に設定
   - ダウンロードリンクに有効期限を設定

3. **社内システム**
   - イントラネット経由での配布
   - アクセスログを記録

#### 配布時のテンプレートメール

```
件名: 【重要】クライアント証明書の配布

○○様

お世話になっております。
MMDPFシステムへのアクセスに必要なクライアント証明書を配布いたします。

■ 証明書情報
- 組織ID: {organization_id}
- 有効期限: {expiry_date}
- ファイル名: client.p12

■ インポート手順
添付の「証明書インポート手順.pdf」をご参照ください。
（または https://docs.example.com/cert-import ）

■ 注意事項
- この証明書は厳重に管理してください
- 第三者への共有は禁止です
- 紛失した場合は速やかにご連絡ください

■ サポート連絡先
- Email: support@example.com

よろしくお願いいたします。
```

## 証明書のインポート手順（ユーザー向け）

### Windows環境

#### 方法1: ダブルクリック（推奨）

1. `client.p12`をダブルクリック
2. 「証明書のインポートウィザード」が起動
3. **保存場所**: 「現在のユーザー」を選択
4. **ファイル名**: そのまま「次へ」
5. **パスワード**: 空欄のまま「次へ」
6. **証明書ストア**: 「証明書をすべて次のストアに配置する」を選択
   - 「参照」→「個人」を選択
7. 「完了」をクリック
8. 「正しくインポートされました」と表示されれば成功

#### 方法2: ブラウザから（Chrome/Edge）

1. ブラウザの設定を開く
2. 「プライバシーとセキュリティ」→「セキュリティ」
3. 「証明書の管理」をクリック
4. 「個人」タブ→「インポート」
5. `client.p12`を選択
6. パスワードは空欄
7. 証明書ストアは「個人」を選択

### macOS環境

#### キーチェーンアクセスを使用

1. `client.p12`をダブルクリック
2. 「キーチェーンアクセス」が起動
3. キーチェーン: 「ログイン」を選択
4. パスワード入力画面: 空欄のまま「OK」
5. macOSのログインパスワードを入力
6. インポート完了

### インポート確認

#### Windows

```powershell
# PowerShellで確認
Get-ChildItem -Path Cert:\CurrentUser\My | Where-Object {$_.Subject -like "*{*}*"}
```

#### macOS

```bash
# ターミナルで確認
security find-identity -v -p codesigning
```

## 証明書の更新

### 更新が必要なタイミング

- 有効期限の30日前
- 組織情報の変更時
- セキュリティ侵害の疑いがある場合

### 更新手順

```bash
# 1. 古い証明書のバックアップ
cd certs/clients
mv {organization_id} {organization_id}_backup_$(date +%Y%m%d)

# 2. 新しい証明書の生成
cd ..
bash generate-certificates.sh {organization_id}

# 3. 配布
# 新しいclient.p12をユーザーに配布

# 4. バックアップの削除（更新完了後）
rm -rf clients/{organization_id}_backup_*
```

### ユーザーへの更新通知

```
件名: 【重要】クライアント証明書の更新のお願い

○○様

お世話になっております。
現在ご利用のクライアント証明書の有効期限が近づいております。

■ 現在の証明書情報
- 有効期限: {current_expiry_date}

■ 更新期限
- {update_deadline}までに更新をお願いいたします

■ 更新手順
1. 添付の新しい証明書（client.p12）をダウンロード
2. 古い証明書を削除（手順書参照）
3. 新しい証明書をインポート

■ 注意事項
- 更新期限を過ぎるとシステムにアクセスできなくなります
- 不明点がございましたらお気軽にお問い合わせください

よろしくお願いいたします。
```

## 証明書の失効

### 失効が必要なケース

- ユーザーの退職・異動
- 証明書の紛失・盗難
- 秘密鍵の漏洩の疑い
- 組織からのアクセス権剥奪

### 失効手順（現状の簡易版）

```bash
# 1. 証明書ファイルの削除
rm -rf certs/clients/{organization_id}

# 2. Nginxの設定変更は不要
# （CA証明書は共通のため、個別の証明書ファイルの削除のみでOK）

# 3. 失効記録の作成
echo "$(date): Revoked certificate for {organization_id}" >> certs/revoked.log
```

### 今後の実装予定（CRL対応）

```bash
# 証明書失効リスト（CRL）の生成（将来実装予定）
openssl ca -config ca.conf -revoke clients/{organization_id}/client.crt
openssl ca -config ca.conf -gencrl -out crl/crl.pem
```

## トラブルシューティング

### ケース1: 証明書選択ダイアログが表示されない

**症状**: ブラウザで証明書選択画面が出ない

**原因**:
- 証明書が正しくインポートされていない
- 証明書ストアが間違っている

**対策**:
1. 証明書が「個人」ストアにあるか確認
2. ブラウザを再起動
3. 証明書を削除して再インポート

### ケース2: 403 Forbidden エラー

**症状**: `CERT_VERIFICATION_FAILED`エラーが表示

**原因**:
- 証明書のCNがUUID形式でない
- CA証明書が一致しない
- 証明書の有効期限切れ

**対策**:
```bash
# 証明書の内容を確認
openssl x509 -in clients/{org_id}/client.crt -noout -text

# CNを確認
openssl x509 -in clients/{org_id}/client.crt -noout -subject

# 有効期限を確認
openssl x509 -in clients/{org_id}/client.crt -noout -dates
```

### ケース3: 組織IDが正しく認識されない

**症状**: `INVALID_ORGANIZATION_ID`エラー

**原因**:
- CNのフォーマットが`{uuid}`形式でない

**対策**:
```bash
# 正しいフォーマットで証明書を再生成
bash generate-certificates.sh {organization_id}

# CNが正しいか確認
openssl x509 -in clients/{organization_id}/client.crt -noout -subject
# 出力例: subject=CN = {c9621ed6-5def-4970-8e7f-fbe97c98e3ed}
```

### ケース4: 開発環境で証明書なしでテストしたい

**対策**:

1. `backend/.env`で環境変数を設定
```bash
NODE_ENV=development
```

2. `frontend/src/services/authService.ts`のコメント部分を有効化
```typescript
client.interceptors.request.use(
  (config) => {
    const organizationId = '{c9621ed6-5def-4970-8e7f-fbe97c98e3ed}';
    if (organizationId) {
      config.headers['X-Organization-Id'] = organizationId;
    }
    return config;
  }
);
```

## セキュリティベストプラクティス

### DO（推奨）

✅ 証明書のバックアップを暗号化して保管
✅ 証明書配布時はセキュアな方法を使用
✅ 有効期限の30日前に更新通知を送信
✅ 失効した証明書の記録を保持
✅ アクセスログを定期的にレビュー
✅ ユーザーに証明書の重要性を教育

### DON'T（非推奨）

❌ 秘密鍵（.key）を配布しない
❌ 平文メールで証明書を送信しない
❌ 証明書を共有フォルダに無防備に配置しない
❌ 有効期限切れの証明書を放置しない
❌ 失効手続きを怠らない

## 付録

### A. コマンドリファレンス

```bash
# 証明書の内容を確認
openssl x509 -in client.crt -noout -text

# CN（Common Name）のみを表示
openssl x509 -in client.crt -noout -subject

# 有効期限を確認
openssl x509 -in client.crt -noout -dates

# PKCS#12形式の内容を確認
openssl pkcs12 -in client.p12 -noout -info

# PEM形式に変換
openssl pkcs12 -in client.p12 -out client.pem -nodes

# 証明書チェーンの検証
openssl verify -CAfile ca/ca.crt clients/{org_id}/client.crt
```

### B. Nginxログの確認

```bash
# 証明書情報を含むアクセスログ
docker exec mmdpf-nginx tail -f /var/log/nginx/access.log

# 特定組織のアクセスのみ抽出
docker exec mmdpf-nginx grep "{c9621ed6-5def-4970-8e7f-fbe97c98e3ed}" /var/log/nginx/access.log

# エラーログの確認
docker exec mmdpf-nginx tail -f /var/log/nginx/error.log
```
