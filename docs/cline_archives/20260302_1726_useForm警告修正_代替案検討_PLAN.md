## 1. タスク概要

DocumentEditDialog.tsx と SaveDialog.tsx で発生している以下の警告への対処方法を検討・実装します：

```
Warning: Instance created by `useForm` is not connected to any Form element. 
Forget to pass `form` prop?
```

現在の実装（早期リターン方式）以外の、より適切な修正方法を検討します。

### 目的
- useForm警告を解消する
- Reactのベストプラクティスに従った実装にする
- ダイアログの動作に影響を与えない

### 期待される成果
- [ ] useForm警告が完全に解消される
- [ ] ダイアログの開閉が正常に動作する

- [ ] パフォーマンスへの影響がない

## 3. 現状分析

### 現在の実装（早期リターン方式）

**メリット:**
- シンプルで理解しやすい
- 確実に警告を解消できる

**デメリット:**
- open=falseの時にコンポーネント全体がアンマウントされる
- useEffectによる初期化が毎回実行される可能性がある
- Reactの推奨パターンではない（条件付きフック呼び出しの回避）

```typescript
const [form] = Form.useForm();
// ...

if (!open) {
  return null;
}
```

## 4. 代替案の検討

### 案1: Modal の forceRender プロパティ（推奨）

**説明:**
Modalに`forceRender={true}`を設定することで、ダイアログが閉じていてもFormコンポーネントが常にレンダリングされ、useFormとの接続が維持されます。

**実装:**
```typescript
<Modal
  title="📄 Document編集"
  open={open}
  forceRender={true}  // ✅ 追加
  onCancel={handleCancel}
  // ...
>
```

**メリット:**
- Ant Designの公式推奨パターン
- コンポーネントの構造を変更しない
- Formの状態が保持される
- 早期リターンが不要

**デメリット:**
- ダイアログが閉じていてもDOMに存在する（わずかなメモリ使用）
- 初回レンダリング時に非表示のコンテンツもレンダリングされる

**パフォーマンス影響:** 極めて小さい（許容範囲内）

### 案2: destroyOnClose プロパティ

**説明:**
Modalに`destroyOnClose={true}`を設定し、閉じた時にコンポーネントを破棄します。

**実装:**
```typescript
<Modal
  title="📄 Document編集"
  open={open}
  destroyOnClose={true}  // ✅ 追加
  onCancel={handleCancel}
  // ...
>
```

**メリット:**
- メモリ使用量が最小
- 開くたびにクリーンな状態で初期化される

**デメリット:**
- useForm警告が依然として発生する可能性がある
- 毎回コンポーネントが再マウントされる（パフォーマンス低下）

**結論:** この案は警告を解消しない可能性が高い

### 案3: 条件付きレンダリング + destroyOnClose

**説明:**
destroyOnCloseとJSX内での条件付きレンダリングを組み合わせます。

**実装:**
```typescript
return (
  <Modal
    title="📄 Document編集"
    open={open}
    destroyOnClose={true}
    onCancel={handleCancel}
    // ...
  >
    {open && (
      <Form form={form} layout="vertical">
        {/* ... */}
      </Form>
    )}
  </Modal>
);
```

**メリット:**
- open=false時にFormがレンダリングされない

**デメリット:**
- 複雑な実装になる
- useForm警告が解消されない可能性が高い

**結論:** 推奨しない

### 案4: useForm の遅延初期化

**説明:**
useFormをopen=trueの時のみ呼び出すようにします。

**実装:**
```typescript
const [form, setForm] = useState<FormInstance | null>(null);

useEffect(() => {
  if (open && !form) {
    setForm(Form.useForm()[0]);
  }
}, [open, form]);
```

**メリット:**
- open=false時にuseFormが呼ばれない

**デメリット:**
- Reactのルール違反（Hooksを条件付きで呼び出している）
- 複雑で保守性が低い
- 動作が不安定になる可能性が高い

**結論:** 推奨しない（Reactルール違反）

## 5. 推奨案の選定

### ✅ 採用: 案1 - Modal の forceRender プロパティ

**理由:**
1. Ant Designの公式推奨パターン
2. シンプルで理解しやすい
3. パフォーマンス影響が極めて小さい
4. Formの状態管理が適切に行われる
5. 既存の実装を大きく変更する必要がない

**実装手順:**
1. DocumentEditDialog.tsx の Modal に `forceRender={true}` を追加
2. SaveDialog.tsx の Modal に `forceRender={true}` を追加
3. 早期リターン (`if (!open) return null;`) を削除
4. 動作確認
