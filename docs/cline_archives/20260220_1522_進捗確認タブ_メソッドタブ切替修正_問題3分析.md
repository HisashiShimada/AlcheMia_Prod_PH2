# 問題3分析: プロジェクトA→Bへの切り替え時に自動選択されない

## 作成日時
2026-02-20 15:42

## 問題の症状
- プロジェクト未選択 → プロジェクトA選択: メソッドタブが自動選択される ✅
- プロジェクトA選択 → プロジェクトB選択: メソッドタブが自動選択されない ❌

## 原因分析

### プロジェクトA→Bへの切り替え時の実行順序

```
1. 親: handleProjectChange(projectB)実行
2. 親: setSelectedMethodId(null)実行
3. 子コンポーネント再レンダリング
   - selectedMethodId = null ✅
   - methods = projectAのメソッド（まだクリアされていない）❌
4. 自動選択useEffect実行（selectedMethodIdがnullになった）
   ※ 依存配列にselectedMethodIdがないので実行されない！
5. API呼び出しuseEffect実行（selectedProjectが変わった）
6. プロジェクトBのメソッドを取得開始
7. setMethods([]) → methodsを空配列にクリア
8. 自動選択useEffect実行（methodsが変わった）
   条件: methods.length > 0 && !selectedMethodId
   → methods.length = 0なので、何もしない ✅
9. API取得完了、setMethods(methodsB)
10. 自動選択useEffect実行（methodsが変わった）
    条件チェック: methods.length > 0 && !selectedMethodId
    → この時点でselectedMethodIdはnull？ それとも既にセット済み？
```

### 検証が必要なポイント

API取得中に何が起きているか？

**子コンポーネントのAPI取得useEffect:**
```typescript
useEffect(() => {
  const fetchWorkerTasks = async () => {
    if (!selectedProject || !selectedProjectName) {
      setMethods([]);  // ← ここでクリアされる
      setTasks([]);
      setProjectId(null);
      return;
    }

    setLoading(true);
    try {
      const result = await getWorkerTasks(selectedProjectName);
      // ... メソッドを取得
      setMethods(methodsData);  // ← 新しいメソッドをセット
      setTasks(allTasks);
    }
  };

  fetchWorkerTasks();
}, [selectedProject, selectedProjectName]);
```

## 根本原因

プロジェクト未選択→Aの場合：
```
1. selectedProject = null, methods = []
2. プロジェクトA選択
3. selectedProject = 'A', methods = []（まだ）
4. API呼び出し
5. methods = [] → methodsA
6. useEffect実行: methods.length > 0 && !selectedMethodId → true
7. 自動選択実行 ✅
```

プロジェクトA→Bの場合：
```
1. selectedProject = 'A', methods = methodsA, selectedMethodId = 'method_A1'
2. プロジェクトB選択
3. selectedProject = 'B', selectedMethodId = null
4. 子コンポーネント再レンダリング
5. API呼び出しuseEffect実行
6. methods = methodsA → [] → methodsB
   ↓ この過程で2回useEffectが実行される
7. methods = [] の時: useEffect実行
   条件: 0 > 0 && !null → false（何もしない）
8. methods = methodsB の時: useEffect実行
   条件: 2 > 0 && !selectedMethodId
   
   【問題】この時点でselectedMethodIdはまだnullか？
```

**考えられるケース:**

### ケース1: selectedMethodIdがまだnullの場合
→ 自動選択されるはず（でも実際はされていない）

### ケース2: selectedMethodIdが既にセットされている場合
→ どこかで意図せずセットされている？

## 推測される原因

プロジェクトを切り替えた瞬間、親の`selectedMethodId`はnullにセットされるが、

子コンポーネントが受け取る`selectedMethodId`のpropsが更新される**前**に、古いmethodsで何かが起きている可能性？

または、API取得が完了してmethodsBがセットされる時点で、親のselectedMethodIdがnullではない状態になっている？

## 解決策の方向性

### 方法1: プロジェクトIDを監視して強制的にリセット

```typescript
const prevProjectRef = useRef<string | null>(null);

useEffect(() => {
  // プロジェクトが変更された場合、強制的に自動選択
  if (selectedProject !== prevProjectRef.current) {
    prevProjectRef.current = selectedProject;
    
    if (methods.length > 0) {
      const sortedMethods = [...methods].sort((a, b) => a.experimentOrder - b.experimentOrder);
      onSelectMethod(sortedMethods[0].methodId);
    }
  } else if (methods.length > 0 && !selectedMethodId) {
    // 通常の自動選択
    const sortedMethods = [...methods].sort((a, b) => a.experimentOrder - b.experimentOrder);
    onSelectMethod(sortedMethods[0].methodId);
  }
}, [methods, selectedProject, onSelectMethod]);
```

### 方法2: プロジェクトが変わったらmethodsをクリアするタイミングを早める

しかし、これは既に実装されている...

### 方法3: 依存配列にselectedProjectを追加

```typescript
useEffect(() => {
  if (methods.length > 0 && !selectedMethodId) {
    const sortedMethods = [...methods].sort((a, b) => a.experimentOrder - b.experimentOrder);
    onSelectMethod(sortedMethods[0].methodId);
  }
}, [methods, selectedProject, onSelectMethod]);
// ↑ selectedProjectを追加
```

プロジェクトが変わった時に必ず実行される。

## 推奨する解決策

**方法1（プロジェクトIDを監視）** を採用します。

理由：
1. プロジェクト変更を明示的に検知できる
2. プロジェクト変更時は強制的に自動選択する
3. 通常時はユーザーの選択を尊重する
4. 最も確実な方法
