# Phase 6計画: 型変換最適化（改訂版）

## メタデータ
- **作成日時**: 2026-02-02 17:15
- **Phase**: Phase 6計画（改訂版）
- **目的**: 不要な型変換の削減、パース時の型定義の直接利用
- **背景**: ユーザーフィードバックに基づく設計原則の明確化
- **改訂理由**: 型継承（extends）を避け、全容を明示的に記述する方針に変更

---

## 🎯 Phase 6の目的

**「MAIMLデータの型変換を最小化し、パース時の型定義を直接利用する」**

### 設計原則（ユーザー要望）

1. ✅ **基本はパース時の型定義（XSD準拠型）をそのまま使う**
2. ✅ **何度も別の型に入れ直すことを防ぐ**
3. ✅ **追加情報が必要な場合のみ新しい型を作る**
4. ✅ **型継承（extends）は使わず、全容を明示的に記述する**

---

## 📊 現状分析

### 型変換の現状

```
MAIMLファイル（XML）
    ↓ パース（xml-js）
MaimlRoot（XSD準拠型） ← これをそのまま使いたい
    ↓ 変換1（maimlParserTyped内）
TransitionInfo, TemplateInfo（派生型）
    ↓ 変換2（petriNetExtractor）
TemplateItem, TemplateMapEntry（エディタ型）
    ↓ 使用
PetriNetEditor
```

**問題点**:
- ❌ 変換が2回発生している
- ❌ 同じ概念を表す型が3つ存在
- ❌ 型変換のコストが発生

---

## 🎯 Phase 6の改善方針

### 理想的な型の流れ

```
MAIMLファイル（XML）
    ↓ パース（xml-js）
MaimlRoot（XSD準拠型） ← 基本はこれをそのまま使う
    ↓ 追加情報が必要な場合のみ
別の型（全容を明示的に記述）
    ↓ 使用
画面コンポーネント
```

### 型定義の3パターン

#### パターン1: XSD準拠型をそのまま使用（型エイリアス）

```typescript
// ✅ 追加情報が不要な場合
import { Template } from '@/types/maiml-unified';

// 型エイリアスで使用（型変換不要）
export type TemplateInfo = Template;
```

**適用条件**: XSD準拠型で十分な場合
**メリット**: 型変換なし、パフォーマンス最高

#### パターン2: 別の型として全容を明示（推奨）

```typescript
// ✅ 追加情報が必要な場合（extendsは使わない）
export interface TransitionWithMetadata {
  // === XSD準拠型のフィールド（全て明示）===
  id: string;
  name?: string;
  label?: string;
  methodId: string;
  program?: {
    instruction?: string;
  };
  // ... Transition型の全フィールドをここに明示的に記述
  
  // === 追加フィールド（Phase 3-4で追加）===
  displayName?: string;
  isExperimentRelevant?: boolean;
  hasInstruction?: boolean;
}
```

**適用条件**: XSD準拠型 + 追加情報が必要な場合
**メリット**: 型の全容が一目でわかる、保守性が高い

#### パターン3: 型継承（❌ 非推奨）

```typescript
// ❌ 避ける: extendsを使った型拡張
interface ExtendedTransition extends Transition {
  displayName?: string;
  isExperimentRelevant?: boolean;
  hasInstruction?: boolean;
}
```

**問題点**: 
- 全容がわかりづらい
- Transition型の定義を見に行く必要がある
- 保守性が低い

## 📋 Phase 6実装計画

### Step 1: 型使用状況の調査

**調査対象:**
- maimlParserTyped.tsの全メソッド
- petriNetExtractor.tsの型使用
- editorv2/types/index.tsの型定義
- 各コンポーネントでの型使用

**調査内容:**
1. XSD準拠型との重複がある型
2. 追加情報が必要な型（displayName等）
3. 型エイリアスで置き換え可能な型

### Step 2: 型定義の統合

**統合方針:**

| 現在の型 | 統合後 | 理由 | パターン |
|---------|-------|------|---------|
| TemplateInfo | Template（型エイリアス） | 追加情報なし、内容が完全に一致 | パターン1 |
| TransitionInfo | TransitionWithMetadata（別型） | displayName等の追加情報あり | パターン2 |
| TemplateItem | Template（型エイリアス） | 追加情報なし、エディタでも同じ | パターン1 |
| EditorPlace | EditorPlace（別型） | data等の追加情報あり | パターン2 |

**実装例:**
```typescript
// frontend/src/types/maiml-extended.ts（新規作成）
import { Template, Transition, Place } from './maiml-unified';

// パターン1: 型エイリアス（追加情報なし）
export type TemplateInfo = Template;

// パターン2: 別の型として全容を明示（追加情報あり）
export interface TransitionWithMetadata {
  // === XSD準拠型のフィールド（Transition型から全てコピー）===
  id: string;
  name?: string;
  label?: string;
  methodId: string;
  program?: {
    instruction?: string;
  };
  // ※ Transition型の全フィールドを明示的に記述
  
  // === 追加フィールド（Phase 3-4で追加）===
  displayName?: string;              // 表示用の整形された名前
  isExperimentRelevant?: boolean;    // 実験関連のTransitionか
  hasInstruction?: boolean;          // Instructionを持つか
}

// パターン2: エディタ専用型（追加情報あり）
export interface EditorPlace {
  // === XSD準拠型のフィールド（Place型から全てコピー）===
  id: string;
  label?: string;
  // ※ Place型の全フィールドを明示的に記述
  
  // === 追加フィールド（エディタ固有）===
  data?: any;                        // ReactFlow用の追加データ
  isHighlighted?: boolean;           // ハイライト表示フラグ
}
```

### Step 3: メソッドの戻り値型を変更

**maimlParserTyped.tsの修正:**

```typescript
// ❌ 現在: 独自型で型変換が発生
getTemplates(): {
  success: boolean;
  templates: TemplateInfo[];  // 独自型（型変換あり）
}

// ✅ 改善後: XSD準拠型を直接使用（追加情報なし）
getTemplates(): {
  success: boolean;
  templates: Template[];  // XSD準拠型そのまま
}

// ✅ 追加情報が必要な場合: 別の型として全容を明示
getTransitions(): {
  success: boolean;
  transitions: TransitionWithMetadata[];  // 全容が明示された型
}
```

### Step 4: 型変換の削除

**petriNetExtractor.tsの修正:**

```typescript
// ❌ 現在: 型変換が発生
const templates = parser.getTemplates().templates;
const templateItems: TemplateItem[] = templates.map(t => ({
  id: t.id,
  name: t.name,
  description: t.description,
  // ... 変換処理（不要）
}));

// ✅ 改善後: そのまま使用（型変換なし）
const templates = parser.getTemplates().templates;
// templatesはTemplate[]型なのでそのまま使用可能
```

### Step 5: エディタ型定義の見直し

**editorv2/types/index.tsの修正:**

```typescript
import { Template, Transition, Place } from '@/types/maiml-unified';

// ケース1: 追加情報が不要な場合は型エイリアス
export type TemplateItem = Template;
export type TransitionItem = Transition;

// ケース2: 追加情報が必要な場合は別の型として全容を明示
export interface EditorPlace {
  // === XSD準拠型のフィールド（Place型から全てコピー）===
  id: string;
  label?: string;
  x?: number;
  y?: number;
  // ※ Place型の全フィールドを明示的に記述
  
  // === 追加フィールド（エディタ固有）===
  data?: any;                // ReactFlow用の追加データ
  isHighlighted?: boolean;   // ハイライト表示フラグ
}
```

**重要**: `extends`は使わず、XSD準拠型のフィールドを全て明示的にコピーして記述する

## ⚠️ 注意事項

### 破壊的変更の可能性

Phase 6の実装により、以下の変更が発生します：

1. **メソッドの戻り値型の変更**
   - `TemplateInfo[]` → `Template[]`
   - `TransitionInfo[]` → `TransitionWithMetadata[]`

2. **型名の変更**
   - 既存の`TemplateInfo`を使用しているコードの修正が必要

3. **段階的な移行が必要**
   - Phase 5のように段階的に実施
   - 後方互換性の維持期間を設ける

### DO（推奨）
✅ XSD準拠型を最優先で使用
✅ 追加情報不要なら型エイリアス
✅ 追加情報必要なら別の型として全容を明示
✅ **extendsは使わない**（全容がわかりづらいため）
✅ 型の全フィールドを明示的に記述
✅ 段階的に移行する
✅ 後方互換性を一定期間維持

### DON'T（非推奨）
❌ 同じ概念を表す型を複数作らない
❌ 不要な型変換を行わない
❌ **extendsを使った型拡張は避ける**（全容がわかりづらい）
❌ XSD準拠型と異なる構造の独自型を作らない
❌ 一度に全てを変更しない

## 📝 型定義の具体例

### 例1: 追加情報なし（型エイリアス）

```typescript
// frontend/src/types/maiml-extended.ts
import { Template } from './maiml-unified';

// ✅ そのまま使用（型変換不要）
export type TemplateInfo = Template;
```

**使用例:**
```typescript
// maimlParserTyped.ts
getTemplates(): {
  success: boolean;
  templates: Template[];  // 型エイリアスTemplateInfoではなく直接Template使用推奨
}

// コンポーネント
const templates: Template[] = parser.getTemplates().templates;
// そのまま使用可能、型変換なし
```

### 例2: 追加情報あり（別型、全容を明示）

```typescript
// frontend/src/types/maiml-extended.ts
import { Transition } from './maiml-unified';

// ✅ 別の型として全容を明示（extendsは使わない）
export interface TransitionWithMetadata {
  // === XSD準拠型のフィールド（Transition型から全てコピー）===
  // ※ 以下はTransition型の実際のフィールドに合わせて記述
  id: string;
  name?: string;
  label?: string;
  methodId: string;
  program?: {
    instruction?: string;
  };
  arc?: Array<{
    id: string;
    from: string;
    to: string;
  }>;
  // ... その他Transition型の全フィールドを明示的に記述
  
  // === 追加フィールド（Phase 3-4で追加）===
  displayName?: string;              // 表示用の整形された名前
  isExperimentRelevant?: boolean;    // 実験関連のTransitionか
  hasInstruction?: boolean;          // Instructionを持つか
}
```

**使用例:**
```typescript
// maimlParserTyped.ts
getTransitions(): {
  success: boolean;
  transitions: TransitionWithMetadata[];
}

// 実装内で変換が必要
private buildTransitionWithMetadata(t: Transition): TransitionWithMetadata {
  return {
    // XSD準拠型のフィールドをコピー
    id: t.id,
    name: t.name,
    label: t.label,
    methodId: t.methodId,
    program: t.program,
    arc: t.arc,
    // ... 全フィールドをコピー
    
    // 追加フィールドを計算
    displayName: this.buildDisplayName(t),
    isExperimentRelevant: this.checkExperimentRelevant(t),
    hasInstruction: this.checkHasInstruction(t),
  };
}
```
