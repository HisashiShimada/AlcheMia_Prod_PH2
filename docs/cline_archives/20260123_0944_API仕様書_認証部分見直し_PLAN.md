### 認証・認可

**認証方式**: JWT + Session Hybrid

**必須ヘッダー**:
```http
Authorization: Bearer maiml_session-{sessionId}_{timestamp}
```

**organization_id の取得**:
- ログイン時に `X-Organization-Id` ヘッダーから組織IDを取得し、セッションに保存します
- ログイン後のAPIでは、`Authorization` ヘッダーのセッショントークンから自動的に取得されます
- リクエストヘッダーで `X-Organization-Id` を指定する必要はありません
- `authMiddleware` がセッション情報を検証し、ユーザー情報（organization_idを含む）を `req.user` に格納します

**権限要件**:
- すべてのAPI: `experiment_admin` または `system_admin` ロール必須

**ミドルウェアチェーン**:
```typescript
router.METHOD('/path', 
  authMiddleware,           // 1. JWT認証（セッション検証、req.userに格納）
  tenantIsolation,          // 2. テナント分離（req.user.organizationIdをreq.organizationIdに格納）
  permissionCheck([...]),   // 3. 権限チェック
  controller.handler        // 4. コントローラー処理
);
```

**ミドルウェアの動作**:
1. `authMiddleware`: JWTトークン（`maiml_session-{sessionId}_{timestamp}`）を検証し、セッション情報を取得して `req.user` に格納（organization_idを含む）
2. `tenantIsolation`: `req.user.organizationId` を `req.organizationId` に格納し、テナント分離を保証
3. `permissionCheck`: ユーザーのロール（`req.user.roleName`）を検証
4. コントローラー: `req.organizationId` を使用してテナント分離されたデータにアクセス

## 7. 技術的詳細

### 認証フローの詳細

**ログイン時（初回のみ）:**
```typescript
// フロントエンドからのリクエスト
POST /api/v1/auth/login
Headers:
  X-Organization-Id: {organization_id}  // ログイン時のみ必須
Body:
  { email, password }

// バックエンド処理
1. X-Organization-Id からorganization_idを取得
2. ユーザー認証
3. セッション作成（organization_idを含む）
4. JWTトークン生成: maiml_session-{sessionId}_{timestamp}
```

**ログイン後のAPI（通常のAPI）:**
```typescript
// フロントエンドからのリクエスト
GET /api/v1/projects
Headers:
  Authorization: Bearer maiml_session-{sessionId}_{timestamp}  // X-Organization-Idは不要

// バックエンド処理（authMiddleware）
1. Authorizationヘッダーからトークンを抽出
2. トークンを検証（maiml_session-{sessionId}_{timestamp}）
3. セッションIDでセッション情報を取得
4. セッションからユーザー情報を取得し、req.userに格納

req.user = {
  userId: string,
  userName: string,
  email: string,
  organizationId: string,  // セッションに保存されたorganization_id
  departmentId: string,
  roleId: string,
  roleName: string,
  sessionId: string
};

// tenantIsolation でorganization_idを抽出
req.organizationId = req.user.organizationId;
```

### ミドルウェアの実装例

```typescript
// authMiddleware.ts の動作
export const authMiddleware = async (req, res, next) => {
  // 1. Authorizationヘッダーからトークンを抽出
  const token = req.headers.authorization?.replace('Bearer ', '');
  
  if (!token || !token.startsWith('maiml_session-')) {
    return res.status(401).json({
      success: false,
      error: {
        code: 'AUTH_TOKEN_INVALID',
        message: '認証トークンが不正です'
      }
    });
  }
  
  // 2. トークンからセッションIDとタイムスタンプを抽出
  const [sessionId, timestamp] = token.replace('maiml_session-', '').split('_');
  
  // 3. セッション情報を取得
  const session = await getSession(sessionId);
  
  if (!session || !session.user) {
    return res.status(401).json({
      success: false,
      error: {
        code: 'AUTH_SESSION_INVALID',
        message: 'セッションが無効です'
      }
    });
  }
  
  // 4. req.userにユーザー情報を格納（organization_idを含む）
  req.user = {
    userId: session.user.userId,
    userName: session.user.userName,
    email: session.user.email,
    organizationId: session.user.organizationId,  // セッションに保存されている
    departmentId: session.user.departmentId,
    roleId: session.user.roleId,
    roleName: session.user.roleName,
    sessionId: sessionId
  };
  
  next();
};

// tenantIsolation.ts の動作
export const tenantIsolation = (req, res, next) => {
  // authMiddleware でセッション情報が req.user に格納されている前提
  if (!req.user || !req.user.organizationId) {
    return res.status(401).json({
      success: false,
      error: {
        code: 'AUTH_TOKEN_INVALID',
        message: '認証情報が不正です'
      }
    });
  }
  
  // organization_id を req.organizationId に格納
  req.organizationId = req.user.organizationId;
  
  next();
};
```
