# タスク計画書: nginx.prod.conf 正規表現バグ修正（orgId抽出不具合）

## メタデータ
- **作成日時**: 2026-04-17 10:54

- **優先度**: 高
- **推定工数**: 0.5時間

## 1. タスク概要

`config/nginx/nginx.prod.conf` の `map` ディレクティブにおいて、クライアント証明書のSubject DNからUUID形式の組織ID（`organization_id`）を抽出する正規表現が誤って記述されており、常に空文字列が返るバグを修正する。

## 2. 目的と期待される成果

### 目的
NLB経由でのHTTPSアクセス時に、ブラウザから提示されたクライアント証明書のCN（UUID形式の組織ID）が正しく抽出され、バックエンドAPIへ `orgId` クエリパラメータとして渡されるようにする。

### 期待される成果
- [ ] ログイン時に E1003「Organization ID is required」エラーが発生しなくなる
- [ ] クライアント証明書を持つユーザーが正常にログインできる

## 3. バグの詳細

### 問題箇所
`config/nginx/nginx.prod.conf` 27行目

### バグのある記述
```nginx
map $ssl_client_s_dn $organization_id {
    default "";
    ~CN=(?<CN>[a-f0-9]\{8\}-[a-f0-9]\{4\}-[a-f0-9]\{4\}-[a-f0-9]\{4\}-[a-f0-9]\{12\}) $CN;
}
```

### バグの原因
`\{8\}` という記述は PCRE（正規表現エンジン）において**量指定子ではなくリテラル文字 `{8}`** として解釈される。
nginxのパーサーが `{` を設定ブロック区切り文字と混同しないよう `\{` とエスケープしたと思われるが、PCREに渡した後も `\{` のままなので量指定子として機能しない。

| 記述 | PCRE解釈 | 意図 |
|------|---------|------|
| `{8}` | 直前の文字を8回繰り返す（量指定子） | ✅ 正しい |
| `\{8\}` | 文字列 `{8}` にマッチ | ❌ 壊れている |

結果として `$organization_id` は常に空文字列となり、`orgId` クエリパラメータがバックエンドに渡らない。

### 修正後の記述
正規表現値全体をダブルクォートで囲むことで、nginxパーサーが `{` を設定ブロック区切り文字として誤解釈しなくなる。

```nginx
map $ssl_client_s_dn $organization_id {
    default "";
    "~CN=(?<CN>[a-f0-9]{8}-[a-f0-9]{4}-[a-f0-9]{4}-[a-f0-9]{4}-[a-f0-9]{12})" $CN;
}
```
