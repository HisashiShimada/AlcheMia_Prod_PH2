## リスク評価

### 高リスク領域

#### 1. JWTトークン構造の変更
**リスク:** 既存セッションが無効化される

**影響範囲:**
- ログイン中のユーザーは再ログインが必要

**対策:**
- メンテナンス時間を設定
- ユーザーへの事前通知
- セッション有効期限の短縮（移行前）

#### 2. 画面遷移ロジックの変更
**リスク:** role_idとrole_nameの変換ミスによる不正な画面遷移

**影響範囲:**
- ログイン後に誤った画面にリダイレクトされる
- 権限チェックが機能しない

**対策:**
- 十分な単体テスト・統合テスト
- role_id↔role_nameの変換ロジックの厳密な検証
- ログイン後の画面遷移テストの自動化

### 中リスク領域

#### 3. API応答形式の変更
**リスク:** フロントエンドとの互換性喪失

**影響範囲:**
- フロントエンドでのエラー発生
- 画面表示の不具合

**対策:**
- API応答形式の厳密な型定義
- フロントエンド側での型チェック強化
- 段階的なデプロイ（バックエンド→フロントエンド）

#### 4. テストデータの不整合

- デプロイの遅延

## 結論

organization_user.roleからrole_idへの移行は、**27ファイルに影響する大規模な変更**です。

特に重要な影響箇所は：
1. **認証フロー** - ログイン、PINコード検証
2. **JWTトークン** - ペイロード構造の変更
3. **画面遷移制御** - ロール別リダイレクト
4. **セッション管理** - ロール別有効期限
5. **権限チェック** - ロールベースアクセス制御

推奨する移行方式は**オプションA（段階的移行）**です。
- role_idカラム追加時にroleカラムを維持
- コードをrole_id対応に変更
- 十分な検証期間を経てroleカラムを削除

この方式により、リスクを最小化しつつ安全に移行できます。
