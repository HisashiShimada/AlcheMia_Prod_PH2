## 考慮すべき仕様

### 1. トランザクション連動

#### 1.1 基本方針
```typescript
// S3アップロード成功 → メタデータ抽出 → DB保存
// どれか1つでも失敗したら全体をロールバック

try {
  // Step 1: S3アップロード
  await storageService.uploadFile(organizationId, fileKey, content);
  
  // Step 2: メタデータ抽出（MAIMLファイルの場合のみ）
  if (fileKey.endsWith('.maiml')) {
    const metadata = await maimlMetadataExtractor.extractMetadataFromXML(content);
    
    // Step 3: DB保存
    await fileMetadataRepository.upsertMetadata(fileKey, metadata);
  }
} catch (error) {
  // ロールバック: S3からファイルを削除
  await storageService.deleteFile(organizationId, fileKey);
  throw error;
}
```

### 2. 検索機能の強化

#### 2.1 ベクトルインデックスによる全文検索

**技術選定**:
- **Option 1**: PostgreSQL pgvector拡張
  - ✅ 既存のPostgreSQLを利用
  - ✅ セマンティック検索と統合しやすい
  - ❌ テキスト全文検索は別途必要

- **Option 2**: PostgreSQL Full Text Search（推奨）
  - ✅ PostgreSQL標準機能
  - ✅ 日本語対応（pg_bigm拡張）
  - ✅ 既存のGINインデックスを活用可能
  - ❌ セマンティック検索とは別系統

**推奨実装**:
```sql
-- Full Text Searchインデックス追加（日本語対応）
CREATE EXTENSION IF NOT EXISTS pg_bigm;

CREATE INDEX idx_file_metadata_maiml_fulltext_bigm
  ON file_metadata
  USING gin (
    (
      COALESCE(maiml_document_name, '') || ' ' ||
      COALESCE(maiml_document_description, '')
```

4. ファイルタイプ（MAIMLファイルを優先）

```typescript
  textMatchScore: number;
  semanticScore: number;
  recencyScore: number;
  fileTypeScore: number;
```

#### 2.5 部分一致検索

**実装方法**:
```sql
-- ILIKE検索（大文字小文字区別なし）
SELECT * FROM file_metadata
WHERE maiml_document_name ILIKE '%検索語%'
   OR maiml_document_description ILIKE '%検索語%';

-- pg_bigm検索（日本語対応、曖昧検索）
SELECT *, similarity(maiml_document_name, '検索語') AS score
FROM file_metadata
WHERE maiml_document_name %> '検索語'  -- 類似度閾値以上
ORDER BY score DESC;
```
