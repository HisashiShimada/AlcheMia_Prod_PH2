## 5. 技術的詳細

### API仕様（既存）

**エンドポイント:**
```
POST /api/v1/formats/:folderName/files
```

**リクエストパラメータ:**
```typescript
// URLパラメータ
folderName: string  // 例: "chemistry", "biology"

// リクエストボディ
{
  fileName: string;              // 拡張子なし、1-100文字
  fileType: 'maiml';            // MAIMLファイルの場合
  templateType: undefined;       // MAIMLファイルの場合は不要
  description?: string;          // 0-500文字
}
```

**レスポンス（成功時）:**
```typescript
{
  success: true;
  data: {
    filePath: string;     // S3パス（例: "formats/dept_001/chemistry/workflow.maiml"）
    fileName: string;     // ファイル名（例: "workflow.maiml"）
    fileType: string;     // 'maiml'
    size: number;         // ファイルサイズ（バイト）
    createdAt: string;    // 作成日時（ISO 8601形式）
  };
}
```

### デフォルトMAIMLテンプレート

```xml
<?xml version="1.0" encoding="UTF-8"?>
<document xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance">
  <method id="method_1">
    <name>{fileName}</name>
    <description>{description}</description>
    <petri_net>
      <place id="place_start">
        <name>Start</name>
        <initial_marking>1</initial_marking>
      </place>
      <place id="place_end">
        <name>End</name>
        <initial_marking>0</initial_marking>
      </place>
      <transition id="transition_1">
        <name>Process</name>
      </transition>
      <arc id="arc_1">
        <source>place_start</source>
        <target>transition_1</target>
      </arc>
      <arc id="arc_2">
        <source>transition_1</source>
        <target>place_end</target>
      </arc>
    </petri_net>
  </method>
</document>
```

### S3パス構築ロジック

```typescript
// MAIMLファイルの場合
const filePath = `formats/${departmentCd}/${folderName}/${sanitizedFileName}.maiml`;

// 例:
// formats/dept_001/chemistry/synthesis_workflow.maiml
// formats/dept_002/biology/cell_culture.maiml
```

### バリデーションルール（XMLと同じ）

**ファイル名:**
- 必須
- 1文字以上、100文字以内
- 英数字、アンダースコア、ハイフンのみ許可（サニタイゼーション後）
- 拡張子は含めない

**概要:**
- オプション
- 0-500文字

## 7. XMLファイル実装との違い

### 共通部分
- 同じAPIエンドポイント（`POST /api/v1/formats/:folderName/files`）
- 同じバリデーションルール
- 同じセキュリティチェック
- 同じファイル一覧更新フロー

### MAIML固有の部分
1. **保存先パス**
   - XML: `formats/{dept_cd}/{templateType}/{fileName}.xml`
   - MAIML: `formats/{dept_cd}/{folderName}/{fileName}.maiml`

2. **テンプレートタイプ**
   - XML: material/condition/result（必須）
   - MAIML: なし（templateType不要）

3. **デフォルトコンテンツ**
   - XML: テンプレートタイプごとに異なる構造
   - MAIML: PetriNet構造（Place, Transition, Arc）

4. **ファイル拡張子**
   - XML: `.xml`
   - MAIML: `.maiml`

## 13. 振り返り

### うまくいった点
- MAIMLコンテンツ生成関数を独立したユーティリティ関数として実装できた

### 改善が必要な点
- 初回実装時に重複チェックのエラーハンドリングを見落としていた
- try-catchブロックの使い方に注意が必要（エラーを握りつぶさない）

### 学んだこと
- エラーハンドリングの実装では、catch句でエラーを握りつぶさないように注意する
- フロントエンドでは、エラーメッセージをForm.ItemのvalidationStatusで表示することで、ユーザーにとって分かりやすいUIになる
- Ant DesignのForm.setFields()メソッドを使用すると、特定のフィールドにエラーを動的に設定できる
