## 1. タスク概要

backend/src/controllers/authController.ts で実施している入力値バリデーションをフロントエンド側で処理するように変更します。これにより、ユーザーエクスペリエンスが向上し、不要なサーバーリクエストを削減できます。

## 2. 目的と期待される成果

### 目的

- サーバー負荷の軽減（不正なリクエストの削減）
- フロントエンド・バックエンドの責任分離の明確化

### 期待される成果
- [ ] フロントエンドで全入力値バリデーションを実施

- [ ] ユーザーフレンドリーなエラーメッセージ表示
- [ ] バリデーションロジックの一元管理

## 5. 技術的詳細

### フロントエンドバリデーション仕様

```typescript
// validation.ts の仕様

export interface ValidationResult {
  isValid: boolean;
  error?: string;
}

// ユーザー名バリデーション
// - 必須
// - 最大100文字
export function validateUsername(username: string): ValidationResult

// パスワードバリデーション
// - 必須
// - 最小8文字
export function validatePassword(password: string): ValidationResult

// PINコードバリデーション
// - 必須
// - 6桁の数字
export function validatePinCode(pinCode: string): ValidationResult

// 新パスワードバリデーション
// - 必須
// - 最小8文字
export function validateNewPassword(password: string): ValidationResult
```

### バックエンドバリデーション（簡素化後）

```typescript
// 残すバリデーション:
// 1. 必須パラメータチェック（セキュリティ上重要）
// 2. 型チェック（string, numberなど）
// 3. 基本的な形式チェック（極端に長い値など、DoS攻撃対策）

// 削除するバリデーション:
// 1. 詳細な長さチェック（最小8文字、最大100文字など）
// 2. 詳細な形式チェック（6桁数字など）
// 3. ユーザーフレンドリーなエラーメッセージ
```

### セキュリティ考慮事項
- [ ] バックエンドで最小限のチェックは維持（フロントエンドバイパス対策）
- [ ] DoS攻撃対策として極端に長い入力は拒否
- [ ] SQLインジェクション対策は引き続き実施（Parameterized Queries）

## 6. リスクと対策

| リスク | 影響度 | 発生確率 | 対策 |
|--------|--------|----------|------|
| フロントエンドバリデーションがバイパスされる | 低 | 中 | バックエンドで最小限のチェックを維持 |
| エラーメッセージの不整合 | 中 | 低 | 両方のエラーメッセージを統一 |
| 既存機能の破壊 | 高 | 低 | 段階的な実装とテスト |
