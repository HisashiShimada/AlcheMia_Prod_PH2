## 背景と目的

### 現在の問題点

**maimlParserExp.ts (約1,700行):**
- xml-jsライブラリを使用（`{_text: "value"}`構造）
- 戻り値がほぼ`any`型で型安全性なし
- TypeScript型定義が活用されていない
- 複雑な再帰処理で保守が困難

**作成した型定義:**
- `frontend/src/types/maiml-schema.ts`: XSDから自動生成された正確な型定義
- `backend/src/utils/maimlTypeConverter.ts`: xml2js出力を型定義に変換するユーティリティ

### 目的

1. ✅ **型安全性の確保**: TypeScriptの型チェックを活用
2. ✅ **保守性の向上**: 型定義ベースで明確なコード
3. ✅ **IDE補完の活用**: 開発効率の向上
4. ✅ **バグの削減**: コンパイル時にエラーを検出

```typescript
/**
 * xml2js出力をMAIML型定義に変換
 */
export function convertToMaimlType<T>(xmljsObject: any): T {
  return extractTextValue(xmljsObject) as T;
}

/**
 * 配列を正規化（単一要素の場合は配列に変換）
 */
export function normalizeArray<T>(value: T | T[] | undefined): T[] {
  if (value === undefined) return [];
  return Array.isArray(value) ? value : [value];
}
```

### 新パーサーの設計

**ファイル名**: `frontend/src/utils/maimlParserTyped.ts`

```typescript
import * as xmljs from 'xml-js';
import { convertToMaimlType, normalizeArray } from '@/utils/maimlTypeConverter';
import type {
  DocumentType,
  ProtocolType,
  MethodType,
  MaimlRootType,
  // ... 必要な型をインポート
} from '@/types/maiml-schema';

/**
 * 型安全なMAIMLパーサー
 */
export class MaiMLParserTyped {
  private maimlRoot: MaimlRootType;
  
  constructor(maimlData: string) {
    const parsed = xmljs.xml2js(maimlData, { compact: true });
    this.maimlRoot = convertToMaimlType<MaimlRootType>(parsed.maiml);
  }
  
  /**
   * プロトコル情報を取得（型安全）
   */
  getProtocol(): ProtocolType | undefined {
    return this.maimlRoot.protocol;
  }
  
  /**
   * メソッド一覧を取得（型安全）
   */
  getMethods(): MethodType[] {
    const protocol = this.maimlRoot.protocol;
    if (!protocol || !protocol.method) return [];
    return normalizeArray(protocol.method);
  }
  
  /**
   * トランジション一覧を取得（型安全）
   */
  getTransitions(): TransitionInfo[] {
    const methods = this.getMethods();
    const transitions: TransitionInfo[] = [];
    
    methods.forEach((method, methodIndex) => {
      const pnml = normalizeArray(method.pnml)[0];
      if (!pnml) return;
      
      const transitionElements = normalizeArray(pnml.transition);
      transitionElements.forEach(transition => {
        if (transition.id) {
          transitions.push({
            id: transition.id,
            methodId: method.id,
            methodIndex: methodIndex,
            name: transition.name || transition.id,
            // 型安全にアクセス可能✅
          });
        }
      });
    });
    
    return transitions;
  }
  
  // 他のメソッドも同様に型安全に実装
}
```

## リスクと対策

### Risk 1: 型変換の不完全性

**リスク**: xml-js出力に型定義にない構造が含まれる可能性

**対策**:
- ✅ 包括的なテストケース作成
- ✅ 実際のMAIMLファイルでの検証
- ✅ エラーハンドリングの強化

### Risk 2: パフォーマンスの低下

**リスク**: 型変換処理がボトルネックになる可能性

**対策**:
- ✅ 変換処理は軽量（再帰的な_text抽出のみ）
- ✅ 必要に応じてメモ化を実装
- ✅ パフォーマンステストを実施

### Risk 3: 既存機能の破壊

**リスク**: 移行時に既存機能が動作しなくなる可能性

**対策**:
- ✅ 段階的移行（一度に全て変更しない）
- ✅ 各ステップで動作確認
- ✅ リグレッションテスト実施
- ✅ ロールバック計画の準備

### Risk 4: 複雑な再帰処理の移行

**リスク**: parsePropertiesFaithfulなどの複雑な再帰処理の移行が困難

**対策**:
- ✅ 型定義を活用した明確な再帰処理
- ✅ ジェネリック型で型安全性を確保
- ✅ 小さな単位でテスト
- ✅ 必要に応じて既存ロジックを参照

### Risk 5: DOMParser実装の互換性

**リスク**: DOMParser版の実装（getTemplatesFromDOM）が複雑

**対策**:
- ✅ 最初はxml-js版の移行に集中
- ✅ DOMParser版は後回し（または削除を検討）
- ✅ 型定義ベースなら空要素問題も解決可能
