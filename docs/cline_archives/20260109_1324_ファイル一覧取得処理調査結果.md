## 📊 結論

**ファイル一覧の情報はS3に直接アクセスして取得しています。**

- DBのメタデータテーブル（`file_metadata`）は**ファイル一覧取得には使用されていません**
- S3の`ListObjectsV2Command`でファイル一覧を直接取得
- DBは補助情報（チェックアウト状態、組織設定）の取得にのみ使用

```javascript
const fetchFiles = useCallback(async () => {
  // organizationID取得
  let currentOrgId = localStorage.getItem('currentOrganizationId');
  
  // APIエンドポイント呼び出し
  const response = await fetch(
    `/api/s3/files?organizationId=${currentOrgId}`, 
    {
      method: 'GET',
      credentials: 'include',
      headers: {
        'Accept': 'application/json',
        'Content-Type': 'application/json',
        'X-Organization-ID': currentOrgId
      }
    }
  );

  const data = await response.json();
  
  if (data.success && Array.isArray(data.files)) {
    setAllFiles(data.files);
    setHierarchicalData(data.hierarchicalData);
  }
}, []);
```

**APIエンドポイント:** `GET /api/s3/files`

**役割:**
- バックエンドのファイル一覧APIを呼び出し
- 取得したデータをstateに保存

### 2. バックエンド層

#### 📄 routes/s3/listingRoutes.js
**場所:** `reference/backend/routes/s3/listingRoutes.js`

```javascript
router.get('/files', async (req, res) => {
  try {
    const { organizationId } = req.query;
    const targetOrgId = organizationId || req.tenantContext.allowedOrgIds[0];
    
    // ============================================
    // ステップ1: DBから組織のS3プレフィックスを取得
    // ============================================
    const orgPrefix = await getOrganizationS3Prefix(targetOrgId);
    // 例: "organizations/org_maiml_lab_001/"
    
    // ============================================
    // ステップ2: S3からファイル一覧を取得
    // ============================================
    const command = new ListObjectsV2Command({
      Bucket: S3_BUCKET_NAME,
      Prefix: orgPrefix,  // ← 組織別フィルタリング
      MaxKeys: 1000
    });

    const s3Response = await s3Client.send(command);
    const rawFiles = s3Response.Contents || [];
    
    // ============================================
    // ステップ3: S3レスポンスを処理
    // ============================================
    const processedFiles = rawFiles
      .filter(file => {
        // .folder_placeholderファイルを除外
        const isPlaceholder = file.Key.endsWith('.folder_placeholder');
        if (isPlaceholder) return false;
        
        // orgPrefix配下でない場合は除外
        if (!file.Key.startsWith(orgPrefix)) return false;
        
        return true;
      })
      .map(file => ({
        key: file.Key,              // S3キー（絶対パス）
        name: path.basename(file.Key),
        size: file.Size,            // S3メタデータ
        lastModified: file.LastModified,  // S3メタデータ
        isFolder: file.Key.endsWith('/') && file.Size === 0,
        organizationId: targetOrgId
      }));

    // ============================================
    // ステップ4: DBからチェックアウト状態のみ取得
    // ============================================
    const fileKeys = processedFiles.map(f => f.key);
    
    if (fileKeys.length > 0) {
      const checkoutQuery = `
        SELECT 
          file_key,
          manager_id,
          is_active,
          status,
          checkout_time,
          work_id,
          assigned_worker_id
        FROM file_checkout_status
        WHERE file_key = ANY($1)
          AND organization_id = $2
          AND is_active = true
          AND status = 'active'
      `;
      
      const checkoutResult = await pool.query(checkoutQuery, [fileKeys, targetOrgId]);
      
      // チェックアウト状態をファイル情報にマージ
      processedFiles.forEach(file => {
        const checkoutInfo = checkoutResult.rows.find(row => row.file_key === file.key);
        if (checkoutInfo) {
          file.isCheckedOut = true;
          file.checkedOutBy = checkoutInfo.manager_id;
          file.checkoutTime = checkoutInfo.checkout_time;
          // ...
        }
      });
    }

    // レスポンス返却
    res.json({
      success: true,
      files: processedFiles,
      hierarchicalData: [],
      totalCount: processedFiles.length,
      organizationId: targetOrgId
    });

  } catch (error) {
    res.status(500).json({
      success: false,
      error: 'ファイル一覧の取得に失敗しました'
    });
  }
});
```

**役割:**
1. DBから組織のS3パス設定を取得
2. S3からファイル一覧を取得（`ListObjectsV2Command`）
3. DBからチェックアウト状態のみ取得
4. データをマージしてレスポンス

```javascript
/**
 * 組織のS3ルートパスを取得（DBから）
 */
async function getOrganizationS3RootPath(organizationId) {
  const pool = getPool();
  
  const result = await pool.query(
    'SELECT s3_root_prefix, org_name FROM organizations WHERE organization_id = $1',
    [organizationId]
  );

  if (result.rows.length === 0) {
    throw new Error(`Organization not found: ${organizationId}`);
  }

  const s3RootPrefix = result.rows[0].s3_root_prefix;
  // 例: "organizations/org_maiml_lab_001"
  
  return s3RootPrefix;
}

/**
 * 組織のS3プレフィックスを取得（ListObjects用）
 * 末尾にスラッシュを付けて返す
 */
async function getOrganizationS3Prefix(organizationId, useCache = true) {
  const rootPath = await getOrganizationS3RootPathCached(organizationId);
  return `${rootPath}/`;
  // 例: "organizations/org_maiml_lab_001/"
}
```

## 🔍 重要な発見

### 1. file_metadataテーブルは使用されていない

```sql
-- このようなクエリは実行されていない
SELECT * FROM file_metadata WHERE organization_id = $1;
```

- ファイル一覧取得時に`file_metadata`テーブルへのSELECTクエリが存在しない
- S3の`LastModified`、`Size`などのメタデータを直接使用
- DBにファイルメタデータを保存していても、参照されていない

### 2. S3がシングルソースオブトゥルース（Single Source of Truth）

- ファイルの存在確認や一覧はすべてS3から取得
- DBは補助情報のみ保存
  - チェックアウト状態（`file_checkout_status`）
  - 組織設定（`organizations.s3_root_prefix`）

### 3. 階層データ（フォルダ構造）の構築方法

S3のオブジェクトキーから動的に階層を構築：

```javascript
// 実体フォルダオブジェクトの判定
const isFolder = file.Key.endsWith('/') && file.Size === 0;

// 例:
// "organizations/org_maiml_lab_001/projects/proj-001/" 
// ↑ 0バイトで'/'で終わる = フォルダオブジェクト
```

- 0バイトのフォルダオブジェクト（Key末尾が`/`）を検出
- `.folder_placeholder`ファイルは除外
- パス文字列をパースして階層構造を生成

### 4. キャッシュ機構

```javascript
// backend/routes/s3/s3Config.js
const CACHE_DURATION_MINUTES = 5;  // 5分間キャッシュ

const cache = cacheManager.get();
if (cache.data && cacheManager.isValid()) {
  // キャッシュを返す
  return res.json({
    files: cache.data,
    hierarchicalData: cache.hierarchicalData,
    cached: true,
    cacheAge: Math.round(cacheAge * 100) / 100
  });
}
```

- S3 API呼び出しを削減するため5分間キャッシュ
- キャッシュ使用時もチェックアウト状態は最新データを取得

## 🎯 パフォーマンス特性

### メリット

✅ **データの整合性**
- S3の最新状態を常に反映
- DBとS3の同期問題が発生しない

✅ **シンプルなアーキテクチャ**
- データソースが明確（S3がメイン）
- 複雑な同期ロジックが不要

✅ **スケーラビリティ**
- S3の高可用性・高耐久性を活用
- DBの負荷を軽減

### デメリット

❌ **API呼び出しコスト**
- S3 APIの呼び出し毎に課金
- リクエスト数に応じたコスト

❌ **レスポンス時間**
- 大量ファイル時（1000件以上）のレスポンス遅延
- ネットワークレイテンシの影響

❌ **検索・フィルタリング性能**
- S3はクエリ機能が弱い
- 複雑な条件でのフィルタリングが困難

### 緩和策

**キャッシュ機構:**
- 5分間のインメモリキャッシュ
- 同一組織の連続リクエストを高速化

**プレフィックスフィルタリング:**
- 組織別にS3パスを分離
- 不要なオブジェクトの取得を回避

**MaxKeys制限:**
- 1回のリクエストで最大1000件まで
- ページングは未実装（今後の課題）

## 🔧 実装上の注意点

### 1. file_metadataテーブルの役割

現状、`file_metadata`テーブルは以下の用途**のみ**で使用されている可能性があります：

- ファイルアップロード時のメタデータ記録
- 監査ログ（誰がいつアップロードしたか）
- ファイル検索機能（別のエンドポイントで使用？）

**ファイル一覧取得では参照されていません。**

### 2. 組織別フィルタリングの重要性

```javascript
const orgPrefix = await getOrganizationS3Prefix(targetOrgId);
// 例: "organizations/org_maiml_lab_001/"

// この組織のファイルのみ取得
const command = new ListObjectsV2Command({
  Bucket: S3_BUCKET_NAME,
  Prefix: orgPrefix  // ← これが重要
});
```

- マルチテナント分離はS3のプレフィックス（パス）で実現
- DBの`organizations.s3_root_prefix`で組織ごとのパスを管理
- セキュリティ上、プレフィックス外のファイルは絶対に返さない

### 3. チェックアウト状態の取得

```javascript
// ファイル一覧取得後、チェックアウト状態のみDBから取得
const checkoutQuery = `
  SELECT file_key, manager_id, is_active, status
  FROM file_checkout_status
  WHERE file_key = ANY($1)  -- ファイルキーの配列
    AND organization_id = $2
    AND is_active = true
`;
```

- S3から取得したファイルキーのリストを元にDB検索
- `file_checkout_status`テーブルのみ参照
- N+1問題を回避するため配列でまとめて取得

## 📝 今後の検討事項

### 1. file_metadataテーブルの活用

現状使われていないため、以下の用途を検討：

- **高速検索機能**: S3よりDBの方が検索が速い
- **メタデータ拡張**: S3にない情報（タグ、カテゴリ等）
- **統計情報**: ファイル数、容量集計
- **監査ログ**: アップロード/ダウンロード履歴

### 2. ページング実装

```javascript
// 現状: 最大1000件まで
MaxKeys: 1000

// 検討: ContinuationTokenでページング
if (s3Response.IsTruncated) {
  continuationToken = s3Response.NextContinuationToken;
}
```

大量ファイル対応のため、ページング実装を検討。

### 3. 全文検索

S3には全文検索機能がないため、以下を検討：

- **Option A**: `file_metadata`テーブルに全文検索インデックス
- **Option B**: Elasticsearch/OpenSearchの導入
- **Option C**: S3 Select（限定的な検索）

### 4. キャッシュ戦略

```javascript
// 現状: インメモリキャッシュ（5分間）
// 検討: Redis等の分散キャッシュ
```

複数サーバー構成時のキャッシュ共有を検討。
