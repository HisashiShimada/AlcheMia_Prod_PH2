## 1. タスク概要

ログイン時にセッション情報（departmentCdのみ）をRedisまたはメモリに登録し、API実行時のauthMiddlewareでアクセストークン認証後、セッション情報を取得してreq.sessionにセットする機能を実装します。

**重要な特徴:**
- **USE_REDIS環境変数で明示的に切り替え**（true: Redis, false: メモリ）
- **非同期処理を避けた同期的な設計**
- **セッションで管理するのはdepartmentCdのみ**（シンプルな設計）
- **後から拡張可能な型定義**

## 5. 技術的詳細

### セッションデータ構造
```typescript
interface SessionData {
  departmentCd: string; // 部門コード（現状これのみ）
  [key: string]: any; // 将来の拡張用
}
```

**補足:**
- 現状はdepartmentCdのみを管理
- userId, organizationId等はJWTから取得（既存機能）
- 必要に応じて後からプロパティを追加可能

### ストレージキー
```
session:{sessionId}
```

### Redis vs メモリストア切り替え
```typescript
// 環境変数で決定（起動時に一度だけ）
const USE_REDIS = process.env.USE_REDIS === 'true';

if (USE_REDIS) {
  console.log('✅ Using Redis for session storage');
} else {
  console.log('⚠️ Using Memory storage for session storage');
}
```

### 同期処理の実現
- Redisは内部で非同期だが、ラッパーメソッドで同期的なインターフェースを提供
- メモリストアは完全同期
- エラー時は例外をスロー（try-catchで処理）
