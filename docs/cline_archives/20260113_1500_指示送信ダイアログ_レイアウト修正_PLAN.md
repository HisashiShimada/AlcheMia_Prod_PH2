## 1. タスク概要

指示送信ダイアログ（InstructionDialog）のレイアウトを修正し、実験条件と試行回数を作業ごとに個別設定できるようにします。

### 現状の問題点
- 実験条件（全て同一条件/実験ごとに条件変更）が全体で1つしか設定できない
- 試行回数が全体で1つしか設定できない
- これらの設定が「タスク詳細カード」の下部に配置されている

### 変更後
- 各作業順序（メソッド）ごとに実験条件と試行回数を個別に設定可能
- レイアウトは作業順序の右側に配置

## 5. 技術的詳細

### データ構造の変更

**code_master.csvのexperiment_condition定義:**
- code_value: 0 → "全て同一条件で実行"
- code_value: 1 → "実験ごとに条件を変更"

**変更前:**
```typescript
interface TaskDetail {
  id: number;
  methodId: string;
}

const [experimentCondition, setExperimentCondition] = useState<'same' | 'different'>('same');
const [trialCount, setTrialCount] = useState<number | ''>('');
```

**変更後:**
```typescript
interface TaskDetail {
  id: number;
  methodId: string;
  experimentCondition: 0 | 1;  // 0: 全て同一条件, 1: 実験ごとに条件変更
  trialCount: number | '';
}
```

### UIレイアウトの変更

**変更前:**
```
[ドラッグハンドル] [作業順序 1] [メソッド名]

（タスク詳細カードの下部）
条件指定: [全て同一条件 / 実験ごとに条件変更]
試行回数: [入力欄]
```

**変更後:**
```
[ドラッグハンドル] [作業順序 1] [メソッド名] | [条件指定] [試行回数]
```

### バリデーションの変更

**変更前:**
```typescript
// 全体の試行回数をチェック
if (trialCount !== '' && (trialCount < 1 || trialCount > 999)) {
  message.warning('試行回数は1〜999の範囲で入力してください');
  return;
}
```

**変更後:**
```typescript
// 各タスクの試行回数をチェック
const invalidTrialCount = taskDetails.find(
  (task) => task.trialCount !== '' && (task.trialCount < 1 || task.trialCount > 999)
);
if (invalidTrialCount) {
  message.warning('試行回数は1〜999の範囲で入力してください');
  return;
}
```

### 計画からの変更点

### 発生した問題と解決方法
**問題1**: experimentConditionの型がcode_masterと不一致
- **解決**: code_masterの定義（0: 全て同一条件, 1: 実験ごとに条件変更）に準拠

**問題2**: 特定タスク選択時にタスク番号の選択肢が正しく計算されない
- **解決**: totalTrialCountをuseMemoで計算し、全タスクの試行回数合計をベースにタスク番号を生成

## 12. 振り返り

### うまくいった点
- データ構造の変更とUIレイアウトの変更を段階的に実施できた
- code_masterとの整合性を事前に確認したことで、データ型の一貫性を確保できた
- useMemoを使ってtotalTrialCountを計算することで、パフォーマンスを最適化できた
- ドラッグ&ドロップ機能を維持したまま、レイアウトを拡張できた

### 改善が必要な点
- 試行回数の入力時、各タスクの値をnumber型とstring型（''）で扱う必要があったため、型変換が少し複雑になった
- 今後API実装時に、experimentConditionとtrialCountをどのように送信するかを明確にする必要がある

### 学んだこと
- Ant DesignのSelectコンポーネントでvalue属性に数値型（0, 1）を使用する場合、onChange時に文字列として受け取る必要がある
- dnd-kitを使ったドラッグ&ドロップでは、各行の構造を柔軟に変更できる
- useMemoを使った派生状態の計算により、パフォーマンスと可読性を両立できる
