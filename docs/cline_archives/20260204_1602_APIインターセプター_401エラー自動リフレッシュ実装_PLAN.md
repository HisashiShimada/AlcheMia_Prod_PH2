## 1. タスク概要

フロントエンドの各APIサービスにおいて、401エラー発生時に自動的にリフレッシュトークンを使用してアクセストークンを更新し、元のリクエストをリトライする機能を実装します。

### 現状の問題点

- ✅ `authService.refreshAccessToken()`関数は実装済み
- ✅ バックエンドのリフレッシュトークン機能は完全実装済み
- ❌ 各APIサービスのレスポンスインターセプターで401エラー時に`refreshAccessToken()`を呼び出していない
- ❌ トークン更新後の自動リトライ処理が未実装
- ❌ セッション切れ時にログイン画面へ自動リダイレクトされない

### 目指す状態

```
ユーザーがAPIを呼び出す
  ↓
バックエンドが401エラーを返す（アクセストークン期限切れ）
  ↓
フロントエンドが自動的にトークン更新を試みる
  ↓
成功 → 元のリクエストを自動リトライ
失敗 → ログイン画面へ自動リダイレクト（authService内で実装済み）
```

### 5.1. 共通インターセプター関数の実装

**ファイル**: `frontend/src/utils/apiInterceptor.ts`

**重要な発見:**
- authUtils.tsの`createApiClient()`は既に6つのファイルで使用されていることが判明しました
- **authUtils.tsを修正するだけで、6ファイルが自動的に401エラー自動リフレッシュに対応します**

```typescript
/**
 * APIインターセプター共通ユーティリティ
 * 401エラー時の自動トークン更新とリトライ処理
 */

import { AxiosError, AxiosInstance, InternalAxiosRequestConfig } from 'axios';
import { authService } from '@/services/authService';

// トークン更新状態の管理
let isRefreshing = false;
let failedQueue: Array<{
  resolve: (value: any) => void;
  reject: (error: any) => void;
}> = [];

/**
 * 待機中のリクエストキューを処理
 * @param error エラー（nullの場合は成功）
 * @param token 新しいアクセストークン
 */
function processQueue(error: any, token: string | null = null): void {
  failedQueue.forEach(promise => {
    if (error) {
      promise.reject(error);
    } else {
      promise.resolve(token);
    }
  });
  failedQueue = [];
}

/**
 * 401エラー処理用レスポンスインターセプターを作成
 * @param client Axiosクライアントインスタンス
 */
export function setupAutoRefreshInterceptor(client: AxiosInstance): void {
  client.interceptors.response.use(
    (response) => response,
    async (error: AxiosError) => {
      const originalRequest = error.config as InternalAxiosRequestConfig & { _retry?: boolean };

      // 401エラーでリトライ未実施の場合のみ処理
      if (error.response?.status === 401 && originalRequest && !originalRequest._retry) {
        
        // トークン更新中の場合、キューに追加して待機
        if (isRefreshing) {
          return new Promise((resolve, reject) => {
            failedQueue.push({ resolve, reject });
          })
            .then(token => {
              if (originalRequest.headers) {
                originalRequest.headers.Authorization = `Bearer ${token}`;
              }
              return client(originalRequest);
            })
            .catch(err => Promise.reject(err));
        }

        // リトライフラグを設定
        originalRequest._retry = true;
        isRefreshing = true;

        try {
          console.log('[apiInterceptor] 401エラー検出: トークン更新を試みます');
          
          // トークン更新を試みる
          const newAccessToken = await authService.refreshAccessToken();

          if (newAccessToken) {
            console.log('[apiInterceptor] トークン更新成功: リクエストをリトライします');
            
            // 待機中のリクエストを処理
            processQueue(null, newAccessToken);

            // 元のリクエストをリトライ
            if (originalRequest.headers) {
              originalRequest.headers.Authorization = `Bearer ${newAccessToken}`;
            }
            return client(originalRequest);
          } else {
            // トークン更新失敗（authService内でログイン画面へリダイレクト済み）
            console.error('[apiInterceptor] トークン更新失敗: ログイン画面へリダイレクトされます');
            processQueue(new Error('トークン更新失敗'), null);
            return Promise.reject(error);
          }
        } catch (refreshError) {
          console.error('[apiInterceptor] トークン更新エラー:', refreshError);
          processQueue(refreshError, null);
          return Promise.reject(refreshError);
        } finally {
          isRefreshing = false;
        }
      }

      // 401以外のエラーはそのまま返す
      return Promise.reject(error);
    }
  );
}
```

### 5.3. 動作フロー

```
1. ユーザーがAPI呼び出し（例: GET /api/v1/projects）
   ↓
2. アクセストークン期限切れで401エラー
   ↓
3. setupAutoRefreshInterceptorが401をキャッチ
   ↓
4. isRefreshing = true に設定
   ↓
5. authService.refreshAccessToken()を呼び出し
   ├─ 成功 → 新しいアクセストークンを取得
   │         ↓
   │         元のリクエストをリトライ（成功）
   │         ↓
   │         ユーザーには何も起こらない（シームレス）
   │
   └─ 失敗 → authService内でログイン画面へリダイレクト
             ↓
             ユーザーは再ログインが必要
```

### 5.4. 複数リクエストの同時処理

```
リクエスト1（401エラー）
  ↓
トークン更新開始（isRefreshing = true）

リクエスト2（401エラー） → キューに追加
リクエスト3（401エラー） → キューに追加
  ↓
トークン更新完了
  ↓
キューの全リクエストを順次リトライ
```

## 6. リスクと対策

| リスク | 影響度 | 発生確率 | 対策 |
|--------|--------|----------|------|
| トークン更新の無限ループ | 高 | 低 | `_retry`フラグで1回のみリトライ |
| 複数リクエストでのトークン更新重複 | 中 | 中 | `isRefreshing`フラグで排他制御 |
| リフレッシュトークンも期限切れ | 中 | 中 | authService内で自動ログアウト実装済み |
| ネットワークエラーとの混同 | 低 | 低 | 401エラーのみを対象にする |

### 発生した問題と解決方法

**問題1: ESLintエラー（any型の使用）**
```
Unexpected any. Specify a different type.
```

**解決方法:**
- `any`型を具体的な型に変更
- `resolve: (value: string | null) => void`
- `reject: (error: Error) => void`
- `error: Error | null`

**問題2: TypeScriptエラー（型の不一致）**
```
型 'unknown' の引数を型 'Error | null' のパラメーターに割り当てることはできません。
```

**解決方法:**
```typescript
const errorObj = refreshError instanceof Error 
  ? refreshError 
  : new Error('トークン更新中に不明なエラーが発生しました');
processQueue(errorObj, null);
```
