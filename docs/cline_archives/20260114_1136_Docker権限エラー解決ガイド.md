# Docker権限エラー解決ガイド

**エラー日時:** 2026-01-14 11:35
**エラーメッセージ:** `PermissionError(13, 'Permission denied')`

## 概要

`docker-compose up -d` 実行時に発生する権限エラーの診断と解決方法を説明します。

---

## エラー原因の診断

このエラーは以下のいずれかが原因です：

1. ✅ **Dockerデーモンが起動していない**
2. ✅ **ユーザーがdockerグループに所属していない**
3. ✅ **WSL2とDocker Desktopの設定ミス**

---

## 🔍 現在の状態を確認

### Step 1: Dockerデーモンの状態確認

```bash
# WSL2 Ubuntu内で実行
sudo service docker status
```

**期待される出力:**
```
Docker is running
```

**もし "is not running" と表示された場合:**
```bash
# Dockerデーモンを起動
sudo service docker start

# 再度確認
sudo service docker status
```

---

### Step 2: dockerグループの確認

```bash
# 現在のユーザーが所属しているグループを確認
groups

# dockerグループに所属しているか確認
groups | grep docker
```

**もし "docker" が表示されない場合:**
```bash
# dockerグループに現在のユーザーを追加
sudo usermod -aG docker $USER

# グループ変更を反映するため、WSL2を再起動
exit
```

**Windows PowerShellまたはコマンドプロンプトで実行:**
```powershell
wsl --shutdown
wsl -d Ubuntu
```

**WSL2再起動後、確認:**
```bash
groups | grep docker
```

"docker" が表示されればOKです。

---

### Step 3: Dockerコマンドの動作確認

```bash
# sudoなしでDockerコマンドを実行
docker --version
docker ps

# docker composeコマンドを確認
docker compose version
```

**期待される出力:**
```
Docker version 24.x.x, build xxxxxx
CONTAINER ID   IMAGE     COMMAND   CREATED   STATUS    PORTS     NAMES

Docker Compose version v2.x.x
```

**もしエラーが出る場合:**
- Step 1, 2を再度確認
- WSL2を再起動

---

## ✅ 解決手順（まとめ）

### 手順1: Dockerデーモンを起動

```bash
sudo service docker start
sudo service docker status
```

### 手順2: dockerグループに追加

```bash
sudo usermod -aG docker $USER
exit
```

### 手順3: WSL2を再起動

**Windows PowerShellで実行:**
```powershell
wsl --shutdown
wsl -d Ubuntu
```

### 手順4: プロジェクトディレクトリに移動

**オプション1: Windowsファイルシステム（遅いが簡単）**
```bash
cd /mnt/c/Users/shuto.shimogama/Documents/mmdpf
```

**オプション2: WSL2ファイルシステム（推奨・高速）**
```bash
# プロジェクトをコピー（初回のみ）
cp -r /mnt/c/Users/shuto.shimogama/Documents/mmdpf ~/mmdpf

# 移動
cd ~/mmdpf
```

### 手順5: docker-compose 実行

```bash
# コンテナを起動
docker compose up -d postgres swift backend frontend

# 起動確認
docker compose ps

# ログ確認
docker compose logs -f backend
```

**期待される出力（docker compose ps）:**
```
NAME                IMAGE                          STATUS
mmdpf-backend       mmdpf-backend                  Up
mmdpf-frontend      mmdpf-frontend                 Up
mmdpf-postgres      postgres:16-alpine             Up (healthy)
mmdpf-swift         bouncestorage/swift-aio:latest Up
```

## 🚨 トラブルシューティング

### エラー: `Cannot connect to the Docker daemon at unix:///var/run/docker.sock`

**原因:** Dockerデーモンが起動していない

**解決策:**
```bash
sudo service docker start
sudo service docker status
```

### エラー: `permission denied while trying to connect to the Docker daemon socket`

**原因:** dockerグループに追加されていない、またはWSL2を再起動していない

**解決策:**
```bash
# dockerグループに追加
sudo usermod -aG docker $USER

# WSL2を再起動（必須）
exit
```

**Windows PowerShellで:**
```powershell
wsl --shutdown
wsl -d Ubuntu
```

### エラー: `docker: command not found`

**原因:** Dockerがインストールされていない

**解決策:**
```bash
# Dockerをインストール（詳細は別ドキュメント参照）
# docs/20260114_0816_WSL2_Ubuntu_Docker直接インストールガイド.md
```

### エラー: `docker compose: command not found`

**原因:** Docker Composeプラグインがインストールされていない

**解決策:**
```bash
# Docker Composeプラグインをインストール
sudo apt-get update
sudo apt-get install -y docker-compose-plugin

# 確認
docker compose version
```

### エラー: `port is already allocated`

**原因:** ポート3000, 3001, 5432などが既に使用されている

**解決策:**
```bash
# 既存のコンテナを停止
docker compose down

# ポート使用状況確認
sudo lsof -i :3000
sudo lsof -i :3001
sudo lsof -i :5432

# 必要に応じてプロセスを停止
sudo kill -9 <PID>
```

## 💡 推奨設定

### Docker自動起動の設定

WSL2起動時に自動的にDockerサービスを起動する設定です。

```bash
# .bashrc に追加
echo '' >> ~/.bashrc
echo '# Docker自動起動' >> ~/.bashrc
echo 'if service docker status 2>&1 | grep -q "is not running"; then' >> ~/.bashrc
echo '    sudo service docker start > /dev/null 2>&1' >> ~/.bashrc
echo 'fi' >> ~/.bashrc

# 設定を反映
source ~/.bashrc
```

**パスワードなしでDocker起動するには:**

```bash
# sudoersファイルを編集
sudo visudo

# 以下の行を最後に追加（YOUR_USERNAMEを実際のユーザー名に置き換え）
YOUR_USERNAME ALL=(ALL) NOPASSWD: /usr/sbin/service docker start

# 保存して終了（Ctrl+X → Y → Enter）
```

**確認:**
```bash
# WSL2を再起動
exit
```

**Windows PowerShellで:**
```powershell
wsl --shutdown
wsl -d Ubuntu
```

**WSL2再起動後、Dockerが自動起動されていることを確認:**
```bash
sudo service docker status
```

## まとめ

Docker権限エラーの解決手順：

1. ✅ `sudo service docker start` でDockerデーモンを起動
2. ✅ `sudo usermod -aG docker $USER` でdockerグループに追加
3. ✅ `wsl --shutdown` でWSL2を再起動
4. ✅ `docker compose up -d` でコンテナを起動
5. ✅ http://localhost:3000 でアクセス確認

**重要:** dockerグループに追加した後は、必ずWSL2を再起動してください。

これで権限エラーが解決し、開発を開始できます！
