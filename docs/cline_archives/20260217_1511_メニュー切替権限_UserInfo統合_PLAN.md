## 1. タスク概要

現在、メニュー切替ボタンの非表示制御において、JWTトークンをデコードしてPermissionsを取得していますが、既存の`userInfo` (sessionStorage) にPermissionsを追加して、そこから取得する方式に変更します。

### 現状の問題点
- 毎回JWTをデコードしている（パフォーマンスのオーバーヘッド）
- JWTデコード処理が複雑（カスタムプレフィックスの除去など）
- デコード失敗時のハンドリングが必要
- ユーザー情報とPermissionsが別管理

### 期待される改善
- パフォーマンスの向上（デコード処理の削減）
- コードの簡潔化
- ユーザー情報の一元管理

### getPermissionsFromToken() の新実装
```typescript
export function getPermissionsFromToken(): Permission[] | undefined {
  // SSR対応
  if (typeof window === 'undefined') {
    return undefined;
  }
  
  // 1. sessionStorageのuserInfoから優先的に取得
  const userInfoStr = sessionStorage.getItem('userInfo');
  if (userInfoStr) {
    try {
      const userInfo: User = JSON.parse(userInfoStr);
      if (userInfo.permissions && Array.isArray(userInfo.permissions)) {
        console.log('[jwtUtils] Permissions loaded from userInfo');
        return userInfo.permissions;
      }
    } catch (error) {
      console.warn('[jwtUtils] Failed to parse userInfo:', error);
    }
  }
  
  // 2. フォールバック: JWTデコード（後方互換性）
  console.log('[jwtUtils] Fallback to JWT decode');
  const token = sessionStorage.getItem('sessionToken');
  if (!token) {
    return undefined;
  }
  
  // 既存のJWTデコード処理
  // 仮セッショントークンの場合はundefinedを返す
  if ((token.startsWith('maiml_session-') || token.startsWith('temp_session-')) && !token.includes('.eyJ')) {
    console.warn('[jwtUtils] Temporary session token detected (no JWT). Returning undefined.');
    return undefined;
  }
  
  const payload = decodeJwt(token);
  if (!payload) {
    console.warn('[jwtUtils] Failed to decode JWT. Returning undefined.');
    return undefined;
  }
  
  return payload.permissions;
}
```

### アーキテクチャ上の考慮事項
- sessionStorageは同一タブ内でのみ有効（タブごとに独立）
- リロード時もデータは保持される
- ブラウザを閉じるとクリアされる
- JWTデコードへのフォールバックで後方互換性を確保
- `User`型のpermissionsはオプショナル（既存コードへの影響を最小化）

### セキュリティ考慮事項
- [ ] sessionStorageに保存するのは権限情報のみ（機密性は低い）
- [ ] JWTトークン自体は引き続きsessionStorageで管理
- [ ] XSS対策: sessionStorageは同一オリジンのみアクセス可能
- [ ] permissionsの改ざん防止: サーバー側で常に検証される
