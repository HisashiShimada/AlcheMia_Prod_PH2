## 3. 現状分析

### 問題点
**authService.logout()の現在の実装:**
```typescript
async logout(): Promise<LogoutResponseData> {
  try {
    const response = await apiClient.post<ApiResponse<LogoutResponseData>>(
      '/auth/logout',
      {}
    );
    
    if (response.data.success) {
      // ❌ sessionTokenのみ削除、userInfoは削除されていない
      if (typeof window !== 'undefined') {
        sessionStorage.removeItem('sessionToken');
      }
      return response.data.data;
    }
    // ...
  }
}
```

### userInfoの保存箇所
1. `frontend/src/utils/sessionStorageHelper.ts` - `setUserInfo()`関数
2. `frontend/src/app/page.tsx` - PIN検証成功時に直接保存

### sessionStorageHelperの利用可能な関数
- `clearUserInfo()` - userInfoのみ削除
- `clearOrganizationId()` - organizationIdのみ削除
- `clearAllSessionStorage()` - すべて削除

## 6. 技術的詳細

### 修正内容

**修正前:**
```typescript
if (response.data.success) {
  if (typeof window !== 'undefined') {
    sessionStorage.removeItem('sessionToken');
  }
  return response.data.data;
}
```

### 修正案の比較

#### 方法1: sessionStorage.removeItem()を直接使用（推奨）
```typescript
if (response.data.success) {
  // セッション情報を削除
  if (typeof window !== 'undefined') {
    sessionStorage.removeItem('sessionToken');
    sessionStorage.removeItem('userInfo'); // userInfo削除
  }
  // organizationIdは削除しない（再ログイン時に使用）
  return response.data.data;
}
```

**メリット:**
- ✅ 既存コードと一貫性がある（sessionTokenと同じ削除方法）
- ✅ 追加のインポート不要
- ✅ コードが直感的で分かりやすい

**デメリット:**
- ❌ sessionStorageHelperの関数が活用されない

#### 方法2: clearUserInfo()を使用
```typescript
import { clearUserInfo } from '@/utils/sessionStorageHelper'; // 追加

if (response.data.success) {
  // セッション情報を削除
  if (typeof window !== 'undefined') {
    sessionStorage.removeItem('sessionToken');
  }
  clearUserInfo(); // userInfo削除
  // organizationIdは削除しない（再ログイン時に使用）
  return response.data.data;
}
```

**メリット:**
- ✅ sessionStorageHelperで統一された管理
- ✅ 将来的な変更に強い（例: userInfoの削除時に追加処理が必要になった場合）

**デメリット:**
- ❌ 追加のインポートが必要
- ❌ sessionTokenとuserInfoで削除方法が異なる

### 選択：方法1を採用（ユーザーの提案に基づく）

シンプルで既存コードと一貫性のある**方法1**を採用します。

### 考慮事項
- `organizationId`は削除しない（再ログイン時に使用されるため）
- `clearAllSessionStorage()`は使用しない（organizationIdも消えてしまうため）
