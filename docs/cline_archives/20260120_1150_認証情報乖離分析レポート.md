# 認証情報乖離分析レポート

**作成日時**: 2026-01-20 11:50
**分析対象**: 通常ログイン vs デバッグログイン

---

## 🚨 重大な乖離を発見

### Cookie名の不一致

| 実装箇所 | Cookie名 | 設定場所 |
|---------|---------|---------|
| **通常ログイン** | `maiml_session` | `authController.verifyPin()` |
| **デバッグログイン** | `auth_token` | `debugAuthController.debugLogin()` |
| **認証ミドルウェア** | `auth_token` | `authMiddleware.ts` |

**問題**: 通常ログインで設定したCookieを認証ミドルウェアが読み取れない

---

### 3. 認証ミドルウェア（authMiddleware.ts）

#### トークン取得順序
```typescript
// 行38-54
// 1. Cookieからトークンを取得
if (req.cookies && req.cookies.auth_token) {  // ← 'auth_token'を探す
  token = req.cookies.auth_token;
}

// 2. Cookieにトークンがない場合、Authorizationヘッダーから取得
if (!token) {
  const authHeader = req.headers.authorization;
  if (authHeader && authHeader.trim() !== '') {
    token = authHeader.trim();
    if (token.toLowerCase().startsWith('bearer ')) {
      token = token.slice(7).trim();
    }
  }
}
```

**現状**: `auth_token` Cookieのみを読み取る

## 問題の影響範囲

### 現在動作するケース ✅

1. **デバッグログイン → API呼び出し**
   - デバッグログインが `auth_token` Cookieを設定
   - authMiddlewareが `auth_token` Cookieを読み取る
   - ✅ 正常に認証される

2. **通常ログイン → Authorizationヘッダー付きAPI呼び出し**
   - フロントエンドがトークンを保持
   - `Authorization: Bearer {token}` ヘッダーで送信
   - authMiddlewareがヘッダーから読み取る
   - ✅ 正常に認証される

### 現在動作しないケース ❌

1. **通常ログイン → Cookie自動送信でのAPI呼び出し**
   - 通常ログインが `maiml_session` Cookieを設定
   - authMiddlewareは `auth_token` Cookieを探す
   - ❌ `maiml_session` Cookieが無視される
   - ❌ Authorizationヘッダーもない場合、401エラー

---

## 修正方針（3つのオプション）

### オプション1: Cookie名を統一（推奨）

**方針**: すべて `maiml_session` に統一

**修正箇所**:
1. `debugAuthController.ts`: Cookie名を `auth_token` → `maiml_session` に変更
2. `authMiddleware.ts`: Cookie名を `auth_token` → `maiml_session` に変更

**メリット**:
- 設計書（認証機能設計書）と一致
- 最小限の変更で修正可能

**デメリット**:
- なし

---

### オプション2: Cookie名を auth_token に統一

**方針**: すべて `auth_token` に統一

**修正箇所**:
1. `authController.ts`: Cookie名を `maiml_session` → `auth_token` に変更（verifyPin関数）
2. `authController.ts`: Cookie削除を `maiml_session` → `auth_token` に変更（logout関数）

**メリット**:
- デバッグログインと統一

**デメリット**:
- 設計書と不一致
- 通常ログインの修正箇所が多い

---

### オプション3: 両方のCookieを読み取る

**方針**: authMiddlewareで両方のCookieに対応

**修正箇所**:
1. `authMiddleware.ts`: `maiml_session` と `auth_token` 両方を確認

```typescript
// 1. Cookieからトークンを取得（両方に対応）
if (req.cookies) {
  token = req.cookies.maiml_session || req.cookies.auth_token;
}
```

**メリット**:
- 通常ログイン・デバッグログイン両方に対応
- 既存コードの変更が最小限

**デメリット**:
- Cookie名が統一されていない状態が残る

## まとめ

### 乖離の原因
- Cookie名の不一致: `maiml_session`（通常ログイン） vs `auth_token`（デバッグログイン、認証ミドルウェア）

### 影響
- 通常ログインでCookie自動送信が動作しない
- デバッグログインは正常に動作

### 推奨修正
- オプション1: Cookie名を `maiml_session` に統一
- sameSiteを `strict` に統一
- セッション有効期限をロール別に対応
