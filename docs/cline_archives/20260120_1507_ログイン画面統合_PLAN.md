## 1. タスク概要

現在、ログイン機能が2つのページに分散しています：
- `http://localhost:3000/login` - 本番用の2段階認証フロー
- `http://localhost:3000` - デモ用ログイン画面（開発時はDebugLoginPanel付き）

これらを統合し、`/` を唯一のログイン画面として機能させます。

## 3. 現状分析

### `/login` (frontend/src/app/login/page.tsx)
**機能:**
- LoginPageContainer コンポーネント
- 2段階認証フロー実装
  - Step 1: LoginPage（ID・パスワード入力）
  - Step 2: PinCodeInputPage（PINコード入力）
- authService を使用した本番API連携
- セッショントークン管理
- エラーハンドリング

**使用コンポーネント:**
- LoginPage（@/components/LoginPage）
- PinCodeInputPage（@/components/PinCodeInputPage）
- authService

### `/` (frontend/src/app/page.tsx)
**機能:**
- 開発環境：DebugLoginPanel付きの旧LoginPage
- 本番環境：AuthContainer（2段階認証）
- ログイン後のメニュー表示（Provider, SystemAdmin, DataAdmin, ExperimentAdmin, ExperimentWorker）
- デモユーザーデータ管理
- メニュー切り替え機能

**使用コンポーネント:**
- LoginPage（デバッグパネル付き）
- AuthContainer（本番用）
- 各種メニューコンポーネント

### 統合の方針

**採用する実装:**
- `/login` の2段階認証フロー（LoginPage → PinCodeInputPage）を基本とする
- `/` のデバッグパネル機能を追加
- `/` のメニュー表示機能を維持

**理由:**
1. `/login` の実装が最新の本番用実装
2. authService を使った適切なAPI連携
3. セッショントークン管理が正しく実装されている

### 発生した問題と解決方法

**問題1: TypeScriptの型エラー**
- 原因: demoUsers の role が string 型で、UserRole 型との互換性がなかった
- 解決: `as UserRole` で型アサーションを追加

**問題2: DebugLoginPanel の onLogin の型不一致**
- 原因: DebugLoginPanel は organizationId を含まない credentials を渡す
- 解決: onLogin に渡す際に `organizationId: 'org_lab_001'` を追加
