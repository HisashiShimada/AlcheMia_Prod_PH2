## メタデータ
- **作成日時**: 2026-01-26 15:30
- **調査担当**: Cline
- **調査対象**: GET /api/v1/projects/:projectName/files

---

## 🎯 調査目的

ユーザーからの懸念事項：
> ファイル一覧取得は毎回最新のS3内部のファイルを取得する想定だが、file_metadataテーブルからデータを取得している可能性がある

この懸念が事実かどうかを確認し、必要であれば修正を提案する。

---

## 📋 調査結果サマリー

### 結論

**✅ 実装は正しい - 懸念事項は該当しない**

ファイル一覧取得APIは、**S3から直接最新のファイル一覧を取得**しており、file_metadataテーブルは使用していません。

### 3. 実装コードの確認

#### projectService.ts の getProjectFiles メソッド

```typescript
async getProjectFiles(
  organizationId: string,
  projectId: string,
  organizationPrefix: string
): Promise<ServiceResult<{...}>> {
  // ... プロジェクト存在確認（DBのみ使用）
  
  // ✅ S3から直接ファイル一覧を取得
  const storageService = getStorageService();
  
  // 現在のファイル一覧
  const currentFiles = await storageService.listFiles(
    organizationPrefix,
    `projects/${projectName}/`
  ).catch(() => []);
  
  // archive配下のファイル一覧
  const archiveFilesList = await storageService.listFiles(
    organizationPrefix,
    `projects/${projectName}/archive/`
  ).catch(() => []);
  
  // ✅ 各ファイルに動的に署名付きURLを生成
  files = await Promise.all(
    rootFiles.map(async (file: any) => {
      const signedUrl = await storageService.getSignedUrl(
        organizationPrefix,
        file.key.replace(`org_${organizationPrefix}/`, ''),
        3600
      );
      
      return {
        id: file.key,
        name: fileName,
        path: file.key,
        size: file.size,
        lastModified: file.lastModified.toISOString(),
        type: fileType,
        isArchive: false,
        version: null,
        signedUrl,  // ← 動的生成
        createdAt: file.lastModified.toISOString(),
      };
    })
  );
  
  return {
    success: true,
    data: {
      projectId,
      projectName,
      files,
      archiveFiles,
    },
  };
}
```

**確認事項:**
- ✅ `storageService.listFiles()` でS3から直接取得
- ✅ `file_metadata`テーブルへのクエリは**一切ない**
- ✅ 署名付きURLも動的に生成（有効期限: 3600秒 = 1時間）
- ✅ `.keep`ファイルは自動的に除外
- ✅ エラー時はグレースフル処理（空配列を返す）


## ✅ 結論

### 現状評価

**✅ 実装は正しい**

1. **ファイル一覧取得APIは常にS3から最新のファイルを取得している**
2. **file_metadataテーブルはファイル一覧取得に使用していない**
3. **署名付きURLも動的に生成しており、キャッシュされていない**

### file_metadataテーブルの役割

- **リロード処理専用**: S3とDBを同期するため
- **将来の拡張用**: 検索、統計、メタデータ管理など
- **ファイル一覧取得には使用しない**

### 推奨事項

**現在の実装を維持**

- 変更は不要
- S3から直接取得する現在の実装が正しい
- パフォーマンス上の問題があれば、将来的にキャッシュ機能を追加することを検討

## 📝 補足情報

### ファイル一覧取得のパフォーマンス

**現在の実装:**
- S3へのAPIコール: 2回（現在のファイル + archiveファイル）
- 署名付きURL生成: ファイル数分

**懸念点:**
- ファイル数が多い場合、署名付きURL生成に時間がかかる可能性
- S3 API呼び出しコストが発生

**対策案（将来）:**
- キャッシュ機能の追加（5分間など）
- ページネーション対応
- 並列処理の最適化

### グレースフル処理

現在の実装では、S3エラー時に空配列を返す設計：

```typescript
.catch(() => [])  // エラー時は空配列
```

**メリット:**
- S3が一時的にダウンしても、API自体はエラーにならない
- ユーザーエクスペリエンスが向上

**デメリット:**
- S3の問題を隠蔽してしまう可能性
- ログに記録されるが、ユーザーには通知されない
