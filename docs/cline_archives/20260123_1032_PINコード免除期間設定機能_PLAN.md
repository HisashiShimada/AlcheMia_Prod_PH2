## 1. タスク概要

現在、ログイン時に毎回PINコード入力が必要ですが、組織ごとに「PINコードを入力しなくてもよい期間」を設定できる機能を実装します。これにより、ユーザビリティを向上させつつ、セキュリティレベルを組織ごとに調整可能にします。

## 2. 目的と期待される成果

### 目的
- 組織のセキュリティポリシーに応じて、PINコード認証の頻度を調整可能にする
- 低リスク組織では利便性を向上（毎回PINコード不要）
- 高リスク組織では高セキュリティを維持（毎回PINコード必須）

### 期待される成果
- [x] 組織テーブルにPIN免除期間設定カラムを追加
- [x] ユーザーテーブルに最終PIN認証日時カラムを追加
- [x] ログイン時にPIN免除期間を判定するロジックを実装
- [x] PIN検証成功時に最終PIN認証日時を更新
- [x] 管理者が組織のPIN免除期間を設定できる機能（将来実装）

## 3. 現状分析

### 現在の実装
1. **pin_codesテーブル**: 
   - PINコードは5分間の一時的な有効期限
   - ログインのたびに新規生成
   
2. **organizationテーブル**:
   - PIN免除期間に関する設定フィールドなし
   
3. **organization_userテーブル**:
   - 最終PIN認証日時の記録なし
   
4. **認証フロー**:
   ```
   ログイン → パスワード検証 → PINコード生成 → メール送信 → PIN検証 → セッション確立
   ```

### 問題点
- すべての組織で一律に毎回PINコード入力が必要
- 頻繁にログインするユーザーにとって煩雑
- 組織のセキュリティポリシーに柔軟に対応できない

## 4. 実装ステップ

### Phase 1: データベーススキーマ変更

#### Step 1.1: organizationテーブルにPIN免除期間設定を追加
- [x] `pin_skip_period_days` カラムを追加（INTEGER, DEFAULT 0）
  - 0: 毎回PINコード必須（現在の動作）
  - 1以上: その日数間はPINコード不要
  - NULL: 0として扱う

```sql
ALTER TABLE organization 
ADD COLUMN pin_skip_period_days INTEGER DEFAULT 0;

COMMENT ON COLUMN organization.pin_skip_period_days IS 'PINコード免除期間(日数):0=毎回必須,1以上=その日数間は不要';
```

#### Step 1.2: organization_userテーブルに最終PIN認証日時を追加
- [x] `last_pin_verified_at` カラムを追加（TIMESTAMP, NULL許容）

```sql
ALTER TABLE organization_user 
ADD COLUMN last_pin_verified_at TIMESTAMP;

COMMENT ON COLUMN organization_user.last_pin_verified_at IS '最終PIN認証日時:PIN免除期間判定に使用';
```

### Phase 2: バックエンド実装

#### Step 2.1: PIN免除期間判定サービスの実装
- [x] `pinCodeService.ts` に `shouldSkipPin` メソッドを追加

  - 最終PIN認証日時を取得
  - 期間内であればtrue、期間外またはNULLであればfalseを返す

```typescript
/**
 * PINコードをスキップできるか判定

 * @param organizationId - 組織ID
 * @returns PINコードをスキップ可能な場合true
 */
async shouldSkipPin(
  userId: string,
  organizationId: string
): Promise<Result<boolean>>
```

#### Step 2.2: 最終PIN認証日時を更新するメソッドの実装
- [x] `pinCodeService.ts` に `updateLastVerifiedAt` メソッドを追加

```typescript
/**
 * 最終PIN認証日時を更新
 * @param userId - ユーザーID
 * @param organizationId - 組織ID
 */
async updateLastVerifiedAt(
  userId: string,
  organizationId: string
): Promise<Result<void>>
```

#### Step 2.3: ログインコントローラーの修正
- [x] `authController.ts` の `login` 関数を修正
  - パスワード検証後、`shouldSkipPin` で判定
  - スキップ可能な場合、直接JWTを生成してセッション確立
  - スキップ不可の場合、従来通りPINコード生成

```typescript
// パスワード検証成功後
const skipPinResult = await pinCodeService.shouldSkipPin(
  user.user_id,
  user.organization_id
);

if (skipPinResult.success && skipPinResult.data === true) {
  // PINコードスキップ: 直接セッション確立
  const jwtResult = await jwtService.generate({
    userId: user.user_id,
    organizationId: user.organization_id,
    role: user.role,
    sessionId: uuidv4(),
  });
  
  // JWT設定、レスポンス返却
} else {
  // PINコード生成（従来の処理）
}
```

## 7. リスクと対策

| リスク | 影響度 | 発生確率 | 対策 |
|--------|--------|----------|------|
| PIN免除期間が長すぎてセキュリティリスク | 高 | 中 | デフォルト0日、推奨値を明記（ドキュメント） |
| 最終PIN認証日時がNULLで判定エラー | 中 | 低 | NULL時はfalseを返す実装 |
| 既存ユーザーの動作変更による混乱 | 低 | 低 | デフォルト0日で既存動作を維持 |
| JWTトークンの有効期限とPIN免除期間の不整合 | 中 | 中 | JWTの有効期限はロール別に維持（既存仕様） |

## 補足: 推奨設定値

### PIN免除期間の推奨値

| セキュリティレベル | 推奨日数 | 用途 |
|------------------|---------|------|
| 最高 | 0日 | 金融機関、医療機関、機密情報を扱う組織 |
| 高 | 1日 | 企業の重要システム、研究機関 |
| 中 | 7日 | 一般企業、標準的なセキュリティ要件 |
| 低 | 30日 | 低リスクデータのみ、テスト環境 |

### デフォルト値
- **新規組織**: 0日（最も安全）
- **既存組織**: 0日（既存動作を維持）

### 注意事項
- PIN免除期間が長いほど、セキュリティリスクが高まります
- 組織のセキュリティポリシーに応じて適切な値を設定してください
- 共用端末を使用する環境では、0日を推奨します
