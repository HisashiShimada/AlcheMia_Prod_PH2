## メタデータ
- **作成日時**: 2026-02-02 17:10
- **Phase**: Phase 6計画
- **目的**: 不要な型変換の削減、パース時の型定義の直接利用

---

## 🎯 Phase 6の目的

**「MAIMLデータの型変換を最小化し、パース時の型定義を直接利用する」**

### 設計原則（ユーザー要望）

1. ✅ **基本はパース時の型定義をそのまま使う**
2. ✅ **何度も別の型に入れ直すことを防ぐ**
3. ✅ **どうしても必要な場合のみ新しい型を使う**

---

## 📊 現状分析

### 現在の型定義の状況

#### 1. XSD準拠型（maiml-unified.ts）

```typescript
// XSDから生成された正式な型
export interface MaimlRoot { ... }
export interface Protocol { ... }
export interface Method { ... }
export interface Transition { ... }
export interface Place { ... }
export interface Arc { ... }
export interface Template { ... }
```

**役割**: MAIMLファイルの正式な構造を表現
**用途**: maimlParserTyped.tsで使用

#### 2. 派生型（maimlParserTyped.ts内）

```typescript
// メソッドの戻り値型
export interface TransitionInfo {
  id: string;
  methodId: string;
  // ... XSD準拠型から抽出した情報
  displayName?: string;      // 追加フィールド
  isExperimentRelevant?: boolean;  // 追加フィールド
  hasInstruction?: boolean;  // 追加フィールド
}

export interface TemplateInfo {
  id: string;
  name?: string;
  description?: string;
  // ... XSD準拠型から抽出した情報
}
```

**役割**: 画面表示用に加工された型
**問題点**: XSD準拠型と重複している部分がある

#### 3. エディタ専用型（editorv2/types/index.ts）

```typescript
// PetriNetEditor専用の型
export interface TemplateItem {
  id: string;
  name?: string | undefined;
  description?: string;
  // ...
}

export interface Place {
  id: string;
  label?: string;
  data?: any;  // 追加フィールド
  // ...
}
```

**役割**: エディタ固有の要件に対応
**問題点**: XSD準拠型やTemplateInfoと重複

### 型変換の現状

```
MAIMLファイル（XML）
    ↓ パース（xml-js）
MaimlRoot（XSD準拠型） ← これをそのまま使いたい
    ↓ 変換1（maimlParserTyped内）
TransitionInfo, TemplateInfo（派生型）
    ↓ 変換2（petriNetExtractor）
TemplateItem, TemplateMapEntry（エディタ型）
    ↓ 使用
PetriNetEditor
```

**問題点**:
- ✅ 変換が2回発生している
- ✅ 同じ概念を表す型が3つ存在
- ✅ 型変換のコストが発生

---

## 🎯 Phase 6の目標

### 理想的な型の流れ

```
MAIMLファイル（XML）
    ↓ パース（xml-js）
MaimlRoot（XSD準拠型） ← 基本はこれをそのまま使う
    ↓ 必要最小限の拡張のみ
拡張型（型エイリアス or インターフェース継承）
    ↓ 使用
画面コンポーネント
```

### 具体的な改善方針

#### 1. XSD準拠型を直接使用

```typescript
// ❌ 現在: 新しい型を作成
interface TemplateInfo {
  id: string;
  name?: string;
  description?: string;
}

// ✅ 改善後: XSD準拠型を直接使用
import { Template } from '@/types/maiml-unified';

// 必要なら型エイリアス
type TemplateInfo = Template;

// または必要最小限の拡張のみ
interface ExtendedTemplate extends Template {
  displayName?: string;  // 表示用の追加フィールドのみ
}
```

#### 2. 型変換を最小化

```typescript
// ❌ 現在: メソッド内で型変換
getTemplates(): TemplateInfo[] {
  const templates = this.maiml.protocol.templates;
  return templates.map(t => ({
    id: t.id,
    name: t.name,
    description: t.description,
    // ... 変換処理
  }));
}

// ✅ 改善後: そのまま返す
getTemplates(): Template[] {
  return this.maiml.protocol.templates || [];
}
```

#### 3. 必要な場合のみ拡張型を使用

```typescript
// エディタ固有の要件がある場合のみ
interface EditorTemplate extends Template {
  // エディタでのみ必要な追加フィールド
  isSelected?: boolean;
  editMode?: 'view' | 'edit';
}
```

## 📋 Phase 6実装計画

### Step 1: 型使用状況の調査

**調査対象:**
- maimlParserTyped.tsの全メソッド
- petriNetExtractor.tsの型使用
- editorv2/types/index.tsの型定義
- 各コンポーネントでの型使用

**調査内容:**
1. XSD準拠型との重複がある型
2. 不要な型変換が発生している箇所
3. 型エイリアスで置き換え可能な型

### Step 2: 型定義の統合

**統合方針:**

| 現在の型 | 統合後 | 理由 |
|---------|-------|------|
| TemplateInfo | Template（XSD準拠型） | 内容が完全に重複 |
| TransitionInfo | Transition + 拡張 | 追加フィールドがあるため拡張のみ |
| TemplateItem | Template型エイリアス | エディタ専用だが内容は同じ |

**実装例:**
```typescript
// frontend/src/types/maiml-extended.ts（新規作成）
import { Template, Transition } from './maiml-unified';

// 型エイリアス（型変換不要）
export type TemplateInfo = Template;

// 必要最小限の拡張
export interface ExtendedTransition extends Transition {
  // Phase 3-4で追加した拡張フィールドのみ
  displayName?: string;
  isExperimentRelevant?: boolean;
  hasInstruction?: boolean;
}
```

### Step 3: メソッドの戻り値型を変更

**maimlParserTyped.tsの修正:**

```typescript
// ❌ 現在
getTemplates(): {
  success: boolean;
  templates: TemplateInfo[];  // 独自型
}

// ✅ 改善後
getTemplates(): {
  success: boolean;
  templates: Template[];  // XSD準拠型を直接使用
}
```

### Step 4: 型変換の削除

**petriNetExtractor.tsの修正:**

```typescript
// ❌ 現在: 型変換が発生
const templates = parser.getTemplates().templates;
const templateItems: TemplateItem[] = templates.map(t => ({
  id: t.id,
  name: t.name,
  // ... 変換処理
}));

// ✅ 改善後: そのまま使用
const templates = parser.getTemplates().templates;
// templatesはTemplate[]型なのでそのまま使用
```

### Step 5: エディタ型定義の見直し

**editorv2/types/index.tsの修正:**

```typescript
// 削除または型エイリアスに変更
import { Template, Transition, Place } from '@/types/maiml-unified';

// 基本はXSD準拠型を使用
export type TemplateItem = Template;
export type TransitionItem = Transition;

// エディタ固有の拡張が必要な場合のみ
export interface EditorPlace extends Place {
  data?: any;  // ReactFlow用の追加データ
}
```

## ⚠️ 注意事項

### 破壊的変更の可能性

Phase 6の実装により、以下の変更が発生します：

1. **メソッドの戻り値型の変更**
   - `TemplateInfo[]` → `Template[]`
   - `TransitionInfo[]` → `ExtendedTransition[]`

2. **型名の変更**
   - 既存の`TemplateInfo`を使用しているコードの修正が必要

3. **段階的な移行が必要**
   - Phase 5のように段階的に実施
   - 後方互換性の維持期間を設ける

### DO（推奨）
✅ XSD準拠型を最優先で使用
✅ 型エイリアスで柔軟性を確保
✅ 拡張が必要な場合はインターフェース継承
✅ 段階的に移行する
✅ 後方互換性を一定期間維持

### DON'T（非推奨）
❌ 同じ概念を表す型を複数作らない
❌ 不要な型変換を行わない
❌ XSD準拠型と異なる構造の独自型を作らない
❌ 一度に全てを変更しない
