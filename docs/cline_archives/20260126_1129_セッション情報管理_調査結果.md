## 🎯 調査目的

AuthContainer.tsxのstate情報に保持されているセッショントークンが、ログイン後のその他画面でアクセス可能かどうかを確認する。

---

## 📊 調査結果サマリー

### ❌ AuthContainer.tsxのstateには他画面からアクセス不可

**理由**: 
- `AuthContainer.tsx`のstateはコンポーネントローカルな状態
- Reactのstateは親コンポーネントから子コンポーネントへprops経由でのみ共有可能
- Context APIなどのグローバル状態管理が実装されていない

### ✅ ただし、SessionStorageには全画面からアクセス可能

**理由**:
- `page.tsx`がPINコード検証成功後に`sessionStorage.setItem('sessionToken', response.session.token)`でトークンを保存
- 全画面から`sessionStorage.getItem('sessionToken')`でアクセス可能

---

### 2. 実際のトークン保存場所

**ファイル**: `frontend/src/app/page.tsx`

```typescript
// PINコード検証成功時の処理（行130-149）
const handleVerifyPin = async (pinCode: string): Promise<void> => {
  setError(null);
  setLoading(true);

  try {
    // PINコード検証API呼び出し
    const response = await authService.verifyPin(pinCode, sessionToken, orgIdFromUrl);

    // ✅ SessionStorageに保存
    if (typeof window !== 'undefined') {
      sessionStorage.setItem('user', JSON.stringify(response.user));
      sessionStorage.setItem('sessionToken', response.session.token); // ← ここで保存
    }

    messageApi.success('ログインに成功しました');
  } catch (err) {
    // エラーハンドリング
  } finally {
    setLoading(false);
  }
};
```

**重要**:
- `page.tsx`が認証フローを管理し、SessionStorageにトークンを保存
- これにより全画面からアクセス可能になっている

### 3. SessionStorageからのトークン取得

**ファイル**: `frontend/src/services/authService.ts`

```typescript
// ログアウト処理（行221-265）
async logout(): Promise<LogoutResponseData> {
  try {
    // ✅ SessionStorageからセッショントークンを取得
    let sessionToken = '';
    if (typeof window !== 'undefined') {
      sessionToken = sessionStorage.getItem('sessionToken') || '';
    }

    // トークンがない場合はエラー
    if (!sessionToken) {
      throw new AuthServiceError(
        'セッショントークンが見つかりません',
        'AUTH_TOKEN_MISSING'
      );
    }

    // Authorizationヘッダーにトークンを設定してリクエスト
    const response = await apiClient.post<ApiResponse<LogoutResponseData>>(
      '/auth/logout',
      {},
      {
        headers: {
          Authorization: `Bearer ${sessionToken}`,
        },
      }
    );
    
    if (response.data.success) {
      // 成功したらSessionStorageからトークンを削除
      if (typeof window !== 'undefined') {
        sessionStorage.removeItem('sessionToken');
      }
      return response.data.data;
    }
    
    throw new AuthServiceError('ログアウトに失敗しました', 'LOGOUT_FAILED');
  } catch (error) {
    throw handleApiError(error);
  }
}
```

**確認結果**:
- ログアウト時には`sessionStorage.getItem('sessionToken')`で正常にアクセスできている
- つまり、実際には全画面からアクセス可能

## ⚠️ 問題点と設計上の課題

### 1. 状態管理の二重化

- **AuthContainer.tsx**: ローカルstateでトークンを保持（アクセス不可）
- **page.tsx**: SessionStorageにトークンを保存（アクセス可能）

**問題**:
- 同じ情報が2箇所で管理されている
- どちらが真の情報源（Single Source of Truth）なのか不明確

### 2. Context APIの不在

**現状**:
- グローバルな認証状態管理機構がない
- SessionStorageに直接アクセスする方式

**課題**:
- TypeScriptの型安全性が失われる（`sessionStorage.getItem()`は`string | null`を返す）
- テストが困難（SessionStorageをモック化する必要）
- SSR（Server-Side Rendering）との互換性が低い

### 3. 認証状態の一貫性

**リスク**:
- SessionStorageが削除されてもReactコンポーネントは気づかない
- 別タブでログアウトしても、現在のタブは認証状態のまま

## ✅ 結論

### 質問への回答

> AuthContainer.tsxのstate情報にセッショントークンが保持されているが、  
> 現状ログイン後のその他画面で上記にアクセスできるようになっているかどうか？

**回答**:

1. **AuthContainer.tsxのstateには直接アクセスできない** ❌
   - Reactのコンポーネントローカルstateであり、他画面からアクセス不可

2. **ただし、SessionStorageには全画面からアクセス可能** ✅
   - `page.tsx`がSessionStorageに保存しているため
   - `sessionStorage.getItem('sessionToken')`でどの画面からもアクセス可能

3. **実用上は問題ない** ✅
   - 現在の実装では`authService.logout()`が正常に動作している
   - すべてのAPI呼び出しでSessionStorageからトークンを取得可能

## 🔧 改善提案（オプション）

現状でも動作はしていますが、以下の改善により保守性と型安全性が向上します：

### 提案1: AuthContextの実装（推奨）

**メリット**:
- TypeScriptの型安全性が向上
- テストが容易になる
- 認証状態の一貫性が保証される

**実装例**:
```typescript
// frontend/src/contexts/AuthContext.tsx
import React, { createContext, useContext, useState, useEffect } from 'react';

interface AuthContextType {
  sessionToken: string | null;
  user: User | null;
  setAuth: (token: string, user: User) => void;
  clearAuth: () => void;
}

const AuthContext = createContext<AuthContextType | undefined>(undefined);

export const useAuth = () => {
  const context = useContext(AuthContext);
  if (!context) throw new Error('useAuth must be used within AuthProvider');
  return context;
};
```

### 提案2: SessionStorageとの同期

**実装例**:
```typescript
// SessionStorageの変更を監視
useEffect(() => {
  const handleStorageChange = () => {
    const token = sessionStorage.getItem('sessionToken');
    if (!token) {
      // 別タブでログアウトされた場合
      clearAuth();
    }
  };
  
  window.addEventListener('storage', handleStorageChange);
  return () => window.removeEventListener('storage', handleStorageChange);
}, []);
```

### 提案3: 状態管理の一本化

**方針**:
- AuthContextをSingle Source of Truthとする
- SessionStorageは永続化層として使用（初期化時のみ読み込み）
- AuthContainer.tsxのローカルstateは削除
