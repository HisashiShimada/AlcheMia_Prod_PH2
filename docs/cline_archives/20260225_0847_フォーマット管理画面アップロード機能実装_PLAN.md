## 1. タスク概要

フォーマット管理画面（FormatManagement.tsx）のアップロードダイアログ（FormatUploadDialog.tsx）に、実際のファイルアップロード機能を実装します。プロジェクト管理画面で既に実装されている`BulkUploadDialog.tsx`を参考にして、同様の機能を実装します。

## 2. 目的と期待される成果

### 目的
- フォーマット管理画面でファイルを実際にS3/Swiftにアップロードできるようにする
- 既存のプロジェクト管理画面と同様のユーザー体験を提供する
- 実装済みのファイルアップロードAPI（POST /api/v1/files/upload）を活用する

### 期待される成果
- [x] FormatUploadDialogで実際のファイルアップロードが可能になる
- [x] 単一ファイル、一括ファイル、フォルダアップロードの3モードに対応
- [x] アップロード進捗が表示される
- [x] アップロード完了後にファイル一覧が自動更新される
- [x] エラーハンドリングが適切に実装される

## 5. 技術的詳細

### 使用する技術・ライブラリ
- React: 18.2.0
- TypeScript
- Ant Design v6
- fileAccessService: uploadFiles関数
- extractErrorMessage: エラーメッセージ抽出ユーティリティ

### アーキテクチャ上の考慮事項
- **マルチテナント分離**: organization_idは自動的に付与される（バックエンド側で処理）
- **S3パス構造**: `{organizationId}/formats/{departmentCd}/{formatName}/{subPath}`
- **汎用性**: 既存のファイルアップロードAPI（POST /api/v1/files/upload）を使用
- **uploadModeの対応**:
  - `single`: 単一ファイル
  - `bulk`: 一括ファイル
  - `folder`: フォルダ（階層構造を保持）

### セキュリティ考慮事項
- [x] ファイルサイズ制限: 500MB/ファイル（バックエンド側で実施）
- [x] ファイルタイプ制限: .maiml, .xml, .json, .txt, .csv, 画像ファイル等
- [x] マルチテナント分離: バックエンドで自動的にorganization_idを付与
- [x] 権限チェック: experiment_admin以上（バックエンド側で実施）

## 6. リスクと対策

| リスク | 影響度 | 発生確率 | 対策 |
|--------|--------|----------|------|
| targetPathの構築ミスによりファイルが意図しない場所に保存される | 高 | 中 | BulkUploadDialogの実装を参考にし、十分にテストする |
| フォルダアップロード時のパス処理が不適切 | 中 | 中 | BulkUploadDialogの実装を踏襲し、webkitRelativePathを正しく処理する |
| アップロード完了後にファイル一覧が更新されない | 中 | 低 | onUploadCompleteコールバックが正しく呼ばれることを確認 |
| エラーハンドリングの不備 | 低 | 低 | BulkUploadDialogと同様のエラーハンドリングを実装 |
