## 1. タスク概要

プロジェクトファイル一覧取得APIにおいて、以下の改善を実施します：
1. **.keepファイルをバックエンド側で除外**

```typescript
const currentFiles = await storageService.listFiles(
  organizationPrefix,
  `projects/${projectName}/`
).catch(() => []);

// archive配下のファイルと.keepファイルを除外
const rootFiles = currentFiles.filter((file: any) => {
  // archive/配下のファイルは除外
  if (file.key.includes('/archive/')) {
    return false;

    return false;
  }
  
  return true;
});
```

## 5. 技術的詳細

### .keepファイルとは
- S3/Swiftで空のフォルダを保持するために配置するダミーファイル
- システム内部でのみ使用され、ユーザーには見せる必要がない

### フィルタリングの実装箇所

#### バックエンド側（推奨）
**メリット:**
- フロントエンドの処理負荷を軽減
- API仕様として統一的に管理できる
- すべてのクライアントで一貫した動作を保証

**実装:**
```typescript
// ファイル名による除外
const fileName = file.key.split('/').pop() || '';
if (fileName === '.keep') {
  return false;
}
```

#### archiveファイルの常時取得とフィルタリング

**現在の実装:**
```typescript
// include_archive=true の場合のみarchiveFilesを取得
if (includeArchive) {
  const archiveFilesList = await storageService.listFiles(...);
  archiveFiles = await Promise.all(...);
}
```

**改善後の実装:**
```typescript
// 常にarchiveファイルを取得（include_archiveパラメータ不要）

const filteredArchiveFiles = archiveFilesList.filter(file => 
  file.key.split('/').pop() !== '.keep'
);

// ファイルが存在する場合のみ署名付きURL生成
if (filteredArchiveFiles.length > 0) {
  archiveFiles = await Promise.all(...);
```

## 14. まとめ

### 主な変更点
1. **バックエンド側で.keepファイルを除外**
   - `files`配列から除外
   - `archiveFiles`配列からも除外

2. **include_archiveパラメータの削除**
   - バックエンド: 常にarchiveファイルを取得
   - API仕様: include_archiveクエリパラメータを削除

3. **フロントエンド側の表示制御**
   - archiveFilesが空配列の場合、archiveフォルダセクションを非表示
   - archiveFilesが存在する場合のみ、archiveフォルダセクションを表示

### 利点
- ✅ ユーザーは不要なファイル（.keep）を見なくて済む
- ✅ 空のarchiveフォルダがUI上で表示されない
- ✅ API仕様がシンプルになる（include_archiveパラメータ不要）
- ✅ フロントエンド側で柔軟な表示制御が可能
- ✅ バックエンドは常に一貫したレスポンスを返す
