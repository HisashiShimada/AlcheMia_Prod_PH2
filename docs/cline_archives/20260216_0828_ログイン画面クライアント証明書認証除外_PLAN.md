## 1. タスク概要

http://localhost:3000/ でログイン画面を開いたときはクライアント証明書認証を実施せず、ログイン後のAPIアクセスでのみクライアント証明書認証を行うようにNginx設定を変更します。

## 2. 目的と期待される成果

### 目的
- ユーザーがログイン画面にアクセスする際に、クライアント証明書を要求されないようにする
- ログイン後のAPIアクセス（認証が必要な操作）でのみクライアント証明書認証を実施する
- セキュリティを維持しつつ、ユーザビリティを向上させる

### 期待される成果
- [ ] ログイン画面（`/`）へのアクセス時にクライアント証明書が不要
- [ ] 認証APIエンドポイント（`/api/auth/login`、`/api/auth/verify-pin`など）でクライアント証明書が不要
- [ ] ログイン後のAPIエンドポイント（`/api/projects`など）でクライアント証明書認証が必須
- [ ] ヘルスチェックエンドポイント（`/health`）でクライアント証明書が不要（既存の動作を維持）

## 5. 技術的詳細

### Nginxのssl_verify_client設定

```nginx
ssl_verify_client off;           # クライアント証明書不要
ssl_verify_client on;            # クライアント証明書必須
ssl_verify_client optional;      # クライアント証明書オプショナル（証明書情報は利用可能）
ssl_verify_client optional_no_ca; # クライアント証明書オプショナル（CA検証なし）
```

### locationブロックの優先順位
Nginxは以下の順序でlocationをマッチング：
1. `=` (完全一致) - 最優先
2. `^~` (プレフィックスマッチ、正規表現より優先)
3. `~` または `~*` (正規表現)
4. プレフィックスマッチ（最長一致）

### 実装方針
```nginx
# グローバル設定
ssl_verify_client optional;

# 認証エンドポイント（証明書不要）
location ~ ^/api/auth/(login|verify-pin|resend-pin) {
    ssl_verify_client off;
    proxy_pass http://backend;
    # ...
}

# その他のAPIエンドポイント（証明書チェック）
location /api/ {
    # ssl_verify_clientは親から継承（optional）
    # 証明書がない場合は$ssl_client_verifyで検証
    if ($ssl_client_verify != SUCCESS) {
        return 403 "Client certificate required";
    }
    proxy_pass http://backend;
    # ...
}

# フロントエンド（証明書不要）
location / {
    ssl_verify_client off;
    proxy_pass http://frontend;
    # ...
}
```
