## 1. タスク概要

ログイン後にリフレッシュトークンを発行する機能は既に実装済みです。このタスクでは、同じユーザーが既にリフレッシュトークンを保持しており、有効期限内であれば、ログイン画面をスキップして自動的にログインする機能を追加します。

### 現状の認証フロー
1. ユーザーがログイン画面でID/パスワード入力
2. バックエンドで認証
3. PIN免除の場合は直接ログイン完了、PIN免除でない場合はPINコード入力
4. 認証完了後、アクセストークン（sessionStorage）とリフレッシュトークン（httpOnly Cookie）を発行
5. リフレッシュトークンは `/api/v1/auth/refresh` エンドポイントで更新可能（トークンローテーション実装済み）

### 追加する機能
- **初回アクセス時の自動ログイン**: ページ読み込み時に有効なリフレッシュトークンがあれば、ログイン画面をスキップして直接メニュー画面へ遷移

### アーキテクチャ上の考慮事項

#### 自動ログインの実行タイミング
- ページロード時（useEffectで実行）
- authStepが'login'の状態でのみ実行
- 既にログイン済みの場合は実行しない（無限ループ防止）

#### セキュリティ考慮事項
- リフレッシュトークンはhttpOnly Cookieで保護（既存の仕組みを継承）
- トークンローテーション（既存の仕組みを継承）
- 自動ログイン失敗時は通常のログインフローへフォールバック

#### エラーハンドリング
- リフレッシュトークンが存在しない場合: ログイン画面を表示（エラーメッセージなし）
- リフレッシュトークンが無効な場合: ログイン画面を表示（エラーメッセージなし）
- ネットワークエラー: ログイン画面を表示（エラーメッセージなし）
- ユーザーが無効化された場合: ログイン画面を表示（エラーメッセージあり）

### 実装の詳細

#### 自動ログインのフロー

```typescript
// frontend/src/app/page.tsx の useEffect 内で実行

useEffect(() => {
  // 1. 既にログイン済み、またはPINコード入力中の場合はスキップ
  if (authStep !== 'login') {
    return;
  }
  
  // 2. 初回実行フラグ（無限ループ防止）
  let hasAttempted = false;
  
  if (hasAttempted) {
    return;
  }
  
  hasAttempted = true;
  
  // 3. 自動ログイン実行
  const attemptAutoLogin = async () => {
    try {
      // リフレッシュトークンAPIを呼び出し
      const response = await authService.refreshToken();
      
      // 成功: ユーザー情報とトークンを保存
      sessionStorage.setItem('sessionToken', response.session.token);
      sessionStorage.setItem('userInfo', JSON.stringify(response.user));
      
      // メニュー画面へ自動遷移
      setCurrentUser(response.user);
      setCurrentMenuType(response.user.initialScreenFunctionCd);
      setAuthStep('authenticated');
      
      console.log('[Auto-Login] 自動ログイン成功');
    } catch (error) {
      // 失敗: 静かにログイン画面を表示（エラーメッセージなし）
      console.log('[Auto-Login] リフレッシュトークンなし/期限切れ - ログイン画面を表示');
      // エラー状態は設定しない（ユーザーに通知しない）
    }
  };
  
  attemptAutoLogin();
}, []); // 依存配列を空にして初回のみ実行
```

#### バックエンドAPIレスポンス形式（既存）

```typescript
// POST /api/v1/auth/refresh
// リクエスト: Cookie に refreshToken が自動的に含まれる
// レスポンス:
{
  success: true,
  data: {
    accessToken: string,      // 新しいアクセストークン
    expiresIn: number,        // 有効期限（秒）
    user: {                   // ユーザー情報
      id: string,
      username: string,
      email: string,
      roleCd: string,
      organizationId: string,
      organizationName: string,
      departmentCd: string,
      initialScreenFunctionCd: string
    }
  }
}
```

## 6. リスクと対策

| リスク | 影響度 | 発生確率 | 対策 |
|--------|--------|----------|------|
| 無限ループ（自動ログイン失敗→再試行の繰り返し） | 高 | 低 | useEffectの依存配列を空にして初回のみ実行、実行済みフラグを追加 |
| リフレッシュトークンが期限切れで401エラー | 中 | 中 | エラー時は静かにログイン画面を表示（エラーメッセージなし） |
| ローディング状態が長時間続く | 中 | 低 | タイムアウト処理を実装（5秒） |
| 既存のログインフローへの影響 | 低 | 低 | 既存のログインフローは変更せず、追加の自動ログインチェックのみ実装 |
| パスワード変更が必要なユーザーの対応 | 中 | 中 | refreshTokenレスポンスにpasswordChangeRequiredフラグがあれば対応 |
