## 1. タスク概要

トランジションステータス更新API（`PUT /api/v1/experiments/projects/:projectId/methods/:methodId/transitions/:transitionId/status`）のバリデーションを、バックエンド規約に準拠した実装に修正します。

### 現状の問題点

1. **リクエストボディのバリデーション不足**
   - `taskNo`（必須）のバリデーションが未実装
   - `progressRate`（オプショナル）のバリデーションが未実装

2. **バリデーション実装方針の違反**
   - `validationResult()`を使用して独自のエラーハンドリングを実装している
   - `handleValidationErrors`ミドルウェアを使用していない
   - backend.mdで定義された統一的な実装パターンに従っていない

3. **エラーレスポンス形式の不統一**
   - `code`フィールドの値が統一されていない可能性

### バリデーション仕様詳細

#### リクエストボディパラメータ

| パラメータ | 型 | 必須 | バリデーション |
|-----------|----|----|--------------|
| taskNo | integer | ○ | 1以上の整数 |
| status | string | ○ | 'initial', 'preparing', 'ready', 'running', 'paused', 'completed', 'error' のいずれか |
| progressRate | integer | × | 0-100の整数、statusが'completed'の場合は自動的に100 |
| comment | string | × | 2000文字以内 |

#### エラーレスポンス形式（統一）

```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "バリデーションエラーが発生しました",
    "details": [
      {
        "field": "taskNo",
        "message": "taskNoは1以上の整数である必要があります",
        "code": "INVALID_FORMAT"
      }
    ]
  },
  "meta": {
    "timestamp": "2026-02-06T16:30:00.000Z",
    "requestId": "req_abc123"
  }
}
```
