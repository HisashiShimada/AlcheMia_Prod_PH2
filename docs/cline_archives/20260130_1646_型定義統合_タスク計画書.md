# 型定義統合タスク計画書

**作成日時**: 2026-01-30 16:46
**目的**: index.tsとeditorTypes.tsを1つのファイルに統合し、重複型定義を削除

## 📋 タスク概要

### 現状の問題
- `frontend/src/components/editorv2/types/index.ts` と `editorTypes.ts` に重複した型定義が存在
- 名称だけ違う類似型が混在（例: Method vs MethodData、Template vs TemplateRef）
- インポート元が2つあり、型の不一致が発生

### 目標
1. index.tsとeditorTypes.tsを1つのファイル（index.ts）に統合
2. 重複した型定義を削除
3. すべての利用箇所を統一した型定義に置き換え

## 🔍 重複型の分析

### 完全に重複している型（削除対象）
1. `ValidationError` - 両方に同じ定義
2. `ValidationResult` - 両方に同じ定義
3. `Property` - 両方に同じ定義
4. `TemplateRef` - 両方に同じ定義

### 拡張型（統合が必要）
1. `NodeData`
   - index.ts: 基本定義
   - editorTypes.ts: 拡張定義（isNewTemplate, methodId等を追加）
   - **方針**: editorTypes.tsの拡張版を採用

2. `DocumentData`
   - index.ts: 複数形プロパティ（creators[], vendors[]等）
   - editorTypes.ts: 単数形プロパティ追加（creator, vendor等）
   - **方針**: 両方を含む統合版を作成

### 名称が違う類似型（統一が必要）
1. **Method関連**
   - editorTypes.ts: `Method`
   - index.ts: `MethodInfo`, `MethodData`
   - **方針**: `MethodData`に統一（index.tsの名称を採用）

2. **MethodDataRaw vs 通常のMethodData**
   - editorTypes.ts: `MethodDataRaw` - API取得直後の生データ
   - index.ts: `MethodData` - ReactFlow形式
   - **方針**: 両方を残す（用途が異なる）

3. **DraftDataSimple vs DraftData**
   - editorTypes.ts: `DraftDataSimple` - 簡易版
   - index.ts: `DraftData` - 完全版
   - **方針**: DraftData（完全版）を採用、簡易版は削除
