# 型統一システム 整理提案

## メタデータ
- **作成日時**: 2026-02-02 15:10
- **目的**: 型システムの整理方針を明確化
- **背景**: maimlParserTyped.tsで独自型を作成してしまった問題への対応

---

## 🎯 整理方針の全体像

### 基本原則
1. **型定義の一元化**: `maiml-unified.ts`のみで型定義
2. **パーサーは型変換のみ**: 独自型を作らず、XSD準拠型を返す
3. **段階的移行**: 既存コードへの影響を最小化

### 現状の問題点
```typescript

export interface TransitionInfo {
```

### 提案: 型定義の拡張方針

#### オプションB-1: XSD準拠型を直接返す（純粋型安全）
```typescript
// maiml-unified.ts（変更なし）
export interface Transition {
  id?: string;
  uuid?: string;
  name?: string;
  description?: string;
}

// パーサー実装（独自型なし）
class MaiMLParser {
  getTransitions(): Transition[] {
    // XSD準拠型をそのまま返す
    return this.typedMaiml.protocol.method[0].pnml[0].transition;
  }
}

// 使用側で必要な情報を追加計算
const transitions = parser.getTransitions();
transitions.forEach(t => {
  const arcs = parser.getArcs().filter(a => 
    a.source === t.id || a.target === t.id
  );
  const arcCount = arcs.length;
  // ...
});
```

**メリット:**
- ✅ 型定義が一元化される
- ✅ XSD仕様との完全な一致
- ✅ パーサーがシンプル

**デメリット:**
- ❌ 使用側で計算処理が必要
- ❌ コードの重複が発生する可能性

#### オプションB-2: 拡張型を別ファイルで定義
```typescript
// ===== maiml-unified.ts（XSD準拠型） =====
export interface Transition {
  id?: string;
  uuid?: string;
  name?: string;
  description?: string;
}

// ===== maiml-extended.ts（拡張型） =====
import type { Transition } from './maiml-unified';

/**
 * Transitionの拡張情報
 * パーサーが計算して付与する追加情報
 */
export interface TransitionExtended extends Transition {
  // XSD準拠型を継承
  // 以下は計算により追加される情報
  methodId: string;
  methodName?: string;
  hasInstruction: boolean;
  arcCount: number;
  arcs: Arc[];
  category: 'experiment' | 'preparation' | 'finalization' | 'other';
}

// パーサー実装
class MaiMLParser {
  // XSD準拠型を返すメソッド（基本）
  getTransitions(): Transition[] {
    return this.typedMaiml.protocol.method[0].pnml[0].transition;
  }
  
  // 拡張情報を含むメソッド（利便性）
  getTransitionsExtended(): TransitionExtended[] {
    const transitions = this.getTransitions();
    return transitions.map(t => ({
      ...t,
      methodId: '...',
      hasInstruction: this.hasInstruction(t.id),
      arcCount: this.getArcCount(t.id),
      arcs: this.getArcs(t.id),
      category: this.categorize(t)
    }));
  }
}
```

**メリット:**
- ✅ 型定義が明確に分離
- ✅ 基本メソッドと拡張メソッドを両方提供
- ✅ 使用側は拡張メソッドを使えば簡単

**デメリット:**
- ❌ ファイルが増える
- ❌ 拡張型の管理が必要

#### オプションB-3: 結果オブジェクトで返す
```typescript
// maiml-unified.ts（変更なし）
export interface Transition { ... }

// パーサー実装
interface TransitionsResult {
  transitions: Transition[];  // XSD準拠型
  metadata: {
    totalMethods: number;
    totalTransitions: number;
    // ...統計情報
  };
  helpers: {
    getArcs: (transitionId: string) => Arc[];
    hasInstruction: (transitionId: string) => boolean;
    categorize: (transition: Transition) => string;
  };
}

class MaiMLParser {
  getTransitions(): TransitionsResult {
    const transitions = this.typedMaiml.protocol.method[0].pnml[0].transition;
    
    return {
      transitions,  // ← XSD準拠型をそのまま返す
      metadata: { ... },
      helpers: {
        getArcs: (id) => this.getArcs(id),
        hasInstruction: (id) => this.hasInstruction(id),
        categorize: (t) => this.categorizeTransition(t)
      }
    };
  }
}

// 使用側
const result = parser.getTransitions();
result.transitions.forEach(t => {
  const arcs = result.helpers.getArcs(t.id);
  const category = result.helpers.categorize(t);
});
```

**メリット:**
- ✅ XSD準拠型を保持
- ✅ ヘルパー関数を提供
- ✅ 柔軟性が高い

**デメリット:**
- ❌ 使用側のコードが少し複雑
- ❌ 結果オブジェクトの設計が必要
