## 1. 問題の概要

`backend/src/services/pinCodeService.ts`の`generateAndSave`メソッドでPINコードをpin_codesテーブルに保存する処理でエラーが発生している。

## 2. 原因分析

### 2.1. データベーススキーマ (docs/design/db/ddl/pin_codes.sql)
```sql
CREATE TABLE pin_codes (
    id SERIAL NOT NULL,                    -- 自動採番
    user_id UUID NOT NULL,
    organization_id UUID NOT NULL,
    pin_code VARCHAR(6) NOT NULL,
    session_token VARCHAR(255) NOT NULL,
    is_used BOOLEAN NOT NULL DEFAULT false,  -- デフォルト値あり
    used_at TIMESTAMP,                       -- NULL許容
    expires_at TIMESTAMP NOT NULL,
    attempts_count INTEGER NOT NULL DEFAULT 0,  -- デフォルト値あり
    max_attempts INTEGER NOT NULL DEFAULT 3,    -- デフォルト値あり
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP  -- デフォルト値あり
)
```

### 2.2. サービスコードのINSERT文
```typescript
const result = await this.pool.query(
  `INSERT INTO pin_codes 
   (user_id, organization_id, pin_code, session_token, expires_at, attempts_count, max_attempts) 
   VALUES ($1, $2, $3, $4, $5, 0, $6)
   RETURNING pin_code, expires_at`,
  [userId, orgId, pinCode, sessionToken, expiresAt, this.MAX_ATTEMPTS]
);
```

### 2.3. 問題点

**❌ パラメータ化の不整合**
- `attempts_count`を`0`とハードコーディングしている
- これにより、プレースホルダーの番号がずれている可能性がある

**考えられるエラー原因:**
1. **パラメータ数の不一致** - プレースホルダー($1-$6)と配列要素数(6個)は合っているが、`0`がハードコードされている
2. **expires_atの型変換** - JavaScriptのDateオブジェクトがPostgreSQLのTIMESTAMP型に正しく変換されていない可能性
3. **外部キー制約違反** - `(user_id, organization_id)`の組み合わせが`organization_user`テーブルに存在しない

## 3. 修正方針

### 修正1: attempts_countもパラメータ化する（推奨）
```typescript
const result = await this.pool.query(
  `INSERT INTO pin_codes 
   (user_id, organization_id, pin_code, session_token, expires_at, attempts_count, max_attempts) 
   VALUES ($1, $2, $3, $4, $5, $6, $7)
   RETURNING pin_code, expires_at`,
  [userId, orgId, pinCode, sessionToken, expiresAt, 0, this.MAX_ATTEMPTS]
);
```

### 修正2: デフォルト値を利用する（シンプル）
```typescript
const result = await this.pool.query(
  `INSERT INTO pin_codes 
   (user_id, organization_id, pin_code, session_token, expires_at) 
   VALUES ($1, $2, $3, $4, $5)
   RETURNING pin_code, expires_at`,
  [userId, orgId, pinCode, sessionToken, expiresAt]
);
```

**推奨: 修正2を採用**
- `attempts_count`、`max_attempts`、`is_used`、`created_at`はすべてデフォルト値があるため、明示的に指定する必要がない
- コードがシンプルになり、メンテナンス性が向上
- デフォルト値の変更がスキーマ側で管理できる

   - パラメータ配列も6要素から5要素に削減

3. **コメントの追加**
