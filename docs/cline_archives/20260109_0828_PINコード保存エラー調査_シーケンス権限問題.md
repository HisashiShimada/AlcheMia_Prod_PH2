## メタデータ

- **タスクID**: pin_code_sequence_permission_error
- **優先度**: 高
- **エラーコード**: permission denied for sequence pin_codes_id_seq

## 1. 問題概要

### 発生したエラー
```
permission denied for sequence pin_codes_id_seq
```

### 発生箇所
- **ファイル**: `backend/src/services/pinCodeService.ts`
- **行番号**: 48行目
- **メソッド**: `generateAndSave()`
- **処理内容**: PINコードをpin_codesテーブルにINSERTする処理

```typescript
const result = await this.pool.query(
  `INSERT INTO pin_codes 
   (user_id, organization_id, pin_code, session_token, expires_at, attempts_count, max_attempts) 
   VALUES ($1, $2, $3, $4, $5, 0, $6)
   RETURNING pin_code, expires_at`,
  [userId, orgId, pinCode, sessionToken, expiresAt, this.MAX_ATTEMPTS]
);
```

## 2. 原因分析

### 根本原因
PostgreSQLでは、`SERIAL`型のカラムを持つテーブルに対してINSERT操作を行う際、自動的にシーケンス（`pin_codes_id_seq`）が使用されます。しかし、**アプリケーションの接続ユーザーがこのシーケンスに対する権限を持っていない**ため、エラーが発生しています。

### テーブル定義の確認
```sql
CREATE TABLE pin_codes (
    id SERIAL NOT NULL,  -- ← シーケンス pin_codes_id_seq が自動生成される
    user_id UUID NOT NULL,
    organization_id UUID NOT NULL,
    ...
);
```

`SERIAL`型は内部的に以下のように展開されます：
```sql
CREATE SEQUENCE pin_codes_id_seq;
CREATE TABLE pin_codes (
    id INTEGER NOT NULL DEFAULT nextval('pin_codes_id_seq'),
    ...
);
```

### 権限の問題
- **テーブルへの権限**: `GRANT ALL PRIVILEGES ON TABLE pin_codes`は付与されている可能性がある
- **シーケンスへの権限**: `GRANT USAGE, SELECT ON SEQUENCE pin_codes_id_seq`が**付与されていない**

## 3. 解決策

### 方法1: 権限付与SQLスクリプトの実行（推奨）

作成したSQLスクリプトを実行して権限を付与します。

**ファイル**: `backend/sql/grant_pin_codes_permissions.sql`

```bash
# PostgreSQLに接続してスクリプトを実行
psql -U postgres -d mmdpf_dev -f backend/sql/grant_pin_codes_permissions.sql
```

または

```bash
# psql対話モードで実行
psql -U postgres -d mmdpf_dev
\i backend/sql/grant_pin_codes_permissions.sql
```

### 方法2: 手動で権限を付与

```sql
-- アプリケーション接続ユーザー（DB_USER）に権限を付与
GRANT ALL PRIVILEGES ON TABLE pin_codes TO postgres;  -- または mmdpf_app など
GRANT USAGE, SELECT ON SEQUENCE pin_codes_id_seq TO postgres;
```

### 方法3: テーブル再作成時に権限を自動付与（将来的な対策）

`fix_pin_codes_schema.sql`を以下のように修正：

```sql
-- テーブル作成後に権限を自動付与
CREATE TABLE pin_codes (...);

-- 権限付与
GRANT ALL PRIVILEGES ON TABLE pin_codes TO postgres;
GRANT USAGE, SELECT ON SEQUENCE pin_codes_id_seq TO postgres;
```

## 6. なぜこの問題が発生したか

### 原因1: テーブル作成時の権限設定漏れ
- `fix_pin_codes_schema.sql`でテーブルを作成した際、テーブル自体への権限は付与されたが、**シーケンスへの権限は付与されなかった**

### 原因2: SERIALによるシーケンスの暗黙的な作成
- `SERIAL`型を使用すると、PostgreSQLが自動的にシーケンスを作成するが、**権限は自動では付与されない**

### 原因3: 権限付与の見落とし
- DDLスクリプトでテーブルを作成する際、シーケンスへの権限付与を明示的に記述する必要がある

## 7. 今後の予防策

### ベストプラクティス1: DDLスクリプトに権限付与を含める

すべてのテーブル作成スクリプトに権限付与を含める：

```sql
CREATE TABLE example_table (
    id SERIAL PRIMARY KEY,
    ...
);

-- 権限付与を必ず含める
GRANT ALL PRIVILEGES ON TABLE example_table TO postgres;
GRANT USAGE, SELECT ON SEQUENCE example_table_id_seq TO postgres;
```

### ベストプラクティス2: マイグレーションスクリプトのテンプレート化

```sql
-- テーブル作成テンプレート
CREATE TABLE {table_name} (...);
GRANT ALL PRIVILEGES ON TABLE {table_name} TO ${DB_USER};
GRANT USAGE, SELECT ON SEQUENCE {table_name}_id_seq TO ${DB_USER};
```

### ベストプラクティス3: 権限確認のCIチェック

デプロイ前に権限が正しく設定されているかをチェックするスクリプトを作成：

```bash
#!/bin/bash
# check_permissions.sh
echo "Checking pin_codes permissions..."
psql -U postgres -d mmdpf_dev -c "SELECT grantee, privilege_type FROM information_schema.role_usage_grants WHERE object_name = 'pin_codes_id_seq';"
```
