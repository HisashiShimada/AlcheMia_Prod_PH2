## 1. タスク概要

既存のフロントエンドには、ログイン後に送信される2段階認証のPINコードを入力する画面が存在しないため、PINコード入力画面を実装し、ログインフローを完結させます。

## 3. 現状分析

### 現在の認証フロー
1. ユーザーがユーザー名・パスワードを入力
2. `/api/v1/auth/login` が仮セッショントークンを返す
3. **（欠落）PINコード入力画面が存在しない**
4. `/api/v1/auth/verify-pin` でPINコード検証し、本セッションJWTを発行

### バックエンドAPI（実装済み）
- `POST /api/v1/auth/login`: PINコード生成・仮トークン発行
- `POST /api/v1/auth/verify-pin`: PINコード検証・JWT発行
- `POST /api/v1/auth/resend-pin`: PINコード再送信

### 必要な実装
- PINコード入力コンポーネント（新規）
- ログインフローの状態管理（修正）
- API統合ロジック（新規）

### PINコード入力UXの実装方針
1. **6つの入力欄方式**（推奨）
   - 各桁を個別の入力欄で表示
   - 自動フォーカス移動
   - Backspaceで前の欄に戻る
   - ペースト対応（6桁を自動分割）

2. **デザイン方針**
   - Ant Designのデザイントークン使用
   - LoginPageと統一感のあるデザイン
   - 明確なフィードバック（成功・エラー）

### API統合

#### PINコード検証API
```typescript
POST /api/v1/auth/verify-pin
Headers:
  Authorization: Bearer {sessionToken}
  X-Organization-Id: {organizationId}
Body:
  {
    "pinCode": "123456"
  }
Response (200):
  {
    "success": true,
    "data": {
      "user": { ... },
      "session": { "token": "...", "expiresAt": "..." },
      "redirectUrl": "/experiment-admin"
    }
  }
```

#### PINコード再送信API
```typescript
POST /api/v1/auth/resend-pin
Headers:
  Authorization: Bearer {sessionToken}
  X-Organization-Id: {organizationId}
Response (200):
  {
    "success": true,
    "data": {
      "message": "PINコードを再送信しました",
      "email": "use***@example.com",
      "expiresIn": 300
    }
  }
```

### セキュリティ考慮事項
- [ ] 仮セッショントークンをSessionStorageに保存（XSS対策）
- [ ] PINコード検証成功後、仮トークンを削除
- [ ] エラーメッセージは汎用的に（情報漏洩防止）
- [ ] 試行回数制限の表示（ユーザーへの警告）

## 7. リスクと対策

| リスク | 影響度 | 発生確率 | 対策 |
