# 最終完了レポート v2: メソッドタブ切替修正（問題3解決版）

## 作成日時
2026-02-20 15:46

## タスク概要
進捗確認タブにおいて、メソッドタブの切り替えが正常に動作しない問題を修正しました。

## 発生した問題（3つ）

### 問題1: ユーザーがメソッドタブをクリックしても切り替わらない
**原因**: useEffectが無条件に最初のメソッドを選択していた

### 問題2: プロジェクト未選択→A選択時にメソッドタブが自動選択されない
**原因**: 依存配列に`selectedMethodId`を含めたことで、タイミングがずれた

### 問題3: プロジェクトA→B切り替え時にメソッドタブが自動選択されない ⚠️
**原因**: プロジェクト変更を検知してもその時点でmethodsがまだ空配列だった

## 最終的な修正内容

### ファイル
`frontend/src/components/ExperimentWorker/ProgressCheckTab.tsx`

### 修正のポイント

1. **useRef追加**: プロジェクトIDの前回値を保持
2. **needsAutoSelectフラグ**: プロジェクト変更時に自動選択が必要かを管理
3. **2つのuseEffectで分離**:
   - useEffect1: プロジェクト変更を検知してフラグをセット
   - useEffect2: methodsが更新されたら、フラグに応じて自動選択

### 最終実装

```typescript
// 前回のプロジェクトIDを保持
const prevProjectRef = useRef<string | null>(null);
const [needsAutoSelect, setNeedsAutoSelect] = useState<boolean>(false);

// useEffect 1: プロジェクト変更を検知
useEffect(() => {
  if (selectedProject !== prevProjectRef.current) {
    console.log('[DEBUG] ProgressCheckTab - Project changed detected');
    prevProjectRef.current = selectedProject;
    setNeedsAutoSelect(true); // 自動選択フラグをセット
  }
}, [selectedProject]);

// useEffect 2: メソッドが更新されたら自動選択
useEffect(() => {
  if (methods.length > 0 && needsAutoSelect) {
    // プロジェクト変更後の自動選択
    const sortedMethods = [...methods].sort((a, b) => a.experimentOrder - b.experimentOrder);
    onSelectMethod(sortedMethods[0].methodId);
    setNeedsAutoSelect(false); // フラグをクリア
  } else if (methods.length > 0 && !selectedMethodId && !needsAutoSelect) {
    // 通常の自動選択ロジック（初回表示時など）
    const sortedMethods = [...methods].sort((a, b) => a.experimentOrder - b.experimentOrder);
    onSelectMethod(sortedMethods[0].methodId);
  }
}, [methods, needsAutoSelect, onSelectMethod]);
```

## 動作フロー（修正後）

### ケース1: プロジェクト未選択→A選択
```
1. selectedProject = null → 'A'
2. プロジェクト変更検知useEffect実行
   prevProjectRef.current = 'A'
   setNeedsAutoSelect(true)
3. API呼び出しuseEffect実行
4. methods = [] → methodsA
5. 自動選択useEffect実行
   conditions: methods.length > 0 && needsAutoSelect
   → true! 自動選択実行 ✅
   setNeedsAutoSelect(false)
```

### ケース2: プロジェクトA→B選択
```
1. selectedProject = 'A' → 'B'
2. プロジェクト変更検知useEffect実行
   prevProjectRef.current = 'B'
   setNeedsAutoSelect(true) ✅ フラグセット
3. API呼び出しuseEffect実行
4. methods = methodsA → [] → methodsB
   ├ methods = [] の時:
   │ 自動選択useEffect実行
   │ conditions: 0 > 0 && true → false (何もしない)
   └ methods = methodsB の時:
     自動選択useEffect実行
     conditions: 2 > 0 && true → true
     → 自動選択実行 ✅
     setNeedsAutoSelect(false)
```

### ケース3: ユーザーがメソッドタブをクリック
```
1. Tabsコンポーネントの onChange が発火
2. 親: setSelectedMethodId(methodId2)
3. 子コンポーネント再レンダリング
4. methodsは変わらないので自動選択useEffectは実行されない
   → ユーザーの選択が維持される ✅
```

### ケース4: 再レンダリング（methodsは変わらない）
```
1. 子コンポーネント再レンダリング
2. methodsは変わらないので自動選択useEffectは実行されない
   → 現在の選択状態が維持される ✅
```

## まとめ

### 根本原因
1. **問題1**: useEffectがユーザーの選択を無視していた
2. **問題2**: 依存配列に`selectedMethodId`を含めたことでタイミングがずれた
3. **問題3**: プロジェクト変更を検知してもその時点でmethodsがまだ空配列だった

### 解決方法
1. **条件追加**: `!selectedMethodId`でユーザーの選択を尊重
2. **useRefとフラグ**: プロジェクト変更を明示的に検知・管理
3. **2つのuseEffectで分離**: プロジェクト変更検知とメソッド自動選択を分離

### 修正の効果
- ✅ プロジェクト未選択→A選択: 最初のメソッドが自動選択される
- ✅ プロジェクトA→B選択: 新しいプロジェクトの最初のメソッドが自動選択される
- ✅ ユーザーがメソッドタブをクリック: 正しく切り替わる
- ✅ 複数のメソッド間を自由に切り替えられる
- ✅ シンプルで理解しやすい実装
- ✅ 既存の動作を壊さない安全な修正
