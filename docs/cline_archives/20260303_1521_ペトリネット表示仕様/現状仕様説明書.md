## 📋 詳細な処理ステップ

### Step 1: MAIMLデータの取得

#### 実装場所
- **API**: `backend/src/routes/projectRoutes.ts`
- **Controller**: `backend/src/controllers/projectController.ts`
- **Service**: `backend/src/services/storageService.ts`

#### 処理内容
```typescript
// フロントエンド
const response = await fetch(`/api/v1/projects/${projectId}/maiml`);
const maimlXml = await response.text();

// バックエンド
// 1. S3/Swiftから.maimlファイルを取得
const fileBuffer = await storageService.downloadFile(
  organizationId,
  `projects/${projectName}/${projectName}.maiml`
);

// 2. BufferをStringに変換
const maimlXml = fileBuffer.toString('utf-8');

// 3. レスポンスとして返却
res.setHeader('Content-Type', 'application/xml');
res.send(maimlXml);
```

#### データ形式
```xml
<?xml version="1.0" encoding="UTF-8"?>
<maiml version="1.0">
  <protocol>
    <method id="method_001">
      <pnml id="pnml_001">
        <place id="place_001" />
        <transition id="trans_001" />
        <arc source="place_001" target="trans_001" />
      </pnml>
      <materialTemplate id="mat_001">
        <placeRef ref="place_001" />
      </materialTemplate>
    </method>
  </protocol>
</maiml>
```

### Step 3: テンプレートマップ構築

#### 実装場所
- **ファイル**: `frontend/src/utils/petriNetExtractor.ts`
- **関数**: `buildTemplateMap()`

#### 処理内容
```typescript
// 1. テンプレートを取得
const templates = parser.getTemplates();
// templates = {
//   material: [{ id: "mat_001", placeRefs: [{ ref: "place_001" }], ... }],
//   condition: [{ id: "cond_001", placeRefs: [{ ref: "place_002" }], ... }],
//   result: [{ id: "res_001", placeRefs: [{ ref: "place_003" }], ... }]
// }

// 2. Place ID → Template のマッピングを作成
const templateMap: Record<string, Template> = {};

templates.material.forEach(t => {
  t.placeRefs.forEach(pr => {
    templateMap[pr.ref] = { ...t, category: 'material' };
  });
});
// 同様にcondition, resultも処理

// 3. 結果
// templateMap = {
//   "place_001": { id: "mat_001", category: "material", name: "原料A", ... },
//   "place_002": { id: "cond_001", category: "condition", name: "温度", ... },
//   "place_003": { id: "res_001", category: "result", name: "生成物", ... }
// }
```

#### 目的
- PlaceノードがどのTemplate（Material/Condition/Result）に対応するかを特定
- ノードの表示タイプを決定するために使用

### Step 4: ペトリネット構造抽出

#### 実装場所
- **コンポーネント**: `PetriNetViewer.tsx`
- **useEffect内**: `maimlData`の変更を監視

#### 処理内容
```typescript
// 1. Method配列を取得
const methods = parser.getMethods();

// 2. 表示するメソッドを決定
const targetMethod = selectedMethodId
  ? methods.find(m => m.id === selectedMethodId)
  : methods[0];  // 指定がなければ最初のメソッド

// 3. PetriNetData構造を作成
const petriNetData: PetriNetData = {
  methods: [targetMethod],  // 単一メソッドモード
  places: targetMethod.pnml.places || [],
  transitions: targetMethod.pnml.transitions || [],
  arcs: targetMethod.pnml.arcs || []
};

// 4. データ例
// petriNetData = {
//   methods: [{ id: "method_001", ... }],
//   places: [
//     { id: "place_001", name: "原料A" },
//     { id: "place_002", name: "温度条件" }
//   ],
//   transitions: [
//     { id: "trans_001", name: "混合" }
//   ],
//   arcs: [
//     { source: "place_001", target: "trans_001" },
//     { source: "place_002", target: "trans_001" }
//   ]
// }
```

#### 単一メソッドモードの理由
```typescript
// ❌ 複数メソッドを渡すとpnmlGroupノードが生成される
const petriNetData = {
  methods: methods,  // 全メソッド
  places: [...],
  // ...
};
// → PetriNetViewer.tsxのnodeTypesにpnmlGroupが未登録
// → 黒い点として表示されてしまう

// ✅ 単一メソッドモードで回避
const petriNetData = {
  methods: [targetMethod],  // 1メソッドのみ
  places: [...],
  // ...
};
// → pnmlGroupノードは生成されない
```

### Step 5: ReactFlow形式変換

#### 実装場所
- **ファイル**: `frontend/src/utils/reactFlowConverter.ts`
- **関数**: `convertToReactFlowFormat()`

#### 5.1. レイアウト計算

```typescript
// calculateSimpleLayout()
// トポロジカルソートでTransitionの階層を決定

// 1. Transitionの依存関係を計算
const transitionLevels = new Map<string, number>();
// trans_001 → level 0 (入力専用Place)
// trans_002 → level 1 (trans_001の出力を入力)
// trans_003 → level 2 (trans_002の出力を入力)

// 2. レベルごとにTransitionを配置
Array.from(transitionsByLevel.entries()).forEach(([level, transitions]) => {
  const x = startX + (level * horizontalSpacing);  // 250px間隔
  transitions.forEach((t, index) => {
    const y = startY + (index * nodeSpacing);      // 80px間隔
    nodePositions.set(t.id, { x, y });
  });
});

// 3. Placeを配置
// - 入力Place: Transitionの左側
// - 出力Place: Transitionの右側
```

**レイアウトパラメータ:**
- 水平間隔: 250px
- 垂直間隔: 80px
- 開始位置: (50, 0)

#### 5.2. ノード生成

```typescript
// Placeノードの生成
const placeNodes: Node<NodeData>[] = places.map(place => {
  const position = nodePositions.get(place.id) || { x: 0, y: 0 };
  const template = templateMap[place.id];  // テンプレート取得
  
  return {
    id: place.id,
    type: getNodeTypeFromCategory(template?.category),  // 'materialTemplate' など
    position: position,
    data: {
      id: place.id,
      name: place.name || template?.name || '',
      nodeId: place.id,
      nodeType: 'place',
      placeType: template?.category || '',
      properties: template?.properties || [],
      template: template,
      templateRef: template
    }
  };
});

// Transitionノードの生成
const transitionNodes: Node<NodeData>[] = transitions.map(transition => {
  const position = nodePositions.get(transition.id) || { x: 0, y: 0 };
  
  return {
    id: transition.id,
    type: 'transition',
    position: position,
    data: {
      id: transition.id,
      name: transition.name || transition.id,
      nodeId: transition.id,
      nodeType: 'transition',
      transition: transition
    }
  };
});
```

**ノードタイプの決定:**
| Template Category | Node Type |
|------------------|-----------|
| 'material' | 'materialTemplate' |
| 'condition' | 'conditionTemplate' |
| 'result' | 'resultTemplate' |
| - (Transition) | 'transition' |

#### 5.3. エッジ生成

```typescript
// Arcからエッジを生成
const edges: Edge<EdgeData>[] = arcs.map((arc, index) => ({
  id: arc.id || `arc-${index}`,
  source: arc.source,
  target: arc.target,
  type: 'default',
  animated: false,
  style: { 
    stroke: '#555', 
    strokeWidth: 2 
  },
  markerEnd: {
    type: MarkerType.ArrowClosed,
    color: '#555'
  }
}));
```

#### 5.4. 戻り値

```typescript
return {
  nodes: [...placeNodes, ...transitionNodes],
  edges: edges
};
```

## ✅ チェックポイント

### データが正しく表示されるための条件

#### 1. MAIMLファイルの構造
- [ ] `<protocol>` → `<method>` → `<pnml>` の階層が正しい
- [ ] `<place>` 要素に `id` 属性がある
- [ ] `<transition>` 要素に `id` 属性がある
- [ ] `<arc>` 要素に `source`, `target` 属性がある

#### 2. テンプレート定義
- [ ] `materialTemplate`, `conditionTemplate`, `resultTemplate` が定義されている
- [ ] 各テンプレートに `<placeRef ref="place_xxx" />` がある
- [ ] placeRef の `ref` が実際の Place ID と一致している

#### 3. Arc接続
- [ ] arc の `source` が実際の Place/Transition ID と一致
- [ ] arc の `target` が実際の Place/Transition ID と一致
- [ ] 孤立ノード（接続のないノード）がない

## 🐛 よくある問題と対処法

### 問題1: ペトリネット図が表示されない

**症状**: 空の画面、またはローディングが終わらない

**原因の可能性**:
1. MAIMLファイルの構造エラー
2. Method配列が空
3. place/transition/arcが空

**確認方法**:
```typescript
// ブラウザDevToolsコンソールで確認
console.log('Methods:', parser.getMethods());
console.log('Places:', parser.getPlaces());
console.log('Transitions:', parser.getTransitions());
console.log('Arcs:', parser.getArcs());
```

### 問題2: ノードが黒い点で表示される

**症状**: ノードが小さな黒い点として表示される

**原因**:
- ノードタイプが未登録（例: pnmlGroup）
- templateMapにPlaceが登録されていない

**対処法**:
- 単一メソッドモードを使用: `methods: [targetMethod]`
- templateMapの内容を確認

### 問題3: エッジ（矢印）が表示されない

**症状**: ノードは表示されるがエッジが表示されない

**原因**:
- arc の source/target ID が不一致
- arcデータが空

**確認方法**:
```typescript
// エッジ接続の検証
console.log('Edges:', edges);
console.log('Node IDs:', nodes.map(n => n.id));

// 無効なエッジを確認
const nodeIds = new Set(nodes.map(n => n.id));
const invalidEdges = edges.filter(e => 
  !nodeIds.has(e.source) || !nodeIds.has(e.target)
);
console.log('Invalid edges:', invalidEdges);
```

## 🎯 まとめ

### ペトリネット表示の仕組み（要約）

mmdpfプロジェクトでは、以下の6ステップでペトリネット図を表示しています：

1. **MAIMLデータ取得** - S3/Swiftから.maimlファイル（XML）を取得
2. **MAIMLパース** - XML文字列を型安全なオブジェクトに変換
3. **テンプレートマップ構築** - Place ID → Template の対応表を作成
4. **ペトリネット構造抽出** - places, transitions, arcs を抽出
5. **ReactFlow形式変換** - レイアウト計算、ノード・エッジ生成
6. **ReactFlow表示** - ブラウザ上でインタラクティブに表示

### 主要なコンポーネント

| コンポーネント | 役割 |
|--------------|------|
| **PetriNetViewer.tsx** | ペトリネット表示（閲覧専用） |
| **PetriNetEditor.tsx** | ペトリネット編集（編集モード） |
| **MaimlParserTyped** | MAIMLパーサー |
| **reactFlowConverter** | ReactFlow形式変換 |
| **petriNetExtractor** | テンプレートマップ構築 |

### 表示される画面

| ロール | 画面 | コンポーネント | 用途 |
|--------|------|--------------|------|
| 実験作業者 | 実験記録タブ | TransitionFlowDiagram | 実験フロー確認（簡易表示） |
| 実験作業者 | 指示確認タブ | PetriNetViewer (via ViewRenderer) | 作業指示確認（完全表示） |
| 実験作業者 | 進捗確認タブ | PetriNetViewer (via ViewRenderer) | 進捗確認（完全表示） |
| 実験管理者 | 進捗モニタリング | PetriNetVisualization | 進捗可視化（進捗情報付き） |
| 実験管理者 | プロジェクト管理 | PetriNetViewer/Editor (via ViewRenderer) | 閲覧・編集 |
| 実験管理者 | PetriNetエディタ | PetriNetEditor | MAIML編集（専用画面） |

### コンポーネントの使い分け

**PetriNetViewer**:
- 完全なReactFlow表示（閲覧専用）
- ズーム・パン・ノードクリック機能
- ViewRenderer経由で使用

**PetriNetVisualization**:
- 進捗情報を重ねて表示
- 完了したトランジションを色分け
- WorkProgressDetailDialog経由で使用

**TransitionFlowDiagram**:
- 簡易的なフロー図
- トランジション一覧表示の代替
- 実験記録タブで直接使用

**PetriNetEditor**:
- 編集機能付きエディタ
- 保存・バリデーション機能
- ViewRenderer経由または専用画面で使用

### 技術スタック

- **表示ライブラリ**: ReactFlow 11.11.4
- **パース**: xml-js 1.6.11
- **UI**: Ant Design 6.x
- **型安全性**: TypeScript + XSD準拠型
