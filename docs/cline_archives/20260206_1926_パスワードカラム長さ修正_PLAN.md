## 1. タスク概要

`user_authentication`テーブルの`password`カラムの長さが50文字に制限されているため、bcryptハッシュ（60文字）が切り詰められて保存され、パスワード検証が失敗する問題を修正します。

## 2. 問題の詳細

### 現状の問題
- **DDL定義**: `password CHARACTER VARYING(50)`
- **bcryptハッシュ長**: 60文字（`$2b$12$` + 22文字のsalt + 31文字のhash）
- **結果**: データベース保存時に10文字切り詰められる
- **影響**: パスワード検証が常に失敗する

### 検証失敗の例
```
password='admin123'
storedHash='$2b$12$vbtP32e7M7zDBqGxtsdfSesnM5WsDEHP.VHmf9u0McD'
→ 49文字（本来は60文字必要）
```

## 6. 技術的詳細

### bcryptハッシュの構造
```
$2b$12$abcdefghijklmnopqrstuv0123456789ABCDEFGHIJK
│ │ │  │                     │
│ │ │  └─ salt (22文字)      └─ hash (31文字)
│ │ └─ cost (2文字)
│ └─ minor version (1文字)
└─ algorithm identifier (3文字)

合計: 3 + 1 + 1 + 2 + 1 + 22 + 31 = 60文字
```

### カラム長の選択理由
- **現状**: 50文字（不足）
- **最小要件**: 60文字（bcryptのみ）
- **推奨**: 255文字（将来の拡張性を考慮）
  - 他のハッシュアルゴリズムへの移行も可能
  - セキュリティベストプラクティスに準拠
