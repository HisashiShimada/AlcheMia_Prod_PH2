## 1. 問題の概要

`backend/src/services/pinCodeService.ts`の`generateAndSave`メソッドで以下のエラーが発生：

```
'column "org_id" of relation "pin_codes" does not exist'
```

## 2. 原因分析

### 2.1. エラーメッセージの解析
- エラー: `column "org_id" does not exist`
- コード: `organization_id` を使用
- DDL: `organization_id` を定義

### 2.2. 問題の特定

**データベースに古いスキーマが適用されている**

- 最新のDDL: `organization_id` カラムを定義
- 実際のDB: `org_id` カラムが存在（古いバージョン）
- コード: `organization_id` を使用（最新DDLに準拠）

### 2.3. 推定される原因

1. 過去に`org_id`という名前でテーブルが作成された
2. その後DDLが`organization_id`に修正された
3. データベースには古いスキーマが残っている

## 3. 解決策

### 解決策1: DDLを再適用（推奨）

最新のDDLでテーブルを再作成する。

**メリット:**
- コードとスキーマが完全に一致
- 他のテーブルとの命名規則が統一
- 将来的な保守性が高い

**手順:**
```sql
-- 1. pin_codesテーブルを削除
DROP TABLE IF EXISTS pin_codes CASCADE;

-- 2. 最新のDDLを適用
-- (docs/design/db/create_tables_authentication.sqlのpin_codes部分)
-- または docs/design/db/ddl/pin_codes.sql を実行
```

### 解決策2: コードを一時的に修正（非推奨）

コード側を`org_id`に変更する。

**デメリット:**
- スキーマとの不整合が残る
- 他のコードとの命名規則が統一されない
- 将来的な保守性が低い

**この解決策は推奨しません。**

## 7. 代替案: マイグレーションスクリプト

データを保持したい場合のマイグレーション：

```sql
-- カラム名を変更
ALTER TABLE pin_codes 
RENAME COLUMN org_id TO organization_id;
```

ただし、現在のDDLと完全に一致させるには、テーブル全体を再作成する方が確実です。

CREATE TABLE pin_codes (
    id SERIAL NOT NULL,
    user_id UUID NOT NULL,
    organization_id UUID NOT NULL,  -- ← 正しいカラム名
    pin_code VARCHAR(6) NOT NULL,
    session_token VARCHAR(255) NOT NULL,
    is_used BOOLEAN NOT NULL DEFAULT false,
    used_at TIMESTAMP,
    expires_at TIMESTAMP NOT NULL,
    attempts_count INTEGER NOT NULL DEFAULT 0,
    max_attempts INTEGER NOT NULL DEFAULT 3,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT pin_codes_pkey PRIMARY KEY (id),
    CONSTRAINT pin_codes_user_fkey 
        FOREIGN KEY (user_id, organization_id) 
        REFERENCES organization_user(user_id, organization_id)
);
