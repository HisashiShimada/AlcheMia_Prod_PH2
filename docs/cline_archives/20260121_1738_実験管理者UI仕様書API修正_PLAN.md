## 5. 技術的詳細

### 5.1. API仕様の主な変更点

#### エンドポイント形式の統一

**変更前:**
```
GET /api/projects
POST /api/projects
GET /api/projects/:id/files
POST /api/v1/projects/:id/reload  // 一部だけv1
```

**変更後:**
```
GET /api/v1/projects
POST /api/v1/projects
GET /api/v1/projects/:projectId/files
POST /api/v1/projects/:projectId/reload
```

#### レスポンス形式の統一

**変更前:**
```json
{
  "projects": [...],
  "total": 150
}
```

**変更後:**
```json
{
  "success": true,
  "data": {
    "projects": [...]
  },
  "pagination": {
    "page": 1,
    "limit": 20,
    "totalItems": 150,
    "totalPages": 8,
    "hasNext": true,
    "hasPrev": false
  },
  "meta": {
    "timestamp": "2026-01-21T16:00:00Z",
    "requestId": "req_abc123"
  }
}
```

#### エラーレスポンス形式の統一

**変更後:**
```json
{
  "success": false,
  "error": {
    "code": "ERROR_CODE",
    "message": "エラーメッセージ",
    "details": [
      {
        "field": "fieldName",
        "message": "詳細メッセージ",
        "code": "FIELD_ERROR_CODE"
      }
    ]
  },
  "meta": {
    "timestamp": "2026-01-21T16:00:00Z",
    "requestId": "req_abc123"
  }
}
```

### 6. エラーハンドリング

#### 共通エラーコード

| コード | HTTPステータス | 説明 |
|-------|---------------|------|
| `AUTH_TOKEN_INVALID` | 401 | 認証トークンが無効 |
| `PERMISSION_INSUFFICIENT` | 403 | 権限不足 |
| `RESOURCE_NOT_FOUND` | 404 | リソースが見つからない |
| `VALIDATION_ERROR` | 400 | バリデーションエラー |
| `SYSTEM_ERROR` | 500 | システムエラー |
```

## 6. リスクと対策

| リスク | 影響度 | 発生確率 | 対策 |
|--------|--------|----------|------|
| API仕様書の内容に不整合がある | 中 | 低 | API仕様書を再確認し、不明点はユーザーに質問 |
| UI仕様書が多数あり修正漏れが発生 | 中 | 中 | チェックリストで確認、優先度を付けて段階的に実施 |
| 既存の実装コードと仕様書が乖離している | 低 | 低 | 仕様書はドキュメントであり、実装は別途確認が必要 |
