## 🎯 ユーザーの要望（3つの目標）

### 目標1: any型の排除
> 極力any型を使わず型定義がはっきりした形式にしたい

**現状の問題**:
```typescript
// 現在のmaimlParserExp.ts
private data: any;  // ← any型
private maiml: any; // ← any型

// プロパティアクセス
const methodId = method._attributes?.id;  // ← 型チェックなし
```

**目指す姿**:
```typescript
// 型安全なアクセス
private typedMaiml: MaimlRoot;  // ← 明確な型

// プロパティアクセス
const methodId: string = method.id;  // ← 型チェックあり
```

---

### 目標2: 正しい形式の構造体
> Maimlファイルを解析した結果の構造体は正しい形式で作りたい

**現状の問題**:
```typescript
// xml-js形式（非標準）
{
  property: {
    _attributes: { key: "concentration", units: "mol/L" },
    value: { _text: "0.5" }
  }
}
```

**目指す姿（XSD準拠型）**:
```typescript
// XSD準拠型（標準）
{
  property: {
    key: "concentration",
    units: "mol/L",
    value: 0.5
  }
}
```

**既に存在するファイル**:
- ✅ `frontend/src/types/maiml-unified.ts` - XSD準拠型定義
- ✅ `frontend/src/types/maiml-schema.ts` - 詳細スキーマ
- ✅ `frontend/src/types/maiml-type-guards.ts` - 型ガード関数
- ✅ `frontend/src/utils/maimlTypeConverter.ts` - 変換ユーティリティ

---

### 目標3: プロジェクト全体での型統一
> プロジェクト全体でMaiml構造のデータに関しては統一した型定義を使用する形にしたい

**現状の分散状態**:
```
maimlParserExp.ts ──→ any型 ──→ 独自形式
                                    ↓
petriNetExtractor.ts ──→ any型 ──→ 独自形式
                                    ↓
各コンポーネント ──→ any型 ──→ 独自形式
```

**目指す統一状態**:
```
maimlParserExp.ts
  ↓ 変換（convertXmlJsToMaimlRoot）
  ↓
MaimlRoot型（XSD準拠）
  ↓ 統一された型で渡される
  ↓
petriNetExtractor.ts ──→ Protocol型
                           ↓
各コンポーネント ──→ Method型, Property型など
```

```typescript
// frontend/src/utils/maimlParserTyped.ts
export class MaimlParserTyped {
  private typedMaiml: MaimlRoot;
  
  constructor(maimlData: string | any) {
    const xmlData = typeof maimlData === 'string' 
      ? xmljs.xml2js(maimlData, { compact: true })
      : maimlData;
    
    this.typedMaiml = convertXmlJsToMaimlRoot(xmlData);
  }
  
  // 型安全なメソッド群
  getTypedMaiml(): MaimlRoot { ... }
  getProtocol(): Protocol { ... }
  getMethods(): Method[] { ... }
  getTransitions(): Transition[] { ... }
  getTemplates(): TemplateCollection { ... }
}
```
