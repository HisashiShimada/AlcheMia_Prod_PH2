### 調査結果

ログイン処理（POST /api/v1/auth/login + POST /api/v1/auth/verify-pin）で参照されるテーブルは以下の通りです。

#### Phase 1: ログイン処理（/api/v1/auth/login）

**参照テーブル: 4個**

1. **organization_user（組織利用者）**
   - **参照目的**: ユーザーIDでユーザー情報を検索
   - **取得カラム**: user_id, user_name, mail_address, role_cd, organization_id, is_active, locked_until, department_cd
   - **検索条件**: `WHERE user_id = $1 AND organization_id = $2`

2. **user_authentication（利用者認証）**
   - **参照目的**: パスワード検証（passwordService.verify()経由）
   - **取得カラム**: password（ハッシュ化されたパスワード）
   - **検索条件**: `WHERE user_id = $1 AND organization_id = $2`

3. **pin_codes（PINコード）**
   - **参照目的**: PINコード生成・保存（pinCodeService.generateAndSendPin()経由）
   - **操作**: INSERT（新規PINコード生成）
   - **保存カラム**: organization_id, user_id, pin_code, session_token, expires_at, attempts_count, created_at

4. **login_history（ログイン履歴）**
   - **参照目的**: ログイン試行履歴の記録（成功・失敗両方）
   - **操作**: INSERT
   - **保存カラム**: user_name, organization_id, login_at, login_sf（成否）, failure_reason, ip_address, user_agent

#### Phase 2: PINコード検証処理（/api/v1/auth/verify-pin）

**参照テーブル: 5個（追加）**

5. **role（ロール）**
   - **参照目的**: 初期画面機能CDの取得
   - **取得カラム**: initial_screen_function_cd
   - **検索条件**: `WHERE organization_id = $1 AND role_cd = $2`

6. **user_authentication（利用者認証）** ※再参照
   - **参照目的**: パスワード期限と一時パスワードフラグの確認
   - **取得カラム**: password_expires_at, is_temporary_password
   - **検索条件**: `WHERE user_id = $1 AND organization_id = $2`

7. **role_permission（ロール権限）**
   - **参照目的**: ユーザーの権限情報取得（rolePermissionRepository経由）
   - **取得カラム**: role, function_id, permission
   - **検索条件**: `WHERE role = $1`（organization_id でもフィルタされる可能性あり）

8. **pin_codes（PINコード）** ※削除処理
   - **参照目的**: 使用済みPINコードの削除
   - **操作**: DELETE
   - **検索条件**: `WHERE session_token = $1`

9. **organization_user（組織利用者）** ※間接参照
   - **参照目的**: pin_codesとJOINしてユーザー情報取得
   - **検索条件**: `JOIN organization_user ON pc.user_id = ou.user_id AND pc.organization_id = ou.organization_id`

### 参照順序フロー

```
【ログイン処理フロー】
1. organization_user テーブル
   ↓ ユーザー検索（user_id + organization_id）
   
2. user_authentication テーブル
   ↓ パスワード検証
   
3. pin_codes テーブル
   ↓ PINコード生成・保存
   
4. login_history テーブル
   ↓ ログイン履歴記録（成功）

【PINコード検証フロー】
5. pin_codes テーブル + organization_user テーブル（JOIN）
   ↓ session_tokenでユーザー情報取得
   
6. role テーブル
   ↓ 初期画面機能CD取得
   
7. user_authentication テーブル
   ↓ パスワード期限・一時パスワードフラグ確認
   
8. role_permission テーブル
   ↓ 権限情報取得
   
9. pin_codes テーブル
   ↓ 使用済みPINコード削除
```

### サマリー

**ログインするまでに参照されるテーブル: 全5テーブル**

| テーブル名 | カテゴリ | 参照タイミング | 操作 |
|-----------|---------|--------------|------|
| organization_user | 認証関連 | ログイン時・PIN検証時 | SELECT（2回） |
| user_authentication | 認証関連 | ログイン時・PIN検証時 | SELECT（2回） |
| pin_codes | 認証関連 | ログイン時・PIN検証時 | INSERT, DELETE |
| login_history | 認証関連 | ログイン時 | INSERT |
| role | 認証関連 | PIN検証時 | SELECT |
| role_permission | 認証関連 | PIN検証時 | SELECT |

**特記事項:**
- マルチテナント分離のため、すべてのクエリで `organization_id` フィルタが必須
- PINコード方式の二段階認証を採用（セキュリティ強化）
- ログイン履歴は成功・失敗両方を記録（監査ログ）
- パスワード期限と一時パスワードのチェックを実施
