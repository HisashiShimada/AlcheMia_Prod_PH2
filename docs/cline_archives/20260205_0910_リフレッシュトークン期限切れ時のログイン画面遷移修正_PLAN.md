### Phase 1-2: 現状調査と問題箇所の特定（完了）

#### ユーザーからの重要なフィードバック

**実行したAPI**: ログアウト（`authService.ts`を使用）

**ログの内容**:
```
http://localhost:3001/api/v1/auth/logout 401 (Unauthorized)
[authUtils] 401エラー検出: トークン更新を試みます
http://localhost:3001/api/v1/auth/refresh 401 (Unauthorized)
```

**このログから判明した真の問題**:
1. ログアウトAPIが401エラー（アクセストークン期限切れ）
2. authUtils.tsが自動的にトークン更新を試みる
3. リフレッシュAPIも401エラー（リフレッシュトークンも期限切れ）
4. ❌ **しかし、ログイン画面へのリダイレクトが発生しない**

#### 問題の本質

**初期の誤解**:
- 当初、保留された4つのAPIサービス（projectApiService.ts等）が原因と考えた
- しかし、ユーザーは`authService.ts`を使用するログアウトAPIを実行していた

**真の問題箇所**:
- `frontend/src/utils/authUtils.ts`のレスポンスインターセプター
- `authService.refreshAccessToken()`が失敗（nullを返す）またはエラーを投げた場合、ログイン画面へのリダイレクトが確実に実行されない

**問題のコードパス**:

```typescript
// authUtils.ts（修正前）
try {
  const newAccessToken = await authService.refreshAccessToken();
  
  if (newAccessToken) {
    // 成功時の処理
  } else {
    // ❌ authService内でリダイレクトされることを期待
    // しかし、何らかの理由でリダイレクトが実行されない場合がある
    processQueue(new Error('トークン更新失敗'), null);
    return Promise.reject(error);
  }
} catch (refreshError) {
  // ❌ エラー時もリダイレクトが実行されない
  processQueue(errorObj, null);
  return Promise.reject(refreshError);
}
```

### Phase 3: 修正実装（完了）

// ❌ バグ: すべての /auth/refresh リクエストを除外してしまった

**問題点**: 正常なトークン更新（200 OK）もブロックしてしまう

**最終修正（正しい実装）**:
```typescript
// ✅ /auth/refresh への401エラーのみを特別処理
if (error.response?.status === 401 && originalRequest?.url?.includes('/auth/refresh')) {
  console.error('[authUtils] リフレッシュトークンが期限切れです: ログイン画面へリダイレクトします');
  
  // セッション情報をクリア
  if (typeof window !== 'undefined') {
    sessionStorage.removeItem('sessionToken');
    sessionStorage.removeItem('tokenExpiresAt');
    sessionStorage.removeItem('userInfo');

  }
  
  return Promise.reject(error);
}
```

- `/auth/refresh`が**401エラー**: 直ちにセッションをクリアしてログイン画面へリダイレクト ✅
- 無限ループを防止 ✅

## Phase 6: 現状の問題まとめ（テスト前）

### 🔍 発見した根本原因

#### 問題1: バックエンドのルートとコントローラーの不一致

**ルートファイル（authRoutes.ts）:**
```typescript
// ❌ リクエストボディで'refreshToken'を要求
body('refreshToken')
  .notEmpty()
  .withMessage('Refresh token is required'),
```

**コントローラー（authController.ts）:**
```typescript
// ✅ Cookieから'refreshToken'を取得
const refreshTokenValue = req.cookies?.refreshToken;
```

**影響:**
- フロントエンドが空のボディで`/auth/refresh`を呼び出す
- バックエンドのバリデーションエラー（400または422）が発生
- フロントエンドで401として扱われ、即座にログイン画面へリダイレクト

#### 問題2: フロントエンドのトークン保存方法

**tokenStorage.ts:**
- アクセストークンのみSessionStorageに保存
- リフレッシュトークンを保存する機能が存在しない

**authService.ts:**
```typescript
// リクエストボディは空
const response = await apiClient.post('/auth/refresh', {});
```

**本来の設計:**
- リフレッシュトークンはhttpOnly CookieとしてバックエンドからSet-Cookieヘッダーで送信
- フロントエンドは自動的にCookieを送信（明示的な処理不要）
- バックエンドはCookieから取得（実装済み）
