## 現状分析

### 問題の詳細

現在の実装では、SystemAdminMenuコンポーネント内でタブを切り替えると、SessionManagementコンポーネントがアンマウント・再マウントされるため、以下の状態がリセットされます：

```typescript
const [autoRefresh, setAutoRefresh] = useState(false);
const [refreshInterval, setRefreshInterval] = useState<number>(5);
```

### 現在の実装構造

**SystemAdminMenu.tsx（親コンポーネント）:**
```typescript
export default function SystemAdminMenu({ user, onLogout, onNavigate, onMenuChange }: SystemAdminMenuProps) {
  const [currentTab, setCurrentTab] = useState('1');
  
  // タブ切り替え
  const handleTabChange = (key: string) => {
    setCurrentTab(key);
  };

  return (
    <Layout>
      <Header user={user} onLogout={onLogout} />
      <SubHeader 
        title={t('menu.system_admin.title')}
        tabs={tabItems}
        activeTabKey={currentTab}
        onTabChange={handleTabChange}
        currentMenu="system_admin"
        onMenuChange={handleMenuChange}
      />

      <Content>
        {/* タブ4: セッション管理 */}
        {currentTab === '4' && <SessionManagement />}
      </Content>
    </Layout>
  );
}
```

**問題点:**
- `currentTab === '4'`の条件分岐により、他のタブに切り替えるとSessionManagementコンポーネントがDOMから削除される
- 再度タブ4に戻ると新しいインスタンスが作成され、stateが初期化される

## 実装可能な解決策

### 方法1: LocalStorageを使用（推奨 ⭐）

**メリット:**
- 実装がシンプル
- ブラウザを閉じても設定が保持される
- 他のコンポーネントへの影響がない
- セキュリティリスクが低い（機密情報ではない）

**デメリット:**
- ブラウザのストレージ容量に依存（ただし、この程度のデータなら問題なし）

**実装例:**
```typescript
// SessionManagement.tsx
export default function SessionManagement() {
  // LocalStorageから初期値を取得
  const [autoRefresh, setAutoRefresh] = useState(() => {
    const saved = localStorage.getItem('sessionManagement_autoRefresh');
    return saved ? JSON.parse(saved) : false;
  });
  
  const [refreshInterval, setRefreshInterval] = useState<number>(() => {
    const saved = localStorage.getItem('sessionManagement_refreshInterval');
    return saved ? JSON.parse(saved) : 5;
  });

  // 値が変更されたらLocalStorageに保存
  useEffect(() => {
    localStorage.setItem('sessionManagement_autoRefresh', JSON.stringify(autoRefresh));
  }, [autoRefresh]);

  useEffect(() => {
    localStorage.setItem('sessionManagement_refreshInterval', JSON.stringify(refreshInterval));
  }, [refreshInterval]);
  
  // ... 残りの実装
}
```

**推定工数**: 30分

### 方法3: Context APIを使用

**メリット:**
- グローバルなstate管理
- 深いネストでもpropsを渡す必要がない
- 複数コンポーネントで共有可能

**デメリット:**
- この用途には過剰な実装
- Contextの設計が必要
- 他の開発者が理解しにくくなる可能性

**実装例:**
```typescript
// contexts/SessionManagementContext.tsx
interface SessionManagementContextType {
  autoRefresh: boolean;
  refreshInterval: number;
  setAutoRefresh: (value: boolean) => void;
  setRefreshInterval: (value: number) => void;
}

const SessionManagementContext = createContext<SessionManagementContextType | undefined>(undefined);

export function SessionManagementProvider({ children }: { children: React.ReactNode }) {
  const [autoRefresh, setAutoRefresh] = useState(false);
  const [refreshInterval, setRefreshInterval] = useState(5);

  return (
    <SessionManagementContext.Provider value={{ autoRefresh, refreshInterval, setAutoRefresh, setRefreshInterval }}>
      {children}
    </SessionManagementContext.Provider>
  );
}

export function useSessionManagement() {
  const context = useContext(SessionManagementContext);
  if (!context) {
    throw new Error('useSessionManagement must be used within SessionManagementProvider');
  }
  return context;
}

// SessionManagement.tsx
export default function SessionManagement() {
  const { autoRefresh, refreshInterval, setAutoRefresh, setRefreshInterval } = useSessionManagement();
  // ... 残りの実装
}
```

## 技術的考慮事項

### LocalStorageのセキュリティ

**保存される値:**
- `sessionManagement_autoRefresh`: boolean (true/false)
- `sessionManagement_refreshInterval`: number (1, 5, 10, 30)

**リスク評価:**
- ✅ 機密情報ではない
- ✅ ユーザー個人の設定値のみ
- ✅ 改ざんされても影響は限定的（最悪でも自動更新が意図せずON/OFFになるだけ）
- ✅ XSS対策は別途実装済み

**結論**: LocalStorage使用は安全

### ブラウザ互換性

LocalStorageは以下のブラウザでサポート済み：
- Chrome 4+
- Firefox 3.5+
- Safari 4+
- Edge (全バージョン)
- IE 8+

現代的なブラウザでは問題なし。

### パフォーマンス

- LocalStorageへの書き込みは同期処理だが、データ量が少ないため影響は無視できる
- 読み込みはuseStateの初期化時に1回のみ

### 結論：LocalStorage方式が最適 🎯

**メニュー切り替えにも完全対応:**
- ✅ システム管理者メニュー ⇔ データ管理者メニュー
- ✅ システム管理者メニュー ⇔ 実験管理者メニュー
- ✅ システム管理者メニュー ⇔ プロバイダメニュー
- ✅ 任意のメニュー間の移動

**追加のメリット:**
- ✅ ブラウザを閉じても設定が保持される
- ✅ ページリロードでも設定が保持される
- ✅ 複数タブを開いた場合も設定が共有される

**重要な注意点：LocalStorageの保存単位**

LocalStorageは**ブラウザ単位**で保存されます：
- ❌ ユーザーごとに自動で分離されるわけではない
- ✅ 同じブラウザを使用するすべてのユーザーで設定が共有される

**実際の動作:**
```
[ユーザーA（同じブラウザ）]
→ 自動更新: ON、更新間隔: 10分に設定
→ LocalStorageに保存

[ログアウト]

[ユーザーB（同じブラウザ）でログイン]
→ セッション管理画面を開く
→ 自動更新: ON、更新間隔: 10分（ユーザーAの設定）が表示される ⚠️
```

**対策案:**

### 対策1: ユーザーIDをキーに含める（推奨）✅

LocalStorageのキーにuser_idを含めることで、ユーザーごとに設定を分離できます。

**実装例:**
```typescript
// SessionManagement.tsx
export default function SessionManagement() {
  const { user } = useAuth(); // 現在のユーザー情報を取得
  
  // ユーザーIDをキーに含める
  const autoRefreshKey = `sessionManagement_autoRefresh_${user.user_id}`;
  const refreshIntervalKey = `sessionManagement_refreshInterval_${user.user_id}`;
  
  const [autoRefresh, setAutoRefresh] = useState(() => {
    const saved = localStorage.getItem(autoRefreshKey);
    return saved ? JSON.parse(saved) : false;
  });
  
  const [refreshInterval, setRefreshInterval] = useState<number>(() => {
    const saved = localStorage.getItem(refreshIntervalKey);
    return saved ? JSON.parse(saved) : 5;
  });

  // 値が変更されたらLocalStorageに保存
  useEffect(() => {
    localStorage.setItem(autoRefreshKey, JSON.stringify(autoRefresh));
  }, [autoRefresh, autoRefreshKey]);

  useEffect(() => {
    localStorage.setItem(refreshIntervalKey, JSON.stringify(refreshInterval));
  }, [refreshInterval, refreshIntervalKey]);
  
  // ... 残りの実装
}
```

**メリット:**
- ✅ ユーザーごとに設定が完全に分離される
- ✅ 同じブラウザで複数ユーザーがログインしても問題なし
- ✅ 実装の変更は最小限（キー名にuser_idを追加するだけ）

**デメリット:**
- LocalStorageに複数ユーザー分のデータが蓄積される（ただし、データ量は微小）

### 対策2: 現状のままで運用（条件付き許容）△

**許容できるケース:**
- 各ユーザーが個人のPCやブラウザプロファイルを使用する場合
- 管理者が少数で、設定共有が問題にならない場合

**許容できないケース:**
- 共有PCで複数のユーザーが同じブラウザを使用する場合
- ユーザーごとに異なる設定が必要な場合

### 推奨実装：対策1（ユーザーIDをキーに含める）🎯

**理由:**
- より正確で安全な実装
- 追加の実装コストはほぼゼロ（キー名の変更のみ）
- 将来的な問題を回避できる

**修正後の実装:**
```typescript

// 修正後（ユーザー単位）
const autoRefreshKey = `sessionManagement_autoRefresh_${user.user_id}`;
```

**推定工数の変更:**
- 実装: 30分 → **35分**（ユーザーID取得処理を追加）
- テスト: 15分（変更なし）
- **合計: 50分**

## LocalStorageへの保存タイミング

### 質問：ユーザーが設定を変更するたびにLocalStorageの保存内容も変更される？

**回答：Yes - リアルタイムで即座に保存されます ✅**

### 動作フロー

**実装の仕組み:**
```typescript
// useEffectを使用して、状態が変更されるたびに自動保存
useEffect(() => {
  localStorage.setItem(autoRefreshKey, JSON.stringify(autoRefresh));
}, [autoRefresh, autoRefreshKey]);  // autoRefreshが変更されたら実行

useEffect(() => {
  localStorage.setItem(refreshIntervalKey, JSON.stringify(refreshInterval));
}, [refreshInterval, refreshIntervalKey]);  // refreshIntervalが変更されたら実行
```

### 具体的な操作例

**シナリオ1: 自動更新チェックボックスをONにする**
```
[ユーザー操作]
1. セッション管理画面を開く
2. 自動更新チェックボックスをクリック（OFF → ON）

[システムの動作]
1. autoRefresh state が false → true に変更
2. useEffect が自動的にトリガー
3. localStorage.setItem('sessionManagement_autoRefresh_123', 'true') が即座に実行 ✅
4. LocalStorageに即座に保存完了
```

**シナリオ2: 更新間隔を変更する**
```
[ユーザー操作]
1. 更新間隔のセレクトボックスをクリック
2. 5分 → 10分 に変更

[システムの動作]
1. refreshInterval state が 5 → 10 に変更
2. useEffect が自動的にトリガー
3. localStorage.setItem('sessionManagement_refreshInterval_123', '10') が即座に実行 ✅
4. LocalStorageに即座に保存完了
```

**シナリオ3: 連続して複数の設定を変更する**
```
[ユーザー操作]
1. 自動更新をONにする
2. すぐに更新間隔を10分に変更
3. さらにすぐに30分に変更

[システムの動作]
1. 自動更新ON → LocalStorageに保存 ✅
2. 更新間隔10分 → LocalStorageに保存 ✅
3. 更新間隔30分 → LocalStorageに保存 ✅

各操作ごとに即座にLocalStorageが更新される
```

### 保存のタイミング図

```
ユーザー操作 → State変更 → useEffectトリガー → LocalStorage保存
     ↓            ↓              ↓                  ↓
  クリック     autoRefresh    自動実行         即座に保存
             が変更される                      (同期処理)
```

### 重要なポイント

**1. 即座に保存される：**
- ✅ ユーザーが設定を変更した瞬間にLocalStorageに保存
- ✅ 保存完了を待つ必要なし（同期処理）
- ✅ 「保存」ボタンを押す必要なし

**2. 変更があった時のみ保存：**
- useEffectの依存配列により、値が実際に変更された時のみ実行
- 無駄な書き込みは発生しない

**3. パフォーマンスへの影響：**
- LocalStorageへの書き込みは同期処理（ブロッキング）
- ただし、データ量が非常に小さい（boolean 1個、number 1個）ため、体感できる遅延は発生しない
- 通常は1ms未満で完了

**4. 信頼性：**
- ✅ ネットワーク接続不要（ローカルストレージ）
- ✅ サーバーダウンの影響を受けない
- ✅ 確実に保存される

### ユーザー体験

**従来（state保持なし）:**
```
1. 自動更新をONにする
2. 他のタブに移動
3. セッション管理タブに戻る
4. 自動更新がOFFに戻っている ❌
```
