## 2. 必要な準備

### 2.1 データベースのセットアップ

PostgreSQLが必要です。以下のテーブルを作成してください。

```sql
-- users テーブル
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    username VARCHAR(255) UNIQUE NOT NULL,
    email VARCHAR(255) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    display_name VARCHAR(255) NOT NULL,
    role VARCHAR(50) NOT NULL,
    organization_id VARCHAR(255) NOT NULL,
    organization_name VARCHAR(255) NOT NULL,
    is_active BOOLEAN DEFAULT true,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- user_sessions テーブル
CREATE TABLE user_sessions (
    id SERIAL PRIMARY KEY,
    user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
    session_token VARCHAR(255) UNIQUE NOT NULL,
    expires_at TIMESTAMP NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- pin_codes テーブル
CREATE TABLE pin_codes (
    id SERIAL PRIMARY KEY,
    user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
    pin_code VARCHAR(6) NOT NULL,
    expires_at TIMESTAMP NOT NULL,
    verified BOOLEAN DEFAULT false,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- password_reset_tokens テーブル
CREATE TABLE password_reset_tokens (
    id SERIAL PRIMARY KEY,
    user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
    reset_token VARCHAR(255) UNIQUE NOT NULL,
    expires_at TIMESTAMP NOT NULL,
    used BOOLEAN DEFAULT false,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- login_attempts テーブル（レート制限用）
CREATE TABLE login_attempts (
    id SERIAL PRIMARY KEY,
    identifier VARCHAR(255) NOT NULL,
    attempts INTEGER DEFAULT 1,
    last_attempt_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- インデックスの作成
CREATE INDEX idx_user_sessions_token ON user_sessions(session_token);
CREATE INDEX idx_user_sessions_expires ON user_sessions(expires_at);
CREATE INDEX idx_pin_codes_user_id ON pin_codes(user_id);
CREATE INDEX idx_pin_codes_expires ON pin_codes(expires_at);
CREATE INDEX idx_password_reset_tokens_token ON password_reset_tokens(reset_token);
CREATE INDEX idx_login_attempts_identifier ON login_attempts(identifier);
```

## 4. 必要な修正

### 4.1 バックエンドにCORSミドルウェアを追加

現在のserver.tsにはCORS設定がありません。以下の修正が必要です：

**backend/package.json に cors を追加:**
```bash
cd backend
npm install cors
npm install --save-dev @types/cors
```

**backend/src/server.ts の修正:**
```typescript
import express, { Application } from 'express';
import cors from 'cors';
import dotenv from 'dotenv';
import authRoutes from './routes/authRoutes';

// Load environment variables
dotenv.config();

const app: Application = express();
const PORT = process.env.PORT || 3001;

// CORS configuration
const corsOptions = {
  origin: process.env.CORS_ORIGIN || 'http://localhost:3000',
  credentials: true,
  optionsSuccessStatus: 200,
};
app.use(cors(corsOptions));

// Basic middleware
app.use(express.json());
app.use(express.urlencoded({ extended: true }));

// Mount authentication routes
app.use('/api/v1/auth', authRoutes);

// Health check endpoint
app.get('/api/health', (_req, res) => {
  res.status(200).json({
    status: 'ok',
    timestamp: new Date().toISOString(),
    environment: process.env.NODE_ENV || 'development',
  });
});

// Root endpoint
app.get('/', (_req, res) => {
  res.json({
    message: 'MMDPF Backend API',
    version: '1.0.0',
    status: 'running',
  });
});

// Start server
if (process.env.NODE_ENV !== 'test') {
  app.listen(PORT, () => {
    console.log(`Server is running on port ${PORT}`);
    console.log(`Environment: ${process.env.NODE_ENV || 'development'}`);
    console.log(`CORS enabled for: ${corsOptions.origin}`);
  });
}

export default app;
```

## 5. 起動手順

```bash

cd backend
```

## 6. 動作確認手順

### 6.1 ログイン機能の確認

1. **ログイン画面の表示確認**
   - ブラウザで `http://localhost:3000` にアクセス
   - ログイン画面が表示されることを確認

2. **ログイン処理の確認**
   - ユーザー名: `testuser`
   - パスワード: `test123`
   - 「ログイン」ボタンをクリック

3. **PIN認証画面の確認**
   - PIN入力画面が表示されることを確認
   - バックエンドのコンソールログで6桁のPINコードを確認
   ```
   PIN Code for user testuser: 123456
   ```
   - 表示されたPINコードを入力

4. **ログイン成功の確認**
   - メニュー画面が表示されることを確認
   - ユーザー情報が正しく表示されることを確認

### 6.2 エラーハンドリングの確認

1. **誤ったパスワードでのログイン**
   - 存在しないユーザー名または誤ったパスワードで試行
   - エラーメッセージが表示されることを確認

2. **誤ったPINコード**
   - 正しいログイン後、誤ったPINコードを入力
   - エラーメッセージが表示されることを確認

3. **レート制限の確認**
   - 短時間に5回以上ログイン失敗を試行
   - レート制限エラーが表示されることを確認

### 6.3 パスワードリセット機能の確認

1. **パスワードリセット申請**
   - ログイン画面で「パスワードを忘れた方」をクリック
   - メールアドレス: `test@example.com` を入力
   - 「リセットリンクを送信」をクリック

2. **リセットトークンの確認**
   - バックエンドのコンソールログでリセットトークンを確認
   ```
   Password reset token for test@example.com: abcd1234...
   ```

3. **パスワードリセット実行**（現在は手動でURLを作成）
   - ブラウザで直接アクセス: `http://localhost:3000/?reset_token=<token>`
   - 新しいパスワードを入力
   - パスワード変更が成功することを確認

### 6.4 ログアウト機能の確認

1. **ログアウトボタンのクリック**
   - メニュー画面でログアウトボタンをクリック
   - ログイン画面に戻ることを確認

2. **セッションの無効化確認**
   - ログアウト後、ブラウザの戻るボタンでメニュー画面に戻れないことを確認

## 7. トラブルシューティング

### 7.1 バックエンドが起動しない

**症状**: `npm run dev` でエラーが発生

**原因と対処**:
```bash
# エラー: Cannot find module 'cors'
npm install cors @types/cors

# エラー: Database connection failed
# → backend/.env のDB設定を確認

# エラー: Port 3001 is already in use
# → 別のプロセスがポートを使用している
lsof -i :3001  # プロセスIDを確認
kill -9 <PID>  # プロセスを終了
```

### 7.2 フロントエンドからAPIに接続できない

**症状**: ログインボタンを押してもエラーが発生

**原因と対処**:
1. **CORSエラー**
   ```
   ブラウザコンソール: Access to fetch at 'http://localhost:3001/...' has been blocked by CORS policy
   ```
   - backend/src/server.ts にCORS設定が追加されているか確認
   - backend/.env の CORS_ORIGIN が正しいか確認

2. **APIのURLが間違っている**
   - frontend/.env.local の NEXT_PUBLIC_API_URL を確認
   - 正しい値: `http://localhost:3001/api/v1`

3. **バックエンドが起動していない**
   - ターミナルでバックエンドが起動しているか確認
   - `curl http://localhost:3001/api/health` で確認

### 7.3 データベース接続エラー

**症状**: バックエンド起動時にデータベース接続エラー

**原因と対処**:
```bash
# PostgreSQLが起動しているか確認
psql -U postgres -h localhost

# データベースが存在するか確認
psql -U postgres -l | grep mmdpf_dev

# データベースが存在しない場合は作成
createdb -U postgres mmdpf_dev

# テーブルが作成されているか確認
psql -U postgres -d mmdpf_dev -c "\dt"
```

### 7.4 PINコードが届かない

**症状**: ログイン後、PINコードが表示されない

**原因と対処**:
- 開発環境では、PINコードはバックエンドのコンソールログに出力されます
- ターミナル（バックエンド）で以下のようなログを探してください:
  ```
  PIN Code for user testuser: 123456
  ```

### 7.5 AuthContainerが表示されない

**症状**: page.tsx で AuthContainer を使用しているが、旧ログイン画面が表示される

**原因と対処**:
- page.tsx の条件分岐を確認
- `isDevelopment` の判定で旧DebugLoginPanelが優先されている可能性
- AuthContainerを使用するように修正（上記 4.2 参照）
