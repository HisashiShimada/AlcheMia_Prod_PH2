# 追加問題分析: プロジェクト選択時の自動選択が動作しない

## 作成日時
2026-02-20 15:37

## 問題の症状
プロジェクト選択時に、メソッドタブが自動選択されない。

## 原因分析

### タイミングの問題を発見

**プロジェクト変更時の実行順序:**

```
1. 親コンポーネント: handleProjectChange実行
   ↓
2. 親: setSelectedMethodId(null) 実行
   ↓
3. 子コンポーネント再レンダリング（propsが変更されたため）
   ↓
4. 自動選択useEffect実行（selectedMethodIdがnullになったため）
   【問題】この時点でmethodsはまだ前のプロジェクトのメソッド！
   → 前のプロジェクトの最初のメソッドが選択されてしまう
   ↓
5. API呼び出しuseEffect実行（selectedProjectが変わったため）
   ↓
6. 新しいメソッドがsetMethods()される
   ↓
7. 自動選択useEffect実行（methodsが変わったため）
   【問題】この時点でselectedMethodIdはもうnullじゃない！
   → 条件 !selectedMethodId が満たされず、何もしない ❌
```

### 根本原因

修正前のコード：
```typescript
useEffect(() => {
  if (methods.length > 0 && !selectedMethodId) {
    // 自動選択
  }
}, [methods, selectedMethodId, onSelectMethod]);
```

**問題点:**
- `selectedMethodId`がnullにリセットされた時点で自動選択が実行される
- しかし、その時点の`methods`は**古いプロジェクトのメソッド**
- 新しいプロジェクトの`methods`が来た時には、`selectedMethodId`は既にセットされている
- 結果: 新しいプロジェクトのメソッドは自動選択されない

## 解決策

### 方法1: プロジェクトIDを監視（推奨）

プロジェクトが実際に変更されたことを検知して自動選択する：

```typescript
// 前回のプロジェクトIDを保持
const prevProjectRef = useRef<string | null>(null);

useEffect(() => {
  // プロジェクトが変更された場合
  if (selectedProject !== prevProjectRef.current) {
    prevProjectRef.current = selectedProject;
    
    // 新しいプロジェクトにメソッドがあれば自動選択
    if (methods.length > 0) {
      const sortedMethods = [...methods].sort((a, b) => a.experimentOrder - b.experimentOrder);
      onSelectMethod(sortedMethods[0].methodId);
    }
  } else if (methods.length > 0 && !selectedMethodId) {
    // プロジェクト変更でない場合、通常の自動選択ロジック
    const sortedMethods = [...methods].sort((a, b) => a.experimentOrder - b.experimentOrder);
    onSelectMethod(sortedMethods[0].methodId);
  }
}, [methods, selectedMethodId, selectedProject, onSelectMethod]);
```

### 方法2: 依存配列からselectedMethodIdを削除（シンプル）

```typescript
useEffect(() => {
  if (methods.length > 0 && !selectedMethodId) {
    const sortedMethods = [...methods].sort((a, b) => a.experimentOrder - b.experimentOrder);
    onSelectMethod(sortedMethods[0].methodId);
  }
}, [methods, onSelectMethod]);
// ↑ selectedMethodIdを削除
```

**メリット:**
- シンプル
- methodsが更新されたタイミングで確実に実行される

**デメリット:**
- selectedMethodIdの変更を監視しない
- でも、親がselectedMethodIdをnullにリセットした後、必ずmethodsも更新されるので問題ない

### 推奨: 方法2（シンプルで確実）

方法2を採用します。理由：
1. プロジェクト変更時、必ず`methods`が更新される（空配列→新しいメソッド、または前のメソッド→新しいメソッド）
2. `methods`が更新されたタイミングで自動選択を実行すれば、確実に新しいプロジェクトのメソッドが選択される
3. ユーザーの手動選択を尊重する（`!selectedMethodId`条件は維持）
4. シンプルで理解しやすい

## 修正内容

**ファイル:** `frontend/src/components/ExperimentWorker/ProgressCheckTab.tsx`

**修正箇所:**
```typescript
// 修正前（問題あり）
useEffect(() => {
  if (methods.length > 0 && !selectedMethodId) {
    const sortedMethods = [...methods].sort((a, b) => a.experimentOrder - b.experimentOrder);
    onSelectMethod(sortedMethods[0].methodId);
  }
}, [methods, selectedMethodId, onSelectMethod]);
//          ^^^^^^^^^^^^^^^^ これが原因

// 修正後（正常）
useEffect(() => {
  if (methods.length > 0 && !selectedMethodId) {
    const sortedMethods = [...methods].sort((a, b) => a.experimentOrder - b.experimentOrder);
    onSelectMethod(sortedMethods[0].methodId);
  }
}, [methods, onSelectMethod]);
//  依存配列からselectedMethodIdを削除
```

## 期待される動作（修正後）

### プロジェクト選択時
```
1. 親: handleProjectChange実行
2. 親: setSelectedMethodId(null)
3. 子コンポーネント再レンダリング
4. API呼び出しuseEffect実行（selectedProjectが変わったため）
5. 新しいメソッドがsetMethods()される
6. 自動選択useEffect実行（methodsが変わったため）
   条件チェック: methods.length > 0 && !selectedMethodId
   → 両方true！自動選択が実行される ✅
```

### ユーザーがメソッドタブをクリック
```
1. onChange発火
2. 親: setSelectedMethodId(methodId)
3. 子コンポーネント再レンダリング
4. 自動選択useEffectは実行されない（methodsは変わっていない）
   → ユーザーの選択が維持される ✅
```

### 再レンダリング時（methodsは変わらない）
```
1. 子コンポーネント再レンダリング
2. 自動選択useEffectは実行されない（methodsは変わっていない）
   → ユーザーの選択が維持される ✅
```

## まとめ

- **問題**: 依存配列に`selectedMethodId`を含めたことで、タイミングがずれた
- **解決**: 依存配列から`selectedMethodId`を削除し、`methods`の更新のみを監視
- **効果**: プロジェクト選択時の自動選択が正常に動作し、ユーザーの手動選択も維持される
