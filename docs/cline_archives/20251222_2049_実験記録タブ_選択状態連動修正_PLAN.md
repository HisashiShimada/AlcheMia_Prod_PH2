### 発生した問題と解決方法

**問題1: 型エラー**
- ExperimentRecordTab の onSelectMethod プロパティの型が `(methodId: string) => void` となっていた
- 解決: `(methodId: string | null) => void` に変更してnull値を受け入れるようにした

**問題2: 不要な自動選択ロジック**
- 実験記録タブに切り替えた際、メソッドが未選択なら自動的に最初のメソッドを選択する処理があった
- この処理がタブ間のメソッド選択引き継ぎを妨げていた
- 解決: useEffectによる自動選択ロジックを削除した

### 最終的な成果物
- [x] プロジェクト変更時の連動処理
  - プロジェクト変更時にメソッドとタスクをnullまたは空文字列にリセット
- [x] メソッド変更時の連動処理
  - メソッドが実際に変更された場合のみタスクをリセット
- [x] タブ間のメソッド選択引き継ぎ
  - 自動選択ロジックを削除し、親コンポーネントで管理されるselectedMethodIdをそのまま使用
  - 指示確認タブと実験記録タブでメソッド選択が共有される

## 12. 振り返り

### うまくいった点

1. **明確な状態管理**: 親コンポーネント（ExperimentWorkerMenu）で一元的に状態を管理することで、タブ間の連動がシンプルに実現できた

2. **適切なリセット処理**: プロジェクト変更とメソッド変更の両方で、下位の選択状態を適切にクリアすることで、ユーザーの混乱を防げた

3. **型安全性の確保**: TypeScriptの型システムを活用し、null値を適切に扱うことでバグを未然に防げた

### 改善が必要な点

特になし。要件通りに実装が完了しました。

### 学んだこと

1. **自動選択の弊害**: ユーザーの意図しない自動選択は、かえって操作性を損なうことがある。特にタブ間で状態を共有する場合は注意が必要

2. **null vs 空文字列**: Select コンポーネントでは `undefined` を使用することで「未選択」状態を明確に表現できる。`null` や空文字列 `''` よりも型安全性が高い

3. **状態リセットのタイミング**: メソッド選択ハンドラーで「実際に変更された場合のみ」タスクをリセットすることで、不要な副作用を防げた
