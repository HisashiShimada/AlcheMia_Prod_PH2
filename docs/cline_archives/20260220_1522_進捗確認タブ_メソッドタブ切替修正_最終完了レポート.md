# 最終完了レポート: メソッドタブ切替修正

## 作成日時
2026-02-20 15:39

## タスク概要
進捗確認タブにおいて、メソッドタブの切り替えが正常に動作しない問題を修正しました。

## 発生した問題（2つ）

### 問題1: ユーザーがメソッドタブをクリックしても切り替わらない
**原因**: useEffectが無条件に最初のメソッドを選択していた

### 問題2: プロジェクト選択時にメソッドタブが自動選択されない
**原因**: 依存配列に`selectedMethodId`を含めたことで、タイミングがずれた

## 最終的な修正内容

### ファイル
`frontend/src/components/ExperimentWorker/ProgressCheckTab.tsx`

### 修正箇所

**元のコード（問題あり）:**
```typescript
useEffect(() => {
  if (methods.length > 0) {
    // 常に最初のメソッドを選択してしまう
    const sortedMethods = [...methods].sort((a, b) => a.experimentOrder - b.experimentOrder);
    onSelectMethod(sortedMethods[0].methodId);
  }
}, [methods, onSelectMethod]);
```

**第1回修正（問題2が発生）:**
```typescript
useEffect(() => {
  if (methods.length > 0 && !selectedMethodId) {
    // ↑ 条件を追加したが...
    const sortedMethods = [...methods].sort((a, b) => a.experimentOrder - b.experimentOrder);
    onSelectMethod(sortedMethods[0].methodId);
  }
}, [methods, selectedMethodId, onSelectMethod]);
//          ^^^^^^^^^^^^^^^^ ← これが問題2の原因
```

**最終修正（正常）:**
```typescript
useEffect(() => {
  console.log('[DEBUG] ProgressCheckTab - Auto-select effect', {
    methodsCount: methods.length,
    selectedMethodId,
    shouldAutoSelect: methods.length > 0 && !selectedMethodId
  });
  
  if (methods.length > 0 && !selectedMethodId) {
    // ↑ 条件を維持
    const sortedMethods = [...methods].sort((a, b) => a.experimentOrder - b.experimentOrder);
    console.log('[DEBUG] ProgressCheckTab - Auto-selecting first method', {
      methodId: sortedMethods[0].methodId,
      methodName: sortedMethods[0].methodName
    });
    onSelectMethod(sortedMethods[0].methodId);
  }
}, [methods, onSelectMethod]);
// ↑ selectedMethodIdを依存配列から削除
```

## 修正のポイント

### 1. 条件追加: `&& !selectedMethodId`
- selectedMethodIdがnullの時のみ自動選択を実行
- ユーザーが選択したメソッドを上書きしない

### 2. 依存配列の最適化: `selectedMethodId`を削除
- `methods`の更新のみを監視
- プロジェクト変更時、必ず`methods`が更新されるため、そのタイミングで自動選択が実行される
- ユーザーがタブをクリックしても、`methods`は変わらないため、自動選択は実行されない

### 3. デバッグログの追加
- useEffectの実行状況を確認できるログを追加
- 問題の早期発見と追跡が容易に

## 動作フロー（修正後）

### ケース1: プロジェクト選択時
```
1. 親: handleProjectChange実行
2. 親: setSelectedMethodId(null)
3. 子コンポーネント再レンダリング

5. 新しいメソッドがsetMethods()される
6. 自動選択useEffect実行（methodsが変わったため）
   条件チェック: methods.length > 0 && !selectedMethodId
   → 両方true！自動選択が実行される ✅
7. 最初のメソッドが選択される ✅
```

### ケース2: ユーザーがメソッドタブをクリック
```
1. Tabsコンポーネントの onChange が発火
2. 親: setSelectedMethodId(methodId) が実行される
3. 子コンポーネントが再レンダリング
4. 自動選択useEffectは実行されない（methodsは変わっていない）
   → ユーザーの選択が維持される ✅
```

### ケース3: 再レンダリング（methodsは変わらない）
```
1. 子コンポーネント再レンダリング
2. 自動選択useEffectは実行されない（methodsは変わっていない）
   → 現在の選択状態が維持される ✅
```

## まとめ

### 根本原因
1. **問題1**: useEffectがユーザーの選択を無視していた
2. **問題2**: 依存配列に`selectedMethodId`を含めたことでタイミングがずれた

### 解決方法
1. **条件追加**: `!selectedMethodId`でユーザーの選択を尊重
2. **依存配列最適化**: `selectedMethodId`を削除し、`methods`の更新のみを監視

### 修正の効果
- ✅ プロジェクト選択時に最初のメソッドが自動選択される
- ✅ ユーザーがメソッドタブをクリックすると正しく切り替わる
- ✅ 複数のメソッド間を自由に切り替えられる
- ✅ シンプルで理解しやすい実装
- ✅ 既存の動作を壊さない安全な修正
