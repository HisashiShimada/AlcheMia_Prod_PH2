## 1. タスク概要

プロジェクト管理画面のファイル一覧取得API（`GET /api/v1/projects/:projectName/files`）がタイムアウトしている問題を解決します。

**根本原因**: フロントエンドのAxiosクライアント（`authUtils.ts`）のタイムアウトが**10秒**に設定されており、大量ファイルの署名付きURL生成に時間がかかる場合にタイムアウトしています。

## 5. 技術的詳細

### 現在の問題点

#### 1. フロントエンドAxiosクライアントのタイムアウトが短すぎる（根本原因）
```typescript
// frontend/src/utils/authUtils.ts
// ❌ 現在: 10秒でタイムアウト
const client = axios.create({
  baseURL: `${baseURL}`,
  timeout: 10000, // 10秒
  headers: {
    'Content-Type': 'application/json',
  },
});
```

大量ファイル（50-100ファイル以上）の署名付きURL生成には10秒以上かかる場合があり、フロントエンド側でタイムアウトエラーが発生します。

#### 2. バックエンド - ファイル一覧取得の並列処理無制限
});

// ✅ 処理時間のログ記録
console.log(`署名付きURL生成完了: ${files.length}ファイル、処理時間: ${endTime - startTime}ms`);
```

#### 3. Expressサーバーのタイムアウト設定（念のため）
```typescript
// backend/src/server.ts
const server = app.listen(PORT, () => { ... });

// ✅ タイムアウト設定追加
server.timeout = 180000; // 3分
server.headersTimeout = 240000; // 4分
server.keepAliveTimeout = 65000; // 65秒
```

#### 2. S3Clientのタイムアウト設定不足
```typescript
// backend/src/services/storageService.ts
// ❌ 現在: maxAttemptsのみ
this.s3Client = new S3Client({
  maxAttempts: 3,
  // タイムアウト設定なし
});
```

#### 3. ファイル一覧取得の並列処理無制限
```typescript

  rootFiles.map(async (file: any) => {
    const signedUrl = await storageService.getSignedUrl(...);
    // ...
  })

```

### 改善後の設計

#### 1. フロントエンドAxiosクライアントのタイムアウト延長（最重要）
```typescript
// frontend/src/utils/authUtils.ts
const client = axios.create({
  baseURL: `${baseURL}`,
  timeout: 120000, // ✅ 120秒（2分）に延長
  headers: {
    'Content-Type': 'application/json',
  },
});
```

**理由**: 
- 署名付きURL生成: 1ファイルあたり約100-200ms
- 100ファイルの場合: 10-20秒必要
- 余裕を持たせて120秒に設定

#### 2. 署名付きURL生成の並列制限（バックエンド）
```typescript
// backend/src/services/projectService.ts
// ✅ 並列数を制限（20ファイルずつ）
const chunkSize = 20;
for (let i = 0; i < rootFiles.length; i += chunkSize) {
  const chunk = rootFiles.slice(i, i + chunkSize);
  const chunkResults = await Promise.all(
    chunk.map(async (file: any) => { ... })
  );
  files.push(...chunkResults);
}
```

### セキュリティ考慮事項
- [ ] タイムアウト値が長すぎないか（DoS対策）

## 6. リスクと対策

| リスク | 影響度 | 発生確率 | 対策 |
|--------|--------|----------|------|
| タイムアウト値が短すぎて正常なリクエストも失敗 | 高 | 低 | 120秒という十分な余裕を持った値に設定 |
| タイムアウト値が長すぎてユーザー体験悪化 | 中 | 低 | 120秒は妥当（処理中のローディング表示を追加） |
| S3接続エラーでAPI全体が失敗 | 中 | 低 | グレースフルな処理（空配列を返す）を維持 |
| 大量ファイル時の処理時間増加 | 中 | 中 | 並列数制限とmaxKeys制限で対応 |
| 既存の動作への影響 | 低 | 低 | タイムアウト設定は緩和方向なので既存機能に悪影響なし |
