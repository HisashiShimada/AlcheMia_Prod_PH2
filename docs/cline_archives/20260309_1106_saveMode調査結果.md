- **調査者**: Cline

## 1. 調査結果サマリー

**結論: saveModeは現在の仕様で必要です。**

- `saveMode`はフロントエンドの指示編集ダイアログ（InstructionEditDialog.tsx）に存在
- タスク登録タブと指示登録タブで異なる保存動作を実現するために使用されている
- **タスク登録タブ**: 指示をローカルに蓄積して、タスク保存時に一括保存（`saveMode="local"`）
- **指示登録タブ**: 指示を即座にDB保存（`saveMode="immediate"`、デフォルト）

**保存処理**:
```typescript
// ステップ1: 指示をローカルstateに追加
const handleInstructionSave = useCallback((instruction: InstructionData, keepDialogOpen?: boolean) => {
  setPendingInstructions(prev => [...prev, instruction]);  // ローカルに蓄積
  message.success('指示を追加しました');
  
  if (!keepDialogOpen) {
    setIsInstructionDialogOpen(false);
    setIsProjectInstructionDialogOpen(false);
    setSelectedMethodIdForInstruction('');
  }
}, []);

// ステップ2: タスク保存時に指示をまとめてDB保存
const handleSave = useCallback(async () => {
  try {
    // ...バリデーション処理

    // チェックされた指示をフィルタリング
    const checkedInstructions = pendingInstructions.filter(inst =>
      inst.methodId === '' || checkedMethodIds.has(inst.methodId)
    );

    // API用の指示データを作成
    const instructionSaveItems: InstructionSaveItem[] = checkedInstructions.map(inst => ({
      methodId: inst.methodId,
      content: inst.content,
      priority: inst.priority,
      type: inst.type,
      targetType: inst.targetType,
      transitionId: inst.transitionId || null,
      taskNumber: inst.taskNumber || null,
    }));

    // API用のリクエストデータを作成（タスクと指示をまとめて保存）
    const requestData = {
      tasks: checkedTasks.map((task, index) => ({
        methodId: task.methodId,
        experimentCondition: task.experimentCondition,
        trialCount: task.trialCount,
        experimentOrder: index + 1,
      })),
      instructions: instructionSaveItems.length > 0 ? instructionSaveItems : undefined,
    };

    // APIを呼び出し（タスクと指示を一括保存）
    const response = await saveTaskRegistration(projectName, requestData);

    // 成功時にpendingInstructionsをクリア
    setPendingInstructions([]);
    
    message.success(response.message || t('taskRegistration.messages.saved'));
  } catch (error) {
    // エラーハンドリング
  }
}, [taskDetails, checkedTaskIds, pendingInstructions, projectName, t]);
```

**動作**: `saveMode='local'` → **ローカルに蓄積して、タスク保存時に一括DB保存**

### 2.3. バックエンドの保存処理の実装確認

**ファイル**: `backend/src/services/taskRegistrationService.ts`

**メソッド**: `saveTaskRegistration()`

**処理フロー**:
```typescript
1. プロジェクト情報を取得
2. チェックアウト状態を確認（ロックされている場合はエラー）
3. MAIMLファイル登録状態を確認（未登録の場合はエラー）
4. リクエストデータのバリデーション
5. MAIMLファイルをパース（トランザクション外）
6. トランザクション内でDB操作を実行:
   6-1. project_task: worker_linked_flg=falseのタスクを削除 → 新規INSERT
   6-2. project_task_detail: 全削除 → 新規INSERT
   6-3. transition_data: 全削除 → 新規INSERT
   6-4. template_data: 全削除 → 新規INSERT
   6-5. instructions: バッチINSERT（オプション）
```

### 2.4. 保存方式の変遷（バックエンド）

#### 以前の実装（～2026-03-09 10:28まで）
- **方式**: UPSERT方式
- **問題点**: 主キーの一部である`experiment_order`の変更ができない
- **使用メソッド**: `batchUpsertTasks()`

#### 現在の実装（2026-03-09 10:50～）
- **方式**: 削除→INSERT方式
- **変更理由**: タスクの順序（experiment_order）変更を可能にするため
- **使用メソッド**: 
  - `deleteByProjectAndWorkerLinkedFlg()` - worker_linked_flg=falseのタスクのみ削除
  - `batchInsertTasks()` - リクエストのタスクを新規INSERT
- **保護機能**: worker_linked_flg=trueのタスクは削除されず保護される

**参考**: `docs/20260309_1028_タスク保存処理_削除INSERT方式変更/PLAN.md`

## 3. saveModeの役割と設計意図

### 3.1. 2つの異なる保存フロー

#### 指示登録タブ（saveMode='immediate'）
**ユースケース**: 指示の個別管理
- 指示を1つずつ作成・編集・削除
- 各操作で即座にDB保存
- 指示一覧をリアルタイムで管理

**処理フロー**:
```
指示作成/編集
  ↓
InstructionEditDialog
  ↓
onSave コールバック
  ↓
saveInstruction() または updateInstruction() API呼び出し
  ↓
即座にDB保存
```

#### タスク登録タブ（saveMode='local'）
**ユースケース**: タスクと指示の一括登録
- タスク設定と指示作成を同時に行う
- 指示をローカルに蓄積
- タスク保存時にタスクと指示を一括DB保存

**処理フロー**:
```
指示追加（複数回可能）
  ↓
InstructionEditDialog
  ↓
onSave コールバック
  ↓
pendingInstructions ステートに追加（ローカル保存）
  ↓
（繰り返し）
  ↓
タスク保存ボタンクリック
  ↓
saveTaskRegistration() API呼び出し
  ↓
タスク + 蓄積された指示を一括DB保存
```

### 3.2. saveModeが必要な理由

1. **異なるUI/UXの実現**
   - 指示登録タブ: 指示単体の即時管理
   - タスク登録タブ: タスク設定との統合的な管理

2. **トランザクション整合性**
   - タスク登録タブでは、タスクと指示を同一トランザクションで保存
   - データの不整合を防ぐ

3. **ユーザビリティ**
   - タスク登録タブ: 複数の指示をまとめて設定してから保存
   - 指示登録タブ: 指示を個別に管理

4. **柔軟性**
   - 同じInstructionEditDialogコンポーネントを2つの異なる文脈で再利用
   - 保存動作のみを切り替え

## 6. 結論

### saveModeは現在の仕様で必要

理由：
1. **2つの異なる保存フローを実現**: タスク登録タブと指示登録タブで異なる動作
2. **コンポーネントの再利用性**: InstructionEditDialogを2つの文脈で再利用
3. **トランザクション整合性**: タスクと指示を同一トランザクションで保存（タスク登録タブ）
4. **ユーザビリティ**: それぞれのタブに最適な保存動作を提供

### 各タブの保存動作

#### 指示登録タブ（saveMode='immediate'）
- ✅ 指示の個別管理
- ✅ 即座にDB保存
- ✅ リアルタイムな指示一覧管理

#### タスク登録タブ（saveMode='local'）
- ✅ タスクと指示の統合的な管理
- ✅ 指示をローカルに蓄積
- ✅ タスク保存時に一括DB保存
- ✅ トランザクション整合性の確保

## 7. 推奨事項

### 現状維持を推奨（saveModeは削除しない）

- `saveMode`は現在の仕様で必要な機能です
- 2つの異なる保存フローを実現するために使用されています
- 削除すると、タスク登録タブの動作が壊れます

### saveModeの適切な使い方

**DO（推奨）**:
- ✅ タスク登録タブでは`saveMode="local"`を使用
- ✅ 指示登録タブでは`saveMode`を省略（デフォルトの'immediate'を使用）
- ✅ InstructionEditDialogを再利用する際は、適切なsaveModeを指定

**DON'T（非推奨）**:
- ❌ saveModeを削除しない
- ❌ タスク登録タブでsaveModeを'immediate'に変更しない
- ❌ 指示登録タブでsaveModeを'local'に変更しない

### もし将来的な拡張が必要な場合

新しい保存モードが必要になった場合は、以下の設計を検討：
1. `saveMode`の型を拡張（例: `'immediate' | 'local' | 'deferred'`）
2. onSaveコールバックの引数にモード情報を含める
3. 各タブで適切なハンドリングを実装
