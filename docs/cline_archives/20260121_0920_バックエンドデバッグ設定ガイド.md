# バックエンドデバッグ設定ガイド

## 作成日時
2026-01-21 09:20

## 概要
VS Codeでバックエンド（Node.js + TypeScript）をデバッグする方法を説明します。

---

## 🎯 デバッグ方法

### 方法1: デバッグモードで起動（推奨）

#### 1. デバッグモードでサーバーを起動

```bash
cd backend
npm run dev:debug
```

このコマンドは以下を実行します：
- TypeScriptファイルをトランスパイル
- ファイル変更時に自動再起動
- **デバッグポート9229で待機**

#### 2. VS Codeでデバッグをアタッチ

**VS Codeの操作：**

1. サイドバーの「デバッグ」アイコンをクリック（または `Ctrl+Shift+D`）
2. 上部のドロップダウンから「Attach to Backend」を選択
3. 緑色の再生ボタンをクリック（または `F5`）

#### 3. ブレークポイントを設定

VS Codeでソースファイルを開き、行番号の左側をクリックして赤い点（ブレークポイント）を設定します。

**例：**
```typescript
// backend/src/controllers/projectController.ts
export const list = async (req: Request, res: Response) => {
  // ここにブレークポイントを設定
  const organizationId = req.organizationId;
  console.log('organizationId:', organizationId);
  
  // ブレークポイントで停止すると変数の値を確認できる
  const projects = await projectService.list(organizationId);
  
  res.json({ success: true, data: projects });
};
```

#### 4. APIをリクエストしてデバッグ

フロントエンドやcurlでAPIをリクエストすると、ブレークポイントで処理が停止します。

---

### 方法2: VS Codeから直接起動

既存の`.vscode/launch.json`に以下のような設定がある場合、VS Codeから直接デバッグ起動できます。

#### VS Codeの操作：

1. デバッグビューを開く（`Ctrl+Shift+D`）
2. 「Backend: Debug」などの設定を選択
3. `F5`キーで起動

この方法では、サーバーの起動とデバッガーのアタッチが同時に行われます。

---

## 🔧 launch.json設定

`.vscode/launch.json`に以下の3つのデバッグ設定があります：

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "type": "node",
      "request": "attach",
      "name": "Attach to Backend",
      "port": 9229,
      "restart": true,
      "skipFiles": ["<node_internals>/**"],
      "sourceMaps": true,
      "outFiles": ["${workspaceFolder}/backend/dist/**/*.js"]
    },
    {
      "type": "node",
      "request": "launch",
      "name": "Backend: Debug",
      "runtimeExecutable": "npm",
      "runtimeArgs": ["run", "dev:debug"],
      "cwd": "${workspaceFolder}/backend",
      "console": "integratedTerminal",
      "skipFiles": ["<node_internals>/**"],
      "sourceMaps": true,
      "outFiles": ["${workspaceFolder}/backend/dist/**/*.js"]
    },
    {
      "type": "node",
      "request": "launch",
      "name": "Backend: Start (Legacy)",
      "program": "${workspaceFolder}/backend/src/server.ts",
      "cwd": "${workspaceFolder}/backend",
      "runtimeArgs": ["-r", "ts-node/register"],
      "envFile": "${workspaceFolder}/backend/.env",
      "sourceMaps": true,
      "skipFiles": ["<node_internals>/**"]
    }
  ]
}
```

**設定の説明：**
- **Attach to Backend** (推奨): 既に起動しているサーバーにアタッチ
  - `npm run dev:debug`で起動したサーバーに接続
  - ファイル変更時の自動再起動に対応
  
- **Backend: Debug**: VS Codeから直接起動してデバッグ
  - デバッグモードでサーバーを起動し、即座にアタッチ
  - 統合ターミナルでログを確認可能
  
- **Backend: Start (Legacy)**: 互換性のための設定
  - 古い形式の起動方法（通常は使用しない）

## 📝 デバッグ操作

### ブレークポイントの種類

| 種類 | 説明 | 設定方法 |
|------|------|----------|
| **通常のブレークポイント** | その行で常に停止 | 行番号の左をクリック |
| **条件付きブレークポイント** | 条件が真の時だけ停止 | 右クリック → 条件付きブレークポイント |
| **ログポイント** | 停止せずにログ出力 | 右クリック → ログポイント |

### デバッグツールバー

デバッグ実行中は以下の操作が可能です：

| ボタン | ショートカット | 説明 |
|--------|---------------|------|
| **続行** | `F5` | 次のブレークポイントまで実行 |
| **ステップオーバー** | `F10` | 次の行へ（関数内に入らない） |
| **ステップイン** | `F11` | 関数の中に入る |
| **ステップアウト** | `Shift+F11` | 現在の関数から抜ける |
| **再起動** | `Ctrl+Shift+F5` | デバッグを再起動 |
| **停止** | `Shift+F5` | デバッグを停止 |

### 変数の確認

デバッグ実行中は以下で変数を確認できます：

1. **変数ペイン**: 左サイドバーに現在のスコープの変数が表示
2. **ウォッチ**: 特定の変数・式を監視
3. **ホバー**: エディタ上で変数にカーソルを合わせると値が表示
4. **デバッグコンソール**: 式を評価して結果を確認

## 🚀 実際の使用例

### 例1: APIエンドポイントのデバッグ

```typescript
// backend/src/controllers/projectController.ts

export const list = async (req: Request, res: Response) => {
  try {
    // ① ここにブレークポイント - リクエスト内容を確認
    const organizationId = req.organizationId;
    const page = parseInt(req.query.page as string) || 1;
    const limit = parseInt(req.query.limit as string) || 20;
    
    // ② ここにブレークポイント - サービス呼び出し前
    const result = await projectService.list(organizationId, { page, limit });
    
    // ③ ここにブレークポイント - 結果を確認
    res.json({
      success: true,
      data: result.items,
      pagination: result.pagination
    });
  } catch (error) {
    // ④ ここにブレークポイント - エラー内容を確認
    console.error('Error in list:', error);
    res.status(500).json({ success: false, error: 'Internal server error' });
  }
};
```

### 例2: ミドルウェアのデバッグ

```typescript
// backend/src/middleware/auth.ts

export const auth = async (req: Request, res: Response, next: NextFunction) => {
  try {
    // ① ここにブレークポイント - トークンを確認
    const token = req.cookies.maiml_session;
    
    if (!token) {
      return res.status(401).json({ error: 'No token provided' });
    }
    
    // ② ここにブレークポイント - デコード結果を確認
    const decoded = jwt.verify(token, process.env.JWT_SECRET!);
    req.user = decoded;
    
    // ③ ここにブレークポイント - 次の処理へ進む前
    next();
  } catch (error) {
    // ④ ここにブレークポイント - エラー内容を確認
    res.status(401).json({ error: 'Invalid token' });
  }
};
```

### 例3: 条件付きブレークポイント

特定の条件の時だけ停止させたい場合：

```typescript
// 例: organizationIdが特定の値の時だけ停止
// 条件: organizationId === 'org_maiml_lab_001'

export const list = async (req: Request, res: Response) => {
  const organizationId = req.organizationId;  // この行に条件付きブレークポイント
  // ...
};
```

**設定方法：**
1. 行番号の左を右クリック
2. 「条件付きブレークポイント」→「式」を選択
3. `organizationId === 'org_maiml_lab_001'` と入力

## 💡 便利なTips

### 1. ログポイントを活用

停止せずにログを出力したい場合：

1. 行番号の左を右クリック
2. 「ログポイント」を選択
3. `organizationId: {organizationId}, page: {page}` のように記述

### 2. デバッグコンソールで式を評価

ブレークポイントで停止中、デバッグコンソールで以下が可能：

```javascript
// 変数の値を確認
organizationId

// 式を評価
req.query.page || 1

// 関数を実行
projectService.list(organizationId, { page: 1, limit: 10 })
```

### 3. skipFilesでnode_internalsをスキップ

`launch.json`の`skipFiles`設定により、Node.js内部のコードをスキップできます。

## ⚠️ トラブルシューティング

### 問題1: デバッガーがアタッチできない

**症状:**
```
Cannot connect to runtime process, timeout after 10000 ms
```

**解決方法:**
1. サーバーが`npm run dev:debug`で起動しているか確認
2. ポート9229が使用中でないか確認：
   ```bash
   lsof -i :9229
   ```
3. ファイアウォールがポート9229をブロックしていないか確認

### 問題2: ブレークポイントが無効になる

**症状:**
ブレークポイントがグレーアウトして「Unverified breakpoint」と表示される。

**解決方法:**
1. TypeScriptのソースマップが生成されているか確認
2. `tsconfig.json`で`sourceMap: true`を確認
3. サーバーを再起動してみる

### 問題3: 変数が表示されない

**症状:**
変数ペインに変数が表示されない、または`<value unavailable>`と表示される。

**解決方法:**
1. コードが最適化されている可能性 → `dev:debug`スクリプトで`--transpile-only`を使用
2. スコープ外の変数を参照していないか確認
3. 非同期処理の途中で停止している可能性 → 適切な位置にブレークポイントを設定

## 🎉 まとめ

**デバッグ手順（推奨）：**

1. ターミナルで起動：
   ```bash
   cd backend
   npm run dev:debug
   ```

2. VS Codeでアタッチ：
   - デバッグビューを開く（`Ctrl+Shift+D`）
   - 「Attach to Backend」を選択

3. ブレークポイントを設定してAPIをリクエスト

4. デバッグツールバーで処理を追跡
