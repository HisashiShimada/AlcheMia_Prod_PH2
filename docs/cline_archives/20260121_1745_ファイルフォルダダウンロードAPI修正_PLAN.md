## 1. タスク概要

現在のファイルダウンロードAPIは`fileId`を指定する方式ですが、以下の要件を満たすように変更します：

**新要件**:
1. ダウンロードしたい**パス**を連携する方式に変更
2. パスがファイルの場合 → ファイルの署名付きURLを返す
3. パスがフォルダの場合 → フォルダ内の全ファイルをZIP化してダウンロード
4. **実運用要件**: クエリパラメータではなく、POSTまたはURIパスで連携

## 5. 技術的詳細

### 使用する技術・ライブラリ

**ZIP圧縮ライブラリ（候補）**:
1. **archiver** (推奨)
   - ストリーミング対応
   - メモリ効率が良い
   - Node.js標準的なライブラリ
   
2. **jszip**
   - ブラウザでも動作
   - メモリ内処理

**推奨**: `archiver` - サーバーサイドでのストリーミングZIP生成に最適

### API設計案（改訂版）

#### 案1: URIパスで指定

```http
POST /api/v1/files/download/projects/Sample_Project/sample.maiml
POST /api/v1/files/download/projects/Sample_Project  # フォルダ
```

**メリット**:
- RESTfulな設計
- パスが明示的

**デメリット**:
- ルーティングが複雑（パスに`/`が含まれる）
- ファイル/フォルダの区別が難しい
- 特殊文字のエンコードが必要

#### 案2: POSTでパスとタイプを指定（推奨）

```http
POST /api/v1/files/download
Body: { 
  "path": "projects/Sample_Project/sample.maiml",
  "type": "file"
}

POST /api/v1/files/download
Body: { 
  "path": "projects/Sample_Project",
  "type": "folder"
}
```

**メリット**:
- **実運用に適している**
- 長いパスでも問題なし
- ファイル/フォルダの区別が明確
- 追加パラメータを送りやすい
- S3のプレフィックス構造に対応しやすい

**デメリット**:
- POSTなので厳密にはRESTfulではない
- ブラウザの直接ダウンロードができない（ただし署名付きURLで対応可能）

**結論**: 案2（POST + Body）を採用

### S3フォルダ（プレフィックス）の扱い

**重要**: S3には実際の「フォルダ」は存在せず、キーのプレフィックスでグルーピングされているだけです。

**S3構造例**:
```
org_maiml_lab_001/projects/Sample_Project/file1.maiml
org_maiml_lab_001/projects/Sample_Project/file2.maiml
org_maiml_lab_001/projects/Sample_Project/subdir/file3.maiml
```

**プレフィックス検索**:
- `projects/Sample_Project`をプレフィックスとして検索
- プレフィックスに一致するすべてのキーを取得（再帰的）
- サブフォルダも含めて取得される

### ファイル/フォルダ判定方法

#### 方法1: リクエストボディのtypeパラメータで判定（推奨）

```typescript
// クライアントが明示的に指定
const { path, type } = req.body;  // type: "file" | "folder"

if (type === 'folder') {
  // フォルダダウンロード処理（S3プレフィックス検索）
} else {
  // ファイルダウンロード処理（署名付きURL生成）
}
```

**メリット**: 
- 明確で曖昧さがない
- クライアント側で意図を明示
- S3のプレフィックス構造に対応しやすい

**デメリット**: クライアント側で判定が必要

#### 方法2: サーバー側でも検証（セキュリティ）

```typescript
// file_metadataで検証
const fileExists = await db
  .selectFrom('file_metadata')
  .where('file_path', 'like', `${fullPath}%`)
  .where('organization_id', '=', organizationId)
  .selectAll()
  .executeTakeFirst();

if (type === 'file' && !fileExists) {
  throw new NotFoundError('ファイルが見つかりません');
}

if (type === 'folder') {
  // プレフィックスに一致するファイルが存在するか確認
  const folderFiles = await db
    .selectFrom('file_metadata')
    .where('file_path', 'like', `${fullPath}%`)
    .where('organization_id', '=', organizationId)
    .select(['file_id'])
    .limit(1)
    .execute();
    
  if (folderFiles.length === 0) {
    throw new NotFoundError('フォルダが見つかりません');
  }
}
```

**結論**: 方法1と方法2を組み合わせる
- クライアントが`type: "file"`または`type: "folder"`を指定
- サーバー側でも存在確認と検証を行う

### フォルダZIP化の実装

```typescript
import archiver from 'archiver';
import { getStorageService } from '@/services/storageService';
import type { Response } from 'express';

/**
 * S3フォルダ（プレフィックス）をZIP化
 * 
 * S3構造例:
 * org_maiml_lab_001/projects/Sample_Project/file1.maiml
 * org_maiml_lab_001/projects/Sample_Project/file2.maiml
 * org_maiml_lab_001/projects/Sample_Project/subdir/file3.maiml
 * 
 * → "projects/Sample_Project"をプレフィックスとして検索
 */
async function createFolderZip(
  organizationPrefix: string,
  folderPath: string,
  res: Response
): Promise<void> {
  const storageService = getStorageService();
  
  // S3プレフィックスを構築
  // folderPathの末尾に'/'がない場合は追加
  const prefix = folderPath.endsWith('/') ? folderPath : `${folderPath}/`;
  
  // プレフィックスに一致するファイル一覧を取得（S3のListObjects）
  const files = await storageService.listFiles(
    organizationPrefix,
    prefix  // プレフィックスとして検索
  );
  
  // ファイル数とサイズのチェック
  if (files.length === 0) {
    throw new NotFoundError('フォルダにファイルが見つかりません');
  }
  
  if (files.length > FOLDER_DOWNLOAD_LIMITS.MAX_FILE_COUNT) {
    throw new ValidationError(
      `ファイル数が制限を超えています（最大${FOLDER_DOWNLOAD_LIMITS.MAX_FILE_COUNT}ファイル）`
    );
  }
  
  const totalSize = files.reduce((sum, file) => sum + (file.size || 0), 0);
  if (totalSize > FOLDER_DOWNLOAD_LIMITS.MAX_ZIP_SIZE) {
    throw new ValidationError(
      `フォルダサイズが制限を超えています（最大1GB）`
    );
  }
  
  // ZIPアーカイブを作成（ストリーミング）
  const archive = archiver('zip', {
    zlib: { level: 9 } // 圧縮レベル（最高圧縮）
  });
  
  // レスポンスヘッダーを設定
  const folderName = folderPath.split('/').filter(Boolean).pop() || 'download';
  res.setHeader('Content-Type', 'application/zip');
  res.setHeader('Content-Disposition', `attachment; filename="${folderName}.zip"`);
  
  // ZIPをレスポンスにパイプ
  archive.pipe(res);
  
  // 各ファイルをZIPに追加（並列ダウンロード）
  const downloadPromises = files.map(async (file) => {
    try {
      const fileContent = await storageService.downloadFile(
        organizationPrefix,
        file.key
      );
      
      // 相対パスを保持（プレフィックスを除去）
      const fullPrefix = `${organizationPrefix}/${prefix}`;
      const relativePath = file.key.replace(fullPrefix, '');
      
      archive.append(fileContent, { name: relativePath });
    } catch (error) {
      console.error(`Failed to add file to zip: ${file.key}`, error);
      // エラーがあっても処理を続行（他のファイルは追加）
    }
  });
  
  // すべてのファイルをダウンロードしてZIPに追加
  await Promise.all(downloadPromises);
  
  // ZIPを確定
  await archive.finalize();
}
```

**S3プレフィックス検索の注意点**:
1. **プレフィックス検索**: `listFiles(prefix)`でプレフィックスに一致するすべてのキーを取得
2. **再帰的取得**: サブフォルダも含めて取得される
3. **区切り文字**: プレフィックスの末尾は`/`で終わる必要がある
4. **フォルダオブジェクト**: S3にはフォルダオブジェクト自体は存在しない（キーのみ）

### セキュリティ考慮事項

**パストラバーサル攻撃の防止**:
```typescript
function validatePath(path: string): void {
  // 絶対パスを禁止
  if (path.startsWith('/')) {
    throw new ValidationError('絶対パスは使用できません');
  }
  
  // '..'を禁止
  if (path.includes('..')) {
    throw new ValidationError('不正なパスが含まれています');
  }
  
  // null byteを禁止
  if (path.includes('\0')) {
    throw new ValidationError('不正な文字が含まれています');
  }
  
  // organization_prefixが含まれていないことを確認
  if (path.startsWith('org_')) {
    throw new ValidationError('パスにorganization_prefixを含めないでください');
  }
}
```

**organization_prefix検証**:
```typescript
function buildFullPath(
  organizationPrefix: string,
  requestedPath: string
): string {
  // 必ずorganization_prefixで始まることを保証
  return `${organizationPrefix}/${requestedPath}`;
}
```

## 6. リスクと対策

| リスク | 影響度 | 発生確率 | 対策 |
|--------|--------|----------|------|
| 大容量フォルダのZIP化でメモリ不足 | 高 | 中 | ストリーミング処理、サイズ制限（1GB）、タイムアウト設定 |
| ZIP化中のタイムアウト | 中 | 中 | タイムアウト時間の延長（5分）、進捗表示 |
| パストラバーサル攻撃 | 高 | 低 | 厳格なパス検証、ホワイトリスト方式 |
| 同時ダウンロードによるサーバー負荷 | 中 | 中 | レート制限、同時実行数制限（ユーザーあたり3並列） |
| S3プレフィックス検索の性能 | 中 | 低 | ListObjectsV2の最適化、ページング |

## 7. 制限事項

### フォルダダウンロード制限

1. **最大ファイルサイズ**: 1GB（圧縮後）
2. **最大ファイル数**: 1,000ファイル
3. **タイムアウト**: 5分
4. **同時ダウンロード数**: ユーザーあたり3並列まで

### 実装上の制限

```typescript
const FOLDER_DOWNLOAD_LIMITS = {
  MAX_ZIP_SIZE: 1024 * 1024 * 1024,  // 1GB
  MAX_FILE_COUNT: 1000,
  TIMEOUT_MS: 5 * 60 * 1000,  // 5分
  MAX_CONCURRENT_DOWNLOADS: 3
};
```

## 8. API仕様（最終案）

### エンドポイント

```
POST /api/v1/files/download
```

### リクエストボディ

**Content-Type**: `application/json`

**パラメータ**:
| パラメータ | 型 | 必須 | 説明 | 例 |
|----------|---|------|------|-----|
| `path` | string | ○ | ダウンロードするパス（相対パス、organization_prefix不要） | `projects/Sample_Project/sample.maiml` |
| `type` | string | ○ | ダウンロードタイプ（`file` または `folder`） | `file` |
| `expires` | integer | × | 有効期限（秒、デフォルト: 3600、ファイルのみ） | `7200` |

**リクエスト例（ファイル）**:
```json
{
  "path": "projects/Sample_Project/sample.maiml",
  "type": "file",
  "expires": 3600
}
```

**リクエスト例（フォルダ）**:
```json
{
  "path": "projects/Sample_Project",
  "type": "folder"
}
```

**パスの形式**:
- ファイル: `projects/Sample_Project/sample.maiml`
- フォルダ: `projects/Sample_Project` （末尾の`/`は不要、自動補完）
- **重要**: organization_prefixは含めない（サーバー側で自動付与）

### レスポンス

#### ファイルの場合（署名付きURL）

**Status**: 200 OK

```json
{
  "success": true,
  "data": {
    "type": "file",
    "file_name": "sample.maiml",
    "file_path": "org_maiml_lab_001/projects/Sample_Project/sample.maiml",
    "file_size": 12345,
    "download_url": "https://s3.amazonaws.com/...",
    "expires_at": "2026-01-21T18:00:00Z",
    "expires_in": 3600
  },
  "meta": {
    "timestamp": "2026-01-21T17:00:00Z",
    "requestId": "req_abc123"
  }
}
```

#### フォルダの場合（ZIP直接ダウンロード）

**Status**: 200 OK  
**Content-Type**: `application/zip`  
**Content-Disposition**: `attachment; filename="Sample_Project.zip"`

**レスポンスボディ**: ZIPファイルのバイナリデータ（ストリーミング）

**注意**: フォルダの場合、JSONレスポンスではなく、直接ZIPファイルをストリーミングで返します。

### エラーレスポンス

```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_INVALID_PATH",
    "message": "不正なパスが指定されています",
    "details": ["パスに'..'が含まれています"]
  },
  "meta": {
    "timestamp": "2026-01-21T17:00:00Z",
    "requestId": "req_abc123"
  }
}
```

**エラーコード**:
- `VALIDATION_INVALID_PATH`: 不正なパス
- `VALIDATION_INVALID_TYPE`: 不正なtype（"file"または"folder"以外）
- `VALIDATION_PATH_TOO_LONG`: パスが長すぎる
- `RESOURCE_NOT_FOUND`: ファイル/フォルダが存在しない
- `FOLDER_EMPTY`: フォルダにファイルが存在しない
- `FOLDER_TOO_LARGE`: フォルダのサイズが制限を超過
- `FOLDER_TOO_MANY_FILES`: ファイル数が制限を超過
- `PERMISSION_INSUFFICIENT`: アクセス権限不足
