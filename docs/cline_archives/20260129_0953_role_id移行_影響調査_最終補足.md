# role → role_id 移行影響調査 最終補足レポート

## 📢 最も重要な前提条件の確定

### roleテーブルの実際の構造

**roleテーブルに格納されているデータ:**
```
role_id: 'ROLE001', 'ROLE002', 'ROLE003', ...
role_name: 'システム管理者', 'プロバイダー', 'データ管理者', ...（日本語表示名）
```

**現在のコードで使用している値:**
```
role: 'provider', 'system_admin', 'data_admin', ...（英語識別子）
```

### 問題点

roleテーブルのrole_nameには**日本語名のみ**が格納されているため、roleテーブルとJOINしても**英語識別子（'provider'等）は取得できません**。

---

## 🔄 修正方法の大幅な変更

### オプション1: roleテーブルに英語識別子カラムを追加（推奨）

**roleテーブルにrole_code（またはrole_key）カラムを追加:**

```sql
ALTER TABLE role ADD COLUMN role_code VARCHAR(30) NOT NULL;

UPDATE role SET role_code = 
  CASE role_id
    WHEN 'ROLE001' THEN 'provider'
    WHEN 'ROLE002' THEN 'system_admin'
    WHEN 'ROLE003' THEN 'data_admin'
    WHEN 'ROLE004' THEN 'experiment_admin'
    WHEN 'ROLE005' THEN 'experiment_worker'
    WHEN 'ROLE006' THEN 'mi_engineer'
  END;

CREATE UNIQUE INDEX idx_role_code ON role(role_code);
```

**roleテーブル構造（修正後）:**
```
role_id    | role_name        | role_code
-----------|------------------|------------------
ROLE001    | プロバイダー      | provider
ROLE002    | システム管理者    | system_admin
ROLE003    | データ管理者      | data_admin
ROLE004    | 実験管理者        | experiment_admin
ROLE005    | 実験作業者        | experiment_worker
ROLE006    | MIエンジニア      | mi_engineer
```

**SQLクエリ修正:**
```sql
SELECT 
  ou.user_id,
  ou.user_name,
  ou.mail_address,
  ou.role_id,           -- 'ROLE001'等
  r.role_code,          -- 'provider'等（既存コードで使用）
  r.role_name,          -- 'プロバイダー'等（表示用）
  ou.organization_id,
  ou.is_active,
  ou.locked_until
FROM organization_user ou
LEFT JOIN role r ON ou.role_id = r.role_id
WHERE ou.user_name = $1 AND ou.organization_id = $2
```

**既存コードでの使用:**
```typescript
// role_codeを使用（既存と同じ）
const user = userResult.rows[0];
const redirectUrl = REDIRECT_URLS[row.role_code as UserRole];
const maxAge = SESSION_MAX_AGE[row.role_code as UserRole];

// JWTペイロードにもrole_codeを格納
const jwtResult = await jwtService.generate({
  userId: userInfo.id,
  organizationId: userInfo.organizationId,
  role: row.role_code,  // 'provider', 'system_admin'等
  sessionId: uuidv4(),
  permissions,
}, row.role_code);
```

**メリット:**
- 既存コードの変更が最小限
- マッピングオブジェクト（ROLE_REDIRECT_URL等）をそのまま使用可能
- 型定義の変更不要

**デメリット:**
- roleテーブルのスキーマ変更が必要

### オプション2: コードでrole_idから英語識別子へのマッピングを定義

**backend/src/constants/roleMapping.ts を新規作成:**

```typescript
/**
 * role_idから英語識別子へのマッピング
 */
export const ROLE_ID_TO_CODE: Record<string, UserRole> = {
  'ROLE001': 'provider',
  'ROLE002': 'system_admin',
  'ROLE003': 'data_admin',
  'ROLE004': 'experiment_admin',
  'ROLE005': 'experiment_worker',
  'ROLE006': 'mi_engineer',
} as const;

/**
 * role_idから英語識別子に変換
 */
export function getRoleCodeFromId(roleId: string): UserRole | null {
  return ROLE_ID_TO_CODE[roleId] || null;
}
```

**SQLクエリ修正:**
```sql
SELECT 
  ou.user_id,
  ou.user_name,
  ou.mail_address,
  ou.role_id,           -- 'ROLE001'等（これを変換する）
  r.role_name,          -- 'プロバイダー'等（表示用）
  ou.organization_id,
  ou.is_active,
  ou.locked_until
FROM organization_user ou
LEFT JOIN role r ON ou.role_id = r.role_id
WHERE ou.user_name = $1 AND ou.organization_id = $2
```

**既存コードでの使用:**
```typescript
import { getRoleCodeFromId } from '../constants/roleMapping';

const user = userResult.rows[0];
const roleCode = getRoleCodeFromId(user.role_id);

if (!roleCode) {
  throw new Error(`Unknown role_id: ${user.role_id}`);
}

const redirectUrl = REDIRECT_URLS[roleCode];
const maxAge = SESSION_MAX_AGE[roleCode];

const jwtResult = await jwtService.generate({
  userId: userInfo.id,
  organizationId: userInfo.organizationId,
  role: roleCode,  // 'provider', 'system_admin'等
  sessionId: uuidv4(),
  permissions,
}, roleCode);
```

**メリット:**
- roleテーブルのスキーマ変更不要
- マッピングをコードで管理できる

**デメリット:**
- 全てのrole_id使用箇所で変換処理が必要
- コード変更箇所が多い
- マッピング定義のメンテナンスが必要

## 📊 修正の推奨順序（最終版）

### 推奨: オプション1を採用

#### Phase 1: roleテーブルにrole_codeカラムを追加
```sql
-- 1. カラム追加
ALTER TABLE role ADD COLUMN role_code VARCHAR(30) NOT NULL DEFAULT '';

-- 2. データ投入
UPDATE role SET role_code = 
  CASE role_id
    WHEN 'ROLE001' THEN 'provider'
    WHEN 'ROLE002' THEN 'system_admin'
    WHEN 'ROLE003' THEN 'data_admin'
    WHEN 'ROLE004' THEN 'experiment_admin'
    WHEN 'ROLE005' THEN 'experiment_worker'
    WHEN 'ROLE006' THEN 'mi_engineer'
  END;

-- 3. UNIQUE制約追加
CREATE UNIQUE INDEX idx_role_code ON role(role_code);

-- 4. NOT NULL制約確認
ALTER TABLE role ALTER COLUMN role_code SET NOT NULL;
```

#### Phase 2: organization_userテーブルの移行
```sql
-- 1. role_idカラム追加（NULLable）
ALTER TABLE organization_user ADD COLUMN role_id VARCHAR(30);

-- 2. 既存roleデータからrole_idへ変換
UPDATE organization_user
SET role_id = CASE role
  WHEN 'provider' THEN 'ROLE001'
  WHEN 'system_admin' THEN 'ROLE002'
  WHEN 'data_admin' THEN 'ROLE003'
  WHEN 'experiment_admin' THEN 'ROLE004'
  WHEN 'experiment_worker' THEN 'ROLE005'
  WHEN 'mi_engineer' THEN 'ROLE006'
END;

-- 3. 外部キー制約追加
ALTER TABLE organization_user
ADD CONSTRAINT fk_organization_user_role
FOREIGN KEY (role_id) REFERENCES role(role_id);

-- 4. NOT NULL制約追加
ALTER TABLE organization_user ALTER COLUMN role_id SET NOT NULL;

-- 5. roleカラムをDEPRECATED化（削除はPhase 6で）
-- COMMENT ON COLUMN organization_user.role IS 'DEPRECATED: Use role_id instead';
```

## 🎯 修正難易度の再評価

### 最終評価: 中

**理由:**
- roleテーブルにrole_codeカラムを追加すれば、既存コードの変更は最小限
- SQLクエリの修正（2箇所）とテストデータの修正（12ファイル）が主な作業
- マッピングオブジェクトや型定義は変更不要

## 📋 最終的な影響箇所まとめ

### データベース変更（必須）
1. **roleテーブル**: role_codeカラム追加
2. **organization_userテーブル**: role_idカラム追加、roleカラムDEPRECATED化

### SQLクエリ修正（2箇所）
1. **backend/src/controllers/authController.ts** - ログイン時のクエリ
2. **backend/src/services/pinCodeService.ts** - PINコード検証時のクエリ

### テストデータ修正（12ファイル）
- DBモックデータに`role_id`, `role_code`, `role_name`を追加
- JWTペイロードは変更不要

### コードロジック修正
- **不要**（SQLクエリでrole_codeをroleとしてエイリアスすれば、既存コードそのまま）

## 結論

**roleテーブルのrole_nameが日本語である**という制約により、**roleテーブルにrole_codeカラムを追加する**ことが最も効率的な解決策です。

これにより：
1. 既存コードの変更を最小限に抑えられる
2. マッピングオブジェクトや型定義は変更不要
3. SQLクエリの修正のみで対応可能

**推奨される移行方式: オプションA（段階的移行） + role_codeカラム追加**
