# buildPropertyXML関数の動作差異分析レポート

## 概要

`reactFlowToMaiml.ts`（TypeScript版）と`reactFlowToMaiml.js`（JavaScript版）の`buildPropertyXML`関数における動作の違いをまとめたレポートです。

## 実施日
2026年3月2日

## 対象ファイル

1. **TypeScript版**: `frontend/src/components/editorv2/utils/converters/reactFlowToMaiml.ts`
2. **JavaScript版**: `../../Downloads/MaiML_Viewer-main 2/MaiML_Viewer-main/frontend/src/components/PetriNetEditorV2/utils/converters/reactFlowToMaiml.js`

---

## 主要な差異

### 1. プロパティ名の取得方法

| 項目 | TypeScript版 | JavaScript版 |
|------|-------------|-------------|
| プロパティ名 | `prop.key` のみ | `prop.key \|\| prop.name` |

**影響**:
- JS版は`name`をフォールバックとして使用可能
- TS版は`key`が必須

---

### 2. xsi:type属性の取得方法

#### TypeScript版
```typescript
const propType = prop.xsiType || 'stringType';
```

#### JavaScript版
```javascript
const propType = prop.attributes?.['xsi:type'] || prop.type || prop.xsiType || 'stringType';
```

**差異ポイント**:
- JS版は複数のフォールバックパスを持つ
  1. `prop.attributes?.['xsi:type']`（優先）
  2. `prop.type`
  3. `prop.xsiType`
  4. デフォルト値
- TS版は`prop.xsiType`のみ

---

### 3. 属性の出力処理（最も重要な差異）

#### TypeScript版
```typescript
// 固定された3つの属性のみを処理
if (prop.units || prop.units) {  // ※同じプロパティを2回チェック（バグ？）
  propertyXml += ` units="${escapeXml(prop.units || prop.units)}"`;
}
if (prop.formatString) {
  propertyXml += ` formatString="${escapeXml(prop.formatString)}"`;
}
if (prop.scaleFactor) {
  propertyXml += ` scaleFactor="${escapeXml(prop.scaleFactor)}"`;
}
```

#### JavaScript版
```javascript
// NestedPropertyEditor形式の属性出力（動的）
if (prop.attributes) {
  Object.entries(prop.attributes).forEach(([attrName, attrValue]) => {
    if (attrName !== 'xsi:type' && attrValue) {
      propertyXml += ` ${attrName}="${escapeXml(attrValue)}"`;
    }
  });
}
// MaiMLParser形式の属性出力（固定）
else {
  if (prop.units || prop.unit) {
    propertyXml += ` units="${escapeXml(prop.units || prop.unit)}"`;
  }
  if (prop.formatString) {
    propertyXml += ` formatString="${escapeXml(prop.formatString)}"`;
  }
  if (prop.scaleFactor) {
    propertyXml += ` scaleFactor="${escapeXml(prop.scaleFactor)}"`;
  }
}
```

**重要な差異**:
- **JS版は2つのフォーマットに対応**:
  1. **NestedPropertyEditor形式**: `prop.attributes`オブジェクトから全属性を動的に出力
  2. **MaiMLParser形式**: 特定の属性のみを出力
- **TS版は1つのフォーマットのみ**:
  - 特定の属性のみを固定的に出力
  - `prop.units`を2回チェックしている（おそらくバグ）

---

### 4. elements要素の処理

#### TypeScript版
```typescript
// elements要素の処理なし
```

#### JavaScript版
```javascript
// NestedPropertyEditor形式: elements（description, value等）を出力
if (prop.elements && Object.keys(prop.elements).length > 0) {
  Object.entries(prop.elements).forEach(([elemName, elemValue]) => {
    if (elemValue !== undefined && elemValue !== '') {
      propertyXml += `${indent}  <${elemName}>${escapeXml(elemValue)}</${elemName}>\n`;
    }
  });
}
```

**差異ポイント**:
- JS版は`prop.elements`オブジェクトから子要素を動的に生成
- TS版はこの処理が完全に欠落

---

### 5. propertyListTypeの子要素処理

#### TypeScript版
```typescript
if (propType === 'propertyListType') {
  // MaiMLParser形式のみ: prop.properties
  if (prop.properties && Array.isArray(prop.properties) && prop.properties.length > 0) {
    prop.properties.forEach(childProp => {
      propertyXml += buildPropertyXML(childProp, indentLevel + 1);
    });
  }
}
```

#### JavaScript版
```javascript
if (propType === 'propertyListType') {
  // NestedPropertyEditor形式: prop.children（優先）
  if (prop.children && Array.isArray(prop.children) && prop.children.length > 0) {
    prop.children.forEach(childProp => {
      propertyXml += buildPropertyXML(childProp, indentLevel + 1);
    });
  }
  // MaiMLParser形式: prop.properties（フォールバック）
  else if (prop.properties && Array.isArray(prop.properties) && prop.properties.length > 0) {
    prop.properties.forEach(childProp => {
      propertyXml += buildPropertyXML(childProp, indentLevel + 1);
    });
  }
}
```

**差異ポイント**:
- JS版は`prop.children`を優先し、存在しない場合は`prop.properties`を使用
- TS版は`prop.properties`のみをサポート

---

### 6. content要素の処理

#### TypeScript版
```typescript
else if (propType === 'content' || propType === 'contentDoubleListType' || propType === 'contentListType') {
  prop.contents.forEach((content) => {
    propertyXml += buildContentXML(content, indentLevel + 1);
  })
}
```

#### JavaScript版
```javascript
else if (propType === 'content' || propType === 'contentDoubleListType' || propType === 'contentListType') {
  propertyXml += buildContentXML(prop, indentLevel + 1);
}
```

**重要な差異**:
- **TS版**: `prop.contents`配列を想定し、各要素を個別に処理
- **JS版**: `prop`オブジェクト自体を`buildContentXML`に渡す

**データ構造の想定の違い**:
```typescript
// TS版が想定する構造
{
  xsiType: 'contentDoubleListType',
  contents: [
    { axis: 'x', size: '100', ... },
    { axis: 'y', size: '100', ... }
  ]
}

// JS版が想定する構造
{
  xsiType: 'contentDoubleListType',
  axis: 'x',
  size: '100',
  ...
}
```

### 7. 通常のpropertyの処理（description/value）

#### TypeScript版
```typescript
else {
  // description（MaiMLParser形式専用）
  if (prop.description !== undefined && prop.description !== '') {
    propertyXml += `${indent}  <description>${escapeXml(prop.description)}</description>\n`;
  }
  // value
  const value = prop.value|| '';
  if (value !== '') {
    propertyXml += `${indent}  <value>${escapeXml(String(value))}</value>\n`;
  }
}
```

#### JavaScript版
```javascript
else if (!prop.elements) {  // elementsがない場合のみ
  // description（MaiMLParser形式専用）
  if (prop.description !== undefined && prop.description !== '') {
    propertyXml += `${indent}  <description>${escapeXml(prop.description)}</description>\n`;
  }
  // value
  const value = prop.value || prop.defaultValue || '';
  if (value !== '') {
    propertyXml += `${indent}  <value>${escapeXml(value)}</value>\n`;
  }
}
```

**差異ポイント**:
- **JS版**: `!prop.elements`条件でelementsとの重複を回避
- **JS版**: `prop.defaultValue`をフォールバックとして使用
- **TS版**: `String(value)`で型変換を明示

## 潜在的な問題点

### TypeScript版の問題

1. **属性チェックの重複**
   ```typescript
   if (prop.units || prop.units) {  // 同じプロパティを2回チェック
   ```
   おそらく`prop.units || prop.unit`の意図

2. **NestedPropertyEditor形式への非対応**
   - `prop.attributes`オブジェクトを無視
   - `prop.elements`オブジェクトを無視
   - `prop.children`配列を無視

3. **content要素のデータ構造の不一致**
   - `prop.contents`配列を想定しているが、実際のデータが単一オブジェクトの可能性

### JavaScript版の問題

1. **content要素の処理の曖昧性**
   - `buildContentXML(prop, ...)`でpropオブジェクト全体を渡している
   - content専用のデータ構造を想定していない

## 推奨事項

### 短期的対応

1. **TypeScript版のバグ修正**
   ```typescript
   // 修正前
   if (prop.units || prop.units) {
   
   // 修正後
   if (prop.units || prop.unit) {
   ```

2. **content要素の処理統一**
   - データ構造の仕様を明確化
   - 配列形式か単一オブジェクト形式かを決定

### 長期的対応

1. **NestedPropertyEditor形式への対応**
   - TypeScript版にJavaScript版の機能を移植
   - `prop.attributes`、`prop.elements`、`prop.children`のサポート

2. **型定義の整備**
   - `Property`型に以下を追加:
     ```typescript
     attributes?: Record<string, string>;
     elements?: Record<string, string>;
     children?: Property[];
     unit?: string;
     defaultValue?: string;
     ```

3. **テストケースの追加**
   - 両形式のデータでのテスト
   - エッジケースのカバレッジ向上

---

## 結論

**JavaScript版の方が柔軟性が高く、2つのデータ形式に対応している**が、**TypeScript版は型安全性を重視しつつ、基本的なMaiMLParser形式のみに対応**している状態です。

今後の開発では、**JavaScript版の柔軟性をTypeScript版に取り込みつつ、型安全性を維持する**方向での統合が推奨されます。
