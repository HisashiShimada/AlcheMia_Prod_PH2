## 1. タスク概要

### 背景

現在、`backend/reference/schemas/`にあるXSDファイルから型定義を生成するスクリプト(`backend/scripts/generate-types-from-xsd.ts`)が存在するが、生成された型定義(`frontend/src/types/maiml-schema.ts`)には**実際のMAIMLファイルと多くの差異**がある。

### 調査結果サマリー

`backend/reference/samples/type-vs-actual-maiml-comparison.md`での分析により判明した主な問題:

1. ❌ **GlobalObjectContentGroupの欠落**: `uuid`, `name`, `description`が型定義に反映されていない
2. ❌ **Property要素の構造不完全**: `value`子要素と`description`子要素が欠落
3. ❌ **動的型指定の未サポート**: `xsi:type`による実行時の型判別情報がない
4. ⚠️ **実用性40%**: Property要素が不完全で実用困難

### 目的

XSDスキーマから**実際のMAIMLファイルに完全対応した型定義**を自動生成できるようにする。

**活用シナリオ:**

##### 1. パーサー入力型としての活用（推奨）

```typescript
// maimlParserExp.ts の改善版
import type { MaimlRootType } from '@/types/maiml-unified';
import type { ParsedTemplate } from '@/components/editorv2/types';

export class MaiMLParserExp {
  // ✅ 統合型定義を入力型として使用
  private data: MaimlRootType;
  
  constructor(maimlData: string | MaimlRootType) {
    if (typeof maimlData === 'string') {
      // xml-jsでパース → 統合型定義に準拠
      this.data = xmljs.xml2js(maimlData) as MaimlRootType;
    } else {
      this.data = maimlData;
    }
  }
  
  // ✅ 統合型定義から UI用型に変換
  getTemplates(): TemplateCategories {
    const protocol = this.data.maiml?.protocol;
    const templates = {
      materials: this.convertToUITemplates(protocol.method.program.materialTemplate),
      conditions: this.convertToUITemplates(protocol.method.program.conditionTemplate),
      results: this.convertToUITemplates(protocol.method.program.resultTemplate)
    };
    return templates;
  }
  
  // 統合型定義 → UI用型への変換
  private convertToUITemplates(templates: MaterialTemplate[]): ParsedTemplate[] {
    return templates.map(t => ({
      id: t.id,
      type: 'material',
      name: t.name || t.id,
      properties: this.convertProperties(t.property),
      // ...
    }));
  }
}
```
