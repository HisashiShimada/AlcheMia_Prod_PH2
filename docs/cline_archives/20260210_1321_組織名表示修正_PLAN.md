## 1. タスク概要

ログイン後に右上のヘッダーに表示されるユーザー情報で、現在は組織ID（例: `a0718dc5-21f3-44e6-87e9-cc2ae83f3385`）がそのまま表示されている。これをorganizationテーブルの`organization_name`（例: `MaiML Lab`）を表示するように修正する。

## 2. 目的と期待される成果

### 目的
- ユーザーにとって分かりやすい組織名を表示し、UXを向上させる

### 期待される成果
- [x] ヘッダーに組織IDではなく組織名が表示される
- [x] ログイン・トークン更新など全ての認証フローで正しく動作する

## 3. 問題の原因

### 調査結果
1. **フロントエンド（Header.tsx）**
   - `user.organizationName` を正しく表示している（問題なし）

2. **バックエンド（authHelpers.ts）**
   - **Line 109**: `organizationName: user.organization_id,` となっている（❌問題箇所）
   - 本来は `organization_name` を取得すべきだが、`organization_id` を設定している
   - このため、フロントエンドには組織IDが返される

3. **他の箇所の状況**
   - `authController.ts` の `verifyPin()`: `pinCodeService.verify()` から正しく `organization_name` を取得している
   - `pinCodeService.ts` の `verify()`: organizationテーブルをLEFT JOINして `organization_name` を取得している（正常）
   - `authController.ts` の `refreshToken()`: organization_nameを取得していない（要修正）

const userQuery = `

## 13. 振り返り

### うまくいった点
- 問題の原因を迅速に特定できた（authHelpers.tsのLine 109）
- 影響範囲を適切に把握できた（2ファイルのみ）
- LEFT JOINを使用することで、organizationテーブルにデータがない場合のフォールバック処理も実装

### 改善が必要な点
- 今後は型定義とレスポンス値の不一致を防ぐため、コードレビューを強化
- organization_nameのようなユーザー向け情報は、最初から必ず取得するようにする

### 学んだこと
- 認証フローでは複数の箇所（login, verifyPin, refreshToken, PIN免除）で同じユーザー情報を返すため、共通化（authHelpers.ts）が重要
- データベースから取得する情報とレスポンスで返す情報の整合性チェックが必要
- LEFT JOINを使用することで、データがない場合のフォールバック処理が容易になる
