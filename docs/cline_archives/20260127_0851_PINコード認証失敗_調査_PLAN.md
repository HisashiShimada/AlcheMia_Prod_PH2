## 6. 調査記録

### 実施日時
開始: 2026-01-27 08:51
完了: 2026-01-27 08:54

### 発見事項

#### 1. フロントエンドの実装
- `authService.ts`のリクエストインターセプターは、SessionStorageから`sessionToken`を自動取得してAuthorizationヘッダーに設定している
- `AuthContainer.tsx`の`handleLoginSuccess`では、sessionTokenをコンポーネントのstateには保存しているが、**SessionStorageには保存していない**

#### 2. バックエンドの実装  
- `authController.ts`の`verifyPin`は、Authorizationヘッダーが必須
- ヘッダーがない場合、400エラー「Authorizationヘッダーが必要です」を返す

#### 3. 処理フロー
1. ログイン成功時：sessionTokenをstateにのみ保存
2. PINコード検証時：リクエストインターセプターがSessionStorageから取得を試みる
3. SessionStorageにトークンがないため、Authorizationヘッダーが設定されない
4. バックエンドで400エラーが返される

### 原因

**ログイン成功時にsessionTokenをSessionStorageに保存していないため、PINコード検証リクエスト時にAuthorizationヘッダーが設定されない**

### 解決方法

`frontend/src/components/auth/AuthContainer.tsx`を以下のように修正しました。

#### 修正1: ログイン成功時にSessionStorageに保存
```typescript
const handleLoginSuccess = (response: LoginResponse) => {
  // SessionStorageに保存（authServiceのインターセプターが参照）
  if (typeof window !== 'undefined') {
    sessionStorage.setItem('sessionToken', response.sessionToken);
  }
  
  setSessionToken(response.sessionToken);
  setMaskedEmail(response.email);
  setPinExpiresIn(response.expiresIn);
  setFlowState('pin-input');
  
  message.success(response.message);
};
```

#### 修正2: ログイン画面に戻る際にSessionStorageをクリア
```typescript
const handleBackToLogin = () => {
  // SessionStorageをクリア
  if (typeof window !== 'undefined') {
    sessionStorage.removeItem('sessionToken');
  }
  
  setFlowState('login');
  setSessionToken(null);
  setMaskedEmail(null);
  setPinExpiresIn(null);
};
```

#### 修正3: 試行回数超過時にSessionStorageをクリア
```typescript
const handlePINMaxAttemptsExceeded = () => {
  message.error('PINコード入力試行回数の上限に達しました。最初からやり直してください');
  
  // SessionStorageをクリア
  if (typeof window !== 'undefined') {
    sessionStorage.removeItem('sessionToken');
  }
  
  setFlowState('login');
  setSessionToken(null);
  setMaskedEmail(null);
  setPinExpiresIn(null);
};
```

### 根本原因の分析
**なぜこの問題が発生したか:**
1. 最近のAPI認証ヘッダー共通化（docs/20260126_1719_API認証ヘッダー共通化_PLAN.md）により、authService.tsのリクエストインターセプターでSessionStorageからトークンを自動取得する実装に変更された
2. しかし、ログイン成功時にsessionTokenをSessionStorageに保存する処理が追加されていなかった
3. そのため、PINコード検証時にAuthorizationヘッダーが設定されず、バックエンドで400エラーが返されていた

**今後の対策:**
- 認証フロー変更時は、全ての関連コンポーネント（AuthContainer、page.tsx等）を漏れなく修正する
- SessionStorage/LocalStorageの保存・削除処理は一箇所に集約することを検討
