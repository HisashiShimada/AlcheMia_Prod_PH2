# 完了レポート: メソッドタブ切替修正

## 作成日時
2026-02-20 15:33

## タスク概要
進捗確認タブにおいて、未選択のメソッドタブをクリックしても、そのメソッドに切り替わらない問題を修正しました。

## 実施内容

### Phase 1: 原因調査（完了）

1. **ProgressCheckTab.tsxの確認**
   - Tabsコンポーネントの実装を確認
   - useEffectによる自動選択ロジックを確認

2. **親コンポーネント（ExperimentWorkerMenu.tsx）の確認**
   - 状態管理とハンドラーの実装を確認
   - 親コンポーネントの実装は正常であることを確認

3. **原因の特定**
   - useEffectがユーザーの選択を無視して常に最初のメソッドを選択していた
   - `selectedMethodId`の状態チェックがなかったため、既存の選択を上書きしていた

4. **原因分析レポート作成**
   - 詳細な問題分析と解決策をドキュメント化
   - ファイル: `原因分析レポート.md`

### Phase 2: 修正実装（完了）

#### 修正箇所
**ファイル**: `frontend/src/components/ExperimentWorker/ProgressCheckTab.tsx`

#### 修正内容

**修正前:**
```typescript
useEffect(() => {
  if (methods.length > 0) {
    // 実験順序でソートして最も小さいメソッドを選択
    const sortedMethods = [...methods].sort((a, b) => a.experimentOrder - b.experimentOrder);
    onSelectMethod(sortedMethods[0].methodId);
  }
}, [methods, onSelectMethod]);
```

**修正後:**
```typescript
useEffect(() => {
  console.log('[DEBUG] ProgressCheckTab - Auto-select effect', {
    methodsCount: methods.length,
    selectedMethodId,
    shouldAutoSelect: methods.length > 0 && !selectedMethodId
  });
  
  if (methods.length > 0 && !selectedMethodId) {
    // ↑ selectedMethodIdがnullの時のみ実行
    // 実験順序でソートして最も小さいメソッドを選択
    const sortedMethods = [...methods].sort((a, b) => a.experimentOrder - b.experimentOrder);
    console.log('[DEBUG] ProgressCheckTab - Auto-selecting first method', {
      methodId: sortedMethods[0].methodId,
      methodName: sortedMethods[0].methodName
    });
    onSelectMethod(sortedMethods[0].methodId);
  }
}, [methods, selectedMethodId, onSelectMethod]);
```

#### 変更点

1. **条件追加**: `&& !selectedMethodId`
   - selectedMethodIdがnullの時のみ自動選択を実行
   - ユーザーが選択したメソッドを上書きしない

2. **依存配列更新**: `[methods, selectedMethodId, onSelectMethod]`
   - selectedMethodIdを依存配列に追加
   - 状態変化を正しく追跡

3. **デバッグログ追加**
   - useEffectの実行状況を確認できるログを追加
   - 問題の早期発見と追跡が容易に

## 期待される動作

```
1. ユーザーがメソッドタブ2をクリック
   ↓
2. onChange が発火、親コンポーネントでselectedMethodIdが更新される
   ↓
3. 子コンポーネントが再レンダリング
   ↓
4. 【問題】useEffect が再実行され、最初のメソッドに戻る ❌
```

### 修正後（正常）
```
1. ユーザーがメソッドタブ2をクリック
   ↓
2. onChange が発火、親コンポーネントでselectedMethodIdが更新される
   ↓
3. 子コンポーネントが再レンダリング
   ↓
4. useEffect が実行されるが、selectedMethodId !== null なので何もしない ✅
   ↓
5. メソッドタブ2が選択された状態で表示される ✅
```

## リスク評価

### リスク: 低

**理由:**
1. 修正範囲が1箇所のみで限定的
2. 条件追加のみで、既存のロジックを変更していない
3. プロジェクト変更時の自動選択は維持される（親がselectedMethodIdをnullにリセットするため）
4. 後方互換性を保持

### 想定されるエッジケース

すべて対応済み：

1. ✅ プロジェクト未選択時 → 自動選択は実行されない（methods.length === 0）
2. ✅ プロジェクト切り替え時 → 正しく自動選択される（親がselectedMethodIdをnullにリセット）
3. ✅ メソッドが1つのみ → 問題なし（最初のメソッドが選択され、切り替えの必要なし）
4. ✅ メソッドが0件 → 空状態が表示される

## まとめ

### 根本原因
useEffectがユーザーの選択を無視して常に最初のメソッドを選択していた

### 解決方法
`!selectedMethodId`条件を追加し、未選択時のみ自動選択するように変更

### 修正の効果
- ✅ ユーザーがメソッドタブをクリックすると正しく切り替わる
- ✅ プロジェクト変更時の自動選択は維持される
- ✅ シンプルで理解しやすい実装
- ✅ 既存の動作を壊さない安全な修正
