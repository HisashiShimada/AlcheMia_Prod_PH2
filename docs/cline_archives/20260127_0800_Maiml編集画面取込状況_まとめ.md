## 📌 重要な設計パターン（reference実装から学ぶ）

### 1. マルチテナント対応の徹底
```javascript
// すべてのAPIで以下のパターンが適用されている
router.use(requireAuth);
router.use(setTenantContext);

// organization_idの検証
if (!req.tenantContext.allowedOrgIds.includes(organizationId)) {
  return res.status(403).json({
    success: false,
    error: 'この組織へのアクセス権限がありません',
    code: 'ORGANIZATION_ACCESS_DENIED'
  });
}
```

### 2. セッション管理統合（V1.15α）
```javascript
// 進捗報告時にworker_sessionsも更新
await ensureDbWrite(
  `UPDATE worker_sessions 
   SET last_activity = $1, is_active = true
   WHERE worker_id = $2`,
  [currentTime, workerId],
  `Update worker session activity for ${workerId}`
);
```

### 3. Phase 3対応: work_id + transition_id
```javascript
// 進捗報告にwork_idとtransition_idが必須
const {
  workerId,
  fileKey,
  workId,          // Phase 3-C: 必須
  transitionId,    // Phase 3-C: トランジション進捗の場合必須
  status,
  progressPercentage
} = req.body;
```

### 4. トランジション単位の進捗管理
```javascript
// v_transition_progress_status Viewを活用
SELECT 
  transition_id,
  transition_name,
  work_id,
  latest_status,
  progress_status,    // 日本語進捗状況
  progress_percentage,
  last_updated,
  data_source
FROM v_transition_progress_status
WHERE worker_id = $1 AND maiml_file_key = $2
ORDER BY transition_id
```

### 5. ワークフロー準拠のチェックアウト/チェックイン
```javascript
// is_active = true AND status = 'active' でチェックアウト中
// チェックイン時は is_active = false に変更
const checkinQuery = `
  UPDATE file_checkout_status 
  SET 
    checkin_time = $1,
    is_active = false,
    status = 'completed',
    updated_at = $2
  WHERE id = $3
  RETURNING *
`;
```
