## 1. タスク概要

プロジェクト管理画面の指示送信時に実施していたproject_statusのチェックが不要になったため、関連するステータスチェック処理を削除します。

## 2. 目的と期待される成果

### 目的
- 指示送信時のproject_statusによる制約を撤廃する
- プロジェクトがどのステータスでも指示を送信できるようにする

### 期待される成果
- [x] project_statusによる指示送信の制約が削除される
- [x] どのステータスでも指示送信が可能になる
- [x] `getTaskRegistrationStatus`のステータス判定ロジックが削除される
- [x] `sendInstructions`のステータス検証ロジックが削除される

## 3. 実装ステップ

### Phase 1: バックエンドのステータスチェック削除
- [x] `projectInstructionService.ts`の`getTaskRegistrationStatus`関数の修正
  - `canSendInstructions`を常にtrueに変更
  - ステータス判定ロジックを削除
- [x] `projectInstructionService.ts`の`sendInstructions`関数の修正
  - プロジェクトステータスのバリデーションを削除（331-343行目付近）

### Phase 2: コメント・ドキュメントの更新
- [x] 関数のJSDocコメントを更新

## 4. 影響範囲

### 変更するファイル
1. `backend/src/services/projectInstructionService.ts` - ステータスチェックロジックの削除

### 影響を受ける機能
- プロジェクト管理画面の指示送信機能
  - 現状: ステータスが0（計画中）、3（承認待ち）、5（異常終了）の場合のみ送信可能
  - 変更後: すべてのステータスで送信可能

### 影響を受けないもの
- フロントエンド側のロジック（特に変更不要）
- 指示の保存・更新・削除機能
- その他のプロジェクト管理機能

## 5. 技術的詳細

### 現在のステータスチェック実装

#### getTaskRegistrationStatus関数（94-116行目付近）
```typescript
// タスク登録有無に関わらず、プロジェクトステータスが0,3,5なら送信可能
// 0=計画中, 3=承認待ち, 5=異常終了
const canSendInstructions = [0, 3, 5].includes(projectStatus);
```

#### sendInstructions関数（331-343行目付近）
```typescript
// プロジェクトステータスが0（計画中）、3（承認待ち）、5（異常終了）のいずれかでない場合はエラー
const allowedStatuses = [0, 3, 5];
if (!allowedStatuses.includes(project.project_status ?? -1)) {
  const statusNames: Record<number, string> = {
    0: '計画中',
    1: 'タスク実行待ち',
    2: 'タスク実行中',
    3: '承認待ち',
    4: '完了',
    5: '異常終了'
  };
  const currentStatusName = statusNames[project.project_status ?? -1] || '不明';
  throw new Error(`指示送信は計画中、承認待ち、異常終了のステータスでのみ可能です（現在: ${currentStatusName}）`);
}
```

### 変更後の実装方針

1. **getTaskRegistrationStatus関数**
   - `canSendInstructions`を常に`true`に設定
   - ステータス判定ロジックを削除
   - JSDocコメントからステータス制約の記述を削除

2. **sendInstructions関数**
   - プロジェクトステータスのバリデーションコード全体を削除
   - JSDocコメントからステータス制約の記述を削除
