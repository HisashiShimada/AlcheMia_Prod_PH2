## 1. タスク概要

現在のSessionStorage + Authorizationヘッダー方式の認証を、HTTPOnly Cookie方式に移行します。

### 現状
- **フロントエンド**: SessionStorageにJWTトークンを保存
- **API通信**: Authorizationヘッダーで `Bearer ${token}` 形式で送信
- **バックエンド**: Authorizationヘッダーからトークンを抽出して検証

### 問題点
- SessionStorageはXSS攻撃に脆弱
- JavaScriptからアクセス可能なため、セキュリティリスクが高い

### 目標
- **HTTPOnly Cookie**: JavaScriptからアクセス不可で、XSS対策
- **Secure属性**: HTTPS通信時のみ送信（本番環境）
- **SameSite属性**: CSRF対策

## 5. 技術的詳細

### Cookie設定の詳細

```typescript
res.cookie('maiml_session', jwtToken, {
  httpOnly: true,           // JavaScriptからアクセス不可（XSS対策）
  secure: NODE_ENV === 'production', // HTTPS通信時のみ送信
  sameSite: 'strict',       // CSRF対策（同一サイトのみ送信）
  maxAge: maxAge,           // 有効期限（ミリ秒）
  path: '/',                // すべてのパスで有効
});
```

### 認証ミドルウェアの実装イメージ

```typescript
export async function authMiddleware(req: Request, res: Response, next: NextFunction) {
  try {
    const jwtService = new JwtService();
    
    // Cookieからトークン取得（Cookie専用）
    const token = req.cookies?.maiml_session;

    // トークンなし
    if (!token) {
      return res.status(401).json({
        success: false,
        error: {
          code: 'AUTH_TOKEN_MISSING',
          message: '認証トークンが提供されていません'
        }
      });
    }

    // JWT検証
    const result = await jwtService.verify(token);
    if (!result.success) {
      return res.status(401).json({
        success: false,
        error: {
          code: result.error.code,
          message: result.error.message
        }
      });
    }

    req.user = result.data;
    next();
  } catch (error) {
    // エラーハンドリング
  }
}
```
