## 1. タスク概要

現在の認証システムにリフレッシュトークン機能を追加し、Redisで管理することで、**最終操作から30分操作がなければ自動ログアウト**する仕様を実装します。

### 現状の問題点

#### 🚨 重大なセキュリティ問題
```typescript
// jwtService.ts（現在）
exp: now + 9999999999  // 約316年！
// TODO: トークンの有効期限をenvファイルから設定する
```

**問題:**
1. **JWTの有効期限が極端に長い**（約316年）
2. **トークン無効化の仕組みがない**
3. **アイドルタイムアウトを実装できない**
4. **トークン漏洩時のリスクが極めて高い**
5. **ログアウト時にトークンが残り続ける**

### 改善内容

#### ✅ セキュア認証システムの実装

**アクセストークン（短命）**
- 有効期限: **15分**
- 用途: API呼び出し
- 保存場所: メモリ（フロントエンド）

**リフレッシュトークン（アイドルタイムアウト対応）**
- 初回有効期限: **30分**
- 操作時の動作: **有効期限を30分延長（rolling）**
- 30分操作なし: **自動ログアウト**
- 保存場所: **Redisで管理**
- セキュア: httpOnly Cookie

**Redis TTL機能**
- 30分後に自動削除
- 操作時に新しいトークンを30分TTLで保存
- トークン無効化が可能（将来の強制ログアウト用）

## 5. 技術的詳細

### アイドルタイムアウトの動作フロー

```
【操作あり（30分以内）】
9:00  ログイン
      → アクセストークン（9:15まで）
      → リフレッシュトークンをRedisに保存（TTL: 30分、9:30まで）

9:16  API呼び出し（16分後）
      → アクセストークン期限切れ
      → 自動的に /api/auth/refresh 呼び出し
      → 新しいアクセストークン（9:31まで）
      → 新しいリフレッシュトークンをRedisに保存（TTL: 30分、9:46まで）
      → 【有効期限が30分延長された！】

【30分操作なし】
9:00  ログイン
      → リフレッシュトークンをRedisに保存（TTL: 30分、9:30まで）

9:31  API呼び出し（31分後）
      → アクセストークン期限切れ
      → 自動的に /api/auth/refresh 呼び出し
      → RedisのTTL期限切れでリフレッシュトークンが削除済み
      → 401エラー
      → フロントエンドが自動ログアウト
```

### Redis保存構造

```
Key形式:
  mmdpf:refresh_token:{tokenId}          → StoredRefreshToken（JSON）
  mmdpf:refresh_token:user:{userId}      → Set<tokenId>（将来用）

TTL:
  自動的に有効期限で削除される（30分）
  トークン更新時に新しい30分TTLで再保存

例:
  Key: mmdpf:refresh_token:abc-123-def-456
  Value: {
    "userId": "user-001",
    "organizationId": "org-001",
    "sessionId": "session-001",
    "tokenId": "abc-123-def-456",
    "issuedAt": 1738580400,
    "expiresAt": 1738582200,
    "ipAddress": "192.168.1.1",
    "userAgent": "Mozilla/5.0..."
  }
  TTL: 1800秒（30分）
```

### セキュリティ考慮事項

#### 1. トークンローテーション
- リフレッシュトークン使用後、古いトークンを即座に無効化
- 再利用攻撃を防止

```typescript
// 更新時の処理
await refreshTokenService.revoke(oldTokenId, userId)  // 古いトークン削除
await refreshTokenService.save(newTokenPayload, ...)   // 新しいトークン保存
```

#### 2. httpOnly Cookie
- JavaScriptからアクセス不可
- XSS攻撃対策

```typescript
res.cookie('refreshToken', token, {
  httpOnly: true,        // JavaScript無効
  secure: true,          // HTTPS必須（本番）
  sameSite: 'strict',    // CSRF対策
  path: '/api/auth/refresh'
})
```

#### 3. 短命アクセストークン
- 15分で期限切れ
- 漏洩リスクの最小化

#### 4. Redis管理
- 中央集権的なトークン管理
- 即座の無効化が可能（将来の強制ログアウト用）

#### 5. IPアドレス・User-Agent記録

## 12. フロントエンド対応（参考）

### トークン更新ロジック

```typescript
// frontend/src/services/authService.ts

/**
 * アクセストークンを自動更新
 */
async function refreshAccessToken(): Promise<string | null> {
  try {
    const response = await fetch('/api/auth/refresh', {
      method: 'POST',
      credentials: 'include'  // Cookie送信
    });

    if (!response.ok) {
      // リフレッシュ失敗（30分経過） → ログインページへ
      window.location.href = '/login';
      return null;
    }

    const data = await response.json();
    return data.data.accessToken;
  } catch (error) {
    console.error('Token refresh failed:', error);
    window.location.href = '/login';
    return null;
  }
}

/**
 * API呼び出しラッパー（自動トークン更新）
 */
async function apiCall(url: string, options: RequestInit = {}) {
  let accessToken = sessionStorage.getItem('accessToken');

  // 初回リクエスト
  let response = await fetch(url, {
    ...options,
    headers: {
      ...options.headers,
      'Authorization': `Bearer ${accessToken}`
    }
  });

  // 401エラー → トークン更新を試みる
  if (response.status === 401) {
    const newToken = await refreshAccessToken();
    if (!newToken) {
      return response;  // ログインページへリダイレクト済み
    }

    // 新しいトークンで再試行
    sessionStorage.setItem('accessToken', newToken);
    response = await fetch(url, {
      ...options,
      headers: {
        ...options.headers,
        'Authorization': `Bearer ${newToken}`
      }
    });
  }

  return response;
}
```

### Redis未起動時の制限事項（開発環境のみ）

```
ログイン:
  ✅ 可能（JWT検証のみ）
  
トークン更新:
  ✅ 可能（JWT検証のみ）
  
トークン有効期限:
  ✅ 自動的に8時間に延長（開発作業中にログアウトされない）
  
手動ログアウト:
  ⚠️ Cookie削除のみ（トークン自体は無効化されない）
  
自動ログアウト:
  ❌ 30分アイドルタイムアウトなし
  ✅ JWT有効期限（8時間）で最終的にログアウト
  
トークン無効化:
  ❌ 不可能（Redisがないため）
  
トークン再利用:
  ⚠️ JWT有効期限内（8時間）は可能（セキュリティリスク）
```

**重要な変更点:**
```
Redis未起動時の動作（開発環境のみ）:
  → JWT_REFRESH_TOKEN_EXPIRES_IN_DEV（8時間）を自動使用
  → 長時間の開発作業でもログアウトされない
  → 開発体験が向上
```

#### Phase 3a: Redis接続管理サービス（新規）

**ファイル:** `backend/src/services/redisConnectionService.ts`

```typescript
export class RedisConnectionService {
  private static redis: Redis | null = null;
  private static isAvailable: boolean = false;
  private static isDevelopment: boolean = process.env.NODE_ENV !== 'production';

  static async initialize(): Promise<void> {
    try {
      this.redis = new Redis({ ... });
      await this.redis.connect();
      await this.redis.ping();
      
      this.isAvailable = true;
      console.log('✅ Redis接続成功');
      
    } catch (error) {
      this.isAvailable = false;
      
      if (this.isDevelopment) {
        // 開発環境: 警告を出して続行
        console.warn('⚠️ Redis未起動: フォールバック動作で起動');
        console.warn('⚠️ トークン管理機能は無効化されます');
      } else {
        // 本番環境: エラーを投げる
        console.error('❌ Redis接続失敗: 本番環境ではRedis必須');
        throw new Error('Redis connection required in production');
      }
    }
  }

  static getInstance(): Redis | null {
    return this.redis;
  }

  static isRedisAvailable(): boolean {
    return this.isAvailable;
  }
}
```

   - 完全なトークン管理
   - セキュアなログアウト
