# ローディングスピナー形状ポリシー

## 標準3パターン

### パターン1: 全画面オーバーレイ型
**用途**: データ取得中・処理中の画面全体をブロック

- スピナーサイズ: `large` (48px)
- 背景色: `rgba(255, 255, 255, 0.8)` (白80%透過)
- スピナー色: `token.colorPrimary` (#CF0027)
- z-index: `9999`
- 位置: 画面中央固定（fixed）
- テキスト: あり（例: "読み込み中..."）
- テキストサイズ: `token.fontSizeLG` (16px)
- テキスト色: `token.colorText` (#212121)
- テキストマージン: スピナーから16px下

**実装例:**
```tsx
<Spin 
  spinning={loading}
  size="large"
  tip="読み込み中..."
  style={{
    position: 'fixed',
    top: 0,
    left: 0,
    right: 0,
    bottom: 0,
    background: 'rgba(255, 255, 255, 0.8)',
    zIndex: 9999,
    display: 'flex',
    alignItems: 'center',
    justifyContent: 'center'
  }}
>
  <div style={{ minHeight: '100vh' }} />
</Spin>
```

### パターン2: コンテナオーバーレイ型
**用途**: 特定のコンテナ（Card、Modal、Table等）内のローディング

- スピナーサイズ: `default` (32px)
- 背景色: `rgba(255, 255, 255, 0.8)` (白80%透過)
- スピナー色: `token.colorPrimary` (#CF0027)
- 位置: コンテナ中央（absolute）
- テキスト: あり（例: "データ取得中..."）
- テキストサイズ: `token.fontSize` (14px)
- テキスト色: `token.colorText` (#212121)
- テキストマージン: スピナーから12px下

**実装例:**
```tsx
<Spin 
  spinning={loading}
  tip="データ取得中..."
>
  <Card>
    {/* コンテンツ */}
  </Card>
</Spin>
```

---

### パターン3: インライン型（ボタン内）
**用途**: ボタンクリック後の処理中を示す

- スピナーサイズ: `small` (16px)
- 背景色: なし（透過）
- スピナー色: `#ffffff` (白) ※ボタンがプライマリの場合
- スピナー色: `token.colorPrimary` (#CF0027) ※ボタンがデフォルトの場合
- 位置: ボタン内アイコン位置
- テキスト: なし（ボタンテキストのみ）

**実装例:**
```tsx
<Button 
  type="primary"
  loading={loading}
  icon={<SaveOutlined />}
>
  保存
</Button>
```

## 共通仕様（全パターン）

### スピナーコンポーネント
- 使用コンポーネント: Ant Design `Spin`
- アニメーション: 回転（1秒で1回転）
- 形状: 円形（ドット8個が円周上に配置）

### サイズ定義
| サイズ | 直径 | 用途 |
|--------|------|------|
| `small` | 16px | ボタン内、テーブルセル内 |
| `default` | 32px | カード、モーダル内 |
| `large` | 48px | 全画面オーバーレイ |

### 色定義
**スピナー色**
- プライマリ: `token.colorPrimary` (#CF0027)
- 白背景用: `token.colorPrimary` (#CF0027)
- 色付き背景用: `#ffffff` (白)

**背景色（オーバーレイ）**
- 全画面: `rgba(255, 255, 255, 0.8)` (白80%透過)
- コンテナ内: `rgba(255, 255, 255, 0.8)` (白80%透過)
- ダークモード: `rgba(0, 0, 0, 0.45)` (黒45%透過)

**テキスト色**
- 通常: `token.colorText` (#212121)
- ダークモード: `#ffffff` (白)

### z-index管理
| パターン | z-index | 理由 |
|----------|---------|------|
| 全画面オーバーレイ | 9999 | 最前面に表示 |
| モーダル内 | (自動) | モーダルのz-indexに従う |
| コンテナ内 | (自動) | コンテナのstacking contextに従う |

## パターン選択

### パターン1（全画面オーバーレイ型）を使用する場合
- ✅ ページ全体のデータを初期ロード中
- ✅ 複数のAPIを同時に呼び出し中
- ✅ 画面遷移前の処理中
- ✅ ファイルアップロード/ダウンロード中（全画面ブロック必要）

### パターン2（コンテナオーバーレイ型）を使用する場合
- ✅ テーブルのデータ取得中
- ✅ カード内の部分データ更新中
- ✅ タブ切り替え時のデータロード中
- ✅ モーダル内のフォーム送信中

### パターン3（インライン型）を使用する場合
- ✅ ボタンクリック後の非同期処理中
- ✅ フォーム送信中（ボタンを無効化）
- ✅ アクション実行中（削除、保存、更新など）
- ✅ 短時間（1-3秒）の処理

## 使用場面と選択基準

### 🔴 全画面オーバーレイが必須の場面
- 認証処理中（ログイン、ログアウト）
- 組織切り替え中
- 初回データロード（ページ表示時）
- ファイルインポート処理中（大量データ）

### 🟡 コンテナオーバーレイが推奨される場面
- テーブルの検索・フィルタリング結果取得中
- グラフ・チャートのデータ更新中
- タブコンテンツの切り替え中
- プレビューデータの取得中

### 🟢 インライン型が適切な場面
- フォーム送信ボタン
- 削除ボタン（確認後）
- エクスポートボタン
- 更新・保存ボタン

## アクセシビリティ

### スクリーンリーダー対応
```tsx
<Spin 
  spinning={loading}
  tip="読み込み中..."
  aria-label="コンテンツを読み込んでいます"
  aria-live="polite"
/>
```

### キーボード操作
- ローディング中は操作不可（背景要素へのフォーカス移動を防ぐ）
- `Escape`キーでキャンセル不可（処理が完了するまで待機）

## 実装ガイドライン

### DO（推奨）
✅ データ取得開始時に即座に表示する
✅ 処理完了後は即座に非表示にする
✅ 適切なメッセージを表示する（"読み込み中..."、"保存中..."）
✅ 長時間処理の場合はプログレスバーを検討する
✅ エラー時はローディングを停止し、エラーメッセージを表示する

### DON'T（非推奨）
❌ 100ms未満の処理で表示しない（チラつき防止）
❌ 複数のスピナーを同時に表示しない
❌ ローディング中にユーザー操作を許可しない
❌ スピナーのみでメッセージなし（何を待っているか不明確）
❌ 無限ローディング（タイムアウト処理を実装）

## タイムアウト処理

### 推奨タイムアウト時間
| 処理種類 | タイムアウト | 処理 |
|----------|--------------|------|
| API取得（軽量） | 10秒 | エラー表示 |
| API取得（重量） | 30秒 | エラー表示 |
| ファイルアップロード | 60秒 | エラー表示 |
| 一括処理 | 120秒 | エラー表示 |

### タイムアウト実装例
```tsx
const [loading, setLoading] = useState(false);

const fetchData = async () => {
  setLoading(true);
  
  const timeoutId = setTimeout(() => {
    setLoading(false);
    message.error('処理がタイムアウトしました。再度お試しください。');
  }, 30000); // 30秒
  
  try {
    const response = await api.getData();
    clearTimeout(timeoutId);
    // 処理成功
  } catch (error) {
    clearTimeout(timeoutId);
    message.error('データ取得に失敗しました。');
  } finally {
    setLoading(false);
  }
};
```

## エラーハンドリング

### ローディング中のエラー対応
1. ローディングを即座に停止
2. エラーメッセージを表示（message.error）
3. ユーザーに再試行を促す
4. エラーログを記録（console.error）

### エラーメッセージ例
```tsx
// API エラー
message.error('データの取得に失敗しました。もう一度お試しください。');

// ネットワークエラー
message.error('ネットワーク接続を確認してください。');

// タイムアウト
message.error('処理がタイムアウトしました。時間をおいて再度お試しください。');

// 権限エラー
message.error('この操作を実行する権限がありません。');
```

## パフォーマンス最適化

### 短時間処理の最適化
```tsx
// 100ms未満の処理ではローディングを表示しない
const MIN_LOADING_TIME = 100;

const fetchData = async () => {
  const startTime = Date.now();
  
  const data = await api.getData();
  
  const elapsedTime = Date.now() - startTime;
  if (elapsedTime < MIN_LOADING_TIME) {
    // ローディング表示不要
    return data;
  }
  
  // 通常処理
  return data;
};
```

### 遅延表示（Debounce）
```tsx
// 300ms以上かかる場合のみローディングを表示
const [loading, setLoading] = useState(false);

const fetchData = async () => {
  const timeoutId = setTimeout(() => {
    setLoading(true);
  }, 300);
  
  try {
    const data = await api.getData();
    clearTimeout(timeoutId);
    return data;
  } finally {
    setLoading(false);
  }
};
```
