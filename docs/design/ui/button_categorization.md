# ボタン用途別カテゴリ一覧

## 1. カテゴリ別ボタン一覧

### 1.1 【データ作成・追加】ボタン

新規データの作成や追加を行うボタン群

| ボタン名 | アイコン | type | 配色 | 出現画面 | 用途 |
|---------|---------|------|------|---------|------|
| 追加 | PlusOutlined | default | - | 会社管理、組織管理、ユーザー管理、部署管理、ロール管理、マスタ管理 | 新規レコード追加モーダルを開く |
| 新規プロジェクト | PlusOutlined | primary | success色 | プロジェクト管理 | 新規プロジェクト作成モーダルを開く |
| 新規XMLファイル/新規MaiMLファイル | PlusOutlined | primary | success色 | フォーマット管理 | 新規フォーマットファイルを作成 |
| 新規フォルダ | FolderAddOutlined | primary | success色 | フォーマット管理 | 新規フォルダを作成 |

**共通パターン:**
- アイコン: PlusOutlined（フォルダのみFolderAddOutlined）
- type: default（一般）/ primary（重要な作成操作）
- 配色: success色を使用することが多い（primaryの場合）
- 位置: ツールバー右側

**共通化提案:** `AddButton` / `CreateButton` コンポーネント

### 1.3 【データ削除・状態変更】ボタン

データの削除や状態の変更を行うボタン群

| ボタン名 | アイコン | type | 配色 | 出現画面 | 用途 |
|---------|---------|------|------|---------|------|
| アクティブ | DeleteOutlined | success | success色 | 会社管理、組織管理、ユーザー管理、部署管理、ロール管理、マスタ管理 | 選択したレコードをアクティブ化 |
| 非アクティブ | DeleteOutlined | danger | danger色 | 会社管理、組織管理、ユーザー管理、部署管理、ロール管理、マスタ管理 | 選択したレコードを非アクティブ化 |
| アクティブ/非アクティブ切替 | - | danger/default | 状態依存 | 会社管理、組織管理、ユーザー管理、部署管理、ロール管理、マスタ管理（テーブル行内） | 個別レコードの状態を切替 |

## 4. 意味合い・用途の類似性マトリクス

### 4.1 データ操作系ボタンの関係

```
データ操作系
├── 作成・追加
│   ├── 追加（default）
│   ├── 新規プロジェクト（primary + success色）
│   └── 新規ファイル/フォルダ（primary + success色）
├── 編集
│   ├── 編集（default - テーブル行内）
│   └── 編集（primary - ツールバー）
└── 削除・状態変更
    ├── アクティブ（success）
    ├── 非アクティブ（danger）
    └── 個別切替（状態依存）
```

**類似性:**
- すべてデータのライフサイクルに関わる
- モーダルダイアログを伴うことが多い
- 権限チェックが必要

**差異:**
- 重要度（default vs primary）
- 配色（標準 vs 強調）
- 配置場所（テーブル内 vs ツールバー）

---

### 4.2 データ入出力系ボタンの関係

```
データ入出力系
├── CSVインポート・エクスポート
│   ├── CSVアップロード（default）
│   └── CSVダウンロード（default）
├── ファイルアップロード
│   ├── アップロード（primary + success色）
│   └── 一括アップロード（primary + success色）
└── ダウンロード
    ├── プロジェクトダウンロード（primary）
    └── ファイルダウンロード（primary）
```

**類似性:**
- すべてファイルI/Oに関わる
- ファイル選択ダイアログを伴う
- 非同期処理が必要

**差異:**
- ファイル形式（CSV vs 一般ファイル）
- 処理規模（単一 vs 一括）
- UI強調度（default vs primary）

---

### 4.3 表示制御系ボタンの関係

```
表示制御系
├── リフレッシュ・リロード
│   ├── リロード（default）
│   └── リフレッシュ（primary）
├── 検索
│   ├── 通常検索（Input）
│   └── 詳細検索（Button + Modal）
└── フィルタ
    ├── 単一条件（Select）
    └── 複数条件組合せ（複数Select）
```

**類似性:**
- すべて表示データの制御に関わる
- リアルタイム性が求められる
- UX最適化が重要

**差異:**
- 検索深度（簡易 vs 詳細）
- UI形式（Button vs Input vs Select）
- 条件の複雑さ

ワークフロー制御系

│   └── 詳細表示

**類似性:**
- すべて業務フローに関わる
- 状態遷移を伴う
- 権限・条件チェックが複雑

**差異:**
- ビジネスロジック（画面固有）
- 状態管理の複雑さ
- UI表現の動的性

モーダル制御系

**差異:**
- 処理結果（破棄 vs 保存）

- 副作用の有無
