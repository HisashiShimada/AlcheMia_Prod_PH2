## 2. write_file（書き込み）の制限

既存規約ファイル（`.clinerules/development/file-writing.md`）より抜粋：

### 文字数・行数の目安

| 内容の種類 | write_file推奨上限 | 推奨アプローチ |
|-----------|------------------|--------------|
| プレーンテキスト | 10,000文字 / 1,000行 | write_file |
| コードブロック少量 | 8,000文字 / 800行 | write_file |
| コードブロック多量 | 5,000文字 / 500行 | 段階的追記 |
| 複雑な構造 | 5,000文字 / 500行 | 段階的追記 |

### 制約の要因

1. **コードブロックの量**: SQLクエリ、TypeScriptコード等が大量に含まれる
2. **特殊文字の多さ**: XMLタグ(`<`, `>`)、バッククォート、特殊記号
3. **構造の複雑さ**: ネストされたコードブロック、マークダウンテーブル
4. **トークン制限**: 出力が長すぎてXMLパースに失敗

**注意**: write_fileは**内容の複雑さ**がエラーの主要因であり、単純な行数だけでは判断できない。

## 3. 読み込みと書き込みの制限の違い

### read_file（読み込み）
- ✅ **制限が緩い**（3,286行でも成功）
- ファイル内容をそのまま取得するだけなので、XMLパースの問題は発生しない
- トークンバジェット（20万トークン）の範囲内であれば、さらに大きなファイルも可能

### write_file（書き込み）
- ⚠️ **制限が厳しい**（500-1,000行が目安）
- Clineの出力をXMLとしてパースする過程で問題が発生しやすい
- 特殊文字やコードブロックが多いと、より低い行数でエラーが発生する

## 5. 実用的なガイドライン

### DO（推奨）

✅ **read_fileは積極的に使用する**
- 3,000行以下のファイル: 確実に読み込み可能
- 3,000-5,000行のファイル: ほぼ確実に読み込み可能
- 5,000行以上のファイル: トークンバジェットに注意しながら使用

✅ **write_fileは制約を意識する**
- 新規ファイル作成: 800行以下を目安に
- コードブロックが多い場合: 500行以下を目安に
- 大規模ファイル: 初期ファイル作成 + replace_in_fileで段階的に追記

✅ **大規模ファイルの変更は replace_in_file を使用**
- 部分的な変更のみを指定
- 小さなSEARCH/REPLACEブロックに分割

### DON'T（非推奨）

❌ **read_fileの制限を過度に心配しない**
- 通常のソースファイル（3,000行以下）は問題なく読み込める
- 読み込みエラーが発生した場合のみ対処を検討

❌ **write_fileで大規模ファイルを一度に書き込まない**
- 500行を超える場合は段階的追記を検討
- コードブロックが多い場合は特に注意

❌ **write_fileの制限を行数だけで判断しない**
- 内容の複雑さ（コードブロック、特殊文字）も考慮する

## 6. トラブルシューティング

### 問題: 大規模ファイルの読み込みエラー

**症状**:
```
Error: File is too large to read
```

**原因**:
- トークンバジェット（20万トークン）を超過
- ファイルサイズが極端に大きい（10,000行以上など）

**解決策**:
1. ファイルの一部のみを読み込む（search_filesで必要な箇所を特定）
2. list_code_definition_namesで概要を把握してから必要な関数のみ読み込む
3. ファイルを分割してリファクタリング（長期的な解決策）

### 問題: 大規模ファイルの書き込みエラー

**症状**:
```
[ERROR] You did not use a tool in your previous response!
```

**原因**:
- XMLパースエラー（コードブロック、特殊文字が多すぎる）
- 出力が長すぎる

**解決策**:
1. 初期ファイル作成（ヘッダー、目次のみ）
2. replace_in_fileで段階的にセクションを追加
3. 各追加後にユーザーの確認を待つ

**詳細**: `.clinerules/development/file-writing.md` を参照

## 8. まとめ

### 読み込み（read_file）
- **実績**: 3,286行のファイルを問題なく読み込み可能
- **推奨**: 通常のソースファイル（3,000行程度）は確実に読み込める
- **制限**: トークンバジェット（20万トークン）が実質的な上限

### 書き込み（write_file）
- **推奨上限**: 500-1,000行（内容の複雑さによる）
- **制約要因**: コードブロック、特殊文字、構造の複雑さ
- **大規模ファイル**: 初期作成 + replace_in_fileで段階的追記

### 実用的な結論
✅ **Clineは通常のソースファイル（1,000-3,000行）を問題なく扱える**
✅ **読み込みは非常に柔軟、書き込みは段階的アプローチが必要**
✅ **行数よりも内容の複雑さが重要**
