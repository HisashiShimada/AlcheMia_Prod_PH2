## 目的1：MaiMLで使う用語の意味を一意に識別できるようにしたい

### F-01-01：prefix・用語管理機能

| 項目 | 内容 |
|------|------|
| **機能名** | prefix・用語管理機能 |
| **機能概要** | prefix・用語を新規登録・参照・削除できる機能 |
| **実現したいこと** | ユーザがprefix・用語を登録・管理することで、自分が定義する用語に一意な識別子を紐づけられるようにする |
| **主な利用者** | 実験管理者、プロバイダー |
| **関連する目的** | 目的1、目的7 |
| **関連する要件** | 要件定義書 3.1.1「名前空間の登録」 |

---

### F-01-02：QName形式バリデーション機能

| 項目 | 内容 |
|------|------|
| **機能名** | QName形式バリデーション機能 |
| **機能概要** | MaiMLファイル内のプロパティキーが `prefix:ローカル名` のQName形式であることを検証し、違反箇所を警告・エラー表示する機能 |
| **実現したいこと** | プロパティキーが名前空間付きQName形式で記述されていることを保証し、用語の意味の一意性を維持する |
| **主な利用者** | 実験管理者、プロバイダー |
| **関連する目的** | 目的1、目的6 |
| **関連する要件** | 要件定義書 6.1 バリデーションルール（VAL-001〜VAL-007） |

## 目的2：組織の階層構造に合わせて名前空間・用語を管理したい

### F-02-01：組織階層グループ管理機能

| 項目 | 内容 |
|------|------|
| **機能名** | 組織階層グループ管理機能 |
| **機能概要** | 組織内の階層構造（組織 → チーム → 個人）を組織階層グループとして登録・管理できる機能。従来の部署テーブルを廃止し、組織階層グループテーブルで一元管理する |
| **実現したいこと** | 組織の階層ごとに名前空間を紐づけることで、「どの階層がどの用語を管理するか」を明確にする |
| **主な利用者** | システム管理者（全階層）、実験管理者（自分の権限範囲内のチーム） |
| **関連する目的** | 目的2、目的9 |
| **関連する要件** | 要件定義書 3.1.2「名前空間の階層構造」 |

---

### F-02-02：名前空間URI自動採番機能

| 項目 | 内容 |
|------|------|
| **機能名** | 名前空間URI自動採番機能 |
| **機能概要** | 組織CD・チームCDをもとに名前空間URIを自動生成する機能。ユーザがURIを手入力しなくてもよい仕組みを提供する |
| **実現したいこと** | URIの形式を統一・一意化し、手入力による形式不統一や重複を防ぐ |
| **主な利用者** | システム管理者、実験管理者 |
| **関連する目的** | 目的2、目的10 |
| **関連する要件** |  |

## 目的3：グローバル層に標準用語を整備し、組織横断で再利用できるようにしたい

### F-03-01：グローバル層用語登録・管理機能

| 項目 | 内容 |
|------|------|
| **機能名** | グローバル層用語登録・管理機能 |
| **機能概要** | MaiML標準・業界共通用語（QUDTなど）をグローバル層の名前空間に登録・編集・削除できる機能。操作できるのはプロバイダー権限を持つユーザのみ |
| **実現したいこと** | 全組織が参照できる標準用語セットをシステム内に整備し、組織横断での用語の統一を促進する |
| **主な利用者** | プロバイダー（登録・管理）、実験管理者・実験作業者（参照のみ） |
| **関連する目的** | 目的3 |
| **関連する要件** | 要件定義書 1.3「汎用（Generic）レベルの名前空間」 |
| **確認事項** | グローバル層の標準用語はシステム導入時の初期データとして提供されるか、プロバイダーが手動で登録するか。 |

---

### F-03-02：標準用語参照機能

| 項目 | 内容 |
|------|------|
| **機能名** | 標準用語参照機能 |
| **機能概要** | グローバル層に登録された標準用語を、すべての組織・階層のユーザが閲覧・検索できる機能。編集は不可（読み取り専用） |
| **実現したいこと** | 全ユーザが標準用語を参照し、MaiMLファイル作成時に活用できるようにする |
| **主な利用者** | 実験管理者、実験作業者 |
| **関連する目的** | 目的3、目的8 |
| **関連する要件** |  |

## 目的7：prefixを体系的に管理し、MaiMLのxmlns宣言と紐づけたい

### F-07-01：prefix登録・管理機能

| 項目 | 内容 |
|------|------|

| 項目 | 内容 |
|------|------|
| **機能名** | 重複チェック機能 |
