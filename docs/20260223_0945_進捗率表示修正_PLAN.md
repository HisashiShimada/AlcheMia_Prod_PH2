## 3. 原因分析

### 3.1 問題の発生箇所

**ファイル**: `frontend/src/components/ExperimentWorker/ProgressCheckTab.tsx`
**行番号**: 166行目

### 3.2 APIレスポンスの構造

```json
{
  "task_status": "in_progress",
  "progress_rate": "50.0000000000000000"  // ← スネークケース、文字列型
}
```

### 3.3 現在のコード（問題箇所）

```typescript
// 166行目付近
const allTasks: Task[] = apiData.methods.flatMap((method: WorkerMethod) =>
  method.tasks.map((task: WorkerTask) => ({
    // ... 他のプロパティ ...
    progressRate: task.progress,  // ❌ 存在しないプロパティを参照
    progress: task.progress,      // ← progressも存在しない
  }))
);
```

### 3.4 問題の原因

1. **プロパティ名の不一致**
   - APIレスポンス: `progress_rate`（スネークケース）
   - コード: `task.progress`（存在しないプロパティ）

2. **データ型の不一致**
   - APIレスポンス: `"50.0000000000000000"`（文字列型）
   - Task型定義: `progressRate: number`（数値型）

3. **結果**: `undefined`が設定され、画面に表示されない

## 6. 技術的詳細

### 修正内容

**修正前（166行目）:**
```typescript
progressRate: task.progress,
```

**修正後:**
```typescript
progressRate: parseFloat(task.progress_rate) || 0,
```

### 修正の説明

1. **`task.progress_rate`**: 正しいAPIレスポンスのプロパティ名を使用
2. **`parseFloat()`**: 文字列`"50.0000000000000000"`を数値`50`に変換
3. **`|| 0`**: 変換失敗時（NaN）のデフォルト値を設定

### 型安全性

- Task型定義では`progressRate: number`と定義済み
- parseFloat()の結果は`number`型なので型安全性が保たれる
- デフォルト値`0`も`number`型

## 7. リスクと対策
