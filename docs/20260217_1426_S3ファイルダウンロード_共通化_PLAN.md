# タスク計画書: S3ファイルダウンロード処理の共通化

## メタデータ
- **作成日時**: 2026-02-17 14:26
- **タスクID**: s3-download-common
- **優先度**: 高
- **推定工数**: 4時間

## 1. タスク概要

S3ファイルを直接ダウンロードする処理を共通化し、ファイルキーをバックエンドに連携するだけで署名付きURLを取得できるようにする。プロジェクト管理やフォーマット管理など複数画面で共通的に使用可能な汎用APIを実装する。

## 2. 目的と期待される成果

### 目的
- ファイルキーベースの汎用的なダウンロードAPI実装
- プロジェクト、フォーマット、その他のファイルで共通利用可能
- ファイル存在確認→署名付きURL生成の統一フロー確立

### 期待される成果
- [x] 汎用的なファイルダウンロードAPIエンドポイント実装
- [x] フロントエンド共通ダウンロード関数実装
- [x] プロジェクト管理画面での適用
- [x] フォーマット管理画面での適用
- [x] コードの重複削減とメンテナンス性向上

## 3. 現状分析

### 既存実装の状況

#### バックエンド
- ✅ `storageService.ts`: `getSignedUrl()`メソッドが実装済み
- ✅ `fileAccessService.ts`: プロジェクト専用のダウンロードサービス実装済み
- ✅ `fileAccessController.ts`: プロジェクト専用のエンドポイント実装済み
  - `/projects/:projectId/files/:fileName/download`

#### フロントエンド
- ✅ `api/fileAccessService.ts`: プロジェクト専用のAPI関数実装済み
- ✅ `api/templateApi.ts`: テンプレート専用の`getTemplateSignedUrl()`実装済み
- ❌ フォーマット管理で直接`fetch`を使用している箇所あり

### 問題点
1. **プロジェクト専用APIしか存在しない**: projectIdとfileNameの組み合わせでしか取得できない
2. **テンプレート用は独自実装**: templateApiで別途実装されており統一されていない
3. **ファイルキーベースの汎用APIが不足**: organization_id + file_keyで直接取得できない
4. **コードの重複**: 同じような処理が複数箇所に散在

### API設計

#### エンドポイント
```
POST /api/v1/files/download-url
```

#### リクエスト
```typescript
{
  fileKey: string; // S3ファイルキー（例: "550e8400-.../projects/sample/file.maiml"）
}
```

#### レスポンス
```typescript
{
  success: true,
  data: {
    fileName: string;
    downloadUrl: string; // 署名付きURL（有効期限: 3600秒）
    fileSize: number;
    contentType: string;
    uploadedAt: string;
    uploadedBy: string;
  },
  meta: {
    timestamp: string;
    requestId: string;
  }
}
```

### セキュリティ考慮事項
- [x] 認証チェック（authMiddleware）

### アーキテクチャ上の考慮事項
- 既存のプロジェクト専用APIは**後方互換性のため維持**
- 新しい汎用APIは**追加**として実装
- フロントエンドは段階的に共通関数に移行可能

## 7. リスクと対策

| リスク | 影響度 | 発生確率 | 対策 |
|--------|--------|----------|------|
| 既存機能の破壊 | 高 | 低 | 既存APIは維持、新APIは追加のみ |
| organization_id不整合 | 高 | 中 | fileKeyにorganization_idが含まれることを検証 |
| ファイルパス検証漏れ | 高 | 低 | 既存のsanitizeFileNameを活用 |
| 署名付きURL有効期限切れ | 中 | 中 | エラーメッセージで明確に通知 |
| パフォーマンス劣化 | 中 | 低 | 既存の実装と同等の処理フロー |
