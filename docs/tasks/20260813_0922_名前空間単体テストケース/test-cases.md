## 1. maiml宣言部分

> **対象**: MAIMLファイルの `<maiml>` タグ宣言部（`xmlns:prefix="uri"` 属性）  
> **処理タイミング**: プロジェクト保存（チェックイン / publish）時に `injectNamespaceDeclarations()` がDBから名前空間を取得して注入する  
> **注入ルール**:  
> ① プロジェクトの `organization_group_cd` に一致するチームスコープの名前空間  
> ② プロジェクト作成者（`project.create_user_id`）の個人スコープの名前空間  
> ③ MAIMLファイルを保存したユーザーの個人スコープの名前空間

### TC-CN-01: チームAに紐づくプロジェクトを保存すると、チームAに登録された名前空間がMAIMLの宣言部に注入される

**スコープ状況**

| スコープ | prefix | scope_key | is_active | 注入される？ |
|---|---|---|---|---|
| 組織（チームA） | NsA | TeamA_cd | TRUE | ✅（プロジェクトの orgGroupCd=TeamA_cd と一致） |

| 項目 | 内容 |
|---|---|
| **テスト種類** | 正常系 |
| **対象** | MAIMLファイルの `<maiml>` タグ宣言部 |
| **前提条件** | 実験管理者でログイン済み。チームA（orgGroupCd=「TeamA_cd」）に紐づくプロジェクトを対象とする。チームAスコープに prefix=「NsA」が登録されている |
| **操作手順** | ① チームAのプロジェクトをチェックインして公開する |
| **期待結果** | MAIMLファイルの `<maiml>` タグに `xmlns:NsA` が宣言されている |
