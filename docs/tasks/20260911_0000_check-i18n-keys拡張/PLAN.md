## タスク概要

`scripts/check-i18n-keys.js` の【6】ハードコード検出は `message.xxx('文字列')` の直接渡しパターンのみを対象としており、以下のパターンが検出できていなかった。

1. **JSX属性ハードコード**: `message="..."` / `description="..."` / `title="..."` 等に英語文字列が直接渡されているケース
2. **オブジェクト引数ハードコード**: `message.success({ content: \`...\` })` のようにオブジェクト経由で文字列が渡されているケース

これら2パターンを新規チェック項目として追加する。

---

## 追加する検出ルール

### 【7】JSX属性ハードコード検出

**対象属性**: `message`, `description`, `label`, `title`, `placeholder`, `content`  
**検出条件**: 属性値が英語大文字始まり（A-Z）の文字列リテラル（4文字以上）  
**除外条件**:
- 同一行に `t('` / `t("` が含まれる行（既にi18n対応済み）
- コメント行（`//`, `/*` 始まり）
- `mock/` ディレクトリ配下のファイル（モックUI）
- 翻訳不要な固有名詞・技術名の誤検知を抑えるためのホワイトリスト

**検出例（今回対応漏れだった箇所）**:
```tsx
// ✅ 検出できるようになる
message="Component Display Error"
description="An error occurred while rendering this component."
message="Failed to fetch URL"
message="TIFF File Selected"
```

### 【8】message オブジェクト引数ハードコード検出

**対象**: `message.xxx({ content: '...' / "..." / \`...\` })` のオブジェクト形式  
**検出条件**: `content:` キーに文字列リテラルが直接渡されているケース  
**除外条件**: 同一行に `t('` / `t("` が含まれる行

**検出例（今回対応漏れだった箇所）**:
```tsx
// ✅ 検出できるようになる
message.success({
  content: `${count} method(s) detected`,   // ← オブジェクト内
```

## 誤検知（false positive）の許容方針

完璧な検出は正規表現では困難なため、以下の方針で実用的な精度を確保する：

- **`mock/` ディレクトリは除外**: モックUIは翻訳対象外
- **英語大文字始まり4文字以上** に絞ることで純粋な技術的文字列（`id`, `key`, `px` 等）を除外
- **誤検知が出ても許容**: 「あえて英語のまま残す」固有名詞（`MAIML`, `Material`, `Condition` 等）は手動で確認して無視できる運用とする
- **ホワイトリスト（除外キーワード）** を追加してよく出る固有名詞を抑制
