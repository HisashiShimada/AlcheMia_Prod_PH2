# Alchemia 品質管理機能 — 機能要約資料

> 原典: `docs/design/Alchemia品質管理機能_基本設計書.md`（初版 2026-08-03）
> 要約作成: 2026-08-17

---

## 1. 機能全体像

### 目的

実験管理者が **MaiML プロジェクト全体の品質を最終評価し、証拠として記録する**工程を Alchemia に実装する。

### 対象3機能

| # | 機能名 | 一言概要 |
|---|---|---|
| 1 | **MaiMLプロジェクト全体評価** | 下位評価・集計サマリーを判断材料に、管理者が全体評価を決定する |
| 2 | **階層別サマリー算出** | 登録済み下位評価をテナント共通の集約ルールで階層別に集計する |
| 3 | **全体評価結果のMaiML記録** | 全体評価と集計断面をエビデンスとして凍結記録する |

### 前提条件（本書の対象外）

- 下位評価（メソッド別・タスク別・トランジション別）は登録済みであること
- 作業者による一次品質記録入力機能・実験計画作成機能・テンプレート機能は対象外

---

## 2. 評価の階層構造

```
MaiML プロジェクト（全体評価 ← 必須）
  └── メソッド（任意評価）
        └── タスク
              └── トランジション（工程）（任意評価）
```

評価粒度は **MaiML全体が必須**、メソッド別・トランジション別が任意。

---

## 3. 評価軸

| 評価軸 | 内容 |
|---|---|
| **確からしさ評価** | 各実験記録項目の不確かさに対する妥当性 |
| **環境評価** | 実験環境の指示値と実測値の乖離（環境品質乖離度） |

### 評価種別

| 種別 | 形式 | 具体例 |
|---|---|---|
| **デジタル評価** | 三値 ＋ 任意の数値スコア | 良好 / 要確認 / 不良 |
| **アナログ評価（感情評価）** | 自由文章 | 定性的所見・コメント |

### 数値スコア写像（既定値）

| 三値 | スコア | 特許の精度達成度との対応 |
|---|---|---|
| 良好 | 100 | 100点 |
| 要確認 | 50 | 50点 |
| 不良 | 0 | 0点 |

## 4. 階層別サマリー算出ロジック（概要）

集計は **2段階**で行われる。

### 第1段：多基準ロールアップ（対象が複数評価基準を持つ場合）

| ルール | 概要 |
|---|---|
| **WORST_CASE**（既定） | 最も悪い評価値を採用 |
| MAJORITY | 多数決で代表値を決定 |
| AVERAGE | 数値スコアの平均で代表値を決定 |

### 第2段：階層代表ステータス・スコア決定

| 設定項目 | 選択肢 |
|---|---|
| 階層代表ステータス | 最悪値採用 / 多数決 |
| 階層スコア | 平均（既定） / 最小値 |

### 算出例（7件のサンプルデータ、既定ルール適用）

| 階層 | N | 良好 | 要確認 | 不良 | 代表ステータス | 平均スコア |
|---|---|---|---|---|---|---|
| メソッド別 | 2 | 1 | 1 | 0 | 要確認 | 75.0 |
| タスク別 | 2 | 1 | 0 | 1 | 不良 | 50.0 |
| トランジション別 | 3 | 2 | 1 | 0 | 要確認 | 83.3 |

### 未評価の扱い

| 設定値 | 挙動 |
|---|---|
| **SEPARATE_COUNT**（既定） | 未評価を別カウント。件数を可視化 |
| EXCLUDE_DENOMINATOR | 分母から除外 |
| TREAT_AS_GOOD | 良好として扱う |

---

## 5. 集約ルール管理方針

- ルールは **テナント（組織）全体で共通**。プロジェクト・テンプレート単位の上書き不可
- 同時に `status=ACTIVE` の版は **1つだけ**
- 新版を有効化すると旧版は自動的に `DEPRECATED` へ遷移
- 評価登録時に ACTIVE 版が参照され、**評価レコード内に凍結**される（過去エビデンスの再現性を保証）

---

## 6. 画面構成

### 6.1 プロジェクト全体評価画面（「全体評価」タブ）

画面は**判断材料の提示 → 意思決定**の導線で構成。

| 領域 | 内容 |
|---|---|
| 階層別サマリー | メソッド別・タスク別・トランジション別の度数分布を集計バーで俯瞰 |
| 要注意項目 | 良好以外（不良・要確認）をコメント付きで重大度順に表示 |
| 全体評価の決定 | デジタル評価（三値＋任意スコア）とアナログ評価（文章）を入力して登録 |

> 全体評価は下位評価と同一の三段階スケールを使用。評価一覧に同一データ構造の1行として追記できる。

### 6.2 集約ルール設定画面（管理画面）

| 設定項目 | 選択肢 |
|---|---|
| 評価値→スコア写像 | 良好／要確認／不良の各数値（カスタマイズ可） |
| 対象ロールアップ | WORST_CASE / MAJORITY / AVERAGE |
| 階層代表ステータス | 最悪値採用 / 多数決 |
| 階層スコア | 平均 / 最小値 |
| 未評価の扱い | SEPARATE_COUNT / EXCLUDE_DENOMINATOR / TREAT_AS_GOOD |
| トランジション階層 | 合算（MERGE） / 分離表示（SPLIT） |

設定変更の影響を **登録済みデータに対するプレビューで即時確認**できる。

## 7. データ設計（キー項目）

### 集約ルール（テナント共通）

| 項目 | 型 | 説明 |
|---|---|---|
| ruleId / version | uuid / integer | ルール系列と版。(ruleId, version) で一意 |
| tenantId | string | テナント識別子 |
| status | enum | ACTIVE / DEPRECATED |
| scoreMapping | object | 良好／要確認／不良の数値スコア写像 |
| targetRollup | enum | WORST_CASE / MAJORITY / AVERAGE |
| levelStatusRule | enum | WORST_CASE / MAJORITY |
| levelScoreRule | enum | MEAN / MIN |
| missingHandling | enum | SEPARATE_COUNT / EXCLUDE_DENOMINATOR / TREAT_AS_GOOD |
| transitionHierarchy | enum | MERGE / SPLIT |

### 評価レコード（MaiML記録）

| 項目 | 型 | 説明 |
|---|---|---|
| evaluationId | uuid | 評価レコード識別子 |
| maimlProjectId | string | MaiML全体（プロジェクト）識別子 |
| evaluationScope | const | MAIML_PROJECT（全体評価スコープ） |
| evaluatedBy / evaluatedAt | string / date-time | 管理者と登録日時 |
| appliedRule | object | 適用ルールの参照と凍結パラメータ |
| overall | object | 全体評価（digital三値＋スコア、analog文章） |
| levelEvaluations | array | 任意：メソッド別・トランジション別の管理者個別評価 |
| aggregationSnapshot | object | 集計結果の断面（再計算しない） |

#### aggregationSnapshot の構成

```
aggregationSnapshot
  ├── levels              # 階層別サマリーの計算結果
  ├── sourceEvaluations   # 集計入力となった全下位評価の凍結値
  └── attentionItems      # 良好以外を抽出した要注意項目
```

入力・規則・出力を同一レコード内に揃えることで、**第三者が独立に再計算・検証できる証拠**として完結する。

---

## 8. エビデンス記録方針

- 集計結果は評価登録時点の**断面（スナップショット）**としてのみ記録
- 参照のたびに再計算しない
- 集約ルールが後日変更されても、当該評価がどの版・写像・規則で算出されたかを**レコード単独で証明**できる

## 9. 特許との対応マッピング

| 本設計の要素 | 特許（特願2026-013606）の対応要素 |
|---|---|
| 三階層集計（全体・メソッド・トランジション） | 工程／タスク／メソッド／実験全体の階層評価 |
| 要注意項目の抽出 | ボトルネック工程抽出部 |
| 数値スコア写像（100 / 50 / 0） | 精度達成度（100点 / 50点 / 0点）← **一致させて接続点とする設計** |
| 評価結果のテンプレートへの付与（将来） | 評価結果とともに実験計画テンプレートを記憶（請求項11） |
| 全体評価結果のMaiML記録 | 実験計画・結果・評価結果を関係づけた実験データ記憶（請求項9） |

> 評価軸の内容（本設計：確からしさ・環境 ／ 特許：時間品質・精度品質）は各階層のセルの中身として保持されるため、将来の写像・拡張時に階層集計ロジックと画面構造をそのまま流用できる。

## 10. 制約・トレードオフ・今後の検討事項

| 論点 | 内容 | 対応方針 |
|---|---|---|
| 集約規則の選択 | 最悪値採用は見逃しリスク低減、平均は過検出のリスク | 設定画面のプレビューで数値影響を可視化し組織方針で決定 |
| 多基準ロールアップ | 単一基準データでは効果が出ず、多基準対象で差が生じる | 多基準対象を含む検証データをテストケースとして別途用意 |
| 未評価の扱い | 除外は完成度が不可視、良好扱いは過大評価 | 既定は SEPARATE_COUNT（別カウント）で未評価件数を可視化 |
| 階層粒度と横断分析 | テナント版により粒度が異なり得る | 横断分析要件具体化時に正規化ビュー併設を検討 |
| 階層間の評価不一致 | 下位に不良が残る状態での全体評価の扱い | 要確認（条件付き相当）で記録し、改善事項を次回へ引継ぎ |
