# 秘匿化対応状況 調査レポート

> 調査日: 2026-07-22

## 1. MAIMLガイドラインにおける秘匿化の規定

MAIMLスキーマ（`docs/design/maiml/*.xsd`）では、以下の**2種類の要素のみ**が `EncryptedData` への変換（秘匿化）を許可している。

### A. グローバル要素（globalObjectContentGroup を持つ型）

`maiml-core.xsd` の `globalObjectContentGroup` 内で `xs:choice` に `encryptionGroup` を持つ型：

| 要素名 | 型名 | セクション |
|---|---|---|
| `document` | `documentType` | document |
| `creator` | `creatorType` | document |
| `vendor` | `vendorType` | document |
| `owner` | `ownerType` | document |
| `instrument` | `instrumentType` | document |
| `protocol` | `protocolType` | protocol |
| `method` | `methodType` | protocol |
| `pnml` | `pnmlType` | protocol |
| `program` | `programType` | protocol |
| `instruction` | `instructionType` | protocol |
| `materialTemplate` | `materialTemplateType` | protocol/data |
| `conditionTemplate` | `conditionTemplateType` | protocol/data |
| `resultTemplate` | `resultTemplateType` | protocol/data |
| `data` | `dataType` | data |
| `results` | `resultsType` | data |
| `material` | `materialType` | data |
| `condition` | `conditionType` | data |
| `result` | `resultType` | data |
| `eventLog` | `eventLogType` | eventLog |
| `log` | `logType` | eventLog |
| `trace` | `traceType` | eventLog |
| `event` | `eventType` | eventLog |

### B. 汎用データコンテナ（genericDataContainerGroup の要素）

`maiml-property.xsd` の `propertyBaseType` / `contentBaseType` 派生型で `xs:choice` に `encryptionGroup` を持つもの：

| 要素名 | 説明 |
|---|---|
| `property` | すべての propertyXxxType（stringType, decimalType, propertyListType 等） |
| `content` | すべての contentXxxType（contentStringListType 等） |

### C. 秘匿化禁止要素（encryptionGroup を持たない）

以下の要素はXSDの型定義に `xs:choice ref="encryptionGroup"` を持たないため、秘匿化すると UPA 制約違反となる：

| 要素名 | 型名 | 理由 |
|---|---|---|
| `place` | `placeType` | Petri Net構造要素。`pnmlType` の子だが独立した型を持ち `encryptionGroup` がない |
| `transition` | `transitionType` | 同上 |
| `arc` | `arcType` | 同上 |

> **根拠**: `docs/design/maiml/encrypted_data_summary.md` セクション11、XSD: `backend/src/schemas/maiml-core.xsd`

## 2. 現行実装の判定ロジック一覧

### 2-1. `backend/src/utils/maimlSchemaHelper.ts`（`isUpaViolation`）

**方式**: XSD ファイル（`backend/src/schemas/*.xsd`）を動的解析  
**ロジック**:
1. 全XSDをパースして `xs:complexType` の `xs:choice` に `encryptionGroup` が含まれるか判定
2. 要素名 → 型名のマップも構築
3. `isUpaViolation(targetPath)` が targetPath の末尾要素名を型名に変換し、型が `encryptionGroup` を持つかチェック

**評価**: ✅ XSDに基づく最も正確な実装  
**制限**: `elementTypeMap` は**トップレベル `xs:element` のみ**を収集しているため、XSD上 `ref` 参照される `property`/`content` 等の型解決が部分的に機能する（`property` 要素は `xs:element ref="property"` ではなく `type="maimlns:stringType"` 等の形で参照されるケースがある）。

---

### 2-2. `backend/src/utils/maimlEncryptionXmlHelper.ts`（`parseMaimlToEncryptionTree` / `ENCRYPTABLE_TAGS`）

**方式**: ハードコードされたタグ名セット  
**現在の定義**:

```typescript
const ENCRYPTABLE_TAGS = new Set([
  'transition', 'place', 'data',
  'material', 'condition', 'result',
  'property', 'parameter',
]);
```

**評価**: ❌ **XSDガイドラインに違反している（2つの誤り）**

| 問題 | 詳細 |
|---|---|
| `transition`, `place` を含む | Petri Net構造要素でXSD上 `encryptionGroup` を持たない → 秘匿化するとUPA制約違反 |
| `parameter` を含む | XSD上に `parameterType` という型は存在しない。`parameter` タグ自体もMAIMLの主要スキーマに定義なし |
| 多くの秘匿化可能要素が欠如 | `document`, `protocol`, `method`, `pnml`, `program`, `instruction`, `materialTemplate`, `conditionTemplate`, `resultTemplate`, `results`, `eventLog`, `log`, `trace`, `event`, `creator`, `vendor`, `owner`, `instrument` が未記載 |

---

### 2-3. `frontend/src/utils/parseMaimlToEncryptionTree.ts`（`ENCRYPTABLE_TAGS`）

**方式**: ハードコードされたタグ名セット  
**現在の定義**:

```typescript
const ENCRYPTABLE_TAGS = new Set([
  'document', 'creator', 'vendor', 'owner', 'instrument',
  'protocol', 'method', 'pnml',
  'program', 'instruction',
  'materialTemplate', 'conditionTemplate', 'resultTemplate',
  'data', 'results', 'material', 'condition', 'result',
  'eventLog', 'log', 'trace', 'event',
  'property', 'content',
]);
```

**評価**: ⚠️ `place`/`transition`/`arc` は明示的に `isEncryptable: false` で除外されており正しい。  
ただし**バックエンドの `maimlSchemaHelper.ts` と独立したハードコードであり、XSD変更時に自動追従しない**。また `parameter` が含まれていない点はバックエンドと不一致（バックエンドが誤っている）。

## 4. 対応方針

### 採用する「正の情報源」

**`backend/src/utils/maimlSchemaHelper.ts`** の XSD 動的解析を唯一の正の情報源とする。

### バックエンド修正

`maimlSchemaHelper.ts` に **`getEncryptableElementNames()`** を追加し、
`maimlEncryptionXmlHelper.ts` の `parseMaimlToEncryptionTree` を async 化して
スキーマキャッシュから `isEncryptable` フラグを動的生成するよう変更する。

### フロントエンド修正

`parseMaimlToEncryptionTree.ts` の `ENCRYPTABLE_TAGS` を
現在のフロントエンド版（XSDと一致している方）に合わせ、
加えて XSD との対応根拠コメントを明記する。
（フロントエンドは SSR/クライアント実行のため XSD ファイルを直接読めないため、
バックエンドAPIレスポンスの `isEncryptable` フィールドを信頼する形を基本とし、
クライアント単体でのパース（モック用途）では正しいハードコードリストを維持する）
