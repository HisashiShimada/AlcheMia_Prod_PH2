# 秘匿化・改竄防止機能 現状まとめ — 動作確認手順

> **調査日時**: 2026-07-22  
> **参照元**: `20260722_1152_秘匿化改竄防止動作確認手順/VERIFICATION_STEPS.md`

---

## 前提条件

| 項目 | 内容 |
|------|------|
| ログインアカウント | Manager 権限以上のユーザー |
| 対象プロジェクト | MAIMLファイルが登録済みのプロジェクト |
| 環境 | 開発環境（http://localhost:3000） |

### 確認前の準備

1. Docker が起動していること（`docker-compose up -d`）
2. プロジェクト管理画面を開き、MAIMLファイルが登録済みのプロジェクトを1件選択しておくこと
3. 確認に使用するプロジェクト名をメモしておくこと

### 推奨確認順序

```
① MAIMLファイルの準備（プロジェクト作成・MAIML登録）
  ↓
② 秘匿化（暗号化） ← 「🔒 暗号化管理」ボタン
  ↓
③ 署名（改竄防止）  ← 「🛡️ 署名」ボタン ← 暗号化後に署名すること（重要）
  ↓
④ 検証              ← curl / ブラウザコンソール
  ↓
⑤ 復号化            ← 「🔒 暗号化管理」ボタン
```

> ⚠️ 暗号化を実行すると既存の署名は無効化されます。暗号化後は必ず再署名を実行してください。

## 1. 秘匿化（暗号化）の動作確認

### 1-1. 暗号化管理モーダルを開く

1. プロジェクト管理画面でプロジェクトを1件クリックして選択する
2. 画面右側のヘッダーエリアに表示される「**🔒 暗号化管理**」ボタンをクリックする
3. 「暗号化管理: {プロジェクト名}」というタイトルのモーダルが表示されることを確認する

### 1-2. 暗号化対象要素を選択する

1. モーダル左側の **MAIMLツリー** から暗号化したい要素をクリックする
   - 例：`material`、`condition`、`result` などの子要素
   - チェックボックスが付いたノードを選択すると複数選択可能
2. モーダル右側の「**暗号化設定**」パネルに「対象: N件」と表示されることを確認する
3. 「秘匿レベル」の設定を確認する

| 秘匿レベル | 内容 |
|-----------|------|
| 自動選択（推奨） | ノードの種別に応じて L1 / L2 を自動判定 |
| L1：要素全体 | タグごと暗号化（要素が完全に隠れる） |
| L2：コンテンツのみ | タグを残してコンテンツのみ暗号化 |

### 1-3. 暗号化用の鍵を設定する

1. 「**鍵設定**」タブをクリックする
2. 「暗号化用の鍵」カード内で鍵ソースを選択する

| 鍵ソース | 操作 |
|---------|------|
| **新しい共通鍵を生成**（推奨） | アルゴリズムを選択（`AES-256-CBC` 等）して「鍵を生成」ボタンをクリック |
| 既存キーファイルを読み込む | 「ファイルを選択」ボタンから鍵ファイル（.key 等）をアップロード |
| 受信者公開鍵を使用 | 「ファイルを選択」ボタンから公開鍵ファイル（.pem 等）をアップロード |

3. 鍵が設定されると「現在の鍵：{keyIdentifier}」というアラート（緑）が表示されることを確認する

### 1-4. 暗号化を実行する

1. 「**暗号化設定**」タブに戻り、「**暗号化を実行**」ボタンをクリックする
2. 確認ダイアログが表示されるので「OK」をクリックする
3. 処理完了後、ツリー上の対象ノードが `<EncryptedData>` 要素に変化することを確認する

**✅ 期待結果**
- ツリーの選択要素が `<EncryptedData ...>` として表示される
- プレビューパネル（右側）に暗号化後のXMLプレビューが表示される
- 「暗号化を実行しました」等のサクセスメッセージが表示される

## 2. 復号化の動作確認

> **前提**: 手順1で暗号化済みの要素があること

### 2-1. 暗号化管理モーダルを開く

1. プロジェクトを選択した状態で「🔒 暗号化管理」ボタンをクリックする

### 2-2. 復号化対象要素と鍵を選択する

1. MAIMLツリーに表示される `<EncryptedData>` ノードをクリックして選択する
2. 「**鍵設定**」タブをクリックし、「復号化用の鍵」カード内の「使用する鍵」セレクトボックスをクリックする
3. 暗号化時に使用した鍵を選択する（鍵名が一覧に表示される）
4. PBKDF2アルゴリズムの場合はパスワード入力欄が表示されるのでパスワードを入力する

### 2-3. 復号化を実行する

1. 「**復号化を実行**」ボタンをクリックする
2. 確認ダイアログが表示されるので「OK」をクリックする

**✅ 期待結果**
- `<EncryptedData>` が元のタグ・コンテンツ（`<material>` 等）に復元される
- 「復号化を実行しました」等のサクセスメッセージが表示される
- 復元後の内容が暗号化前と一致している

## 3. 署名（改竄防止）の動作確認

### 3-1. 電子署名管理モーダルを開く

1. プロジェクトを選択した状態で「**🛡️ 署名**」ボタンをクリックする
   - ヘッダーエリアのボタン群の中に「暗号化管理」ボタンの右隣に配置されている
2. 「電子署名管理: {プロジェクト名}」というタイトルのモーダル（幅600px）が表示されることを確認する

### 3-2. 現在の署名状態を確認する

1. モーダル上部の「署名状態」カードを確認する

| 表示 | 意味 |
|------|------|
| 🟡 **署名なし** （黄色タグ） | まだ署名が適用されていない |
| ✅ **署名済み** （緑色タグ） | 署名が適用済み |

### 3-3. 署名を実行する

1. 「操作」カード内の「**🛡️ 署名を実行**」ボタン（Primary, 青）をクリックする
2. 処理完了後、以下を確認する
   - 「署名を実行しました」のサクセスメッセージが表示される
   - 「署名状態」カードに **✅ 署名済み** タグが表示される
   - 「最終署名日時」に現在時刻が設定される

**✅ 期待結果**
- 「署名済み」タグが表示される
- バックエンドログに `POST /api/v1/signature/projects/:name/sign` のリクエストが記録される
- DBの `integrity_audit_log` テーブルに署名イベントが記録される

> ⚠️ **注意**: 「署名を削除」ボタンは現在スタブ実装のため、実際にはMAIMLから署名が除去されません。

## 4. 検証（改竄防止）の動作確認

> ⚠️ 検証機能はフロントエンドUIに専用ボタンが**未実装**です。  
> 以下の方法で動作確認を行います。

### 方法A: ブラウザの開発者ツール（コンソール）から実行

ブラウザの開発者ツール（F12 → コンソールタブ）に以下を入力して実行します。

```javascript
// 手順1: MAIMLのハッシュ値を取得
const hashRes = await fetch('/api/v1/signature/projects/{プロジェクト名}/hash');
const hashData = await hashRes.json();
console.log('ハッシュ結果:', hashData.data);

// 手順2: 署名を検証（hashData.dataから値を取得して設定）
const verifyRes = await fetch('/api/v1/signature/projects/{プロジェクト名}/verify', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    signatureId: hashData.data.signatureId ?? 'sig-001',
    signatureValue: hashData.data.signatureValue ?? '',
    storedHash: hashData.data.digestValue ?? '',
  })
});
const verifyData = await verifyRes.json();
console.log('検証結果:', verifyData.data);
```

### 方法B: curlコマンドで実行

```bash
# ステップ1: MAIMLのハッシュ値を取得
curl -X GET \
  "http://localhost:3001/api/v1/signature/projects/{プロジェクト名}/hash" \
  -H "Cookie: {ブラウザからコピーしたCookie}" \
  -H "Content-Type: application/json" | jq .

# ステップ2: 署名を検証（digestValue・signatureValueはステップ1のレスポンスから取得）
curl -X POST \
  "http://localhost:3001/api/v1/signature/projects/{プロジェクト名}/verify" \
  -H "Cookie: {ブラウザからコピーしたCookie}" \
  -H "Content-Type: application/json" \
  -d '{
    "signatureId": "sig-001",
    "signatureValue": "{ステップ1で取得したsignatureValue}",
    "storedHash": "{ステップ1で取得したdigestValue}"
  }' | jq .
```

**✅ 期待結果（検証成功時）**

```json
{
  "success": true,
  "data": {
    "overallValid": true,
    "hashMatch": true,
    "signatureValid": true,
    "certificateValid": true,
    "timestampValid": true,
    "verifiedAt": "2026-07-22T02:55:00.000Z"
  }
}
```

**✅ 改ざん検知時のレスポンス（改ざんシミュレーション）**

MAIMLファイルを直接編集して内容を変更した後に検証を実行すると：

```json
{
  "success": true,
  "data": {
    "overallValid": false,
    "hashMatch": false,
    "signatureValid": false
  }
}
```

## 5. 監査ログの確認

署名・検証の実行結果は監査ログAPIで確認できます。

```bash
curl -X GET \
  "http://localhost:3001/api/v1/signature/audit-log" \
  -H "Cookie: {ブラウザからコピーしたCookie}" | jq .
```

**期待レスポンス**

```json
{
  "success": true,
  "data": {
    "entries": [
      {
        "id": "...",
        "projectName": "{プロジェクト名}",
        "action": "sign",
        "timestamp": "2026-07-22T02:55:00.000Z",
        "result": "success",
        "digestValue": "...",
        "signatureId": "sig-001"
      }
    ],
    "total": 1,
    "source": "local-log"
  }
}
```

> ⚠️ `source: "local-log"` の場合はインメモリ保存のためサーバー再起動でログが消えます。

## 6. 既知の制限一覧

| 項目 | 内容 | 回避策 |
|------|------|--------|
| 検証UIが未実装 | フロントエンドに検証ボタンがない | curl / ブラウザコンソールで代替 |
| 署名削除が未実装 | `removeSignature()` はスタブ。MAIMLから `<Signature>` が除去されない | - |
| 署名状態の永続化 | モーダルを開き直すと常に「署名なし」と表示される（実際には署名済み） | DBの状態管理テーブル整備後に解消予定 |
| 監査ログの永続化 | `source: "local-log"` の場合はインメモリ保存 | DBへの記録実装後に解消予定 |
| 鍵のダウンロード導線 | 生成した鍵をUIからダウンロードできない | DBの `encryption_keys` テーブルを直接確認 |
| TSAがモックのみ | タイムスタンプが本物のTSAから発行されない | 外部TSA通信実装後に解消予定 |
| TSTの正当性検証なし | CMS署名検証が仮実装（常にtrue） | FIX-4 対応後に解消予定 |
