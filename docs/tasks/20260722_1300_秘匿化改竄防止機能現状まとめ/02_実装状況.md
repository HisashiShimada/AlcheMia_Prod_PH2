### 1-2. 暗号化の仕組み

#### 暗号化アルゴリズム

| アルゴリズム | 鍵長 | モード | 備考 |
|------------|------|--------|------|
| AES-256-CBC | 256bit | CBC | 推奨（デフォルト） |
| AES-128-CBC | 128bit | CBC | - |
| AES-256-GCM | 256bit | GCM | 認証付き暗号化 |
| PBKDF2 | - | - | パスワードから鍵を導出 |

#### 秘匿レベル

| レベル | 内容 | XML変換例 |
|--------|------|----------|
| **L1（要素全体）** | タグごと暗号化（要素が完全に隠れる） | `<material>...</material>` → `<EncryptedData>...` |
| **L2（コンテンツのみ）** | タグを残してコンテンツのみ暗号化 | `<material><EncryptedData>...</material>` |
| 自動選択 | ノードの種別に応じて L1 / L2 を自動判定 | - |

#### MAIMLへの埋め込み形式

暗号化後の要素は XML Encryption 仕様（W3C）に基づく `<EncryptedData>` 構造として埋め込まれます。

```xml
<EncryptedData xmlns="http://www.w3.org/2001/04/xmlenc#"
               Type="http://www.w3.org/2001/04/xmlenc#Element">
  <EncryptionMethod Algorithm="http://www.w3.org/2001/04/xmlenc#aes256-cbc"/>
  <KeyInfo xmlns="http://www.w3.org/2000/09/xmldsig#">
    <KeyName>{keyIdentifier}</KeyName>
  </KeyInfo>
  <CipherData>
    <CipherValue>{Base64エンコードされた暗号文}</CipherValue>
  </CipherData>
</EncryptedData>
```

現在の実装では `USE_TEST_KEYS=true` 設定時に `backend/test-keys/encryption/` 配下の固定ファイルを参照する「テストモード」が使われています。本番環境向けのKMS連携は未実装です。

```
backend/test-keys/
├── encryption/
│   ├── aes-256-cbc.key      # AES-256-CBC用テスト鍵
│   ├── aes-128-cbc.key      # AES-128-CBC用テスト鍵
│   └── aes-256-gcm.key      # AES-256-GCM用テスト鍵
└── signing/
    ├── private.pem           # RSA署名用秘密鍵
    └── public.pem            # RSA署名用公開鍵
```

### 1-4. UPA制約チェック

`maimlSchemaHelper.ts` が XSD スキーマを解析し、暗号化操作が XML Schema の **UPA（Unique Particle Attribution）制約** に違反しないかを事前検証します。UPA違反が検出された場合は暗号化操作をブロックして警告を返します。

### 2-2. 署名（signMaiml）の処理内容

1. MAIMLファイルをストレージから取得
2. MAIMLをexcl-C14N正規化しSHA-256でDigestValue（ハッシュ）を計算 → `computeCanonicalHash()`
3. 秘密鍵を取得（現在はテストモードで固定ファイル参照）→ `getSigningPrivateKey()`
4. 秘密鍵でDigestValueを暗号化しSignatureValueを生成 → `signHash()`
5. TSQを構築（SignatureValueのハッシュをmessageImprintとして設定）→ `buildTimestampRequest()`
   - ⚠️ 現在: SignatureValueのexcl-C14N正規化なしでハッシュ化（未修正）
6. TSAへリクエスト送信・TSR受信 → `requestTimestamp()`
   - ⚠️ 現在: ローカルモック（`tsaProvider: 'local-mock'`）のみ対応
7. TSRのステータス確認・TSTを取得 → `parseTimestampResponse()`
8. TSTをBase64エンコードし `<EncapsulatedTimeStamp>` として格納 → `embedTimestampToken()`
9. `<Signature>` をMAIMLに追記・ストレージへ保存
10. 監査ログへ記録 → `recordTimestampRequest()`

### 2-3. 検証（verifyMaiml）の処理内容

1. MAIMLから `<Signature>` 要素を取得 → `extractSignatureFromXml()`
2. `<QualifyingProperties>` からTSTを取得 → `extractTimestampToken()`
3. TSTの正当性検証（CMS署名・EKU確認・証明書チェーン）→ `verifyTimestampToken()`
   - ⚠️ 現在: 仮実装（CMS署名を実際に検証せず通過）
4. messageImprintが正規化SignatureValueのハッシュと一致するか確認 → `verifyMessageImprintAndNonce()`
5. 公開鍵でSignatureValueを復号し、DigestValueと照合 → `verifySignature()`
6. MAIMLを再C14N正規化してSHA-256計算し、DigestValueと比較 → `recomputeAndCompare()`
7. TSTInfo.genTimeがMAIML内`<date>`要素の作成日以降か確認 → `checkTimeConsistency()`
   - ⚠️ 現在: 比較対象が現在時刻になっている（要修正）
8. 証明書の有効性確認（失効確認を含む）→ `validateSignerCertificate()` / `validateTsaCertificate()`
   - ⚠️ 現在: 有効期限チェックのみ（CRL/OCSP未実装）
9. 全検証を総合し、改ざんあり/なし判定
10. 監査ログへ記録 → `recordVerificationResult()`

### 2-4. 署名XMLの構造（XAdES-T形式）

現在の実装が生成する構造（**誤り**あり — 詳細は `03_未実装課題.md` 参照）：

```xml
<Signature Id="sig-{timestamp}" xmlns="http://www.w3.org/2000/09/xmldsig#">
  <SignedInfo>
    <CanonicalizationMethod Algorithm="http://www.w3.org/2001/10/xml-exc-c14n#"/>
    <SignatureMethod Algorithm="http://www.w3.org/2001/04/xmldsig-more#rsa-sha256"/>
    <Reference URI="">
      <DigestMethod Algorithm="http://www.w3.org/2001/04/xmlenc#sha256"/>
      <DigestValue>{Base64(SHA-256ハッシュ)}</DigestValue>
    </Reference>
  </SignedInfo>
  <SignatureValue>{Base64(RSA署名)}</SignatureValue>
  <KeyInfo>
    <X509Data>
      <X509Certificate>{署名者証明書}</X509Certificate>
    </X509Data>
  </KeyInfo>
  <Object>
    <xades:QualifyingProperties Target="#sig-...">
      <!-- ⚠️ 以下は誤った構造（SignatureProperties → UnsignedSignatureProperties であるべき） -->
      <xades:SignatureProperties>
        <xades:SignatureProperty Id="tst-...">
          <xades:SignatureTimeStamp>
            <xades:EncapsulatedTimeStamp>{Base64(TST)}</xades:EncapsulatedTimeStamp>
          </xades:SignatureTimeStamp>
        </xades:SignatureProperty>
      </xades:SignatureProperties>
    </xades:QualifyingProperties>
  </Object>
</Signature>
```

仕様書が要求する正しい構造：

```xml
<Object>
  <QualifyingProperties Target="#sig-...">
    <UnsignedProperties>
      <UnsignedSignatureProperties>
        <SignatureTimeStamp Id="tst-...">
          <EncapsulatedTimeStamp>{Base64(TST)}</EncapsulatedTimeStamp>
        </SignatureTimeStamp>
      </UnsignedSignatureProperties>
    </UnsignedProperties>
  </QualifyingProperties>
</Object>
```
