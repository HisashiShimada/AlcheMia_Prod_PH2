## 原因

**`data.admin@aiml.com`（データ管理 太郎、ROLE003）は、実験管理機能（`functionId: 040000`）の権限が `0`（読取専用）のため、公開操作を実行できない。**

- フロントエンドが権限チェックを行い、公開APIリクエストをバックエンドに送信しなかった
- または、バックエンドが `E5015: 権限不足` として拒否した
- いずれの場合も、バックエンドログに Publish リクエストは残っていない

エラーメッセージ「公開できません　システムエラーが発生しました」は、権限不足に対するフロントエンド側の汎用エラー表示と考えられる。

---

## 対応方針

### 短期対応（即時）
- **公開操作は実験管理の書込権限（`functionId: 040000, permission: 1`）を持つユーザーで実施する**
  - 例: `exp.admin@aiml.com`（実験管理 太郎、ROLE004）

### 中期対応（改善）
- **エラーメッセージの改善**: 「システムエラー」ではなく「権限が不足しています。実験管理の書込権限が必要です。」等、ユーザーが対処できるメッセージを表示する
  - 現在 `E5015` に対するメッセージが汎用的すぎる可能性がある

## ソースコード確認（2026-05-12）

### 確認対象

公開ボタン押下時のフロントエンド・バックエンドの処理フローを、実際のソースコードで確認した。

---

### ① フロントエンド：公開ボタンの disabled 条件（権限チェックなし）

**ファイル**: `frontend/src/components/project/ProjectManagement.tsx`

```tsx
disabled={
  !selectedProject ||
  !(selectedProject?.status === ProjectStatus.REVIEW_WAITING ||
    selectedProject?.status === ProjectStatus.COMPLETED) ||
  publishStatusLoading ||
  isPolling
}
```

**→ disabled 条件にユーザー権限の判定は含まれていない。**  
プロジェクトが `REVIEW_WAITING` または `COMPLETED` 状態であれば、実験管理：読取専用ユーザーでもボタンが押せる。

---

### ② バックエンド：`checkPermission` ミドルウェアが 403 を返す

**ファイル**: `backend/src/routes/projectRoutes.ts`（publish エンドポイント定義）

```typescript
router.post(
  '/:projectId/publish',
  authMiddleware,
  checkPermission('040000', 1),  // 実験管理（040000）の書込可（1）が必要
  ...
  projectController.publish
);
```

**ファイル**: `backend/src/middleware/permissionCheckMiddleware.ts`

```typescript
// 権限レベルが不足している場合（permission=0 < requiredPermission=1）
if (userPermission.permission < requiredPermission) {
  res.status(403).json({
    success: false,
    error: {
      code: 'INSUFFICIENT_PERMISSION',   // ← このコードが返る
      message: '必要な権限レベルが不足しています（必要: 1, 所有: 0）'
    }
  });
}
```

実験管理：読取専用ユーザーは `permission = 0` なので `0 < 1` → **HTTP 403 / `INSUFFICIENT_PERMISSION`** が返る。

---

### ③ フロントエンド：エラーコードを翻訳して Alert を表示

**ファイル**: `frontend/src/components/project/MaimlPublishDialog.tsx`

```typescript
} catch (err: unknown) {
  const code = axiosErr?.response?.data?.error?.code ?? 'E4001';
  // → code = 'INSUFFICIENT_PERMISSION'
  setErrorCode(code);
}

const getErrorMessage = (code: string): string => {
  const key = `maimlPublish.errors.${code}`;
  // → key = 'maimlPublish.errors.INSUFFICIENT_PERMISSION'
  const msg = t(key);
  // → ja.json に 'maimlPublish.errors.INSUFFICIENT_PERMISSION' は未定義 → キーをそのまま返す
  // → msg === key → フォールバック発動
  return msg === key ? t('maimlPublish.errors.E4001') : msg;
  // → "システムエラーが発生しました"
};
```

### 処理フロー全体

| ステップ | 内容 |
|---|---|
| 公開ボタン | 権限チェックなし。プロジェクト状態が `REVIEW_WAITING` / `COMPLETED` なら押せる |
| バックエンド | `checkPermission('040000', 1)` で permission=0 → `INSUFFICIENT_PERMISSION`（HTTP 403）を返す |
| フロントエンド | `INSUFFICIENT_PERMISSION` が翻訳定義になく、`E4001` フォールバックが使われる |
| 表示メッセージ | **「公開できません　システムエラーが発生しました」** が表示される ✅ |

**→ 実験管理：読取専用ユーザーが公開ボタンを押すと、「公開できません　システムエラーが発生しました」が表示されることをソースコードで確認した。**

---

### 修正案（中期対応の具体的内容）

`frontend/src/locales/ja.json` の `maimlPublish.errors` に以下を追加することで、適切なメッセージが表示される：

```json
"INSUFFICIENT_PERMISSION": "実験管理の書込権限が必要です",
"PERMISSION_DENIED": "実験管理の書込権限が必要です"
```
