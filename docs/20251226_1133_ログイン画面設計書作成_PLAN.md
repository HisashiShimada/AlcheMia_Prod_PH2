## 5. 技術的詳細

### 使用する技術・ライブラリ
- **フロントエンド**:
  - React 18.2.0
  - Next.js 15+
  - Ant Design v6（Form, Input, Button, Modal, Alert）
  - TypeScript
  - Axios（API通信）

- **バックエンド**:
  - Node.js + Express.js
  - jsonwebtoken（JWT生成・検証）
  - bcrypt（パスワードハッシュ化）
  - nodemailer（メール送信）
  - PostgreSQL（セッション・ユーザー管理）

### 認証フローの概要

#### 通常ログインフロー
1. ユーザーがユーザーIDとパスワードを入力
2. クライアント証明書を自動的に送信（ブラウザ設定）
3. バックエンドでクライアント証明書を検証
4. ユーザーID + 組織ID（PC埋め込み）でユーザー認証
5. パスワード検証
6. PINコード生成・メール送信
7. PINコード入力画面に遷移

#### 二段階認証フロー
1. ユーザーがメールで受け取ったPINコードを入力
2. バックエンドでPINコード検証
3. JWT + Sessionを生成
4. ロール別の初期画面に遷移

## 6. リスクと対策

| リスク | 影響度 | 発生確率 | 対策 |
|--------|--------|----------|------|
| クライアント証明書の配布・管理が複雑 | 高 | 中 | 証明書配布手順書を別途作成、自動インストールスクリプトの提供を検討 |
| メールアドレスを持たないユーザーの運用が煩雑 | 中 | 高 | 管理者向けの通知メール一覧画面を用意、口頭伝達の手順書を作成 |
| PINコードの有効期限が短く使いづらい | 中 | 中 | 再送信機能の実装、有効期限のバランス調整（5分→10分検討） |
| 組織情報の埋め込み方法が不明確 | 高 | 中 | クライアント証明書CN/OUを推奨、フォールバック方式も用意 |
| ロール別遷移先の定義漏れ | 中 | 低 | 全ロールの遷移先を明確に定義、未定義時のフォールバック処理 |
| 既存テーブルへの影響 | 中 | 低 | usersテーブルへのカラム追加は互換性を保ちつつ実施 |
