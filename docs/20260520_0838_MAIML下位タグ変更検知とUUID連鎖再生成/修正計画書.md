## Phase 1: protocol/method/pnml/program の ID 引き継ぎ修正

**対象不具合**: ②③⑤（連鎖）  
**根本原因**: `MaimlParserTyped.getDocument()` が `protocolId/methodId/pnmlId/programId` を返せず、`documentData` にセットされない  
**修正ファイル**: `frontend/src/components/editorv2/PetriNetEditorInner.tsx`

### 修正内容

MAIMLロード処理で `extractDocumentFromMaiML()`（documentParser.ts）を呼び出し、取得した `protocolId/methodId/pnmlId/programId` を `documentData` state に確実にセットする。

```typescript
// 修正イメージ: MAIMLロード処理（handleLoadMaiml または useEffect 内）
import { extractDocumentFromMaiML } from '@/utils/documentParser';

// ① MaimlParserTyped 経由でドキュメント基本情報を取得（既存）
const parser = new MaimlParserTyped(maimlData);
const doc = parser.getDocument();

// ② extractDocumentFromMaiML で protocolId/methodId/pnmlId/programId を補完（追加）
const fullDocData = extractDocumentFromMaiML(maimlData);

setDocumentData(prev => ({
  ...prev,
  ...doc,  // 既存の取得情報
  protocolId: fullDocData?.protocolId ?? prev?.protocolId,
  methodId:   fullDocData?.methodId   ?? prev?.methodId,
  pnmlId:     fullDocData?.pnmlId     ?? prev?.pnmlId,
  programId:  fullDocData?.programId  ?? prev?.programId,
}));
```

### 動作確認ポイント
- [ ] 変更なし再保存で `protocol_ito1_25262a67` が引き継がれること
- [ ] 変更なし再保存で `method_ito1_25262a67` が引き継がれること
- [ ] 変更なし再保存で pnml/program ID が引き継がれること
- [ ] method/pnml/program/data/eventLog UUID が引き継がれること（連鎖解決）

## Phase 3: transition の `<name>` タグ不正追加修正

**対象不具合**: ⑥  
**根本原因**: `reactFlowConverter.ts` で `data.name` にフォールバック（description/id）を代入しているため、MAIML に `<name>` がない transition でも `data.name` に値が入り保存時に出力される  
**修正ファイル**: `frontend/src/utils/reactFlowConverter.ts`

### 修正内容

`data.name` を MAIML の `<name>` タグ値のみとし、表示用ラベルは別フィールドに分離する。

```typescript
// 修正前
data: {
  name: transition.name || transition.description || transition.id,
  ...
}

// 修正後
data: {
  name: transition.name ?? undefined,  // MAIMLの<name>タグ値のみ（なければ undefined）
  label: transition.name || transition.description || transition.id,  // 表示用ラベル（既存フォールバック）
  ...
}
```

`NodeData` 型（`frontend/src/types/editor.ts`）に `label` フィールドが存在しない場合は追加が必要。

### 関連確認

- `TransitionNode` や `PetriNetEditorInner` が `node.data.name` を表示ラベルとして使っている箇所があれば `node.data.label ?? node.data.name ?? node.id` に修正する
- `multiMethodConverter.ts` の同様のフォールバックも確認（同じ修正が必要な場合あり）

### 動作確認ポイント
- [ ] MAIML に `<name>` がない transition を再保存しても `<name>` タグが追加されないこと
- [ ] MAIML に `<name>` がある transition は再保存後も `<name>` タグが維持されること
- [ ] エディタ上での transition の表示ラベルが崩れないこと

## Phase 4: multiMethodConverter の instruction UUID 修正

**対象不具合**: ④  
**根本原因**: `buildMethodXML` の instruction UUID が `savedUuids` を参照せず `generateUUID()` 直書き  
**修正ファイル**: `frontend/src/utils/multiMethodConverter.ts`

### 修正内容

```typescript
// 修正前
transitions.forEach((transition: Node<NodeData>) => {
  const instructionId = transition.data.instructionId || `instruction_${transition.id}`;
  methodXml += `        <instruction id="${instructionId}">\n`;
  methodXml += `          <uuid>${generateUUID()}</uuid>\n`;

// 修正後
transitions.forEach((transition: Node<NodeData>) => {
  const instructionId = transition.data.instructionId || `instruction_${transition.id}`;
  methodXml += `        <instruction id="${instructionId}">\n`;
  methodXml += `          <uuid>${savedUuids?.instructions.get(instructionId) || generateUUID()}</uuid>\n`;
```

`buildMethodXML` が `savedUuids` を引数で受け取っていない場合は引数に追加する。

### 動作確認ポイント
- [ ] 複数メソッドの MAIML を変更なし再保存しても instruction UUID が変わらないこと
