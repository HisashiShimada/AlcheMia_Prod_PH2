### Step B-4: template dirty フラグをセットするタイミングを追加

以下の3箇所に template dirty フラグのセット処理を追加する。

#### (a) `handleUpdateNodeProperty` — placeのプロパティ変更時

nodeTypeが 'place' で `data.templateId` を持つノードのプロパティが変わった場合、そのtemplateIdをdirtyにする。

```typescript
// handleUpdateNodeProperty 内（pnml dirty に加えて）
if (newData.templateId) {
  setDirtyFlags(prev => ({
    ...prev,
    templates: new Set([...prev.templates, newData.templateId!]),
  }));
}
```

#### (b) `handleUpdateNodeId` — placeのIDが変わった時

placeのIDが変わると、そのplaceを参照するtemplate（placeRef.ref）のUUIDも再生成が必要。  
該当templateをallTemplatesから検索してdirtyにする。

```typescript
// handleUpdateNodeId 内（pnml dirty に加えて）
// 旧placeIdを参照するtemplateをdirtyにする
const allTemplates = window.clineAllTemplates;
if (allTemplates) {
  (['material', 'condition', 'result'] as const).forEach(category => {
    (allTemplates[category] || []).forEach((t: Template) => {
      if (t.placeRef?.ref === oldId) {
        setDirtyFlags(prev => ({
          ...prev,
          templates: new Set([...prev.templates, t.id]),
        }));
      }
    });
  });
}
```

#### (c) `handleSaveTemplate` — テンプレート保存時

テンプレートが新規作成または更新された場合、templateIdをdirtyにする。  
**現状**: `markTemplateDirty(level, methodId)` でprotocol/method/programレベルのdirtyは立てているが、templateId単位のdirtyは未対応。

```typescript
// handleSaveTemplate 内（markTemplateDirty 呼び出しの後に追加）

  setDirtyFlags(prev => ({
    ...prev,
    templates: new Set([...prev.templates, savedTemplateId]),
  }));
}
```

### 修正後

```typescript
const handleEditMethodId = useCallback((index: number, newMethodId: string) => {
  console.log('✏️ [PetriNetEditorInner] Method ID編集:', { index, newMethodId });
  
  // 旧methodIdを取得（dirtyFlagsのキーは旧methodId）
  const oldMethodId = methods[index]?.methodId;
  
  setMethods(prev => {
    const updated = [...prev];
    updated[index] = {
      ...updated[index],
      methodId: newMethodId
    };
    return updated;
  });
  
  // ── UUID: methodId変更で旧methodIdをキーに protocol/method/pnml/program を dirty にする ──
  // 旧methodIdで立てることで savedUuids から除外し、新UUIDを生成させる
  if (oldMethodId) {
    setDirtyFlags(prev => ({
      ...prev,
      protocol: true,
      methods: new Set([...prev.methods, oldMethodId]),
      pnmls: new Set([...prev.pnmls, oldMethodId]),
      programs: new Set([...prev.programs, oldMethodId]),
    }));
  }
  
  onContentChange?.();
  console.log('✅ [PetriNetEditorInner] Method ID編集完了');
}, [methods, setDirtyFlags, onContentChange]);
//  ↑ 依存配列に methods/setDirtyFlags/onContentChange を追加
```

**注意**: 旧 `methodId` でdirtyフラグを立てる点が重要。  
`savedUuids` のキーは旧methodIdなので、旧methodIdをdirtyにすることで `filteredUuids` から除外され、新UUIDが生成される。

## Phase D: handleEditMethodId で template.methodId 更新

**対象不具合**: ④（Case 5: methodId変更でtemplateがMAIML出力に含まれなくなる）  
**ファイル**: `frontend/src/components/editorv2/PetriNetEditorInner.tsx`  
**行番号**: 2526-2539

### 問題

- TemplateContextに登録されているtemplateは `methodId` フィールドを持つ
- `handleEditMethodId` でmethodsのmethodIdは新しい値に更新されるが、TemplateContext内のtemplate.methodIdは旧methodIdのまま
- `buildMethodXML` / `convertReactFlowToMaiML` でtemplateをmethodIdで検索するとヒットせず、templateがMAIML出力に含まれなくなる

### 修正後（Phase C の修正に追加）

```typescript
const handleEditMethodId = useCallback((index: number, newMethodId: string) => {
  console.log('✏️ [PetriNetEditorInner] Method ID編集:', { index, newMethodId });
  
  const oldMethodId = methods[index]?.methodId;
  
  setMethods(prev => {
    const updated = [...prev];
    updated[index] = { ...updated[index], methodId: newMethodId };
    return updated;
  });
  
  // ── UUID: dirtyFlags セット（Phase C） ──
  if (oldMethodId) {
    setDirtyFlags(prev => ({
      ...prev,
      protocol: true,
      methods: new Set([...prev.methods, oldMethodId]),
      pnmls: new Set([...prev.pnmls, oldMethodId]),
      programs: new Set([...prev.programs, oldMethodId]),
    }));
  }
  
  // ── template.methodId の更新（Phase D） ──
  // TemplateContext内で旧methodIdを持つtemplateを新methodIdに更新する
  if (oldMethodId && window.clineAllTemplates && window.clineUpdateTemplate) {
    (['material', 'condition', 'result'] as const).forEach(category => {
      const templates: Template[] = window.clineAllTemplates?.[category] || [];
      templates.forEach((t: Template) => {
        if (t.methodId === oldMethodId) {
          window.clineUpdateTemplate?.(t.id, { ...t, methodId: newMethodId });
        }
      });
    });
  }
  
  onContentChange?.();
  console.log('✅ [PetriNetEditorInner] Method ID編集完了');
}, [methods, setDirtyFlags, onContentChange]);
```

### 動作確認ポイント
- [ ] methodIdを変更して保存すると、変更前に登録されていたtemplateがMAIMLに含まれること（Case 5）
- [ ] 変更後のmethodIdでtemplateが正しく紐づいていること

## 実装順序と注意点

### 推奨実装順序

```
Phase A → Phase B（B-1 → B-2 → B-3 → B-4）→ Phase C + D（同一関数の修正なのでまとめて）
```

### Phase A を最初に行う理由

Phase A の修正（依存配列追加）は、B/C/D の修正の前提条件。  
B/C/D で dirtyFlags を正しくセットしても、Phase A が未修正では保存時に古い dirtyFlags が参照されるため、全て効果がない。

### Phase C + D は同一関数（handleEditMethodId）への修正

`handleEditMethodId` に対して以下を一度に行う:
1. `oldMethodId` の取得を先頭で行う
2. dirtyFlags セット（Phase C）
3. template.methodId 更新（Phase D）
4. 依存配列の更新（`[]` → `[methods, setDirtyFlags, onContentChange]`）
