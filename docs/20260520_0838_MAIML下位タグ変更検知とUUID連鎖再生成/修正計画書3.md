同様に conditionTemplate、resultTemplate のUUID解決部分も同じパターンで修正する（計3箇所）。

### 修正内容

`handleUpdateNodeId`（L1573付近）内で、`clineUpdateTemplate` 呼び出しの**前**に `dirtyTemplateIds` を収集するよう順序を変更する。

```typescript
// ── 変更後の処理順序 ──

const dirtyTemplateIds: string[] = [];
if (window.clineAllTemplates) {
  (['material', 'condition', 'result'] as const).forEach(cat => {
    (window.clineAllTemplates?.[cat] || []).forEach((t) => {
      if (t?.id && t.placeRefs?.some((pr) => pr.ref === oldId)) {
        dirtyTemplateIds.push(t.id);
      }
    });
  });
}

// STEP 2（既存）: TemplateContextのplaceRefsを更新（oldId → newId）
// ... 既存の clineUpdateTemplate 処理 ...

// STEP 3（修正）: 収集済みのdirtyTemplateIdsをdirtyフラグにセット
if (dirtyTemplateIds.length > 0) {
  setDirtyFlags(prev => ({
    ...prev,
    templates: new Set([...prev.templates, ...dirtyTemplateIds]),
  }));

// （既存の後続処理もdirtyフラグのセットがあれば重複を除去）
```

## フェーズ4: テンプレートID変更が反映されない問題

**対象不具合**: ⑤  
**修正ファイル**: `frontend/src/components/editorv2/PetriNetEditorInner.tsx`  
**リスク**: 中〜高（既存テンプレート更新の中核ロジック変更）  
**確認ケース**: テンプレートID変更（名前変更は引き続きOKであること）

### 修正内容

`handleSaveTemplate` の既存テンプレート更新パス（L2003-2053付近）で、**旧IDを基準に検索・更新**するよう修正する。

```typescript
// ── 変更前 ──
// L1825
const templateId = templateRef.id || nodeId;   // 新ID

// L2012
const found = templates.find((t: Template) => t.id === templateId);  // 新IDで検索 → 常に空

// L2032
window.clineUpdateTemplate(templateId, { id: templateId, ... });  // 新IDをキーに → 更新されない

// L2151-2153
setDirtyFlags(prev => ({ ...prev, templates: new Set([...prev.templates, templateId]) }));  // 新IDでdirty

// ── 変更後 ──
// L1825付近: 旧IDと新IDを両方取得
const newTemplateId = templateRef.id || nodeId;                    // 新ID（ユーザー入力）
const originalTemplateId = (() => {                                // 旧ID（ノードのdata）
  const nodeInState = nodes.find(n => n.id === nodeId);
  return nodeInState?.data?.template?.id
    || nodeInState?.data?.templateRef?.id
    || nodeId;
})();

// L2012: 旧IDで検索
const found = templates.find((t: Template) => t.id === originalTemplateId);  // 旧IDで検索

// L2032: 旧IDをキーに、id フィールドは新IDで更新
window.clineUpdateTemplate(originalTemplateId, {   // 旧IDをキーに渡す
  id: newTemplateId,                               // idフィールドは新IDに
  uuid: convertedTemplateRef.uuid,
  name: convertedTemplateRef.name || '',
  ...
});

// ID変更時はnodesのdata内のtemplateIdも更新
if (originalTemplateId !== newTemplateId) {
  setNodes(nds => nds.map(n => {
    if (n.id === nodeId) {
      return {
        ...n,
        data: {
          ...n.data,
          template: n.data.template ? { ...n.data.template, id: newTemplateId } : n.data.template,
          templateRef: n.data.templateRef ? { ...n.data.templateRef, id: newTemplateId } : n.data.templateRef,
        }
      };
    }
    return n;
  }));
}

// L2151付近: dirtyフラグは旧IDで（savedUuidsのキーが旧ID）
setDirtyFlags(prev => ({
```

## フェーズ5: ノード追加でdirtyフラグが立たない問題

**対象不具合**: ①  
**修正ファイル**: `frontend/src/components/editorv2/PetriNetEditorInner.tsx`  
**リスク**: 低  
**確認ケース**: Case 3（ノード追加後に保存でpnml/method/protocol UUIDが更新されること）

### 事前確認（修正前に必要）

ブラウザコンソールで以下を確認してから修正する：

1. ノード追加時に `methods[activeMethodIndex]?.methodId` が何の値か確認
2. `markPnmlDirtyForCurrentMethod` 内で早期リターンが発生しているか確認

### 修正内容（候補A）

`markPnmlDirtyForCurrentMethod`（L1102付近）で methodId が空でも protocol は dirty にする：

```typescript
// ── 変更前 ──
const markPnmlDirtyForCurrentMethod = useCallback(() => {
  const currentMethodId = methods[activeMethodIndex]?.methodId;
  if (!currentMethodId) return;   // ← methodId が空文字で早期リターン
  setDirtyFlags(prev => ({
    ...prev,
    protocol: true,
    methods: new Set([...prev.methods, currentMethodId]),
    pnmls: new Set([...prev.pnmls, currentMethodId]),
  }));
}, [methods, activeMethodIndex, setDirtyFlags]);

// ── 変更後 ──
const markPnmlDirtyForCurrentMethod = useCallback(() => {
  const currentMethodId = methods[activeMethodIndex]?.methodId;
  if (!currentMethodId) {
    // methodId が未設定でも protocol だけは dirty にする
    setDirtyFlags(prev => ({ ...prev, protocol: true }));
    return;
  }
  setDirtyFlags(prev => ({
    ...prev,
    protocol: true,
    methods: new Set([...prev.methods, currentMethodId]),
    pnmls: new Set([...prev.pnmls, currentMethodId]),
  }));
}, [methods, activeMethodIndex, setDirtyFlags]);
```

## 注意事項

- フェーズ2の修正は「既存ファイル編集モード（savedUuids がnon-null）」でのみ有効な変更。**新規作成モード（savedUuids=null）では `template.uuid` を引き続き使う**ロジックのため、新規作成の回帰確認も必須。
- フェーズ4のID変更は `clineUpdateTemplate` の内部実装（TemplateContextのupdate関数）も影響する可能性がある。修正前に `window.clineUpdateTemplate` の実装（TemplateContext.tsx）を確認すること。
- 各フェーズの修正後は `npm run build` でTypeScriptコンパイルエラーがないことを確認する。
