# 不具合調査レポート3

## 調査日時
2026-05-21 16:55

## 調査対象
動作確認ケースで発見された以下の不具合

- Case3: ノード削除はUUID更新されるが、ノード追加ではUUID更新されない
- Case4: id変更によるref変更時のUUID更新が動作しない
- Case5b: propertyを追加/valueを書き換えてもtemplateのUUIDが変わらない / contentが書き込まれなくなった

---

## Case3: ノード追加でUUIDが更新されない

### 症状
- ノード削除 → pnml/programのUUID再生成 → ✅ 正常
- ノード追加 → pnml/programのUUID再生成 → ❌ 更新されない

### 原因

**`PetriNetEditorInner.tsx` の `handleAddNode` （またはノード追加処理）でdirtyフラグが設定されていない。**

ノード削除は `handleDeleteNode` 内で `markPnmlDirtyForCurrentMethod()` または `markDirty('pnml')` 相当の呼び出しがあるが、ノード追加ハンドラーには同等の処理が抜けている。

### 根拠
`multiMethodConverter.ts` の `buildMethodXML` では：
```typescript
const pnmlUuid = savedUuids?.pnmls.get(methodId) || generateUUID();
```
`savedUuids.pnmls` に `methodId` のキーが残っている限り、既存UUIDを再利用する。  
つまり「dirtyフラグが立ってキーを消す処理」がないと常に既存UUIDが使われる。

### 修正方針
ノード追加処理（onConnect後・ノード追加ボタン等）で、削除時と同様に  
`markPnmlDirtyForCurrentMethod()` を呼び出し、`savedUuids.pnmls` から当該methodIdのエントリを削除する。

## Case4: id変更によるref変更のUUID更新が動かない

### 症状
- placeノードのidを変更 → 対応するtemplateのplaceRefが更新される
- しかしtemplate / pnmlのUUIDが再生成されない

### 原因（2段階の問題）

#### 問題A: TemplateContextの`updateTemplate`検索キーが新IDになっている

`PetriNetEditorInner.tsx` の `handleSaveTemplate` 内：
```typescript
const templateId = templateRef.id;  // ← 新しいID（ダイアログで変更後）
window.clineUpdateTemplate(templateId, {
  id: templateId,
  ...
});
```

`TemplateContext.tsx` の `updateTemplate` 実装：
```typescript
const updateTemplate = useCallback((templateId: string, updatedTemplate: Template) => {
  setTemplates((prevTemplates) => {
    (['material', 'condition', 'result'] as const).forEach((category) => {
      const index = updated[category].findIndex((t) => t.id === templateId);
      // ↑ templateId = 新IDで検索しているが、既存エントリは旧IDなのでヒットしない
```

つまり **oldId→newId に変更したとき、oldIdのエントリが見つからず更新が行われない**。

#### 問題B: TemplateEditorDialogで`node.id`（旧ID）を保持していない

`handleSave` では：
```typescript
const isNewTemplate = node.data.isNewTemplate || false;
onSave(node.id, templateRef, isNewTemplate, templateCategory, isCommonTemplate, methodId);
```
`node.id` を `oldNodeId` として渡しているが、呼び出し先の `handleSaveTemplate` でこの `oldNodeId` を使って `updateTemplate(oldNodeId, ...)` を呼んでいるかが問題。

`clineUpdateTemplate(templateId, ...)` の `templateId` が **新IDになっている** 場合は検索ミスが発生する。

### 修正方針

`PetriNetEditorInner.tsx` の `handleSaveTemplate` で：
```typescript
// 修正前
window.clineUpdateTemplate(templateId, updatedTemplate);

// 修正後
const oldId = nodeId;   // onSaveの第1引数 = node.id = 旧ID
window.clineUpdateTemplate(oldId, {
  ...updatedTemplate,
  id: templateId,       // 新IDはupdatedTemplate内に格納
});
```

`updateTemplate(oldId, updatedTemplate)` とすることで、旧エントリを正しく更新できる。

## Case5b: templateのUUID更新なし / contentが書き込まれない

### 症状A: propertyを追加/valueを書き換えてもtemplateのUUIDが変わらない

#### 原因
`multiMethodConverter.ts` のテンプレートUUID生成ロジック：
```typescript
const tmplUuid = savedUuids?.templates.get(tmpl.id) || generateUUID();
```
`savedUuids.templates` にテンプレートIDのエントリがある限り既存UUIDが使われる。  
TemplateEditorDialogでpropertyを変更した後、`savedUuids.templates` から当該テンプレートIDのエントリを**削除するdirtyフラグ処理がない**。

#### 修正方針
`handleSaveTemplate` 呼び出し時（テンプレート内容が変更された場合）に、  
`markTemplateDirty(templateId)` 相当の処理を追加し、  
`savedUuids.templates` から当該エントリを削除する。

---

### 症状B: contentが書き込まれなくなった

#### 原因
`reactFlowToMaiml.ts` の `buildPropertyXML` 関数内：
```typescript
else if (propType === 'content' || propType === 'contentDoubleListType' || propType === 'contentListType') {
  if (prop.contents && prop.contents.length > 0) {
    prop.contents.forEach((content) => {
      propertyXml += buildContentXML(content, indentLevel + 1);
    });
  }
}
```
`propType` が `'content'` 系に分類されている場合のみ `prop.contents` を出力している。  
`TemplateEditorDialog` で content を追加したとき、`PropertyData` の `type` フィールドが `'content'` になっていない場合、この分岐に入らず **contentが無視される**。

#### 確認すべき点
1. `TemplateEditorDialog.tsx` でcontentを追加したときの `PropertyData.type` の値
2. `buildPropertyXML` に渡されるときの `prop.type` の値

#### 修正方針
`buildPropertyXML` の content 分岐条件を確認し、  
`PropertyData` 型の `type` フィールドが適切に `'content'` 系にセットされるよう  
TemplateEditorDialogのcontent追加ハンドラーを修正する。  
または、`buildPropertyXML` 側で `prop.contents` が存在する場合は常にcontentとして出力するよう修正する。
