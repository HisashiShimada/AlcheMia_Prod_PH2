### 修正1: Template ID変更時の保存処理（不具合1）

**修正ファイル**: `frontend/src/components/editorv2/PetriNetEditorInner.tsx`

**修正箇所**: `handleSaveTemplate`（既存テンプレート更新分岐、約2039行目）

#### 現在の実装
```typescript
window.clineUpdateTemplate(templateId, {  // templateId = 新ID → 旧エントリが見つからない
  id: templateId,
  ...
});
```

#### 修正後の実装
```typescript
const oldId = nodeId;   // onSaveの第1引数 = node.id = 旧ID（ダイアログを開いた時点のID）
const newId = templateRef.id || nodeId;  // ダイアログで変更後のID

if (oldId !== newId) {
  // IDが変わった場合: 旧IDを削除 → 新IDで追加
  if (window.clineDeleteTemplate) {
    window.clineDeleteTemplate(oldId);
  }
  if (window.clineAddTemplate) {
    window.clineAddTemplate({
      category: finalTemplateCategory as 'material' | 'condition' | 'result',
      template: {
        id: newId,
        uuid: convertedTemplateRef.uuid,
        name: convertedTemplateRef.name || '',
        description: convertedTemplateRef.description,
        category: finalTemplateCategory,
        properties: convertedTemplateRef.properties,
        contents: convertedTemplateRef.contents || [],
        placeRefs: convertedTemplateRef.placeRefs || [],
        templateRef: convertedTemplateRef.templateRef,
        methodId: finalMethodId,
      },
    });
  }
  // savedUuids.templates から旧IDを削除（旧エントリのUUIDをdirtyにする）
  setSavedUuids(prev => {
    if (!prev) return prev;
    const updatedTemplates = new Map(prev.templates);
    updatedTemplates.delete(oldId);
    return { ...prev, templates: updatedTemplates };
  });
} else {
  // IDが変わっていない場合: 従来通りupdateTemplate（旧IDで検索）
  if (window.clineUpdateTemplate) {
    window.clineUpdateTemplate(oldId, {
      id: oldId,
      uuid: convertedTemplateRef.uuid,
      name: convertedTemplateRef.name || '',
      description: convertedTemplateRef.description,
      category: finalTemplateCategory,
      properties: convertedTemplateRef.properties,
      contents: convertedTemplateRef.contents || [],
      placeRefs: convertedTemplateRef.placeRefs || [],
      templateRef: convertedTemplateRef.templateRef,
      methodId: finalMethodId,
    });
  }
}
```

**注意点**:
- `nodeId` は `handleSaveTemplate` の第1引数（ダイアログを開いた時点の元のID）
- `templateRef.id` はダイアログ内で編集後のID（新ID）
- ノードの `data.template.id` / `data.templateRef.id` も新IDに更新するため、`existingPlaceRefsToUpdate` を使ったノード更新処理で `convertedTemplateRef`（新IDを持つ）がそのまま反映される

### 修正2: 単一メソッドコンバーターのPNML/PROGRAM ID命名規則統一（不具合2）

**修正ファイル**: `frontend/src/utils/reactFlowToMaiml.ts`

**修正箇所**: `convertReactFlowToMaiML` 関数内（839〜842行目）

#### 現在の実装
```typescript
const methodId = documentData?.methodId || originalStructure?.method?.id || 'methodID';
const pnmlId = documentData?.pnmlId || originalStructure?.pnml?.id || 'pnmlID';
const pnmlName = originalStructure?.pnml?.name || `${fileName}PNML`;
const pnmlDescription = originalStructure?.pnml?.description || '';
const programId = documentData?.programId || originalStructure?.program?.id || 'programID';
```

#### 修正後の実装
```typescript
const methodId = documentData?.methodId || originalStructure?.method?.id || 'methodID';
const pnmlId = `pnml_${methodId}`;       // multiMethodConverter.ts と同じ命名規則に統一
const pnmlName = originalStructure?.pnml?.name || `${fileName}PNML`;
const pnmlDescription = originalStructure?.pnml?.description || '';
const programId = `program_${methodId}`; // multiMethodConverter.ts と同じ命名規則に統一
```

**UUIDへの影響確認**:
- `pnmlUuid = savedUuids?.pnmls.get(methodId) || ...` — キーは `methodId` であり、命名規則変更後も同じキーを使用するためUUIDは引き継がれる
- `programUuid = savedUuids?.programs.get(methodId) || ...` — 同上
- **methodIdが変わらない限り、pnmlId/programIdも変わらないためUUIDは維持される**

**後方互換性への注意**:
- 既存の単一メソッドMAIMLを初回保存するとPNML/PROGRAM IDが `pnml_${methodId}` 形式に変わる
- これは `frontend/src/reference/components/PetriNetEditorV2/utils/converters/multiMethodConverter.js`（reference版）と同じ実装であり、**仕様として問題なし**
- システム外で作成されたMAIMLファイルをアップロードして保存した場合も同様（アップロード機能経由でシステムへの登録は可能であるため、統一的な命名規則を適用する）

### 修正3: methodID変更時に `savedUuids.programs` の旧エントリを削除（不具合3）

**前提**: PNMLとPROGRAMは同じ `<method>` 配下の独立した兄弟要素。片方の変更がもう片方に影響しない場合は再採番不要。

**修正の根拠**: methodIDが変わることで `program_${methodId}` というprogramのIDも変わる。IDが変わったタグのUUIDは再採番すべきだが、`savedUuids.programs` に**旧methodIdのエントリが残っている**ため再採番がスキップされている。PNMLは偶然的に新UUIDが生成されていたが、PROGRAMは旧UUIDのまま。

**修正ファイル**: `frontend/src/components/editorv2/PetriNetEditorInner.tsx`

**修正箇所**: `handleUpdateMethodId`（またはmethodId変更後の後処理）

#### 現在の問題
methodIdを変更しても `savedUuids.programs`（および `savedUuids.pnmls`）の旧methodIdのエントリが残り続け、保存時に旧UUIDが再利用されてしまう。

#### 修正後の実装
```typescript
// handleUpdateMethodId 内（methodId変更後の後処理として追加）
const oldMethodId = /* 変更前のmethodId */;
const newMethodId = /* 変更後のmethodId */;

// 旧methodIdのsavedUuidsエントリを削除
setSavedUuids(prev => {
  if (!prev) return prev;
  const updatedPnmls = new Map(prev.pnmls);
  updatedPnmls.delete(oldMethodId);
  const updatedPrograms = new Map(prev.programs);
  updatedPrograms.delete(oldMethodId);  // ← programの旧エントリを削除（これが今回の修正）
  const updatedMethods = new Map(prev.methods);
  updatedMethods.delete(oldMethodId);
  return { ...prev, pnmls: updatedPnmls, programs: updatedPrograms, methods: updatedMethods };
});

// 新methodIdをdirtyにする
setDirtyFlags(prev => ({
  ...prev,
  protocol: true,
  methods: new Set([...prev.methods, newMethodId]),
  pnmls: new Set([...prev.pnmls, newMethodId]),
  programs: new Set([...prev.programs, newMethodId]),
}));
```

**意図**:
methodIDが変わると `pnml_${newMethodId}` / `program_${newMethodId}` というIDが採用される。savedUuidsに新methodIdのキーが存在しない → `generateUUID()` で新UUIDが生成される、という正しい連鎖を実現する。
