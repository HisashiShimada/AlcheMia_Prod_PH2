## 根本原因の詳細

### 根本原因 A: useCallback クロージャー問題（Case 3/6）

**ファイル**: `frontend/src/components/editorv2/PetriNetEditorInner.tsx`  
**行番号**: 約3053行目の依存配列

```typescript
// 現状（バグあり）
}, [nodes, edges, documentData, handleCloseSaveConfirmDialog, onContentSaved]);
//  ↑ dirtyFlags と savedUuids が依存配列に含まれていない
```

**動作の問題**:
- `handleAddNode` など各ハンドラは `setDirtyFlags` を呼んで state を更新する
- しかし `handleSaveConfirmAction` は `useCallback` でメモ化されており、依存配列に `dirtyFlags`・`savedUuids` がないため**ロード時の初期値（全false/null）をクロージャーでキャプチャしたまま**
- 保存時に参照する `dirtyFlags` は常に `{ protocol: false, methods: new Set() ... }` → 全UUIDをsavedUuidsからそのまま引き継ぐ
- 結果として「変更があっても UUID が変わらない」という症状になる

**修正方針**:
```typescript
// 修正後
}, [nodes, edges, documentData, handleCloseSaveConfirmDialog, onContentSaved, dirtyFlags, savedUuids, multiMethodMode, methods, activeMethodIndex]);
```
`dirtyFlags` と `savedUuids`（および保存処理で使用する他の state）を依存配列に追加する。

---

### 根本原因 B: DirtyFlagsにtemplate用フラグがない（Case 4 / テンプレートプロパティ変更）

**ファイル**: `frontend/src/types/editor.ts`、`frontend/src/components/editorv2/PetriNetEditorInner.tsx`

**現状の DirtyFlags 型**:
```typescript
export interface DirtyFlags {
  protocol: boolean;
  methods: Set<string>;    // methodId単位
  pnmls: Set<string>;      // methodId単位
  programs: Set<string>;   // methodId単位
  // templates がない！
}
```

**現状の filteredUuids 構築（Step 4）**:
```typescript
const filteredUuids: ExtractedUuids | null = savedUuids
  ? {
      ...savedUuids,           // ← templates/instructions/places/transitions/arcs はスプレッドでそのままコピー
      protocol: dirtyFlags.protocol ? '' : savedUuids.protocol,
      methods: new Map([...savedUuids.methods.entries()].filter(...)),
      pnmls: new Map([...savedUuids.pnmls.entries()].filter(...)),
      programs: new Map([...savedUuids.programs.entries()].filter(...)),
    }
  : null;
```

**問題**:
- `templates` は `...savedUuids` のスプレッドでコピーされるため、dirtyチェックが行われない
- テンプレートのプロパティ/コンテンツを変更しても、保存時にtemplateのUUIDが savedUuids から引き継がれる
- Case 4（placeのIDが変わりtemplateのplaceRef.refが変わった場合）も同様

**修正方針**:

1. `DirtyFlags` に `templates: Set<string>` を追加（templateId単位）
2. テンプレートの dirty フラグをセットするタイミングを `markTemplateDirty` に追加
3. `filteredUuids` 構築時に templates も dirty チェックを行う

```typescript
// DirtyFlags 修正
export interface DirtyFlags {
  protocol: boolean;
  methods: Set<string>;
  pnmls: Set<string>;
  programs: Set<string>;
  templates: Set<string>;  // 追加: dirty な templateId のセット
}

// filteredUuids 構築（Step 4）修正
templates: new Map(
  [...savedUuids.templates.entries()].filter(
    ([tid]) => !dirtyFlags.templates.has(tid)
  )
),
```

4. template dirty フラグをセットするタイミング:
   - `handleUpdateNodeProperty`: place/templateのプロパティ変更時（placeに紐づくtemplateIdをdirtyに）
   - `handleUpdateNodeId`: placeのIDが変わった時（そのplaceのplaceRefを持つtemplateをdirtyに）
   - `handleSaveTemplate`: テンプレート保存時（templateIdをdirtyに）

### 根本原因 C: methodId変更ハンドラにdirtyフラグなし（Case 5 UUID連鎖）

**ファイル**: `frontend/src/components/editorv2/MethodTabPanel.tsx`（または呼び出し元）  
**問題**: MethodTabPanel で methodId を変更するハンドラが `markPnmlDirtyForCurrentMethod` を呼んでいない

**調査結果**:
```
grep -n "onMethodIdChange|handleMethodTab|method.*rename" PetriNetEditorInner.tsx
→ 0件 ヒット
```

`MethodTabPanel` に `onMethodIdChange` のようなコールバックが存在するか、または methodId の変更が `setMethods` 経由で行われているが、その際に dirtyFlags が更新されていない。

**修正方針**:
- `MethodTabPanel` でmethodIdが変更された際に呼ばれるコールバックを確認し、そこで以下を実施:
```typescript
// methodId変更時: 旧methodIdで protocol/method/pnml/program を dirty にする
setDirtyFlags(prev => ({
  ...prev,
  protocol: true,
  methods: new Set([...prev.methods, oldMethodId]),
  pnmls: new Set([...prev.pnmls, oldMethodId]),
  programs: new Set([...prev.programs, oldMethodId]),
}));
```
- **注意**: 新methodIdではなく**旧methodId**でフラグを立てる（savedUuidsのキーが旧methodIdのため、除外することで新UUIDが生成される）

### 根本原因 D: template.methodId が更新されない（Case 5 template紐づけ消失）

**ファイル**: `frontend/src/components/editorv2/MethodTabPanel.tsx`（または呼び出し元）

**問題**:
- TemplateContextに登録されているtemplateは `methodId` フィールドを持つ
- methodIdを変更しても、TemplateContext内のtemplate.methodIdは旧methodIdのまま
- `buildMethodXML` / `convertReactFlowToMaiML` でtemplateをmethodIdで検索すると、旧methodIdのままなのでヒットしない
- 結果としてtemplateがMAIML出力に含まれなくなる

**修正方針**:
- methodId変更時に TemplateContext の該当templateの `methodId` を新しいmethodIdに更新する
- `TemplateContextType` に `updateTemplateMethodId(oldMethodId: string, newMethodId: string): void` を追加するか、`updateTemplate` を使って一括更新する

```typescript
// methodId変更コールバック内で
if (window.clineAllTemplates) {
  // 旧methodIdに紐づくtemplateを全て新methodIdに更新
  ['material', 'condition', 'result'].forEach(category => {
    const templates = window.clineAllTemplates[category] || [];
    templates.forEach((t: Template) => {
      if (t.methodId === oldMethodId) {
        window.clineUpdateTemplate?.(t.id, { ...t, methodId: newMethodId });
      }
    });
  });
}
```

## 補足: handleSaveConfirmAction の依存配列問題の詳細

```typescript
// PetriNetEditorInner.tsx 約3053行目
  }, [nodes, edges, documentData, handleCloseSaveConfirmDialog, onContentSaved]);
//     ↑ この依存配列が問題
```

`handleSaveConfirmAction` は useCallback でメモ化されており、依存配列に記載されていない state は**初回レンダリング時の値**がクロージャーにキャプチャされる。

- `dirtyFlags` → 初期値 `{ protocol: false, methods: new Set() ... }` のまま
- `savedUuids` → 初期値 `null` または ロード時の値のまま（その後の変更が反映されない）

これにより：
1. `handleAddNode` が `setDirtyFlags(...)` でstateを更新しても
2. `handleSaveConfirmAction` 内で参照する `dirtyFlags` は古いまま
3. 保存時は常に `dirtyFlags.protocol === false` → UUIDが変わらない

**修正により追加が必要な依存配列**:
```typescript
}, [
  nodes, edges, documentData, handleCloseSaveConfirmDialog, onContentSaved,
  dirtyFlags,        // 追加
  savedUuids,        // 追加
  multiMethodMode,   // 追加（保存分岐で使用）
  methods,           // 追加（multiMethodModeで使用）
  activeMethodIndex, // 追加（updatedMethodsで使用）
  metadata,          // 追加（MAIMLメタデータで使用）
]);
```
