## 不具合5：Template編集ダイアログでID変更時に変更が保存されない

### 症状
TemplateEditorDialogでテンプレートのIDを変更しても、変更が保存されない。

### 原因

**ファイル**: `frontend/src/components/editorv2/PetriNetEditorInner.tsx`（約2019行目）

`handleSaveTemplate` の中で `originalTemplate` を検索する際、`templateId`（**新ID**）を検索キーとして使用している。

```typescript
// 問題のコード
const found = templates.find((t: Template) => t.id === templateId);
```

この時点でテンプレート配列内にはまだ**旧ID**のエントリしか存在しないため、新IDで検索すると `found = undefined` となる。

結果として：
1. `originalTemplate.id` が空文字になる
2. `oldTemplateId = originalTemplate.id || templateId` → `templateId`（新ID）になる
3. `updateTemplate(templateId, ...)` → 新IDで配列を検索するが配列には旧IDしかない → 何も更新されない

### 修正方針

検索キーを `templateId`（新ID）から `node.data.template?.id`（変更前の旧ID）に変更する。

```typescript
// 修正後
const found = templates.find((t: Template) => t.id === (node.data.template?.id || templateId));
```

`node.data.template?.id` がない場合（新規作成等）のフォールバックとして `templateId` を残す。

## 不具合6：単一メソッドから複数メソッドに変更した際にPNML/ProgramのIDが書き換わる

### 症状
test_data/ito1_1.maiml（単一method）に新しいメソッドを追加すると、既存methodのPNML IDとProgram IDが書き換わった。

### 比較

**ito1_1.maiml（単一method時）:**
```xml
<pnml id="pnml_ito1_3187e22c">
<program id="program_ito1_3187e22c">
```
→ `documentData.pnmlId` / `documentData.programId`（DocumentData型のフィールド）が優先される

**ito1_2.maiml（複数method追加後）:**
```xml
<pnml id="pnml_method_ito1_3187e22c">
<program id="program_method_ito1_3187e22c">
```
→ `multiMethodConverter.ts` の `pnml_${methodId}` / `program_${methodId}` 形式が使われる

### 根本原因

`DocumentData` 型に `protocolId` / `methodId` / `pnmlId` / `programId` フィールドが存在し、DocumentEditDialogから手動入力できる状態になっている。

- **単一method時（`reactFlowToMaiml.ts`）**:
  ```typescript
  const pnmlId = documentData?.pnmlId || originalStructure?.pnml?.id || `pnml_${methodId}`;
  ```
  → `documentData.pnmlId`（`pnml_ito1_3187e22c`）が優先され旧IDがそのまま使われる

- **複数method時（`multiMethodConverter.ts`）**:
  ```typescript
  const pnmlId = `pnml_${methodId}`;  // 常にmethodIdベースの命名
  ```
  → `pnml_method_ito1_3187e22c` になる

DocumentEditDialogで設定されたIDが `documentData` に残り続けるため、単一/複数の切り替え時に命名規則が不一致となる。

### 修正方針

#### 修正6-1: DocumentData型からID系フィールドを削除

これらのフィールドはUIからの手動入力を可能にしており、命名規則の不一致バグの温床となっているため削除する。

- **`frontend/src/utils/documentParser.ts`**（インターフェース定義 行13〜27）
  - `protocolId?: string;` を削除
  - `methodId?: string;` を削除
  - `pnmlId?: string;` を削除
  - `programId?: string;` を削除

- **`frontend/src/types/editor.ts`**（DocumentData extends Document 行112〜129）
  - エディター用拡張プロパティのProtocol/Method/PNML/Program IDフィールドを削除

#### 修正6-2: DocumentEditDialogからID入力フィールドを削除

- **`frontend/src/components/editorv2/DocumentEditDialog.tsx`**
  - `<Form.Item label="Protocol ID" name="protocolId">` 削除
  - `<Form.Item label="Method ID" name="methodId">` 削除
  - `<Form.Item label="PNML ID" name="pnmlId">` 削除
  - `<Form.Item label="Program ID" name="programId">` 削除

- **`frontend/src/reference/components/PetriNetEditorV2/components/DocumentEditDialog.jsx`**
  - 同様の入力フィールドを削除

#### 修正6-3: reactFlowToMaiml.ts のdocumentDataフォールバックを削除

`documentData?.pnmlId` / `documentData?.programId` への参照をなくし、常に `pnml_${methodId}` 形式で統一する。

```typescript
// 修正前
const pnmlId = documentData?.pnmlId || originalStructure?.pnml?.id || `pnml_${methodId}`;
const programId = documentData?.programId || originalStructure?.program?.id || `program_${methodId}`;

// 修正後
const pnmlId = originalStructure?.pnml?.id || `pnml_${methodId}`;
const programId = originalStructure?.program?.id || `program_${methodId}`;
```

同様に `protocolId` / `methodId` の参照も `documentData?.` 部分を削除する。

#### 修正6-4: PetriNetEditorInner.tsx のID引き継ぎロジックを削除

MAIMLロード時に `protocolId`, `methodId`, `pnmlId`, `programId` を `documentData` にマージしているロジックを削除する。

#### 修正6-5: 今回スキップ

`multiMethodConverter.ts` に既存MAIMLのpnml/program ID文字列引き継ぎを追加するには、`ExtractedUuids` 型にID文字列Mapを追加し、`maimlUuidExtractor.ts` でID文字列を抽出する大きな変更が必要なため、今回はスキップする。

#### 修正6-6: documentParser.ts のXML→IDの抽出・自動生成ロジックは保持

`parseDocumentElement()` でMAIMLのXMLタグからID属性を読み取る処理、および `getFullDocumentData()` でIDが無効な場合に自動生成する処理は引き続き必要なため**保持する**。
