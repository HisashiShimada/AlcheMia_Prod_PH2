# OpenStack Swift 別端末移行手順

## メタデータ
- **作成日時**: 2026-01-08 15:03
- **対象**: ローカルDockerから別サーバーのSwift環境への移行
- **前提条件**: ローカルDocker環境でSwiftが正常動作していること

---

## 1. 概要

### 移行の目的
- 開発環境のローカルDockerから、専用サーバーのOpenStack Swiftへ移行
- 本番に近い環境でのテスト実施
- 複数の開発者による共有環境の構築

### 移行前後の比較

| 項目 | 移行前（ローカル） | 移行後（別サーバー） |
|------|------------------|-------------------|
| エンドポイント | localhost:8080 | 192.168.x.x:8080 |
| アクセス方法 | Docker内部 | ネットワーク経由 |
| 認証情報 | test:tester | 本番用認証情報 |
| データ永続性 | ローカルボリューム | サーバーストレージ |
| パフォーマンス | 低 | 中〜高 |
| 可用性 | 低（PC電源依存） | 高（専用サーバー） |

## 2. 別サーバーのSwift環境セットアップ

### 2.1. 別サーバーでのSwiftインストール

#### 方法1: Dockerを使用（推奨）

```bash
# 別サーバーにSSH接続
ssh user@192.168.x.x

# Docker & Docker Composeのインストール確認
docker --version
docker-compose --version

# mmdpf用のディレクトリを作成
mkdir -p /opt/mmdpf
cd /opt/mmdpf

# docker-compose.ymlを作成
cat > docker-compose.yml <<'EOF'
version: '3.8'

services:
  swift:
    image: bouncestorage/swift-aio:latest
    container_name: mmdpf-swift
    ports:
      - "8080:8080"
    environment:
      - AUTH_URL=http://0.0.0.0:8080/auth/v1.0
      - ACCOUNT=mmdpf
      - USER=mmdpf_user
      - PASSWORD=your-secure-password-here
    volumes:
      - /opt/mmdpf/swift-data:/srv
    restart: unless-stopped
    networks:
      - mmdpf-network

networks:
  mmdpf-network:
    name: mmdpf-network
    driver: bridge
EOF

# Swiftコンテナの起動
docker-compose up -d

# 起動確認
docker-compose ps
docker-compose logs swift
```

#### 方法2: ネイティブインストール（Ubuntu）

```bash
# OpenStack Swiftのインストール
sudo apt update
sudo apt install -y swift swift-proxy swift-account swift-container swift-object

# 設定ファイルの配置
# /etc/swift/ 配下に設定ファイルを配置
# （詳細は OpenStack Swift 公式ドキュメントを参照）

# Swiftサービスの起動
sudo systemctl start swift-proxy
sudo systemctl start swift-account
sudo systemctl start swift-container
sudo systemctl start swift-object

# 起動確認
sudo systemctl status swift-proxy
```

### 2.2. コンテナの作成

```bash
# Swiftコンテナ内に入る（Docker版の場合）
docker exec -it mmdpf-swift bash

# コンテナの作成
swift -A http://localhost:8080/auth/v1.0 \
  -U mmdpf:mmdpf_user \
  -K your-secure-password-here \
  post mmdpf-files

# コンテナの確認
swift -A http://localhost:8080/auth/v1.0 \
  -U mmdpf:mmdpf_user \
  -K your-secure-password-here \
  list

# 正常に "mmdpf-files" が表示されることを確認
```

### 2.3. ファイアウォール設定

```bash
# ポート8080を開放（UFWの場合）
sudo ufw allow 8080/tcp
sudo ufw reload

# iptablesの場合
sudo iptables -A INPUT -p tcp --dport 8080 -j ACCEPT
sudo iptables-save > /etc/iptables/rules.v4
```

### 2.4. 接続テスト（別サーバー側）

```bash
# 別サーバーのローカルから接続テスト
curl -v -H "X-Auth-User: mmdpf:mmdpf_user" \
  -H "X-Auth-Key: your-secure-password-here" \
  http://localhost:8080/auth/v1.0

# 認証トークンが返却されることを確認
```

## 3. mmdpfバックエンドの環境変数変更

### 3.1. backend/.env の修正

```bash
# ローカルの開発環境で backend/.env を編集
cd /home/mi_ito/mmdpf/backend
vi .env
```

#### 変更前（ローカルDocker）

```bash
# Storage Configuration
STORAGE_TYPE=swift

# OpenStack Swift Configuration
SWIFT_AUTH_URL=http://localhost:8080/auth/v1.0
SWIFT_USERNAME=test:tester
SWIFT_PASSWORD=testing
SWIFT_ACCOUNT=test
SWIFT_CONTAINER=mmdpf-files

# S3互換APIモード
USE_S3_COMPATIBLE_API=true
S3_ENDPOINT=http://localhost:8080
S3_ACCESS_KEY_ID=test:tester
S3_SECRET_ACCESS_KEY=testing
S3_BUCKET_NAME=mmdpf-files
S3_REGION=us-east-1
S3_FORCE_PATH_STYLE=true
```

#### 変更後（別サーバー）

```bash
# Storage Configuration
STORAGE_TYPE=swift

# OpenStack Swift Configuration
SWIFT_AUTH_URL=http://192.168.x.x:8080/auth/v1.0
SWIFT_USERNAME=mmdpf:mmdpf_user
SWIFT_PASSWORD=your-secure-password-here
SWIFT_ACCOUNT=mmdpf
SWIFT_CONTAINER=mmdpf-files

# S3互換APIモード
USE_S3_COMPATIBLE_API=true
S3_ENDPOINT=http://192.168.x.x:8080
S3_ACCESS_KEY_ID=mmdpf:mmdpf_user
S3_SECRET_ACCESS_KEY=your-secure-password-here
S3_BUCKET_NAME=mmdpf-files
S3_REGION=us-east-1
S3_FORCE_PATH_STYLE=true
```

**重要な変更点:**
1. `localhost` を別サーバーのIPアドレス `192.168.x.x` に変更
2. 認証情報を本番用に変更
   - `SWIFT_USERNAME`: `test:tester` → `mmdpf:mmdpf_user`
   - `SWIFT_PASSWORD`: `testing` → 本番用パスワード
   - `SWIFT_ACCOUNT`: `test` → `mmdpf`

### 3.2. 環境変数の反映

```bash

cd /home/mi_ito/mmdpf/backend
npm run dev

# または
```

## 5. データ移行（オプション）

既存のローカルSwiftデータを別サーバーに移行する場合：

### 5.1. ローカルからのデータエクスポート

```bash
# ローカルSwiftコンテナからファイル一覧を取得
docker exec mmdpf-swift swift -A http://localhost:8080/auth/v1.0 \
  -U test:tester -K testing list mmdpf-files > local_files.txt

# ファイルをダウンロード
mkdir -p /tmp/swift-export
cd /tmp/swift-export

while IFS= read -r file; do
  docker exec mmdpf-swift swift -A http://localhost:8080/auth/v1.0 \
    -U test:tester -K testing download mmdpf-files "$file" -o "$file"
done < local_files.txt
```

### 5.2. 別サーバーへのデータインポート

```bash
# エクスポートしたファイルを別サーバーにコピー
scp -r /tmp/swift-export/* user@192.168.x.x:/tmp/swift-import/

# 別サーバーにSSH接続
ssh user@192.168.x.x

# ファイルをアップロード
cd /tmp/swift-import
find . -type f | while read file; do
  docker exec mmdpf-swift swift -A http://localhost:8080/auth/v1.0 \
    -U mmdpf:mmdpf_user -K your-secure-password-here \
    upload mmdpf-files "$file" --object-name "${file#./}"
done
```

## 6. トラブルシューティング

### 問題1: 接続できない

**症状:**
```
Error: connect ECONNREFUSED 192.168.x.x:8080
```

**原因と対策:**
1. **ファイアウォールでポートが閉じている**
   ```bash
   # 別サーバーで
   sudo ufw status
   sudo ufw allow 8080/tcp
   ```

2. **Swiftコンテナが起動していない**
   ```bash
   # 別サーバーで
   docker-compose ps
   docker-compose up -d swift
   ```

3. **ネットワークルーティングの問題**
   ```bash
   # 開発マシンで
   ping 192.168.x.x
   traceroute 192.168.x.x
   ```

### 問題2: 認証エラー

**症状:**
```
403 Forbidden
または
401 Unauthorized
```

**原因と対策:**
1. **認証情報が間違っている**
   ```bash
   # .envファイルの認証情報を確認
   cat backend/.env | grep SWIFT
   
   # 正しい認証情報で手動テスト
   curl -v -H "X-Auth-User: mmdpf:mmdpf_user" \
     -H "X-Auth-Key: your-secure-password-here" \
     http://192.168.x.x:8080/auth/v1.0
   ```

2. **コンテナが存在しない**
   ```bash
   # 別サーバーで
   docker exec -it mmdpf-swift bash
   swift -A http://localhost:8080/auth/v1.0 \
     -U mmdpf:mmdpf_user -K your-secure-password-here \
     list
   
   # コンテナが存在しない場合は作成
   swift -A http://localhost:8080/auth/v1.0 \
     -U mmdpf:mmdpf_user -K your-secure-password-here \
     post mmdpf-files
   ```

### 問題3: ファイルアップロード失敗

**症状:**
```
Error: Failed to upload file
```

**原因と対策:**
1. **コンテナの権限不足**
   ```bash
   # 別サーバーで
   docker exec -it mmdpf-swift bash
   ls -la /srv
   chmod -R 777 /srv  # 開発環境の場合のみ
   ```

2. **ディスク容量不足**
   ```bash
   # 別サーバーで
   df -h
   docker system df
   docker system prune -a  # 不要なデータを削除
   ```

### 問題4: パフォーマンスが遅い

**原因と対策:**
1. **ネットワーク帯域が狭い**
   ```bash
   # ネットワーク速度を測定
   iperf3 -c 192.168.x.x
   ```

2. **Swiftサーバーのリソース不足**
   ```bash
   # 別サーバーで
   docker stats mmdpf-swift
   htop
   ```

## 7. セキュリティ考慮事項

### 7.1. 本番環境への移行時の注意点

1. **強力なパスワードの使用**
   ```bash
   # 20文字以上のランダムなパスワードを生成
   openssl rand -base64 32
   ```

2. **HTTPSの使用（推奨）**
   - Nginx等のリバースプロキシでSSL/TLS終端
   - Let's Encryptで証明書を取得

3. **IPアドレス制限**
   ```bash
   # ファイアウォールで特定IPのみ許可
   sudo ufw allow from 192.168.1.0/24 to any port 8080
   ```

4. **監査ログの有効化**
   - Swiftのログを別途保存
   - アクセスログを定期的に確認

### 7.2. 環境変数の管理

```bash
# .envファイルの権限設定
chmod 600 backend/.env

# Gitにコミットしないように確認
grep "^\.env$" .gitignore
```

## 8. 運用手順

### 8.1. 日常的な監視

```bash
# Swiftサービスの状態確認
docker-compose ps

# ディスク使用量確認
du -sh /opt/mmdpf/swift-data

# ログ確認
docker-compose logs --tail=100 swift
```

### 8.2. バックアップ

```bash
# 定期バックアップスクリプト
#!/bin/bash
BACKUP_DIR=/backup/swift-$(date +%Y%m%d)
mkdir -p $BACKUP_DIR

# データのバックアップ
docker run --rm -v /opt/mmdpf/swift-data:/data \
  -v $BACKUP_DIR:/backup alpine \
  tar czf /backup/swift-data.tar.gz /data

# 古いバックアップの削除（30日以上前）
find /backup -name "swift-*" -mtime +30 -exec rm -rf {} \;
```

### 8.3. トラブル時の対応

```bash
# Swiftコンテナの再起動
docker-compose restart swift

# 完全な再作成
docker-compose down
docker-compose up -d swift

# ログの詳細確認
docker-compose logs -f swift
```
