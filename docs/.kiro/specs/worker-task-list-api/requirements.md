# Requirements Document

## プロジェクト概要（Input）

実験作業者画面のタスク一覧の取得を行うバックエンドの機能を実装する。
仕様の部分については
'docs\design\api\api_progress_monitoring.md'
の4. タスク一覧取得APIを確認してください。

---

## 要件定義（Requirements）

### 要件1: タスク一覧取得

**目的:** 実験管理者および実験作業者として、プロジェクト内の全タスク状況を一覧で確認したい。その結果、進捗管理と作業割り当ての状況を把握できる。

#### 受入基準

1. When 有効なプロジェクトIDを指定してタスク一覧取得APIを呼び出す場合、the タスク一覧取得APIは該当プロジェクトの全タスク情報をメソッド単位でグループ化して返却すること
2. When タスク一覧を取得する場合、the タスク一覧取得APIはタスク番号、ステータス、担当者、作成日時、更新日時、進捗率を含むこと
3. The タスク一覧取得APIは認証済みユーザーのみがアクセス可能であること
4. The タスク一覧取得APIは`experiment_admin`、`experiment_worker`、`system_admin`ロールのユーザーのみが実行可能であること
5. When プロジェクト内に複数のメソッドが存在する場合、the タスク一覧取得APIは各メソッドをexperiment_order順に並べて返却すること

### 要件2: タスクフィルタリング

**目的:** 実験管理者として、特定の条件でタスクを絞り込みたい。その結果、効率的に必要な情報にアクセスできる。

#### 受入基準

1. When メソッドIDを指定してタスク一覧を取得する場合、the タスク一覧取得APIは指定されたメソッドに属するタスクのみを返却すること
2. When ステータスを指定してタスク一覧を取得する場合、the タスク一覧取得APIは指定されたステータス（not_started、started、in_progress、completed、forced_terminated）のタスクのみを返却すること
3. When 担当者IDを指定してタスク一覧を取得する場合、the タスク一覧取得APIは指定された担当者に割り当てられたタスクのみを返却すること
4. When 複数のフィルタ条件を指定する場合、the タスク一覧取得APIはすべての条件を満たすタスクのみを返却すること

### 要件3: タスクソート

**目的:** 実験管理者として、タスクを任意の順序で表示したい。その結果、状況に応じた優先順位で情報を確認できる。

#### 受入基準

1. When ソート基準を指定しない場合、the タスク一覧取得APIはタスク番号の昇順でタスクを返却すること
2. When ソート基準（sortBy）を指定する場合、the タスク一覧取得APIは指定された項目（task_no、created_at、updated_at、status）でソートしてタスクを返却すること
3. When ソート順（order）を指定する場合、the タスク一覧取得APIは昇順（asc）または降順（desc）でタスクを返却すること
4. The タスク一覧取得APIは同一メソッド内のタスクに対してのみソートを適用すること

### 要件4: メソッドグループ化

**目的:** 実験管理者として、タスクをメソッド単位で整理して表示したい。その結果、実験フロー全体の進捗を把握できる。

#### 受入基準

1. The タスク一覧取得APIは各メソッドにmethod_id、method_name、experiment_orderを含むこと
2. When プロジェクトのMAIMLファイルに複数のメソッドが定義されている場合、the タスク一覧取得APIはすべてのメソッドを含むレスポンスを返却すること
3. When メソッドにタスクが割り当てられていない場合、the タスク一覧取得APIは該当メソッドを空のタスク配列とともに返却すること
4. The タスク一覧取得APIは各メソッドのexperiment_orderに基づいてメソッドを並べること

### 要件5: マルチテナント分離

**目的:** システム管理者として、組織間のデータ分離を確保したい。その結果、セキュリティとプライバシーを保護できる。

#### 受入基準

1. The タスク一覧取得APIはすべてのデータベースクエリにorganization_idフィルタを適用すること
2. The タスク一覧取得APIは認証済みユーザーの所属組織のタスクのみを返却すること
3. If ユーザーが他組織のプロジェクトIDを指定した場合、then the タスク一覧取得APIは404エラー（プロジェクトが存在しない）を返却すること
4. The タスク一覧取得APIはレスポンスに他組織の情報を含まないこと

### 要件6: 認証と認可

**目的:** セキュリティ管理者として、適切な権限を持つユーザーのみがAPIにアクセスできるようにしたい。その結果、不正アクセスを防止できる。

#### 受入基準

1. If 認証トークンが提供されていない場合、then the タスク一覧取得APIは401エラー（認証エラー）を返却すること
2. If 認証トークンが無効または期限切れの場合、then the タスク一覧取得APIは401エラーを返却すること
3. The タスク一覧取得APIはAuthorizationヘッダーからJWTトークンを取得して検証すること

### 要件7: バリデーション

**目的:** 開発者として、不正なリクエストを適切に処理したい。その結果、システムの安定性とユーザー体験を向上できる。

#### 受入基準

1. If プロジェクトID（projectId）が提供されていない場合、then the タスク一覧取得APIは400エラー（バリデーションエラー）を返却すること
2. If プロジェクトIDがUUID形式でない場合、then the タスク一覧取得APIは400エラーを返却すること
3. If ステータスが無効な値の場合、then the タスク一覧取得APIは400エラーとともに有効な値のリストを返却すること
4. If ソート基準（sortBy）が無効な値の場合、then the タスク一覧取得APIは400エラーとともに有効なソート項目のリストを返却すること
5. If ソート順（order）が"asc"または"desc"以外の場合、then the タスク一覧取得APIは400エラーを返却すること

### 要件8: エラーハンドリング

**目的:** 開発者として、エラー時に適切な情報を提供したい。その結果、問題の診断と解決を容易にできる。

#### 受入基準

1. If 指定されたプロジェクトが存在しない場合、then the タスク一覧取得APIは404エラー（プロジェクトが存在しない）を返却すること
2. If データベース接続エラーが発生した場合、then the タスク一覧取得APIは500エラー（システムエラー）を返却すること
3. If MAIMLファイルの読み込みに失敗した場合、then the タスク一覧取得APIは500エラーを返却すること
4. The タスク一覧取得APIはすべてのエラーレスポンスにerror code、message、detailsを含むこと
5. The タスク一覧取得APIはすべてのレスポンスにmeta情報（timestamp、requestId）を含むこと

### 要件9: レスポンス形式

**目的:** フロントエンド開発者として、統一されたレスポンス形式で情報を受け取りたい。その結果、一貫性のあるクライアント実装ができる。

#### 受入基準

1. The タスク一覧取得APIは成功時にsuccessフィールドをtrueに設定して返却すること
2. The タスク一覧取得APIは成功時にdataフィールドにタスク一覧データを含めて返却すること
3. The タスク一覧取得APIはエラー時にsuccessフィールドをfalseに設定して返却すること
4. The タスク一覧取得APIはエラー時にerrorフィールドにエラー情報を含めて返却すること
5. The タスク一覧取得APIはすべてのレスポンスにmetaフィールド（timestamp、requestId）を含めること

### 要件10: パフォーマンス

**目的:** システム管理者として、APIが適切なパフォーマンスで動作することを確保したい。その結果、ユーザー体験を向上できる。

#### 受入基準

1. The タスク一覧取得APIは100タスク以内のプロジェクトに対して2秒以内にレスポンスを返却すること
2. The タスク一覧取得APIは効率的なデータベースクエリを使用してN+1問題を回避すること
3. When 大量のタスクが存在する場合、the タスク一覧取得APIは適切なJOINとGROUP BYを使用してクエリ数を最小化すること
4. The タスク一覧取得APIは不要なデータ取得を避け、必要な情報のみをクエリすること

### 要件11: データ整合性

**目的:** データ管理者として、返却されるデータの整合性を保証したい。その結果、信頼性の高い情報を提供できる。

#### 受入基準

1. The タスク一覧取得APIはMAIMLファイルで定義されたメソッド情報とproject_taskテーブルのデータを突合して返却すること
2. If MAIMLファイルに存在しないメソッドIDを持つタスクがデータベースに存在する場合、then the タスク一覧取得APIはそのタスクを含めずにログに警告を記録すること
3. The タスク一覧取得APIは担当者情報がnullの場合も適切に処理すること
4. The タスク一覧取得APIは日時フィールドをISO 8601形式（YYYY-MM-DDTHH:mm:ss.sssZ）で返却すること

## 非機能要件

### セキュリティ
- すべてのデータベースクエリにorganization_idフィルタを適用
- Parameterized Queriesを使用してSQLインジェクションを防止
- 認証トークンの検証を実装
- ロールベースアクセス制御（RBAC）を実装

### 可用性
- データベース接続エラー時の適切なリトライ処理
- エラーログの記録とモニタリング

### 保守性
- 統一されたエラーハンドリングパターンの使用
- 適切なログ出力（情報、警告、エラー）
- コードコメントとドキュメンテーション

---

## 受入条件

このAPIが完成したと判断するための条件：

1. ✅ すべての受入基準がテストで検証されている
2. ✅ マルチテナント分離が正しく実装されている
3. ✅ 認証と認可が適切に機能している
4. ✅ エラーハンドリングがすべてのケースで適切に動作している
5. ✅ レスポンス形式が統一された形式に準拠している
6. ✅ パフォーマンステストで基準を満たしている
7. ✅ セキュリティチェックリストがすべてクリアされている
8. ✅ APIドキュメントが最新化されている
