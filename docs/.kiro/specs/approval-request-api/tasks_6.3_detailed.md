# タスク6.3 統合テスト実装 - 詳細分割

## 概要
POST /api/v1/projects/:projectId/approval-request エンドポイントの統合テストを実装します。
各サブタスクはTDDのRED-GREEN-REFACTORサイクルに従って実装されます。

## サブタスク一覧

- [ ] 6.3.1: テスト環境セットアップとベーステスト
  - テストファイル作成とSupertestセットアップ
  - テストデータベース接続確認
  - 共通ヘルパー関数実装（JWT生成、テストユーザー作成等）
  - サーバー起動/停止の確認

- [ ] 6.3.2: 正常系統合テスト（200 OK）
  - **RED**: 正常な承認依頼リクエストのテストを書く
  - **GREEN**: リクエストが成功し、正しいレスポンスが返ることを確認
  - **REFACTOR**: テストコードの整理
  - 検証項目：
    - ステータスコード200
    - レスポンス形式（success: true, data, meta）
    - データベースのproject_status更新確認
    - 通知レコード作成確認

- [ ] 6.3.3: 認証エラーテスト（401 Unauthorized）
  - **RED**: JWTトークンなしのリクエストテストを書く
  - **GREEN**: 401エラーが返ることを確認
  - **REFACTOR**: エラーレスポンス検証の共通化
  - 検証項目：
    - ステータスコード401
    - エラーメッセージ

- [ ] 6.3.4: 権限エラーテスト（403 Forbidden）
  - **RED**: 不適切なロール（例：data_admin）でのリクエストテストを書く
  - **GREEN**: 403エラーが返ることを確認
  - **REFACTOR**: 権限テストの共通化
  - 検証項目：
    - ステータスコード403
    - エラーメッセージ

- [ ] 6.3.5: バリデーションエラーテスト（400 Bad Request）
  - **RED**: 不正なprojectId形式のテストを書く
  - **GREEN**: 400エラーが返ることを確認
  - **REFACTOR**: バリデーションテストの整理
  - 検証項目：
    - 不正UUID形式
    - comment長すぎる（1001文字）
    - エラーレスポンス形式

- [ ] 6.3.6: リソース不存在テスト（404 Not Found）
  - **RED**: 存在しないprojectIdのテストを書く
  - **GREEN**: 404エラーが返ることを確認
  - **REFACTOR**: テストコードの最適化
  - 検証項目：
    - ステータスコード404
    - エラーメッセージ

- [ ] 6.3.7: ビジネスルール違反テスト（409 Conflict）
  - **RED**: 'active'以外のステータスのプロジェクトでテストを書く
  - **GREEN**: 409エラーが返ることを確認
  - **REFACTOR**: 全体のテストコード見直し
  - 検証項目：
    - draft状態でのリクエスト
    - waiting_approval状態でのリクエスト
    - approved状態でのリクエスト
    - archived状態でのリクエスト
    - 適切なエラーメッセージ

## 実行順序
1. 6.3.1 → 6.3.2 → 6.3.3 → 6.3.4 → 6.3.5 → 6.3.6 → 6.3.7
2. 各サブタスクはRED-GREEN-REFACTORサイクルで実装
3. 前のサブタスクが完了してから次に進む

## 成功基準
- 全テストが合格（green）
- カバレッジ70%以上を維持
- レスポンスタイム < 500ms
- エッジケースも網羅
