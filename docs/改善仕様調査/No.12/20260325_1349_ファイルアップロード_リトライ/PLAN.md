## タスク概要

ファイルアップロード時にサーバーエラー・ネットワークエラー・タイムアウトが発生した場合、自動的に最大3回リトライする機能を実装する。
リトライ間隔は指数バックオフ（1秒→2秒→4秒）とし、HTTP 400/401/403/404 など入力起因のエラーはリトライせず即時エラー表示する。

## 目的と期待される成果

- [ ] ネットワーク一時切断・サーバー一時エラーで自動復旧できる
- [ ] リトライ対象外エラー（認証エラー等）は即時エラー表示する
- [ ] ダイアログ上にリトライ中の状態（何回目のリトライか）が表示される
- [ ] 最大リトライ回数を超えた場合はエラーメッセージを表示する

## 実装ステップ

### Phase 1: 型定義追加
> **型定義とは**: 「このデータはこういう形です」という設計図をコードで書くこと。
> Phase 2・3 で使うデータの形を先に定義しておく。

- [ ] `frontend/src/types/file.ts` に `UploadRetryOptions`・`UploadRetryState` 型を追加
  - `UploadRetryOptions`：リトライの**設定**（最大何回？何秒待つ？）
  - `UploadRetryState`：リトライの**状態**（今何回目？）→ UI表示に使用

### Phase 2: リトライユーティリティ実装
> **目的**: アップロード失敗時に自動で再試行するロジックを追加する。
> 現状は失敗すると即エラーになるが、失敗の種類によって自動リトライするようにする。

- [ ] `frontend/src/services/fileAccessService.ts` に `withRetry()` 関数を追加
  - `isRetryableError()`：エラーがリトライ対象かどうかを判定する関数
    - HTTP 500/502/503/504（サーバー一時エラー）→ リトライする
    - ERR_NETWORK（ネットワーク切断）/ ECONNABORTED（タイムアウト）→ リトライする
    - HTTP 400/401/403/404（入力ミス・認証エラー）→ リトライしない（即エラー）
  - `withRetry()`：失敗したら指数バックオフで待機してから再試行する関数
    - 指数バックオフ（1秒→2秒→4秒）
    - リトライするたびに「今何回目か」をUI側へコールバックで通知する
- [ ] 既存の `uploadFiles()` 関数を `withRetry()` でラップするよう改修
  - 変更前: `await client.post(...)` で直接APIを呼ぶ
  - 変更後: `await withRetry(() => client.post(...), ...)` でリトライ付きに変更

### Phase 3: UIにリトライ状態を表示
> **目的**: ダイアログ上に「リトライ中... (1/3)」のようなメッセージを表示する。

- [ ] `frontend/src/components/project/BulkUploadDialog.tsx` にリトライ状態表示を追加
  - `UploadState` に `retryState` フィールドを追加（Phase 1 の型を使用）
  - 「アップロード中」表示を「リトライ中... (1/3)」に切り替わるよう変更
  - リトライ中はキャンセルボタンを無効化
- [ ] `frontend/src/components/project/FormatUploadDialog.tsx` に同様の表示を追加

## リトライ仕様

| 項目 | 値 |
|---|---|
| 最大リトライ回数 | 3回 |
| バックオフ方式 | 指数バックオフ |
| 待機時間 | 1秒 → 2秒 → 4秒 |

## リトライ対象エラー

| エラー | 対応 |
|---|---|
| HTTP 500 / 502 / 503 / 504 | リトライ |
| ネットワークエラー（ERR_NETWORK） | リトライ |
| タイムアウト（ECONNABORTED） | リトライ |
| HTTP 400 / 401 / 403 / 404 | 即時エラー表示（リトライなし） |

## リスク

| リスク | 影響度 | 対策 |
|---|---|---|
| リトライ中に同じファイルが二重登録される | 中 | サーバー側の冪等性を確認、またはアップロード前に重複チェック |
| リトライ中にユーザーが別操作を行う | 低 | リトライ中はUIを操作不可（ローディング状態）にする |

## 失敗時のエラーメッセージ仕様

エラーメッセージは以下の **2か所** に表示される：
- **画面上部のトースト通知**（Ant Design `message.error()`）
- **ダイアログ内の赤色 Alert**（タイトル: 「アップロードエラー」、説明に下記メッセージ、閉じるボタン付き）

| エラーの種類 | エラーコード | 表示メッセージ |
|---|---|---|
| ネットワーク切断（3回リトライ後） | E3001 | サーバーに接続できません。ネットワークを確認してください |
| タイムアウト（3回リトライ後） | E3002 | リクエストがタイムアウトしました。再度お試しください |
| HTTP 500/502/503/504（3回リトライ後） | E4001 | サーバー内部エラーが発生しました。管理者にお問い合わせください |
| HTTP 403（即時エラー・リトライなし） | E5012 | アクセスが拒否されました |
| HTTP 401（即時エラー・リトライなし） | E5013 | 認証が必要です。再度ログインしてください |
| HTTP 400（即時エラー・リトライなし） | E1003 | 入力内容に誤りがあります |
| HTTP 404（即時エラー・リトライなし） | E6001 | 指定されたリソースが見つかりません |
| ストレージエラー | E4006 | ストレージエラーが発生しました。管理者にお問い合わせください |
| 全ファイル失敗（すべてのファイルが失敗） | E9999 | エラーが発生しました。しばらくしてから再度お試しください |

> **参照**: `frontend/src/utils/errorMapper.ts`、`frontend/src/utils/errorUtils.ts`

## まとめ

サーバーエラー・ネットワークエラー・タイムアウトが発生した際に最大 3 回まで自動リトライするユーティリティ（`withRetry()`）を追加するタスク。指数バックオフ（1秒→2秒→4秒）で再試行し、HTTP 400/401/403/404 などの入力起因エラーはリトライ対象外として即時エラー表示する。

変更対象はフロントエンド **4 ファイル**（型定義・サービス・BulkUploadDialog・FormatUploadDialog）。ダイアログ上には「接続エラーが発生しました。自動リトライ中... (X/3)」のステータスを表示し、リトライ中はキャンセルボタンを無効化することでユーザーへの状況通知と二重操作防止を両立する。

| ファイル | 変更内容 |
|---|---|
| `frontend/src/types/file.ts` | `UploadRetryOptions`・`UploadRetryState` 型追加、`UploadFilesParams` に `onRetry` コールバック追加 |
| `frontend/src/services/fileAccessService.ts` | `isRetryableError()`・`withRetry()` 追加、`uploadSingleFile()` 内の `client.post()` を `withRetry()` でラップ |
| `frontend/src/components/project/BulkUploadDialog.tsx` | `retryState` state 追加、`onRetry` コールバック接続、「自動リトライ中... (X/3)」Alert 表示 |
| `frontend/src/components/project/FormatUploadDialog.tsx` | 同上（BulkUploadDialog と同一の対応） |

なお、`withRetry()` でラップしているのは通常方式（10MB 以下）の `uploadSingleFile()` 内のリクエストのみ。チャンク方式（`uploadFileWithChunks()`）はチャンク単位でリトライを行うと一時ファイルの整合性が複雑化するため、現時点ではリトライ対象外としている。
