## 削除API（deleteFile）との比較

削除APIでは以下のように `project_maiml_flg` を更新しています：

**ファイル**: `backend/src/controllers/fileAccessController.ts`

```typescript
// ③ オプショナル: project_maiml_flg更新（checkProjectStatus === true かつ MAIMLファイルの場合）
if (checkProjectStatus === true) {
  const fileName = fileKey.split('/').pop() || '';
  const isMaimlFile = fileName.endsWith('.maiml');

  if (isMaimlFile && (fileKey.startsWith('projects/') || fileKey.includes('/projects/'))) {
    console.log('🔍 [File Delete] MAIMLファイル削除、project_maiml_flg更新開始:', fileKey);

    // fileKeyからプロジェクト名を抽出
    const pathParts = fileKey.split('/');
    const projectsIndex = pathParts.findIndex((part: string) => part === 'projects');
    
    if (projectsIndex !== -1 && pathParts.length > projectsIndex + 1) {
      const projectName = pathParts[projectsIndex + 1];

      try {
        // プロジェクト情報を取得
        const existingProject = await projectRepository.findByName(organizationId, projectName);

        if (!existingProject) {
          console.warn(`⚠️ [File Delete] プロジェクトが見つかりません: ${projectName}`);
        } else if (existingProject.project_maiml_flg) {
          // project_maiml_flgがtrueの場合のみfalseに更新
          const updatedProject: Project = {
            ...existingProject,
            project_maiml_flg: false,
          };

          await projectRepository.update(updatedProject);
          console.log('✅ [File Delete] project_maiml_flg=false更新完了:', projectName);
        }
      } catch (updateError) {
        console.error('❌ [File Delete] project_maiml_flg更新失敗（処理は続行）:', {
          projectName,
          error: updateError,
        });
      }
    }
  }
}
```

**削除APIの実装状況**:
- MAIMLファイル削除時に `project_maiml_flg = false` に更新
- プロジェクト名を抽出してプロジェクト情報を取得
- フラグがtrueの場合のみfalseに更新

## まとめ

### 現状

| 処理 | project_maiml_flg更新 | 実装箇所 |
|------|---------------------|---------|
| **MAIMLファイルアップロード** | ❌ **未実装** | - |
| **MAIMLファイル削除** | ✅ **実装済み** | `fileAccessController.ts` (deleteFile) |
| **MAIMLファイル編集保存** | ✅ **実装済み** | `maimlService.ts` (saveMaiML) |

### 問題点

1. **一貫性の欠如**
   - 削除時と保存時はフラグを更新するが、アップロード時は更新しない
   - ユーザーがプロジェクト管理画面からMAIMLファイルをアップロードしても、フラグが更新されない

2. **実装が中途半端**
   - Service層で `hasMaimlFile` フラグを計算している
   - コメントに「Phase 2」と記載されているが、DB更新処理が実装されていない
   - 実装する意図はあったが、未完成のまま残っている

3. **ユーザー体験への影響**
   - プロジェクト管理画面でMAIMLファイルをアップロードしても、`project_maiml_flg` が false のまま
   - 実験管理者が「MAIMLファイルがない」と誤認する可能性がある

## 推奨対応

### Option 1: アップロード時にもフラグを更新する（一貫性を保つ）

`fileAccessService.ts` の `uploadFiles` メソッドに以下の処理を追加：

```typescript
// MAIMLファイルがアップロードされた場合、project_maiml_flgを更新
if (hasMaimlFile && targetPath.startsWith('projects/')) {
  const pathParts = targetPath.split('/');
  if (pathParts.length >= 2) {
    const projectName = pathParts[1];
    
    try {
      const existingProject = await projectRepository.findByName(organizationId, projectName);
      
      if (existingProject && !existingProject.project_maiml_flg) {
        const updatedProject: Project = {
          ...existingProject,
          project_maiml_flg: true,
        };
        
        await projectRepository.update(updatedProject);
        console.log('✅ [Upload] project_maiml_flg=true更新完了:', projectName);
      }
    } catch (updateError) {
      console.error('❌ [Upload] project_maiml_flg更新失敗（処理は続行）:', {
        projectName,
        error: updateError,
      });
    }
  }
}
```

### Option 2: updateMaimlFlag 関数を廃止し、各API内で直接更新する（現在の方針）

- 削除API: すでに実装済み
- 保存API（maimlService.saveMaiML）: すでに実装済み
